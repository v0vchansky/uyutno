# `engine/` — фасад и всё, что меняет документ

Владеет документом, историей и состоянием инструментов. Ни `three`, ни `react`, ни DOM — слой гоняется в Jest node как state-машина ([ADR 0015](../../../../docs/adr/0015-arhitektura-dvizhka-planera.md), [testing-strategy](../../../../docs/product/architecture/testing-strategy.md), слой 2). Решения: [ADR 0018](../../../../docs/adr/0018-mutatsii-tranzaktsii-i-undo-planera.md) (мутации, транзакции, undo), [ADR 0019](../../../../docs/adr/0019-avtomat-instrumentov-i-vvod-planera.md) (автомат инструментов и ввод).

## Фасад и неймспейсы

`PlannerManager` — единственный публичный вход в движок. API нарезан неймспейсами по доменам: `document` (содержимое документа и производное), `view` (активный вид и камеры), `history` (undo/redo), `tools` (автомат конструктора); `selection` для мебели добавится своим шагом. Актуальный состав методов — в самих неймспейсах и в `src/index.ts`.

Правило: **неймспейс = один домен, его события — префикс `<домен>:`**. Новая команда идёт в существующий неймспейс своего домена, а не заводит новый; файлы внутри `engine/` при этом раскладываются по папкам свободно (`commands/`, `history/`, `tools/`) — папка и неймспейс не обязаны совпадать.

Читают снаружи через `get()`-снимки, узнают об изменениях через `subscribe` (wildcard) / `on`. Шина наружу пакета не отдаётся. Исключение подписчика изолируется фасадом и уходит в DI-логгер — оно не должно рвать команду и доставку остальным.

## Транзакция — единица изменения

`PlannerStore.transact` — **единственная точка мутации документа**. Порядок внутри:

1. рецепт мутирует черновик immer;
2. если изменилось содержимое (что-то кроме `view`) — синхронно `normalize` (нормализация хранимого в том же снимке) и `rebuild` (производное от финализированного снимка);
3. запись в историю по мете транзакции — снимок уже нормализован;
4. события — **по одному на изменившийся факт** и ни одного на no-op;
5. dirty-флаг — **после** эмита.

Документ, производное и флаги истории обновлены **до** эмита: подписчик всегда читает новый снимок. Исключение — dirty: подписчик `document:changed` ещё видит прежнее значение `isDirty()`, актуальное приходит отдельным событием следом. Транзакция, не изменившая документ (immer вернул тот же объект), не порождает ни записи, ни событий. Команда, отказавшая валидацией, транзакцию не начинает — документ остаётся тем же объектом.

Отсюда следствия, о которых легко забыть: rebuild — не «оптимизация на потом», а часть каждой транзакции содержимого; поэтому транзакций на `pointerMove` не бывает (см. границу с автоматом ниже), и поэтому ручных commit-точек в командах, инструментах и панелях нет.

## История

- **Два контейнера** — `layout` и `scene`. Это срезы одного документа, а не два графа: запись хранит **ссылки** на замороженные поддеревья всех этажей, поэтому снимок стоит O(1) по памяти и времени (структурное разделение immer). Модель — memento «stack + pointer»: baseline не откатывается, новый коммит режет redo-хвост.
- **Коалесинг** — по ключу: если ключ совпал с ключом последнего коммита, запись на указателе заменяется (серия правок одного поля = один шаг). **Ключ формирует команда, а не UI** — иначе гранулярность истории зависела бы от того, какая панель дёрнула команду.
- **Серию рвут:** любой другой коммит, undo/redo, `load` и смена выделения — `tools` зовёт `breakSeries()` (внутренний метод стора, не публичный API фасада).
- **Лимит** — `MAX_HISTORY` записей сверх baseline на контейнер, жёстко на каждом push: вытесненная запись становится новым baseline. Замена по коалесингу длину не меняет.
- **Активная зона** — зона активного вида, **но последняя запись/undo/redo переключает её на свою** до следующей смены вида. Так «Ctrl+Z откатывает то, что я только что сделал» остаётся верным, когда правка планировки приходит не из конструктора.
- **Не в истории:** `view` (активный вид и камеры), `settings`, выделение, состояние инструментов, промежуточные кадры жеста.
- Перед любой заменой поддерева мимо команд (restore, `load`) стор синхронно зовёт внутренний хук `beforeReplace` — туда подключён `tools.interrupt()`. Это хук, а не событие шины: «сейчас заменю» — не свершившийся факт, и порядок вызова важен.

## Dirty — отдельно от истории

«Есть несохранённые изменения» — не «история непуста»: undo тоже делает документ грязным. Флаг живёт в сторе, ставится любой транзакцией содержимого (включая restore), не ставится изменениями `view`; наружу — `document.isDirty()` / `document.markSaved()` и событие `document:dirty-changed` **только при смене значения**. `document:changed` подразумевает `dirty = true`, но флага не несёт.

## Шина

Имя события — `<неймспейс>:<факт в прошедшем времени>`. Payload — plain-данные (снимки, флаги), без объектов Three/DOM и без UI-подсказок. Одно событие на факт; edge-triggered пар вида `X_ACTIVE`/`X_INACTIVE` не заводить. `history:changed` может прийти без изменения документа (сменился вид → сменилась активная зона) — подписчик не вправе выводить из него «документ изменился».

## `Result` вместо исключений

Sync-команды возвращают `Result<T, E>` — discriminated union `{ ok: true; value } | { ok: false; error }`, где `error` — объект с полем `kind` и контекстом. Наружу движок исключений не бросает; `throw` внутри — только для нарушенных инвариантов, которых не может быть у корректного вызова. Каждая ветка ошибки каждой команды — отдельный тест.

## Автомат инструментов и его контракт с проекцией

`tools` — **один** типизированный автомат на discriminated union по `kind` (хаб правки + состояния рисования и драга). Второго автомата не будет: линейки, грипы мебели, будущие инструменты — режимы этого же. Состояния — plain-данные (они же payload шины и снимок для `useSyncExternalStore`), каждый переход даёт новый объект, состояние не мутируется.

Контракт с проекцией:

- **Вход — координаты плана.** Вьювер переводит экран → план сам (чистые функции `document/geometry/viewport.ts`) и отдаёт `PointerInput` / `KeyAction`. DOM-событий, канваса, пикселей и `window` в `engine/` нет и быть не может — слой без DOM.
- **Документ не меняется до коммита жеста.** Живое превью рисования и live-позиции драга — поля `ToolState`; вьювер рисует позицию как «переопределение жеста, иначе точка документа», поэтому ретриангуляции на кадр нет. Коммит — **одна** команда фасада на завершении (`pointerUp` драга, завершение контура, Enter в инпуте). Прерванный **драг** (Esc, `blur`, `pointercancel`, смена вида, `load`) не коммитится и следа в истории не оставляет; **рисование** рвут только Esc, `interrupt()`, смена вида и смена инструмента — потеря фокуса поставленные точки не роняет.
- **`tools:changed` идёт на каждое изменение состояния, включая `pointerMove`** — осознанное исключение, чтобы DOM-оверлей следовал за курсором. Плата: селекторы обязаны возвращать снимки/примитивы, а проекция чужого вида приостановлена.
- **Undo/redo маршрутизирует автомат:** в рисовании — локальный стек точек, в драге — отмена жеста, в хабе — история документа. Кнопки панели зовут тот же `tools.key`, а не `history.undo()` напрямую.

## Что здесь запрещено

- **Менять документ мимо `transact`** — включая «мне только поле подправить» в неймспейсе или инструменте. Снимок заморожен, так что попытка упадёт, но и обходить заморозку копией нельзя.
- **Писать в историю руками.** Запись — побочный эффект транзакции по её мете. `saveState()` из инструмента или панели — паттерн референса, от которого мы ушли осознанно (у него их были десятки).
- **Импортировать `three`, `react` и трогать DOM/`window`** — линт не пустит, но и обходить через динамический импорт нельзя: на этом держится дешёвый слой 2.
- **Держать состояние UI.** Пиксели, css-классы, ссылки на канвас, «какая панель открыта», hover-стили — это `ui/` и `projection/`. В `engine/` живёт только то, из чего UI выводится.
- **Глобалы и синглтоны.** Всё состояние — внутри экземпляра стора/менеджера: два планера на странице обязаны быть независимы.
