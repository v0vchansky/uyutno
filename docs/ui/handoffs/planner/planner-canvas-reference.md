# Эталон холста конструктора

Холст рисует наш код на Canvas 2D — макета в вёрстке для него нет. Здесь таблица «состояние → атрибуты отрисовки» и правила поведения при зуме. Референсные сцены — в `Planner P0 Constructor.dc.html`, группа e8, сцены 1–15 по чеклисту 8.1 брифа.

Подписи длин, поля ввода длины и подписи комнат в этой таблице не описаны: они не чертёжная графика, а обычная вёрстка поверх холста — см. `planner-editor-ui.md`.

Одно исключение — **подложка под подписью длины**: она есть всегда, а не только на штриховке. Подпись лежит поверх тела стены и штриховки, и без подложки текст на них не читается; ровный белый прямоугольник под всеми подписями спокойнее, чем подложка, которая появляется и исчезает в зависимости от того, что оказалось под текстом. Формулировка «без фона и рамки, читается как текст» в `planner-editor-ui.md` относится к **рамке поля ввода**, а не к этой подложке.

## Новые токены

Тема проекта красит интерфейс, а не чертёж. Чертёжной графике нужны свои токены — семантические, по решению 21: имя говорит, что токен красит, и не переиспользует роли светлой темы. Предлагаю добавить в `theme-uyutno.css` восемь значений:

| Токен                     | Значение     | Что красит                           |
| ------------------------- | ------------ | ------------------------------------ |
| `--draft-canvas`          | #FFFFFF      | фон холста конструктора              |
| `--draft-wall-body`       | #DEDEDE      | тело стены (заливка между сторонами) |
| `--draft-contour-line`    | #949494      | сторона контура                      |
| `--draft-room-fill`       | #FCFCFC      | заливка комнаты                      |
| `--draft-room-hatch`      | #F0F0F0      | штриховка комнаты                    |
| `--draft-point`           | #767676      | обводка хендла точки                 |
| `--draft-furniture-muted` | #EDEDED      | силуэты мебели в конструкторе        |
| `--draft-guide`           | = `--accent` | гайд снапа, крестик, превью ленты    |

Отдельного цвета выделения не вводим: выделение — это `--accent`, тот же, что у гайда. Разводятся они формой и весом, а не цветом (решение 4) — см. ниже.

Фон холста белый, хотя фон страницы редактора серый (`--background`). Это чередование по гайдлайну: холст — рабочая поверхность на серой странице, как белая карточка. Серое на сером не кладём.

### Почему гайд не путается с выделением

Оба терракотовые, но принадлежат разным категориям формы:

|             | гайд снапа                            | выделение           |
| ----------- | ------------------------------------- | ------------------- |
| штрих       | пунктир 4/3                           | сплошной            |
| толщина     | 1px                                   | 2–2.6px             |
| длина       | через весь кадр, за пределы геометрии | ровно по объекту    |
| ручки       | нет                                   | есть (хендлы точек) |
| время жизни | только пока движется мышь             | до снятия выделения |

Гайд — тонкая бесконечная пунктирная линия без ручек; выделение — короткая толстая сплошная с кружками. Сцены 2 и 7 показывают их на одной геометрии: гайд уходит за края кадра, выделение обрывается на концах стороны.

### Слой растровой подложки

Подложка лежит **под стенами**, а не над ними: её назначение — обводить план по фотографии, и линии, которые пользователь чертит, должны быть видны целиком. Если положить подложку сверху, свежая геометрия уходит под полупрозрачную картинку, и обводить приходится вслепую. Переключателя порядка слоёв не даём. Относится к P2, в первом вьювере подложки нет.

Крестик снапа рисуется поверх курсора и его не заменяет.

## Поведение при зуме

**Фиксированный экранный размер, не масштабируется:** хендлы точек, крестик курсора, толщина линий сторон и гайдов, подписи длин и поля ввода. Хендл одинаков на общем плане и в крупном приближении.

**Масштабируется вместе с планом:** тела стен, заливка и штриховка комнат, шаг штриховки, растровая подложка, силуэты мебели.

Все значения масштабируемых величин в таблице выше даны **при зуме 1,0× = 100%** — в том числе шаг штриховки 8px и радиус силуэта мебели 3px. На других шагах шкалы они умножаются на текущий зум.

**Появляется и исчезает по порогам:**

- подпись длины скрывается, когда сегмент на экране короче ~30px или текст с запасом не влезает в его длину;
- поле ввода длины показывается на сегменте от ~45px (ломаная) и ~70px (прямоугольник); ниже остаётся подпись или ничего;
- введённое значение при уходе поля за порог сохраняется и возвращается, когда сегмент снова станет длинным.

Шкала зума дискретная, 41 шаг, 1,0× = 100% — это масштаб плана, не масштаб экрана. Зум идёт вокруг курсора. Вращения у конструктора нет.

## Доступность холста

Решение 22, отдельной строкой: **холст остаётся графикой с текстовым описанием плана** — `role="img"` и `aria-label` вида «план: 3 комнаты, 45 м²», обновляемый при изменении геометрии. Полной клавиатурной навигации по хендлам в этой версии нет: обход по Tab конфликтовал бы с Tab между полями ввода длины, который в конструкторе главнее. Доступны с клавиатуры панели, рейл и модалки. Это решение, а не упущение; путь к клавиатурной работе с планом не закрыт.
