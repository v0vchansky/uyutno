# Design handoffs

Дизайн-исходники из Claude Design. Хранятся как эталонный референс для вёрстки и как «оригинальное намерение» при спорах «так задумано или это баг».

Обратное направление — брифы, которые мы **отдаём** в Claude Design перед экспортом, — лежит в [`docs/ui/briefs/`](../briefs/). Один бриф на фичу, имя файла — слаг фичи; результат по нему приезжает сюда, в `handoffs/<slug>/`.

## Как пользоваться

`.dc.html` — интерактивные прототипы, открываются в браузере (`open <файл>`). При вёрстке экрана держим прототип рядом с редактором и сверяем пиксель-в-пиксель, но реализуем на компонентах HeroUI и токенах темы, а не переносим инлайн-CSS.

## Источник правды

- **Токены темы** — `apps/platform/src/client/theme-uyutno.css`.
- **Правила UI** (шкала отступов, типографика, цвет, компоновка, длинные списки, иконки) — [`docs/ui/guidelines.md`](../guidelines.md).
- **Шапки и подвалы** (состояния, меню профиля, мобильное меню) — [`docs/ui/layout.md`](../layout.md).
- **Бренд-ассеты** (favicon, og-image, логотипы) — `apps/platform/public/`.

`README.md` внутри каждой папки handoff-а — снимок на момент экспорта, содержит устаревшие правила. **При расхождении с `docs/ui/guidelines.md` — верен гайдлайн.**

Пример известного расхождения: handoff `auth/README.md` описывает шкалу отступов `6/8/10/12/16/20/24/40/48` — актуальная шкала в гайдлайне другая.

## Раскладка

- `<feature>/` — один экспорт из Claude Design.
- Название папки — по фиче/дропу, не по дате.
- Дубликаты (`theme-uyutno.css`, `ui-guidelines.md`) в handoff не переносим — они уже в проекте выше.
