# Handoff: авторизация и бренд uyutno

## Overview

Пакет описывает четыре экрана авторизации (`/login`, `/register`, `/forgot-password`, `/reset-password`), тему оформления для HeroUI v3 и логотип со всеми размерами. Дополнительно приложены прототипы лендинга и редактора — как справка по общему визуальному языку.

## About the Design Files

Файлы в этом пакете — **дизайн-референсы, собранные в HTML**. Это прототипы, показывающие внешний вид и поведение, а не production-код для копирования. Задача: **воспроизвести эти экраны в существующем окружении проекта** — Express + React 19 SSR, HeroUI v3.2.4, Tailwind v4 — используя компоненты HeroUI (`Button`, `TextField`, `Card`) вместо инлайновых стилей из прототипов.

Инлайновые стили в прототипах — следствие среды, где они создавались. В реальном коде их быть не должно: цвета берутся из токенов темы, компоненты — из `@heroui/react`.

## Fidelity

**High-fidelity.** Цвета, типографика, отступы и радиусы финальные. Воспроизводить попиксельно, но средствами HeroUI.

## Design Tokens

Файл `theme-uyutno.css` — готовая тема. Подключение в `apps/platform/src/client/global.css`:

```css
@import 'tailwindcss';
@import '@heroui/styles';
@import './theme-uyutno.css';
```

Имена переменных взяты из `@heroui/styles/themes/default/variables.css`. Относительно дефолта изменены только значения цветов: акцент с синего на терракоту, нейтрали обнулены по хроме (у дефолта HeroUI лёгкий сине-фиолетовый подтон, hue ≈ 286).

| Токен                 | Значение             | HEX     | Где виден                              |
| --------------------- | -------------------- | ------- | -------------------------------------- |
| `--accent`, `--focus` | `oklch(61% 0.18 44)` | #D65400 | кнопки, кольцо фокуса, ссылки-действия |
| `--accent-foreground` | `oklch(100% 0 0)`    | #FFFFFF | текст на кнопке                        |
| `--background`        | `oklch(97% 0 0)`     | #F7F7F7 | фон страницы                           |
| `--foreground`        | `oklch(24% 0 0)`     | #3D3D3D | основной текст                         |
| `--muted`             | `oklch(54% 0 0)`     | #838383 | подписи, плейсхолдеры                  |
| `--surface`           | `oklch(100% 0 0)`    | #FFFFFF | карточки, поля                         |
| `--surface-secondary` | `oklch(96.5% 0 0)`   | #F5F5F5 | вторичные кнопки, плашки               |
| `--default`           | `oklch(96% 0 0)`     | #F3F3F3 | нейтральная кнопка                     |
| `--border`            | `oklch(91% 0 0)`     | #E4E4E4 | рамки полей                            |
| `--separator`         | `oklch(93% 0 0)`     | #EAEAEA | разделители                            |
| `--radius`            | `0.5rem`             | —       | шкала радиусов; `--radius-3xl` = 24px  |
| `--field-radius`      | `0.75rem`            | —       | поля ввода, 12px                       |

**Радиусы.** В HeroUI у `.button` жёстко `rounded-3xl` (= `--radius` × 3 = 24px), у `.card` — `min(32px, --radius-3xl)` = 24px. Нам нужны карточки 24px, но кнопки прямоугольнее, а переменными это не выражается — обе величины считаются от одного `--radius`. Поэтому в конце `theme-uyutno.css` лежит блок `@layer components` с точечным переопределением: кнопки 12px, крупные CTA (`data-size="lg"`) 14px. Это единственное место, где тема выходит за пределы значений переменных.

**Тени.** Совпадают с дефолтом HeroUI (`--surface-shadow`, `--field-shadow`), продублированы в файле для наглядности.

**Типографика.** Интерфейс — Inter (400/500/600). Логотип — Nunito 700, только в слове «уютно», нигде больше.

**Шкала отступов.** Кратно 4: 6, 8, 10, 12, 16, 20, 24, 40, 48.

## Screens / Views

Все четыре экрана строятся на одном шаблоне:

- Внешний контейнер: `min-height: 100vh`, фон `--background`, контент по центру, padding 48px 24px.
- Колонка контента: `max-width: 360px`, `display: flex`, `flex-direction: column`, `gap: 24px`.
- Сверху шапка: знак 34×26px, затем заголовок 22px/600 и подпись 14px цветом `--muted`, всё по центру, gap 14px между знаком и текстом, 6px между заголовком и подписью.
- Середина: карточка `--surface`, радиус 24px, padding 24px, тень `--surface-shadow`, внутри колонка с gap 16px.
- Снизу: строка-переключатель 14px, ссылка цветом `--accent`, вес 500.

**Поля ввода.** Высота 44px, радиус 12px, фон белый, рамка — `box-shadow: 0 0 0 1px var(--border)`; в фокусе `0 0 0 2px var(--accent)`. Лейбл 13px/500 над полем, gap 6px. Подсказка под полем 12px цветом `--muted`.

**Кнопки.** Основная: высота 44px, радиус 12px, фон `--accent`, текст 15px/500 белый; hover `oklch(55% 0.18 44)` (#C24A00). Соцвход: высота 44px, радиус 12px, фон `--default`, текст 14px/500, иконка 18px слева, gap 8px; hover `oklch(93% 0 0)`.

### 1. `/login` — Вход

Заголовок «Вход в уютно», подпись «Продолжить работу над планировками». Поля: Почта (`type=email`, `autocomplete=email`, плейсхолдер «name@example.ru»), Пароль (`type=password`, `autocomplete=current-password`). Под паролем справа ссылка «Забыли пароль?» 13px, `--muted`, ведёт на `/forgot-password`. Кнопка «Войти». Разделитель «или»: две линии `--separator` и текст 12px. Две кнопки соцвхода в grid 1fr 1fr, gap 8px. Внизу: «Ещё нет аккаунта? Зарегистрироваться» → `/register`.

### 2. `/register` — Регистрация

Заголовок «Создать аккаунт», подпись «Чтобы сохранить планировку и вернуться к ней». Поля: Почта, Пароль (`autocomplete=new-password`, плейсхолдер «Не менее 8 символов», подсказка «Буквы и цифры, минимум 8 символов»). Кнопка «Создать аккаунт». Под ней правовая строка 12px/1.5 цветом `--muted`. Далее разделитель и соцвход как на входе. Внизу: «Уже есть аккаунт? Войти» → `/login`.

### 3. `/forgot-password` — Восстановление

Заголовок «Забыли пароль?», подпись «Пришлём ссылку для входа на почту». Одно поле Почта, кнопка «Отправить ссылку». Под кнопкой — плашка успеха: фон `--surface-secondary`, радиус 12px, padding 12px 14px, слева круглая галочка 16px на `--accent`, текст 13px/1.5. Копия: «Если такая почта у нас есть, письмо придёт в течение минуты. Ссылка действует час.» Формулировка намеренно не раскрывает, зарегистрирован ли адрес. Внизу ссылка «Вернуться ко входу».

В макете плашка показана сразу — в коде она появляется только после успешной отправки, форма при этом остаётся на месте.

### 4. `/reset-password` — Новый пароль

Заголовок «Новый пароль», подпись «Для аккаунта {email}» — адрес подставляется по токену из ссылки. Поля: Пароль, Повторите пароль. Кнопка «Сохранить и войти». В макете второе поле показано в состоянии ошибки: рамка `0 0 0 2px oklch(55% 0.16 27)` (#C63C2E), под полем текст 12px цветом `oklch(48% 0.16 27)` — «Пароли не совпадают». Внизу ссылка «Вернуться ко входу».

## Interactions & Behavior

- Валидация на сабмите, не на каждый ввод. Ошибка поля: рамка красная + текст под полем.
- Ошибка формы (неверная пара логин-пароль) — плашка над кнопкой, та же геометрия, что у плашки успеха, но с красным акцентом.
- Кнопка на время запроса: `disabled`, текст меняется на «Входим…» / «Создаём…» / «Отправляем…».
- `/forgot-password` после успеха: плашка успеха, кнопка отключается на 60 секунд с обратным отсчётом («Отправить ещё раз через 45 с»).
- `/reset-password` с истёкшим или неизвестным токеном: вместо формы — сообщение и кнопка «Запросить новую ссылку» → `/forgot-password`.
- Соцвход ведёт на OAuth-редирект Yandex ID и VK ID (см. ADR 0005).
- Успешный вход: редирект на `/projects`, либо на проект, который пользователь пытался сохранить из демо.
- Enter в любом поле отправляет форму.
- Переходы между экранами — обычная навигация, без анимаций.

## Responsive

Единственный брейкпоинт — 400px и уже: боковой padding контейнера уменьшается до 16px, карточка до padding 20px, кнопки соцвхода перестраиваются в одну колонку (`grid-template-columns: 1fr`). Экраны авторизации обязаны работать на мобильном (в отличие от редактора).

## State Management

Локальное состояние формы: `email`, `password`, `passwordRepeat`, `status` (`idle | submitting | error | success`), `fieldErrors`, `resendCountdown` для восстановления. Сессия — серверная, в cookie, по ADR 0005. Данных с бэкенда экраны не читают, кроме проверки токена на `/reset-password`.

## Assets

Папка `assets/`, все файлы — SVG, отрисованы вручную в этом проекте:

| Файл                   | Размер   | Назначение                       |
| ---------------------- | -------- | -------------------------------- |
| `logo-full.svg`        | 132×32   | знак + слово, шапка и подвал     |
| `logo-mark.svg`        | 32×32    | только знак                      |
| `logo-mark-mono.svg`   | 32×32    | знак на `currentColor`           |
| `favicon.svg`          | 32×32    | плитка со скруглением 8px        |
| `favicon-16.svg`       | 16×16    | упрощённый, наклон убран         |
| `apple-touch-icon.svg` | 180×180  | без скругления, ОС скруглит сама |
| `og-image.svg`         | 1200×630 | превью для соцсетей              |

Знак — два скруглённых квадрата, повёрнутые на −8° и +7°; второй с прозрачностью 0.45. Начиная с 16px наклон убирается, иначе края мылятся. Слово «уютно» в `logo-full.svg` и `og-image.svg` набрано текстом в Nunito 700 — если рендер идёт там, где шрифта нет, перевести в кривые.

Иконки Yandex ID и VK ID в прототипах заменены монограммами в фирменных цветах (#FC3F1D и #0077FF). Перед релизом взять официальные SVG из брендбуков сервисов.

Охранное поле логотипа — не меньше высоты знака с каждой стороны.

## Иконки

Рекомендуемый набор — **lucide-react**: сетка 24×24, `strokeWidth: 1.5`, цвет всегда `currentColor`. Два размера: 16px в кнопках и полях, 20px в панелях редактора.

Иконок инструментов планировщика (стена, дверь, окно, замер, привязка) нет ни в одном готовом наборе — в прототипе редактора они самодельные. Их нужно нарисовать отдельно в той же сетке и с тем же штрихом.
