# 0001. Фиксируем архитектурные решения через ADR

- Статус: Принято
- Дата: 2026-08-07

## Решение

Архитектурные решения фиксируем в `docs/adr/` короткими markdown-файлами. Формат — три секции: **Решение**, **Почему**, **Что важно знать** (последняя необязательна). Правила и шаблон — в [README](./README.md).

## Почему

Через полгода вайбкодинга невозможно вспомнить, почему выбрано именно так. AI-агент каждой новой сессии — без памяти о предыдущих решениях; без записи начнёт переизобретать (иногда правильно, чаще нет). При этом полноценные MADR-шаблоны с рассмотренными альтернативами и сравнительными плюсами/минусами оказались источником придуманной воды: секции заполнялись «для галочки», а не отражали реальное мышление — свой минимальный формат честнее и его действительно хочется читать.

## Что важно знать

- ADR пишем **только для дорогих/необратимых/кроссмодульных решений**. Локальные и обратимые — не ADR.
- Принятые ADR не редактируем — новый ADR замещает старый. Исключение: правки до старта работы над этим блоком кода (обсуждается явно, не по умолчанию).
