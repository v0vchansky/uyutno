# 0004. Стек бэкенда: REST на Express, Kysely + pg, миграции через dbmate, валидация через Zod

- Статус: Принято
- Дата: 2026-08-08

## Решение

- **API-стиль:** REST, доменные роуты `/api/v1/<domain>`, JSON-payloads, стандартные HTTP-статусы.
- **PostgreSQL:** Kysely (типобезопасный query builder) поверх `pg` (node-postgres, мажор **8**). Схема БД — TS-типы, запросы — SQL-подобный chain API, без code-gen.
- **Миграции:** dbmate. Файлы в `apps/platform/db/migrations/<timestamp>_<name>.sql` с секциями `-- migrate:up` и `-- migrate:down`. Состояние — в таблице `schema_migrations`. Ручные `ALTER TABLE` на проде запрещены — любое изменение схемы едет миграцией, вместе с кодом в одном PR.
- **Валидация входных данных:** Zod, мажор **4**. Схемы объявляются один раз и переиспользуются на сервере (`req.body`/`req.query`/`req.params`) и клиенте (валидация форм, типизация ответов).

## Почему

Стек должен быть предсказуемым, отлаживаемым (от HTTP-запроса до SQL) и без vendor-специфики (self-hosted, РФ-хостинг, bash-деплой). tRPC отсекается: жёстко связывает клиент/сервер общим TS-кодом, плохо ложится на сторонних потребителей (SEO-краулеры, потенциальный публичный API), хуже отлаживается стандартными инструментами; type-safety достижим шарингом Zod-схем. GraphQL — избыточен для v0-объёма (пара CRUD + endpoints редактора). Prisma отсекается: тяжёлая, свой schema-язык, гигантский генерируемый клиент, скрывает SQL, противоречит self-hosted-философии. Drizzle — сильный кандидат, но активно ломающиеся изменения на длинной дистанции. Голый `pg` — теряется типизация runtime-ответов, каждый запрос требует ручного описания типа. Kysely — минимальный слой поверх `pg`: тайпы из объявленной `Database`-схемы, всегда видно, какой SQL уйдёт в БД; raw SQL поддерживается через `sql`-эскейп. dbmate вместо встроенного Kysely Migrator — миграции не должны зависеть от конкретного query builder'а (сменить Kysely без переписывания миграций). Zod — стандарт TS-мира, схема = тип, шаринг клиент↔сервер даёт «бесплатный» type-safety без tRPC.

## Что важно знать

- **Без ORM больше boilerplate** для типовых CRUD (три отдельных query builder-цепочки на write/update/delete). Приемлемо на v0, при росте — свои repository-хелперы.
- **Ручные миграции требуют дисциплины.** Любая мелочь (переименование колонки, индекс) едет миграцией; нарушение = рассинхрон кода и схемы.
- **Kysely — молодой инструмент** по сравнению с Prisma. Сложные CTE и специфичные PostgreSQL-фичи могут потребовать raw SQL через `sql`-эскейп.
- **REST требует ручного описания API-контрактов** между клиентом и сервером. Компенсируется Zod и (если понадобится) OpenAPI-спекой поверх.
