# 0009. Frontend UI-стек: Tailwind CSS v4, HeroUI v3, React 19

- Статус: Принято
- Дата: 2026-08-09

## Решение

- `tailwindcss` — мажор **4** (актуальный минорный/патч тянем на момент установки).
- `@heroui/react` — мажор **3** (на 2026-08 это `3.2.4`).
- `react`, `react-dom` — мажор **19**.
- Тема HeroUI — дефолтная. Кастомные токены заводим тогда, когда появится первый реальный экран с требованием к брендингу, не заранее.
- Конфигурация Tailwind — CSS-first (`@theme` в глобальном стиле), без `tailwind.config.js`.

## Почему

ADR 0003 зафиксировал HeroUI/Tailwind без версий. HeroUI, Tailwind и React связаны peer-зависимостями — смешивать несовместимые мажоры даёт неочевидные ошибки на билде/рантайме, версии нужно закрепить перед стартом скелета.

HeroUI v3 (март 2026) — ground-up rewrite специально под Tailwind v4 и React 19; peer-deps требуют `tailwindcss >=4.0.0` и `react >=19.0.0`. HeroUI v2 в статусе deprecated (команда сосредоточена на v3, багфиксы в v2 по остаточному принципу). Более консервативный набор (Tailwind v3.4 + HeroUI v2 + React 18) через 6-12 месяцев превратится в форсированную миграцию без реальной выгоды сейчас: Tailwind v4 вышел в январе 2025 (экосистема подтянулась), React 19 стабилен с конца 2024 (react-router v8, TanStack Query, react-aria его официально поддерживают).

## Что важно знать

- **React 19 lock-in.** Часть старых wrapper-ов вокруг DOM-API могут не иметь релиза под 19 — придётся выбирать альтернативы или форкать.
- **Tailwind v4 несовместим с v3 плагинами.** Часть популярных плагинов (`@tailwindcss/forms`, кастомные presets) могут не иметь v4-версии — если понадобятся, писать вручную.
- **HeroUI v3 молодая** — Q&A/Stack Overflow ещё не догнали, чаще смотреть в исходники и официальные доки.
- **Тёмная тема на v0 не делаем** — редактор целиком светлый.
