# 0009. Frontend UI-стек: Tailwind CSS v4, HeroUI v3, React 19

- Статус: Принято
- Дата: 2026-08-09
- Автор(ы): @v0vchansky

## Контекст и постановка задачи

ADR 0003 зафиксировал стек фронтенда как «Express + React SSR на Webpack, HeroUI/Tailwind, голый Three.js», но без конкретных версий. К моменту старта скелета `apps/platform` нужны зафиксированные версии, потому что HeroUI, Tailwind и React связаны peer-зависимостями и попытка смешать несовместимые мажоры даёт неочевидные ошибки на этапе билда/рантайма.

## Драйверы решения

- **Актуальность.** Стартуем с последних стабильных мажоров, чтобы не тратить время на миграции через полгода.
- **Совместимость по peer-deps.** UI-библиотека и её CSS-движок должны совпадать по мажорным версиям — иначе стили не применяются или конфликтуют.
- **Поддержка.** Используем ветки, которые активно развиваются, а не deprecated-предшественники.

## Рассмотренные варианты

- **Вариант A: Tailwind v3.4 + HeroUI v2 + React 18.** Более консервативный набор — v3 Tailwind стабилен, HeroUI v2 (форк NextUI) на нём работает.
- **Вариант B: Tailwind v4 + HeroUI v3 + React 19.** Актуальные мажоры каждой библиотеки на 2026-08.

## Выбранный вариант

**Выбран: Вариант B.** HeroUI v3 (март 2026) — это ground-up rewrite специально под Tailwind v4 и React 19; peer-deps требуют `tailwindcss >=4.0.0` и `react >=19.0.0`. Ставить старые версии = сидеть на ветке, которую HeroUI больше не развивает.

## Обоснование

### Почему не A

- HeroUI v2 в статусе deprecated: команда сосредоточена на v3, багфиксы в v2 идут по остаточному принципу.
- Tailwind v4 вышел в январе 2025, за полтора года экосистема (плагины, IntelliSense, документация) подтянулась.
- React 19 стабилен с конца 2024, все ключевые библиотеки (react-router v8, TanStack Query, react-aria) его официально поддерживают.
- «Консервативный» выбор превратился бы в форсированную миграцию через 6–12 месяцев без реальной выгоды сейчас.

### Что даёт B

- **Tailwind v4 (Oxide-движок):** CSS-first конфиг через `@theme` вместо `tailwind.config.js`, ощутимо быстрее сборка, native CSS-переменные вместо генерации.
- **HeroUI v3:** компонентная модель без обязательного `<HeroUIProvider>`-обёртки, все анимации на CSS без JS-рантайма, встроенный React Aria Components для доступности, поддержка OKLCH-цветов.
- **React 19:** нативная поддержка форм через `<form action>`, `use()`, улучшенный SSR-стриминг (в v0 не используем, но задел на будущее).

## Что фиксируется этим ADR

- `tailwindcss` — мажор **4** (актуальный минорный/патч тянем на момент установки).
- `@heroui/react` — мажор **3** (актуальный минорный/патч на момент установки; на 2026-08 это `3.2.4`).
- `react`, `react-dom` — мажор **19**.
- Тема HeroUI — дефолтная. Кастомные токены заводим тогда, когда появится первый реальный экран с требованием к брендингу, не заранее.
- Конфигурация Tailwind — CSS-first (`@theme` в глобальном стиле), без `tailwind.config.js`.

## Что НЕ фиксируется этим ADR

- Конкретный набор HeroUI-компонентов — используем по мере надобности.
- Способ подключения иконок (heroicons, lucide, свои SVG-спрайты) — решается при появлении первого экрана.
- Тёмная тема — не решаем в v0, редактор целиком светлый.

## Последствия

### Плюсы

- Свежий стек без немедленных миграций впереди.
- Меньше конфигурационного шума (нет `tailwind.config.js`, нет провайдера HeroUI).
- Готовая доступность из коробки (React Aria).
- Быстрая сборка Tailwind за счёт Oxide.

### Минусы

- **React 19 lock-in.** Часть комьюнити-библиотек (особенно старые wrapper-ы вокруг DOM-API) могут не иметь релиза под 19 — придётся выбирать альтернативы или форкать.
- **Tailwind v4 несовместим с v3 плагинами.** Часть популярных плагинов (`@tailwindcss/forms`, кастомные presets) могут не иметь v4-версии — если понадобятся, писать вручную.
- **Мало готовых примеров.** HeroUI v3 молодая — Q&A/Stack Overflow ещё не догнали, чаще придётся смотреть в исходники и официальные доки.

## Как проверить/пересмотреть

- **Если понадобится сторонняя UI-либа**, которая жёстко тянет `tailwindcss@3` или `react@18` без релиза под свежие мажоры → взвесить, что дешевле: заменить либу или откатить мажор.
- **Если HeroUI v3 не будет получать обновлений полгода+** → пересмотреть в пользу альтернативы (shadcn/ui, Radix + свои стили).
- **Если Tailwind v4 CSS-first конфиг окажется неудобным** для нашей темизации → откатиться на `tailwind.config.ts` в рамках того же мажора.
