# 0016. Модель документа планера: contour-first дерево, единицы, id, snapshot-friendly plain-data

- Статус: Принято
- Дата: 2026-08-19

## Решение

Документ планера — **одно plain-JSON дерево** `Document`, единственный источник правды для всех вьюверов (конструктор, 2D-план, 3D, walk — проекции, ADR 0015). В нём хранится то, что нарисовал/выбрал пользователь, плюс результат нормализации rebuild; всё, что выводится из контуров, — выводится на каждом rebuild и не сериализуется. Слои и фасад — ADR 0015; геометрия — ADR C; undo — ADR D; хранение/миграции — ADR F; проекция в Three — ADR G. Схемы `items` по `kind`, `finishes`, `underlay`, `settings` здесь намеренно не детализированы — дорешиваются в ADR H/J/K/G без изменения формы дерева.

### Единицы, координаты, углы (B1)

- **Единица — сантиметр**, 1 см = 1 юнит для всех координат, размеров и констант ([README](../product/features/planner/README.md), «Единицы и координаты»). Площади и объёмы — только форматирование в UI; **`settings.units`** — настройка документа (спека 07), значения `'cm' | 'm' | 'mm'`. **Имперской системы в продукте нет** (решение автора 2026-08-19), `'ftin'` из типа убран.
- **Квантование**: любая координата, попавшая в документ через снап/ввод, округляется до **0.001 см** (спека 01 «Снап», аудит keep). Точки не мутируются — новая координата = новая версия узла.
- **Плоскость плана `(x, y)` → мир Three `(x, height, −y)`**, `+Y` мира — вверх (аудит, «Сквозные практики»). Документ хранит только координаты плана; маппинг применяется **ровно в одном месте** — в слое проекции (ADR G). Никаких инверсий `z`/`ry` в сериализации, никаких ремапов в подсистемах (линейки, свет, подписи).
- **Углы в документе — градусы везде**, включая поворот текстур (`rotation: 90`, а не `1.5707963…`); радианы — только внутри тригонометрии и в проекции, конвертация на границе.

### Идентификаторы (B2)

- У каждой хранимой сущности — стабильный строковый `id`, UUID v7 (ADR 0006) пакетом **`uuidv7`** (зависимость `@uyutno/planner`, ADR 0015). Ссылки между сущностями — **только по id, никогда по индексу массива**.
- Ссылка на отсутствующий id при загрузке — не «битый проект»: запись молча пропускается (решение автора Q11), детали парсера — ADR F.

### Дерево (B3, B4) — скетч формы, не схема

```ts
type Id = string; // uuidv7
type Point = { id: Id; x: number; y: number }; // см, план, квантовано до 0.001

type Document = {
  format: 'uyutno.planner';
  version: number; // целое, монотонное; сейчас 1
  settings: { units: 'cm' | 'm' | 'mm'; wallHeight: number /* 280 */ /* … */ };
  view: {
    activeView: 'constructor' | 'plan' | 'orbit' | 'walk'; // явное поле, восстанавливается при загрузке
    cameras: {/* per вид: позиция, поворот, зум 0..1 — спека 08 */};
  };
  floors: Floor[]; // v0: ровно один
};

type Floor = {
  id: Id;
  layout: {
    // «планировка»
    points: Record<Id, Point>; // единый пул вершин этажа; сварка = общий id
    contours: { id: Id; kind: 'outer' | 'inner'; points: Id[] }[]; // замкнутые петли граней стен после нормализации нарисованного: outer — обвод тела стен, inner — полость-комната (ADR 0017)
    covers: { id: Id; kind: 'outer' | 'inner'; points: Id[]; ceilingHidden: boolean /* … */ }[]; // полы — самостоятельные контуры (Q12); inner — пол-вычитание (дырка)
    areas: { id: Id; points: Id[]; height: number }[]; // зоны с низким потолком
    cuts: { id: Id; a: Id; b: Id /* концы — id точек; материал — ADR J */ }[]; // вертикальные грани зон, явные записи (как roomtodo)
    rooms: { id: Id; anchor: Id[]; name: string; ceilingHeight: number /* … */ }[]; // атрибуты комнаты + якорь
  };
  scene: {
    // «обстановка и отделка»
    items: {
      id: Id;
      kind: 'model' | 'door' | 'window' | 'opening' | 'poster' | 'carpet';
      catalogId: string;
      x: number;
      y: number;
      elevation: number;
      rotation: number; /* … ADR H */
    }[];
    finishes: Record<SurfaceKey, {/* … ADR J */}>; // ключ поверхности — из стабильных id документа, схема ключей — ADR J
    rulers: { id: Id; a: { x: number; y: number }; b: { x: number; y: number } }[]; // плоские {x,y} плана
    hidden: Id[];
    underlay?: {/* … ADR K */};
  };
};
```

| Хранится (источник правды)                                                                                                                                                                                                                                                                                                           | Выводится на rebuild, **не сериализуется**                                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| точки (один раз, по id), контуры граней, полы-контуры (с видом `outer`/`inner` и флагом «скрыть потолок»), зоны, записи cuts (id, концы по id точек, материал — Q12), атрибуты комнат с якорем, проёмы/мебель мировыми координатами плана, материалы по ключам поверхностей, линейки, скрытое, подложка, активный вид и камеры видов | стены-тела и их толщина, оси, грани как объекты, полигоны/триангуляция комнат, дырки полов, потолки, плинтусы, сама грань cut и её высота (из зоны), дырки и лутки проёмов, `axisPos`, индекс «проём→ось», митра |

**Принцип привязки хранимого к производному** (решения автора Q3/Q35, спека 02/03): производные сущности **не имеют персистентной идентичности** — пересоздаются целиком на каждом rebuild, стабильных id между сохранениями нет и не нужно. Всё, что «висит» на производном, хранится с якорем в стабильных данных и пере-привязывается на каждом rebuild/загрузке:

- **Проём и настенный предмет** — мировые координаты плана; пере-дроп на ближайшую ось с гейтом **10 см** при загрузке и после каждой пересборки; при загрузке без оси — остаётся без привязки, при rebuild — удаляется (спека 03 «Оси стен»). `axisPos` и индекс проём→ось — состояние движка (результат rebuild), не документа.
- **Комната** — запись атрибутов с якорем `anchor: Id[]` (id точек контура на момент последнего rebuild); новая комната берёт атрибуты старой записи по перекрытию площади (спека 02), движок переписывает `anchor`. Полы ужимаются под комнату; их материал и видимость потолка наследуются по перекрытию (Q20).
- **Материал грани стены** — привязан к концам грани через id хранимых точек (Q35, «совпадение концов»). **Cut** — явная запись `cuts[]` `{ id, a, b, материал }` с концами по id точек (как roomtodo, Q12); грань и высота cut выводятся из зоны на rebuild, запись без опоры удаляется вместе с зоной. Точная схема ключа `SurfaceKey` — ADR J.
- **Вид пола и видимость его потолка — хранимые** (правка по месту 2026-08-20, задача 0069). `Cover.kind: 'outer' | 'inner'`: вложенность пола обязана быть хранимой, а не выводимой из containment, потому что спека 02 («Осиротевшие внутренние полы») требует **удалять** дырку, оставшуюся без хозяина — при выводимой вложенности она молча стала бы обычным полом, и пользователь увидел бы, что вырез зарос. `Cover.ceilingHidden: boolean`: спека 02 («Видимость потолка») хранит флаг **на полу, а не на комнате**, наследует его по перекрытию площади независимо от атрибутов комнаты, а при слиянии полов берёт от первого пола-донора. Обоих полей достаточно; флаг видимости крышки зоны и профиль плинтуса в модель не заводятся до шага 7 (там же панель, из которой ими управляют).
- **Общие точки**: полы и зоны, «приваренные» к углу комнаты, ссылаются на **тот же id** в `points` — угол пола едет за углом стены без mutable parent/children и без пере-привязки по координатам (аудит, `CPoint.move`). Проверка опоры зоны при rebuild — тождество координат с шагом квантования (Q22).

Rebuild — часть транзакции фасада (ADR 0015): строит производное и **нормализует хранимое** (переписывает `contours`/`points` результатом слияния нарисованного с сохранением id по квантованной координате и удаляет точки без владельцев — ADR 0017; ужимает полы, дописывает авто-полы, удаляет зоны без опоры и проёмы без оси, переписывает `anchor`), поэтому один снимок undo содержит уже пересобранный документ (спека 02, «Автоматическая перестройка»).

### Snapshot-friendly (B5)

- Документ — **plain JSON**: объекты, массивы, строки, конечные числа, boolean, `null`. Запрещены: классы и методы, `Map/Set/Date`, `undefined` как значение (поле либо есть, либо отсутствует), `NaN/Infinity`, циклические ссылки, объекты Three/DOM. Инвариант `load(save(x)) == x` — testing-strategy.
- Обновления — **иммутабельные со структурным разделением через `immer`** (`produce`, авто-freeze включён всегда — и в проде, plain-объекты на выходе): неизменённые поддеревья сохраняют ссылку, снимок для undo — ссылка, а не копия. `layout` и `scene` выделены поддеревьями, чтобы undo (ADR D) мог снапшотить их по ссылке; что именно и как снапшотится — ADR D. Единственная точка мутации — транзакция фасада (ADR 0015).
- Производное состояние — **вне документа**: результат rebuild — в движке, меши — в проекции; мемоизация по ссылочной идентичности входных узлов (сменилась ссылка — пересчитать), гранулярность — ADR G. Полный синхронный recompute на коммит (Q23) этому не мешает.

### Версия и этажи (B6, B7)

- `format` + `version: number` — с первого дня, `version = 1`. Миграция при загрузке — silent side-effect, **не история** (спека 09/10); политика миграций — ADR F.
- `floors[]` в модели, UI показывает один этаж (README). **Активный этаж, выделение, активный инструмент — состояние движка/UI**, в документ не входят. Активный вид (`view.activeView`, явное поле) и камеры видов (позиция/поворот/зум 0..1) — `Document.view`: спека 10 требует их сохранять; при загрузке восстанавливается **последний активный вид**, а не «всегда конструктор» (как roomtodo/аудит; спека 08 правится под 10 — парковка). Меняются через неймспейс `view` фасада с событием `view:changed` (не `document:changed`, ADR 0015), в undo не входят (ADR D снапшотит `layout`/`scene`).

## Почему

Одна модель без второй «data/3D»-копии — следствие принципа «одна модель, 3D — memoized-проекция» (README, п. 2) и главного антипаттерна референса: две параллельные модели с ручной конвертацией — источник рассинхрона (аудит, drop). Разделение «хранится/выводится» повторяет проверенный формат конкурента (points-once + id-refs; оси/триангуляция/дырки не хранятся — аудит keep), но в одном документе, а не в отдельном слое сохранения. Стабильные id осей/граней отсекаются: решением Q3/Q35 привязка идёт по мировым координатам и площади, как у roomtodo. Мутабельный граф `parent/children` для сварки точек отсекается: общий id в едином пуле даёт то же поведение и не ломает снапшоты. Радианы в документе отсекаются: `Math.PI/2` в JSON — шум и потеря точности прямых углов при повторных конвертациях, UI и так в градусах. Ручная дисциплина спредов вместо `immer` отсекается — одна пропущенная копия ломает структурное разделение и все снимки undo. Отдельный «объект сессии» для камер рядом с документом отсекается: второй сейв, вторая версия и второй round-trip ради того, что решается выбором снапшотируемых поддеревьев.

## Что важно знать

- **Загрузка = обычный синхронный rebuild** (решение автора, Q23): полигонов комнат/потолков/плинтусов в сейве нет — атрибуты с якорем + пересборка. Формулировки спеки 10:19 («комнаты, потолки, плинтусы» среди сохраняемого) и 02:138 («без полной пересборки») — противоречие спеки, в парковке.
- **Углы в градусах везде** — подтверждено автором; спека 05 упоминает поворот текстуры в радианах внутри — для документа правило одно, конвертация в ADR J/G (парковка).
- **Общий id точки между контуром, полом и зоной** — удаление точки командой должно проверять всех владельцев; обязанность транзакции фасада, не отдельных инструментов (точки, оставшиеся без владельцев после слияния, удаляет `normalize` — ADR 0017).
- **Уточнено ADR 0017 (2026-08-19):** `Contour.kind`, «контуры — результат нормализации нарисованного», GC точек без владельцев в `normalize`.
- **Правка по месту 2026-08-19 (решение автора по дизайн-брифу):** имперская система удалена из продукта целиком — `settings.units` (B1) сузился до `'cm' | 'm' | 'mm'`, `'ftin'` убран из `UNITS`, рантайм-валидации `setSettings` и таблицы шага нуджа `NUDGE_STEP_CM`. Единицы переключаются контролом в самом редакторе, а не в отложенных «Настройках проекта» (спека 07, README планера). Формат документа этим не ломается: `version` остаётся `1` — старых сейвов с `'ftin'` не существует, сохранение появится только на шаге 3.
- **`Record<Id, Point>` вместо массива** — O(1) доступ и стабильные ссылки на узлы под `immer`; порядок точек задаётся `contours[].points`.
- **`view` внутри документа** — камера попадает в JSON сейва; серверный dirty-флаг (Q14) камерой не ставится, диф-гвард локального черновика на зум сработает — приемлемо.
