# 0017. Геометрический пайплайн планера: контуры → лента → триангуляция → комнаты → оси

- Статус: Принято
- Дата: 2026-08-19

## Решение

Геометрическое ядро планера — чистые функции над plain-данными в `packages/planner/src/document/geometry/` (ADR 0015: без Three/DOM/React, Jest node); вход — замороженный `FloorLayout` (ADR 0016), выход — нормализованный `layout` и `DerivedFloor`. Алгоритмы и пороги — как у roomtodo ([аудит](../product/architecture/competitor-practices-audit.md), строки «Где = C», решения автора Q2/Q12/Q19/Q20/Q22/Q23/Q32–Q36); побочные эффекты референса не переносятся. Инструменты, снап, история — ADR D/E: ядро отдаёт предикаты и квады ленты, вызывает их E. Всё, что помечено «2b/шаг 4/шаг 6/ADR G/J/F», здесь фиксируется формой и стадией, реализуется позже без смены формы.

### Место, модель контуров, стена-тело, `DerivedFloor` (C1)

- Модули (файл = функция/семейство, типы и константы рядом): `predicates/`, `band/`, `triangulate/`, `contours/` (`rebuildContours`), `axes/`, `reattach/`; позже `covers/`, `areas/`, `connectors/`.
- **Хранимые контуры = результат нормализации, как `arrRooms` roomtodo** (референс, верифицировано по исходнику — [задача 0051](../tasks/v0/0051-TASK-planner-adr-geometry-pipeline.md), «Заметки»; решения автора 2026-08-19 — там же): `layout.contours[]` после `normalize` — обводы тел стен (`kind: 'outer'`) и полости-комнаты (`kind: 'inner'`). Инструменты коммитят «сырое»: «Стены» — квады ленты как N `outer` с общими id вершин соседних квадов; «Прямоугольная комната» — один `outer` + один `inner` (сплошной прямоугольник со сторонами ≤ 2 × ширины — один `outer`; уточнено задачей 0058: полость, не проходящая `contourValid` — сливер при стороне 20–~22 см, — тоже даёт сплошной `outer`, иначе команда отвергла бы пакет целиком; чистая `rectContours` в `contours/`); «Комната по точкам» — один `inner`. `normalize()` в той же транзакции прогоняет `rebuildContours` и **переписывает `contours`/`points`** результатом слияния: `outer` = обводы fill-групп, `inner` = комнаты (C6). «Пара контуров граней» получается сама, отдельного формата коммита нет.
- Поле **`kind: 'outer' | 'inner'` у `Contour`** — внесено в ADR 0016 (B3, правка по месту 2026-08-19); без него классификация центроида (`fill = inside(outer) > inside(inner)`) на перекрывающемся входе (новые квады поверх стен, драг грани через соседнюю) невозможна — паритет вложенности там врёт.
- **Дисциплина id:** вершина результата получает id существующей точки по тождеству квантованной координаты (ключ `x|y` после `quantize`; координаты выхода, включая точки пересечений от `clean-pslg`, квантуются до 0.001 — B1), иначе новый id из инжектированного генератора (`normalize(draft, { createId })`); контур сохраняет id, если последовательность id его точек совпала с прежней с точностью до циклического сдвига, иначе получает новый; точки без владельцев (`contours/covers/areas/cuts`) удаляются. Следствие: две точки в одной координате = одна (спека 01 «Дубли точек», «Слияние точек»); общий id пола/зоны (ADR 0016 B4) переживает нормализацию. `normalize` пишет в draft только при фактическом изменении (набор контуров `{id, kind, points}` или координат отличается). Порядок контуров детерминирован, как `sortByArea` референса: по убыванию |площади|, при разнице < `SORT_AREA_EPS` `outer` после `inner`, остаточный tie-break — `(minX, minY)` первой вершины; `rooms[]` следует порядку `inner`.
- **Стена-тело в 2D = треугольники fill-групп** (как roomtodo, верифицировано), не per-face лента; лента — только превью и коммит квадов. Класса `empty` на выходе нет: не-fill группы делятся на комнаты и exterior (C6).
- `DerivedFloor` шага 2 (plain, заморожен, локальные плоские массивы, без глобальных пулов и обратных ссылок):

  ```ts
  type Triangle = [Id, Id, Id]; // вершины — точки layout: вход нормализован, Steiner-точек нет
  type DerivedFloor = {
    id: Id;
    walls: { contourId: Id; triangles: Triangle[] }[]; // fill-группа на outer-контур
    rooms: { contourId: Id; roomId: Id; outline: Id[]; holes: Id[][]; triangles: Triangle[]; area: number }[];
    axes: { a: PlanPosition; b: PlanPosition; depth: number; faces: [FaceRef, FaceRef] }[]; // FaceRef = { contourId; a: Id; b: Id }
  };
  ```

  Инварианты: каждой комнате — ровно одна запись `rooms[]` (`roomId`; записи без комнаты допустимы — C7); `outline` = точки её `inner` (это и есть `anchor`); `holes` = обводы `outer`, лежащих непосредственно внутри. Позже без смены формы: `covers/areas/cuts` (2b), дырки/лутки проёмов и индекс проём→ось (шаг 6), плинтусы/потолки/меши (ADR G). Один пайплайн для правки и загрузки: `load` → `normalize` → `rebuild`; двойная триангуляция (normalize на черновике + rebuild на снимке) допускается — `rebuild` чистая от финализированного снимка (задача 0048).

### Библиотеки (C2)

| Нужда                    | Что берём                                          | Почему готовое                                                                                                                              |
| ------------------------ | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Constrained-триангуляция | `cdt2d@1.0.0` (точная версия; CJS, без типов)      | готовая CDT для PSLG на robust-предикатах; 10 лет без изменений — стабильна; `{ exterior: true }` — полная CDT оболочки, классификация наша |
| Санитизация PSLG         | `clean-pslg@1.1.2` (точная; CJS)                   | пересечения/дубли/T-стыки на точной арифметике; спайк: `cdt2d` на грязном входе молча теряет ограничения                                    |
| Ориентационный предикат  | `robust-predicates@^3.0.3` (`orient2d`; ESM, типы) | 0 ошибок против точного эталона там, где наивный cross ошибается; скорость как у наивного                                                   |
| Property-тесты           | `fast-check@^4` (devDep)                           | testing-strategy                                                                                                                            |

Отсекаются: `constrainautor`+`Delaunator` (нет санитизации PSLG — писать свой clean-pslg), Clipper2/`polygon-clipping` (полигон-буль не нужен, юнион — через `rebuildContours`, Q2), `robust-orientation` (транзитивная dep, без типов, ×3.5 медленнее), свой `orient2d`. Обвязка (проверено спайком, задача 0051): свои `.d.ts` (`@types/*` не существуют), default-импорт CJS в ESM работает; `cleanPSLG` мутирует вход и возвращает boolean → обёртка копирует массивы и фильтрует вырожденные рёбра `[i,i]`; `clean-pslg` тянет `buffer` — в клиентском webpack нужен стаб; знак `orient2d` библиотеки противоположен наивному `(b−a)×(c−a)` — обёртка ядра нормализует к «> 0 = против часовой (y вверх)», закреплено тестом. Детали настройки (Jest, webpack) — задача 0054.

### Эпсилоны и константы (C3)

Два эпсилона: `L_EPS = 1e-8` (тождество координат, дедуп, параллельность/коллинеарность) и `B_EPS = 1e-4` (близость к границе/на-отрезке); третьего (`1e-6` в ray casting референса, верифицировано) нет — `pointInContour` = «сначала `pointOnContour` (B_EPS), потом чётность пересечений с полуоткрытыми рёбрами через `orient2d`». Работает только в связке: общие вершины бит-в-бит через квантование 0.001 в командах фасада (ADR 0016 B1) + снап пересечений к общим вершинам в `lineIntersectLine`. Константы — именованные экспорты рядом с использованием, не `constants.ts`: `L_EPS`, `B_EPS`; `MIN_CONTOUR_AREA = 50` см², `MIN_SP_RATIO = 1`; `CLEAR_CONTOUR_MIN_LEN = 5`; `TRIANGLE_NARROW = 0.1`; `SORT_AREA_EPS = 10`; `RE_MITER_ANGLE = 0.75π`; `PARALLEL_EPS = 0.05` рад; `MAX_WALL_WIDTH = 80`, `MIN_WALL_LENGTH = 15`; `MAX_CONNECTOR_LENGTH = 40`, `CONNECTOR_ON_LINE_EPS = 1` (Q33); `DEFAULT_WALL_WIDTH = 10` (дефолт параметра ленты); `CLOSE_EPS = 0.1` (предикат замыкания — чистая функция ядра, вызывает E); `REATTACH_GRID = 10`. Параметры функций, не константы: ширина ленты, сторона офсета, замкнутость, `separateContacting`.

### Предикаты (C4)

Из 22 функций dd08 (аудит «dd08») 1:1 с контрактом и тестами по квадрантам: `angleBetweenLines` (`atan2(dx, dy)`, `[0, 2π)`, не `acos`), `parallelLines`, `compareContours` (8 исходов, не сводить к булевой алгебре), `compareContoursByArea`, `contourArea` (знаковая), `contourPerim`, `contourValid`, `contourSelfIntersected`, `pointOnContour`, `pointInBounds`, `bisectorPoint`, `segmentsOverlay`, `checkContact`, `sortByArea`, `findMinMax`, `triangleCenter/Area/IsNarrow`, `pointInContours` (счётчик), `manhDist`/`euclDist`. Переписываются по вердиктам rework: `offsetPoint` (бывш. `perpendicularPoint`) — нормаль `(dy, −dx)/len`, enum стороны `'left' | 'right'`, гард нулевой длины; `projectPointOnLine` — честный dot product, флаги `asSegment`/`vertices`; `pointOnSegment` — параметрически `t ∈ [0, 1]` с B_EPS-коридором; `pointInContour` — robust ray casting; `orient2d`/`rightOriented`/`segmentsIntersected`/`lineIntersectLine` — через `robust-predicates`; `compareContoursOnePoint` — полный union вместо `undefined`; `distanceToLine` — abs с гардом. Ядро отдаёт обе метрики; какую применяет снап/хит-тест/замыкание — E (Q34); внутри ядра метрика по референсу там, где она часть алгоритма (`triangleIsNarrow`, `checkContact`).

### Лента и митринг (C5)

Свой per-segment офсет + пересечение, без polygon-offset либы. `blocksFromContour(points, width, side, closed, startNeighbourSegments?)`: односторонняя лента (одна грань — сама линия), выход — независимые квады `[A, C, D, B]` с переносом `A = C, B = D`; митра → плоский торец: открытая полилиния — `ang > 0.75π && ang < 2π − 0.75π` **и** `!pointInBounds`, замкнутая — только по углу (Q32, [спека 01](../product/features/planner/01-walls-and-contours.md) «Митра углов»); null-guard параллельных соседей → butt; гарды: 1 точка → `[]`, 2 точки короче `width` → `[]`, последний сегмент открытой короче `width` — отбрасывается; butt-капы концов; T-стык — ближайшее из двух пересечений с соседними лучами. Замкнутость — явный признак, обход по модулю длины; знак офсета — enum стороны. Автовыбор стороны (`signSide` до третьей точки, рёбра < 5 см не участвуют) — состояние инструмента (E). Квад-стрип — промежуточный формат golden-фикстур; после коммита толщина не хранится.

### Триангуляция, детекция комнат, порядок фаз (C6)

- `triangulateContours({ outer, inner, bound, subtract, cutPairs })` — семь шагов dd01 с rework: вход квантован → дедуп точек/рёбер hash-map по квантованному ключу (не O(V·E)) → `resplitSegments` (коллинеарные осевые перекрытия/T-стыки, в дополнение к clean-pslg) → `clean-pslg` в чистой обёртке → `cdt2d({ exterior: true })` → half-edge-lite (`fixed` по отсортированной паре) → flood-fill групп по не-fixed рёбрам **явным стеком** → sliver-safe репрезентативный треугольник (all-sliver группы отбрасываются) → центроид-классификация `fill = inside(outer) > inside(inner)` с bound∩/subtract-семантикой. Плоские массивы на выходе.
- `rebuildContours(...)` — публичная чистая функция: `filterContours` → триангуляция → группы → boundary walk каждой группы (старт min-X, виртуальная prev `[x − 10, y]`, экстремальный угол; guard `res.length > n` — soft-fail признаком в результате, логирует движок) → `clearDict` (dead-end вершины) → повторные обходы той же группы = дырки → **нормализация ориентации по знаку площади** (наш `contourArea` — shoelace, > 0 = против часовой при y вверх, как обёртка `orient2d`; `outer` и обводы комнат — площадь > 0, дырки — < 0; референс знак не гарантирует — верифицировано) → `clearContour` (слияние ближе 5 см, удаление коллинеарных) → `contourValid`. **Классы групп:** fill — тело стены; **комната** — не-fill группа, ни одно ребро которой не лежит на выпуклой оболочке триангуляции (ребро с одним инцидентным треугольником); остальное — exterior. Дырки комнаты — обводы, найденные повторными обходами её группы (по членству, не containment-тестом). Контракт пригоден шагу 6 (юнион луток + проверка числа внешних контуров, Q2) и полам (bound/subtract, `separateContacting`).
- **Порядок фаз** (аналог `rebuildWallsAndCovers`, аудит keep, с оговорками ADR 0016). `normalize(draft)`: (1) `rebuildContours(outer, inner, cutPairs зон)` → переписать `contours/points` → (2) пере-привязка `rooms[]` (C7) → [2b: (3) отбраковка зон без опоры/с пересечением стен (тождество координат, Q22) и cuts без зоны → (4) `rebuildCovers` → (5) `findAutoCovers` → (6) `findCoverHoles` + удаление осиротевших внутренних полов] → [шаг 6: (7) пере-дроп проёмов, гейт 10 см]. `rebuild(snapshot)`: триангуляция нормализованного `layout` → `walls`, `rooms` → `axes` (C8) → [шаг 4: коннекторы; 2b: треугольники полов/зон, грани cuts; шаг 6: индекс проём→ось]. `roundAllPoints` не нужен (квантование в командах, B1); `connectAllPoints` не нужен (общий id, B4).
- **Скоуп шага 2:** фазы (1)–(2) normalize и `walls/rooms/axes` rebuild. Cut-пары зон — fixed-рёбра триангуляции: делят треугольники комнаты на группы (аудит 03-rooms «зона перепартиционирует комнату»), но новых записей комнат не порождают; как это совмещается с критерием комнаты — решается при реализации зон (2b; референс группирует не-fill без остановки на fixed).

### Пере-привязка комнат (C7)

`compareContoursByArea` (сетка 10×10 по bbox старой, INTERSECT при ≥ 1 общей точке) — только для атрибутов `rooms[]`; «старый контур» записи = её `anchor`, разрешённый по координатам черновика после мутации команды (пропавшие id пропускаются, < 3 точек — донором быть не может); для каждой новой комнаты донор = первая (в порядке `rooms[]`) запись с INTERSECT; донор не расходуется (обе половинки разделённой комнаты наследуют — [спека 02](../product/features/planner/02-rooms-floors-ceilings.md) «Комнаты»); без донора → новая запись `{ id, anchor, name: '', ceilingHeight: settings.wallHeight }` (Q20). **Запись, не совпавшая ни с одной новой комнатой, остаётся сиротой** с прежним `anchor` (спека 02 «Модель контур-first»: «замкнул обратно — атрибуты возвращаются»); референс такие записи теряет (верифицировано) — расхождение осознанное; в v0 сироты хранятся бессрочно (решение автора 2026-08-19), чистка — по мере надобности. `anchor` переписывает `normalize` в той же транзакции. Материалы граней — по совпадению концов грани (id точек, Q35), схема ключа — ADR J.

### Оси (C8)

Производные, без id: `findAxes` O(n²) по парам граней всех контуров — `parallelLines(PARALLEL_EPS)` → `rightOriented` → `parallelBox` (4-case, `manhDist(E, F) < L_EPS` — отказ) → `boxCenterSeg` (`MAX_WALL_WIDTH`/`MIN_WALL_LENGTH`); ось на каждую пару по участку перекрытия, слияния нет (Q19, [спека 03](../product/features/planner/03-openings.md) «Оси стен»). **Направление детерминировано (наше решение; референс не гарантирует — верифицировано):** `a` = конец с меньшим `x` (при равенстве — меньшим `y`), `faces[0]` — грань слева от `a→b` (y вверх); угол — один источник, направление `a→b`. `depth` = расстояние между гранями = «текущая толщина» для инпута ширины (задача 0060). Индекс проём→ось — локальный результат rebuild (шаг 6). Коннекторы/заглушки (`createConnectors`: кросс-пары торцов оси, ≤ `MAX_CONNECTOR_LENGTH`, «чужой конец на линии» с `CONNECTOR_ON_LINE_EPS`, попарно без N-way солвера — Q36) — стадия после осей, реализация шаг 4.

### Полы, зоны, cuts — форма и стадии (C9)

Полы — самостоятельные контуры (Q12): `findAutoCovers` (seed — `inner`, subtract — `outer` и существующие полы) → дефолтный пол только там, где пола нет; `rebuildCovers` ужимает ручные; `findCoverHoles` smallest-first явным компаратором; merge INTERSECT — авто, CONTACT — по решению UI (спека 02); осиротевшие внутренние полы удаляются. Зоны: рёбра как cut-пары; отбраковка при пересечении стен/самопересечении/потере опоры (тождество координат, Q22). Cuts — явные записи `cuts[] { id, a, b }` (материал — ADR J): адресуются неупорядоченной парой id точек; ребро, общее для двух касающихся зон, имеет одну запись (владелец — записавшая первой, вторая переиспользует); запись без зоны-владельца удаляется в `normalize`; грань и высота (max высот соседних зон / высота стен) — производные rebuild. Реализация — 2b.

### Тестовый контракт (C10)

- Golden ([testing-strategy](../product/architecture/testing-strategy.md)): `packages/planner/src/document/geometry/fixtures/<case>.json` — `{ name, input: PlannerDocument, expected: { layout: нормализованный FloorLayout, derived: DerivedFloor } }` (лента — `{ input: полилиния/width/side/closed, expected: квады }`); id детерминированные (`p1`, `c1`… через инжектированный генератор), числа с округлением до 1e-6; обновление эталона — явный шаг `UPDATE_GOLDEN=1 pnpm test` с ревью диффа. Стартовый набор: 4 стены → 1 комната; самопересекающийся контур → `contourSelfIntersected` (отказ на завершении — решение E); внутренняя стенка делит; удалил стену — слились; комната в комнате → дырка; висячая стена — нет ложных контуров; T-стык; плоский торец ≥ 135° открытая/замкнутая; короткий последний сегмент; две коллинеарные короткие грани против длинной → две оси; сдвиг стены сохраняет запись комнаты.
- Property (`fast-check`, фиксированный seed): нет NaN/Infinity; комнаты — валидные полигоны без самопересечений и `contourValid`; ориентация по контракту; `normalize(normalize(x)) == normalize(x)`, `rebuild` детерминирован; инвариантность к порядку входных контуров с точностью до перестановки комнат (донор атрибутов при равном входе детерминирован, при перестановке может смениться — фиксируется явно). «Вся математика и все ветки»: по каждому предикату обе стороны каждого порога, вырожденные входы, знак/ориентация.

### Производительность (C11)

Не решаем: полный синхронный recompute на коммит (Q23), без индексов/debounce/worker; bbox-prefilter, hash-map дедуп, двойная триангуляция — детали реализации.

## Почему

Курс «как roomtodo» (аудит, «Решения автора»): пять лет отладки в обвязке триангуляции, митринге, детекции комнат и осях — копируем алгоритмы и пороги; не копируем побочные эффекты — рекурсию flood-fill (единственный реальный landmine аудита), глобальный пул вершин `TR.points`, in-place мутации входа `clean-pslg`, третий эпсилон в ray casting (недетерминированный результат на границе), недетерминированное направление оси (`axisPos` отмерялся бы от разных концов). Хранимые контуры = результат нормализации, потому что так устроен `arrRooms` референса (верифицировано): один пайплайн обслуживает правку и загрузку (решение автора, ADR 0016), а снимок undo содержит уже пересобранный документ (спека 02 «Автоматическая перестройка») — хранить «сырые» квады и слитые обводы порознь означало бы вторую модель. `kind` нужен, потому что после слияния «внешний/дырка» по вложенности неотличимы от «тело/полость» на перекрывающемся входе, а классификация центроида требует различать наборы.

`cdt2d`+`clean-pslg` — потому что спайк показал: `cdt2d` на грязном входе не бросает, а молча отдаёт неверную триангуляцию, а `clean-pslg` вставляет точные точки пересечений; `constrainautor`+`Delaunator` отсекается — санитизацию PSLG пришлось бы писать; Clipper2/`polygon-clipping` — полигон-буль не нужен (юнион — `rebuildContours`, Q2); `robust-orientation` — без типов и медленнее при том же результате; свой `orient2d` — наивный cross ошибается на почти-коллинеарных тройках, адаптивный Shewchuk писать самим = изобретать библиотеку; polygon-offset либы — односторонняя лента и независимые квады с тремя правилами (ре-митр, T-стык, коннекторы) ими не воспроизводятся (аудит dd02).

Стена-тело = треугольники, а не лента, потому что после слияния лент никакой per-face ленты нет — есть fill-группа между гранями (референс рисует именно её, верифицировано), а лента живёт только до коммита. Направление оси — наше правило, потому что референс его не гарантирует (верифицировано), а спека 03 требует абсолютный `axisPos` от начала оси. Фикстуры — документы и `DerivedFloor`, а не пиксели: пиксели хрупки (testing-strategy), а сериализованный документ уже нужен шагу 3 (build-order).

## Что важно знать

- **ADR 0016 уточнён по месту (2026-08-19):** (а) `Contour.kind: 'outer' | 'inner'`; (б) `contours[]` — результат нормализации нарисованного, а не буквально «то, что рисует юзер»; (в) точки без владельцев удаляет `normalize`, проверка владельцев при удалении точки командой остаётся обязанностью транзакции. `PlannerDocument.ts` правится в задаче 0054.
- **Сироты `rooms[]`** — по спеке 02, вопреки референсу; хранятся бессрочно (v0), `rooms[]` растёт на каждую разомкнутую комнату — доли килобайта на запись; лимит/чистка при сохранении — если станет заметно (ADR F).
- **Термины:** здесь `outer` = обвод тела стен, `inner` = полость-комната; у нас все записи `rooms[]` — полости, поэтому паритет «внешняя для внешней, дырка для дырки» спеки 02 не применяется (формулировка спеки — в парковку); «внешняя комната получает дырку» (спека 02 «Комната внутри комнаты») — про вложенность (`holes` в `DerivedFloor.rooms`) — другой смысл.
- **`clearContour` работает и на хранимых контурах:** одиночная коллинеарная вершина без иных владельцев не переживает нормализацию; инструменты шага 2 таких не создают (разрез стены — дроп чужой точки, T-стык); если понадобится сохранять — правило владельцев, задача 0054.
- **Знаки:** `orient2d` `robust-predicates` — инверсия относительно наивного cross; `contourArea` референса имеет другой знак — тесты фиксируют нашу конвенцию, а не копируют знаки референса.
- **`buffer`-стаб** для `clean-pslg` в клиентском webpack — `{ Buffer: { isBuffer: () => false } }` (0 KiB); если появится другой потребитель `buffer` — полифилл (+26 KiB).
- **Фикстуры мигрируют с форматом** (ADR F): `input` — `PlannerDocument` с `format`/`version`, ids через инжектированный генератор.
- **Зоны/полы/cuts/плинтусы/потолки** — стадии зафиксированы здесь, реализация как инструментов и отрисовки — шаг 2b build-order (решение автора 2026-08-19).
