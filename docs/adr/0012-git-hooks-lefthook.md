# 0012. Git-хуки: lefthook + lint-staged, pre-commit с ESLint / Prettier / tsc

- Статус: Принято
- Дата: 2026-08-09

## Решение

- **Инструмент управления хуками:** lefthook (мажор **2**), конфиг в корне (`lefthook.yml`).
- **Фильтр staged файлов:** lint-staged (мажор **17**).
- **Pre-commit-хук:**
  1. `lint-staged` — ESLint `--fix` на staged `.ts`/`.tsx`/`.js`, затем Prettier `--write` на staged `.ts`/`.tsx`/`.md`/`.json`/`.yaml`/`.css`.
  2. `tsc --noEmit --incremental` — type-check всей монорепы (инкрементальный кеш `.tsbuildinfo` в `.gitignore`).
  3. Оба шага запускаются lefthook'ом **параллельно** (`parallel: true`) — не пересекаются по ресурсам, вместе укладываются в секунды.
- **Pre-push-хук:** пусто. Заведём отдельным изменением конфига (не ADR), если появится потребность.
- **Fail-режим:** non-zero exit блокирует коммит.
- **`--no-verify`:** разрешён (для WIP-коммитов, экстренных фиксов, случаев когда хук временно сломан).
- **Активация хуков** — через `pnpm install` (`prepare`-скрипт или `postinstall`, конкретика — задача имплементации).

## Почему

Работа через вайбкодинг — AI-агент коммитит по несколько раз в час; без хука кривой код (незапущенный линт, битые типы, забытый форматтер) регулярно утекает в историю. Ручной запуск `pnpm lint` / `format` / `typecheck` не соблюдается ни человеком, ни агентом.

lefthook, а не husky: один YAML вместо папки со скриптами (`.husky/pre-commit`, `.husky/pre-push`, `.husky/_/*` — папка с несколькими файлами, каждый ревьюить отдельно), parallel-запуск из коробки (в husky пришлось бы вручную писать shell с `&`/`wait`, теряя читаемость), single self-hosted binary (совпадает с философией «bash + self-hosted»). husky не выигрывает ничего существенного — гибкость shell-скриптов не нужна, вся логика «запусти команду X и Y».

lint-staged, а не встроенный lefthook-фильтр — стандарт JS-мира, любой AI-агент знает наизусть; переносится между husky/lefthook без изменений.

Type-check на pre-commit, а не на pre-push: AI-агент коммитит часто, между коммитами по 30 секунд — к push'у накопится 10+ коммитов, часть которых ломает компиляцию, разбирать «какой из десяти сломал» дороже, чем поймать сразу. `--incremental` быстрый (доли секунды на небольших изменениях).

`--no-verify` разрешён: блокировать = воевать с базовым инструментом git; нужен для WIP-коммитов и экстренных фиксов. Дисциплина bypass'а — вопрос практики, а не технической блокировки.

## Что важно знать

- **Type-check на каждом коммите может тормозить**, когда монорепа разрастётся. Триггер пересмотра — стабильно >5 секунд → переносим в pre-push, на pre-commit оставляем только lint + format.
- **`--incremental` иногда флакает** при переключении веток (некорректный кеш) — лечится удалением `.tsbuildinfo` и одним лишним запуском.
- **Первый `pnpm install` качает lefthook-бинарь** — приемлемо, происходит один раз.
- **Commit-msg-хук не заводим** — формат коммитов свободный, только на русском.
