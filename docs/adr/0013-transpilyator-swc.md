# 0013. Транспилятор: SWC вместо Babel

- Статус: Принято
- Дата: 2026-08-09

## Решение

- **Транспилятор TS/TSX → JS** для webpack-сборки клиента и сервера: **SWC** (`@swc/core`) через `swc-loader`.
- Конфиг — единый `.swcrc` в **корне монорепы** (с задачи 0047; до неё лежал в `apps/platform/`). Оба webpack-конфига (клиент и сервер) используют одно правило `swcRule` из `apps/platform/webpack/common.js`, которое передаёт `swc-loader` этот файл явно через `configFile`; Jest (`jest.config.base.mjs`) читает те же опции для `@swc/jest`. Один источник правды для платформы и воркспейс-пакетов (`packages/*`).
- Никакого `babel.config`, `@babel/*` пакетов, `babel-loader` в зависимостях.

## Почему

`@babel/core@8` (актуальный мажор на 2026-08) — ESM-only, а `babel-loader@10` внутри делает `require('@babel/core')` и падает с `ERR_REQUIRE_ESM`. Экосистема babel-loader ещё не догнала babel 8. Откатываться на babel 7 в новом проекте — тащить legacy ради самого babel'а, у которого нет уникальных преимуществ для нашего кейса (нет specific-плагинов, которые нужны нам, но отсутствуют в SWC).

SWC — стандарт транспиляции 2026 года: нативная ESM/CJS-совместимость, в 5–10 раз быстрее babel на холодной сборке, стабильный `swc-loader`, знает TS/JSX/decorators из коробки без пресетов. Для нашего набора (TypeScript + React 19 automatic JSX) конфиг умещается в 20 строк `.swcrc`.

## Что важно знать

- **Нет типизации на этапе транспиляции.** SWC, как и babel-transform-typescript, стирает типы без проверки. Type-check — отдельным шагом (`tsc --noEmit` в pre-commit по ADR 0012).
- **`.swcrc` дублируется по духу с `tsconfig.json`** (target, jsx-runtime). При смене одного — не забыть про другой.
- **`configFile` в `swc-loader` задан явно, а не через поиск `.swcrc` вверх от файла:** SWC ищет `.swcrc` только до `root` (= cwd, при сборке — `apps/platform`), корневой файл монорепы из `apps/platform` он молча не находит и падает на дефолт (classic JSX-runtime, `React is not defined` в SSR). Проверено в задаче 0047.
- **Плагины SWC на Rust**, писать свои — дороже, чем babel-плагин. Если понадобится нестандартная трансформация — сначала искать существующий SWC-плагин, только потом рассматривать возврат на babel.
