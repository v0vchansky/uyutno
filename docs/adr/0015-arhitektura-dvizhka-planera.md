# 0015. Архитектура движка планера: слои, фасад, мост с React

- Статус: Принято
- Дата: 2026-08-18

## Решение

Планер — ядро на plain-данных за фасадом `PlannerManager`; React-UI — сменный скин поверх публичного API фасада и типизированной шины. Опирается на ADR 0002, ADR 0003, ADR 0007, [testing-strategy](../product/architecture/testing-strategy.md), принципы [features/planner](../product/features/planner/README.md) и вердикты [аудита практик roomtodo](../product/architecture/competitor-practices-audit.md) («Сквозные архитектурные практики», строки «Где = A»; решения автора Q17, Q23).

### Пакет, слои, направление импортов (A1, A3, A10)

Планер — **отдельный воркспейс-пакет `packages/planner`** с первого коммита: npm-имя `@uyutno/planner` (префикс воркспейсов по ADR 0002), платформа подключает его как `"@uyutno/planner": "workspace:^"` и импортирует только из корня пакета: `import { createPlanner, Planner } from '@uyutno/planner'`. Следствия пакета: свой `package.json` (зависимости `three`, `immer`, `mitt`, `uuidv7`) и `tsconfig.json` (extends корневого `tsconfig.base.json`); **пакет не собирается отдельно** — своего build/`dist` нет, платформа потребляет исходники `.ts/.tsx` напрямую, и они попадают в оба webpack-бандла платформы: в клиентский — как обычные исходники, в SSR-бандл — через allowlist `webpack-node-externals` (иначе SSR требовал бы `@uyutno/planner` как внешний модуль в рантайме); Jest — свой `jest.config.mjs` пакета поверх корневого базового по ADR 0014. Настройка сделана в задаче 0047. Внутри пакета — только относительные импорты. Папки = слои:

| Папка         | Что содержит                                                                                                                                                                                                                                    | Может импортировать             |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| `document/`   | Модель документа (ADR 0016) и чистая геометрия (`document/geometry/`, ADR C): plain JSON-данные и чистые функции. Ни Three, ни DOM, ни React                                                                                                    | внешние либы без DOM/Three      |
| `engine/`     | `PlannerManager` (фасад), команды-транзакции, состояние вида, заглушка истории, шина событий, результат rebuild. Ни Three, ни DOM, ни React                                                                                                     | `document/`                     |
| `projection/` | Проекции документа во вьюверы: `projection/three/` (одна `Scene`, один `WebGLRenderer`, камеры видов, `RenderLoop`) и позже `projection/canvas2d/` (конструктор стен, Q17). Подписаны на шину, читают документ через фасад, в документ не пишут | `engine/`, `document/`, `three` |
| `ui/`         | React (`React.FC`): `<Planner />` — тонкая обёртка над фабрикой (canvas + жизненный цикл), `PlannerContext`, хук `usePlannerSelector`, панели. Единственный слой с `react`                                                                      | всё выше                        |
| `index.ts`    | Публичный API пакета: `createPlanner` (фабрика, A7), `Planner` (компонент), типы параметров и документа                                                                                                                                         | —                               |

Граница с платформой — физическая: у пакета нет алиаса `@app/*` (ADR 0010 — алиас платформы), импортировать `apps/platform` из него нельзя, всё внешнее — DI (A8). Энфорс `no-restricted-imports` per-directory (как в ADR 0007) остаётся только для слоёв внутри пакета: `document/`, `engine/` — без `three`/`react` и без импортов из вышележащих слоёв; `projection/` — без `react`; остальным модулям платформы — только `@uyutno/planner` (нынешние правила про `@app/planner` в `eslint.config.mjs` заменяются). Конкретный конфиг — имплементация. Тесты co-located, компоненты — папками по `src/client/CLAUDE.md`.

### Ядро + сменный UI-скин, публичный API (A2)

- Документом владеет `PlannerManager`; `document.get()` возвращает замороженный (immer) иммутабельный снимок. UI и проекции документ не мутируют — только вызывают команды фасада.
- Команда = транзакция: мутация документа через `produce` → синхронный rebuild производного (Q23) → ровно одно событие шины. Единственная точка мутации; ручных commit-точек в инструментах/панелях нет.
- Публичный API нарезан неймспейсами по зонам ответственности. Шаг 1: `document` (`get`, `load`, команды-мутации), `view` (`get`, `setActive`, `setCamera`, `resetCamera` — активный вид и камеры видов), `history` (`get(): {canUndo, canRedo}`, `undo`, `redo` — заглушка до ADR D). `selection` (ADR I) и `tools` (ADR E) добавляются своими шагами. Правило: неймспейс = один домен, его события — префикс `ns:` в карте шины.
- Sync-команды возвращают свой `Result<T, E>` — discriminated union `{ ok: true; value } | { ok: false; error }`, async — `Promise` с типизированной ошибкой; исключений наружу нет.

### Мост движок ↔ React (A4)

Один механизм: движок — источник правды, React подписан через `useSyncExternalStore`. `PlannerManager.subscribe(cb)` = подписка на wildcard `*` шины; `usePlannerSelector(selector)` вызывает `selector(manager)` в `getSnapshot`. Селекторы возвращают примитивы или ссылки на иммутабельные снимки (`document.get()`, `view.get()`, `history.get()`) — стабильны по построению. Экземпляр менеджера — через `PlannerContext` внутри пакета, не через `Registry` платформы (планер не импортирует `common`).

### Шина событий (A5)

`mitt` с типизированной картой `PlannerEvents` (ключ — имя, значение — payload). Шаг 1: `document:changed { document }` (изменилось содержимое: `floors`, `settings`), `view:changed { activeView, cameras }` (активный вид или камера — `Document.view`, ADR 0016), `history:changed { canUndo, canRedo }` (одно событие вместо трёх каналов, аудит). Правило расширения: имя `<неймспейс>:<факт в прошедшем времени>`, payload — plain-данные без Three-объектов и UI-подсказок, одно событие на факт, без edge-triggered пар (`X_ACTIVE`/`X_INACTIVE`); шина наружу пакета не отдаётся — только `subscribe`/`on` фасада.

### Стек зависимостей шага 1 (A6)

| Нужда                | Что берём                                                                                    | Почему готовое                                                                                                                      |
| -------------------- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 3D                   | `three` `0.185.x` (ADR 0003; в `package.json` ещё не добавлен)                               | дано                                                                                                                                |
| Идентификаторы       | `uuidv7` (уже в `apps/platform/package.json`, дублируется в deps пакета; UUID v7 — ADR 0006) | без новой зависимости, сортируемые по времени                                                                                       |

| Шина                 | `mitt`                                                                                       | ~200 байт, TS-карта событий, wildcard `*` (нужен `RenderLoop` и `useSyncExternalStore`)                                             |

### Инициализация и жизненный цикл (A7)

- **Композиционный корень — фабрика вне React:** `createPlanner({ canvas, projectId, logger, … }) → { manager, projection, dispose }` (живёт в `projection/` или рядом с `index.ts`, без `react`). Порядок: пустой документ → `PlannerManager` → `ThreeProjection(manager, canvas)` (единственный `WebGLRenderer`, `ResizeObserver` на контейнер canvas, подписки на шину). `dispose()` — в обратном порядке: `off` подписок, `ResizeObserver.disconnect()`, отмена `requestAnimationFrame`, обход сцены с `dispose()` геометрий/материалов/текстур, `renderer.dispose()` + `forceContextLoss()`.
- `<Planner projectId logger />` (экспорт `@uyutno/planner`) — тонкая обёртка: рендерит `<canvas>`, в `useEffect` вызывает `createPlanner` с ним, кладёт `manager` в `PlannerContext`, на unmount зовёт `dispose()`. Владелец canvas один — React создаёт элемент и передаёт его фабрике. Платформа монтирует `<Planner />` из `project/pages/ProjectPage`. Порядок: документ → движок → проекция → UI.
- Render-on-demand: `RenderLoop.invalidate()` выставляет бюджет кадров — константа-дефолт `FRAME_BUDGET = 5` (аудит keep «RenderUpdater»), переопределяемая параметром проекции (`createPlanner({ frameBudget })`); луп через `requestAnimationFrame` декрементирует бюджет и самозавершается — в покое ни одного `rAF`. Инвалидируют: любое событие шины, resize, интеракция камеры. Ровно один `WebGLRenderer` на планер; превью — через render target того же рендерера (аудит rework, шаг 9).
- Гвард (testing-strategy, слой 3, Playwright): `projection.getStats()` отдаёт `renderer.info.render.frame` и `renderer.info.memory.{geometries,textures}`; тест ассертит: за секунду покоя `frame` не растёт (idle FPS≈0), `geometries` не растёт после N операций и повторного mount/unmount. Как Playwright достаёт результат фабрики (dev-only проп/колбэк, не `window.__*`) — деталь имплементации.

### DI-контракт с платформой (A8)

Параметры `createPlanner` = пропсы `<Planner />` (плюс `canvas` у фабрики) шага 1: `projectId: string`, `logger: PlannerLogger` (структурный интерфейс `{ debug, info, warn, error }`, объявлен в пакете; реализацию передаёт платформа). Параметр `storage: { load(projectId), save(projectId, document) }` появится в шаге 3 (ADR F) тем же способом; сейчас документ создаётся пустым внутри. Планер не читает `useRegistry()`, cookies, URL, `window`-глобалы; глобалов и синглтонов внутри планера нет.

### Тестируемость (A9)

`document/` и `engine/` — Jest (node), без Three и DOM: юниты чистой логики (слой 1) и фасад как state-машина (слой 2), покрытие «вся математика и все ветки». Всё, что импортирует `three`, лежит только в `projection/` и тестируется Playwright (слои 3–4); фабрика `createPlanner` без React делает движок headless-запускаемым в этих тестах. Хуки `ui/` при необходимости — Jest jsdom с фейковым менеджером.

## Почему

Тестируемость и переносимость — свойства архитектуры: ядро на plain-данных за фасадом гоняет слои 1–2 в Jest без ESM-боли Three (testing-strategy); монолит с глобалами конкурента (аудит: `WC.core`-синглтон, `WC._`/`R2D._` из глубины React) теряет оба свойства, поэтому его форма не копируется. Проекции — отдельный слой, а не часть движка: Canvas2D-конструктор и Three-виды показывают один документ (Q17), значит документ не знает о вьюверах. Пакет сразу, а не модуль `apps/platform/src/client/planner` с ESLint-границей и «переезд позже одним `git mv`»: «ядро без импортов из платформы» становится физическим свойством (у пакета нет `@app/*`), а не линтерным правилом, которое сегодня уже расходится с ADR 0007; настройка `tsconfig`/webpack/Jest всё равно понадобилась бы при переезде — плюс правка импортов потребителей. Композиционный корень вне React: «UI — сменный скин» доказывается тем, что движок и проекция поднимаются без React (headless-тесты слоя 2, Playwright-ручка `getStats()`); вариант «`<Planner />` создаёт менеджер и проекцию» отсекается — жизненный цикл движка привязывался бы к React-дереву. Redux-обвязка конкурента отсекается: редьюсеры там вызывают движок, в проде два слайса режима вида (аудит, «Redux как зеркало…», «Два слайса режима вида») — второй источник правды с побочными эффектами. Zustand/Jotai отсекаются по ADR 0003: внешнее хранилище дублировало бы состояние, которым уже владеет фасад. Голая шина без `useSyncExternalStore` отсекается: React должен читать состояние синхронно при монтировании и переживать concurrent-рендер без tearing, иначе состояние дублируется в `useState`. `EventTarget` отсекается: `CustomEvent.detail` — `any`. `nanoevents` отсекается: нет wildcard `*`. Ручная иммутабельность вместо `immer` отсекается: замороженный снимок — единственная механическая гарантия «React не мутирует документ» и дешёвый снапшот для undo; выключать auto-freeze в проде не нужно — заморозка на `produce` для планов квартир пренебрежима. `changed`-флаги roomtodo не проектируются (Q23): инвалидация — факт изменения документа через шину, гранулярность ребилда — ADR G.

## Что важно знать

- **ADR 0007/0010 говорят про `planner` как клиентский модуль с переездом «в v1»** — по этому ADR пакет заводится сразу; граф ADR 0007 не меняется (`planner ──► —`, потребители `project`/`common`/`landing`), меняется физическое место и алиас (`@uyutno/planner` вместо `@app/planner`). Правила `@app/planner` и override для `apps/platform/src/client/planner/**` в `eslint.config.mjs` заменены на per-layer override для `packages/planner/src/{document,engine,projection,ui}/**` (задача 0047); `auth` и `core` не импортируют `@uyutno/planner`; ADR 0007/0010 поправлены по месту. Клиентского модуля `core` и логгера пока нет — `logger` приходит DI-параметром.
- **Селекторы должны быть стабильны:** `usePlannerSelector(m => ({ ...m.view.get() }))` даст бесконечный ре-рендер. Возвращать примитивы или снимки фасада как есть.
- **Wildcard `*` — общая подписка:** каждое событие дёргает `getSnapshot` всех подписчиков и `invalidate()`. Дёшево, пока событий единицы на действие; покадровое движение камеры в шину не пускать — камера коммитится в `view` по завершении интеракции.
- **SSR-бандл — общее правило, не точечный allowlist:** bare-импорты (npm-зависимости) — внешние; воркспейс-пакеты `@uyutno/*` бандлятся (`nodeExternals({ allowlist: [/^@heroui\//, /^@uyutno\//] })` в `webpack.server.js`). Зависимости пакета (`three`, `immer`, `mitt`), которых под pnpm strict нет в `node_modules` платформы, попадают в SSR-бандл **by design** — иначе рантайм их не найдёт; модуль-уровневый импорт `three` в SSR исполняется штатно (проверено, задача 0047).
- **Jest и SWC для пакета:** `packages/planner/jest.config.mjs` расширяет корневой `jest.config.base.mjs` (свои `roots`, `types: ["jest"]` в tsconfig пакета), опции SWC — из корневого `.swcrc` (`configFile` в `swc-loader`, те же опции в `@swc/jest`); `pnpm test`/`pnpm typecheck` в корне гоняют оба воркспейса (`pnpm -r`).
- **`immer` замораживает глубоко** — снимок нельзя «на минутку» подправить в проекции; производные структуры проекция держит у себя (мемоизация — ADR G).
