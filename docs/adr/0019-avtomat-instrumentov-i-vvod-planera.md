# 0019. Автомат инструментов и пайплайн ввода/снапа планера

- Статус: Принято
- Дата: 2026-08-19

## Решение

Инструменты конструктора — **один типизированный автомат** в неймспейсе `tools` фасада (`engine/`, ADR 0015 A2); снап и хит-тест — чистые функции в `document/geometry/snap/` и `document/geometry/hittest/` над плоскими массивами кандидатов; ввод (pointer events, клавиатура) — в `projection/` (Canvas2D-проекция — ADR 0020, клавиатура — `projection/input/keyboard.ts`). Опора: [ADR 0015](./0015-arhitektura-dvizhka-planera.md), [ADR 0016](./0016-model-dokumenta-planera.md), [ADR 0017](./0017-geometricheskiy-payplayn-planera.md) (предикаты, лента `blocksFromContour`, `CLOSE_EPS`, `DerivedFloor` с треугольниками по id точек, `normalize`), [ADR 0018](./0018-mutatsii-tranzaktsii-i-undo-planera.md) (команды `document.*`, история, хук `beforeReplace`); [спека 01](../product/features/planner/01-walls-and-contours.md), [09](../product/features/planner/09-undo-redo.md), [06](../product/features/planner/06-selection-transform.md), [08](../product/features/planner/08-cameras-views.md); [аудит](../product/architecture/competitor-practices-audit.md) — строки «Где = E», решения автора Q10/Q17/Q18/Q27/Q31/Q34. **Граница с ADR 0018:** документ не меняется до коммита — live-превью рисования и live-драг живут в `ToolState`, транзакций на `pointerMove` нет; коммит — одна команда фасада на завершении жеста (`pointerUp` драга, завершение контура кликом или Enter в инпуте); прерванный жест (Esc, `blur`, `pointercancel`, смена вида, `document.load`) не коммитится, состояние инструмента возвращается к исходному.

### Один автомат: состояния, команды, события (E1)

`tools.get(): ToolState` — discriminated union по `kind`; общие поля вне union: `snapFlags`, `viewport`. Каждый переход — новый plain-объект (payload шины), состояние не мутируется.

| `kind`                         | Что несёт                                                                                                                                                                                            | Выходы                                                                                                                                            |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `editing` (хаб)                | `hover`, `selection: HitTarget \| null` (точка / сторона / комната конструктора), `pressed` до порога драга                                                                                          | `start(...)` → `making-*`; сдвиг > `DRAG_THRESHOLD/scale` → `dragging-point`/`dragging-wall`; клик → выделение; dblClick по точке → `deletePoint` |
| `making-walls`                 | `points` (зафиксированные), `cursor` (живая, снапнутая), `side: 'left' \| 'right'`, `sideFixed`, `preview` (квады `blocksFromContour`, ADR 0017 C5), `snap: SnapResult`, локальные стеки `undo/redo` | замыкание/завершение → `document.addContours` → `editing`; Esc → `editing`; undo до пустого → `editing`                                           |
| `making-rect`                  | `origin \| null`, `cursor`, `snap`, `preview`                                                                                                                                                        | второй клик → `addContours` → `editing`; Esc → `editing`                                                                                          |
| `making-room`                  | `points`, `cursor`, `snap`, локальные стеки                                                                                                                                                          | манхэттен-замыкание при ≥ 4 → `addContours` (`inner`) → `editing`; Esc/undo до пустого → `editing`                                                |
| `dragging-point`               | `pointId`, `origin`, `pointOverrides: Record<Id, PlanPosition>`, `snap`, `dropTarget: HitTarget \| null`                                                                                             | `pointerUp` → `movePoints` → `editing` (выделена точка); Esc/`blur`/`pointercancel` → `editing` без коммита                                       |
| `dragging-wall`                | `face: FaceRef`, `origin`, `pointOverrides` (обе точки), `snap` (гайды подавлены)                                                                                                                    | `pointerUp` → `movePoints` двух концов → `editing`; отмена — как выше                                                                             |
| `making-area` / `making-cover` | зарезервированы (2b), в шаге 2 `start` их не принимает                                                                                                                                               | —                                                                                                                                                 |

```ts
type HitTarget = { kind: 'point'; id: Id } | { kind: 'wall'; face: FaceRef } | { kind: 'room'; roomId: Id }; // FaceRef — ADR 0017 C1
type Viewport = { scale: number /* CSS px на см */; center: PlanPosition; width: number; height: number }; // document/geometry/viewport.ts
type Editing = { kind: 'editing'; hover: HitTarget | null; selection: HitTarget | null; pressed?: Pressed };
type MakingWalls = {
  kind: 'making-walls';
  points: PlanPosition[];
  cursor: PlanPosition | null; // null до первого события указателя (уточнено 0057)
  side: OffsetSide;
  sideFixed: boolean;
  startNeighbours: StartNeighbourSegments | null; // T-стык: соседи первой точки на чужой стене (0057)
  preview: WallBlock[];
  snap: SnapResult | null;
  guides: SnapGuide[]; // guidesFor(snap, { lastPoint, segments, face }) — вьювер только рисует (0057)
  undo: PlanPosition[][];
  redo: PlanPosition[][];
};
type DraggingPoint = {
  kind: 'dragging-point';
  pointId: Id;
  origin: PlanPosition;
  pointOverrides: Record<Id, PlanPosition>;
  snap: SnapResult;
  dropTarget: HitTarget | null;
};
type ToolState = { snapFlags: SnapFlags; viewport: Viewport } & (
  Editing | MakingWalls | DraggingPoint | MakingRect | MakingRoom | DraggingWall
); // остальные — по таблице; полная форма — в коде, задача 0057
```

- **`Viewport` — единый тип** (`document/geometry/viewport.ts` вместе с чистыми `planToView/viewToPlan/viewportBounds(v)` — bbox для куллинга/хит-теста): слой `document/`, поэтому его импортируют `engine/` (`ToolState`), `document/geometry/snap|hittest`, `projection/canvas2d` и `ui/` (DOM-оверлей). Вьювер отдаёт его через `tools.setViewport(v)`.
- **Команды** (координаты **плана**; экран → план делает вьювер): `start('walls' | 'rect' | 'room')`, `cancel()` (= Esc: жест/рисование отменяется без коммита, в `editing` без жеста — снимает выделение, спека 06), `interrupt()` (отмена жеста + сброс hover/выделения → `editing`), `pointerDown/Move/Up(input: PointerInput)`, `doubleClick(input)`, `pointerCancel()`, `blur()`, `commitPoint(point)` (постановка точки из инпута длины — Q27), `key(action: KeyAction): { handled: boolean }`, `setSnapFlags(patch)`, `setViewport(v)`. `PointerInput = { x, y, mods: { ctrl, meta, shift, alt }, button }`; `KeyAction = { kind: 'cancel' } | { kind: 'undo' } | { kind: 'redo' } | { kind: 'nudge'; dx; dy; factor }`. Смена инструмента посреди рисования = `cancel()` + `start`.
- **Undo/redo идут через автомат** — и клавиши, и кнопки панели зовут `tools.key({ kind: 'undo' | 'redo' })`: в `making-*` — локальный стек точек, в `dragging-*` — отмена жеста (история не трогается), в `editing` — `history.undo()/redo()`; режим знает только автомат. Прямой `history.undo()` — программный/тестовый путь: перед применением снапшота (и перед `document.load`) хук движка **`StoreHooks.beforeReplace()`** зовёт `tools.interrupt()` (ADR 0018 D9).
- **Своя машина** на discriminated union: одна точка перехода `transition(next)` (`exit(prev)` → замена → `enter(next)` → `tools:changed`), без побочек рендера в переходе; без классов состояний и без `xstate`. После завершения контура — возврат в `editing`, как roomtodo `stateEditing` на завершении (верифицировано по исходнику, задача 0052: 66064; SFK 70898–70902).
- **Событие `tools:changed { state: ToolState }` — на каждое изменение состояния, включая `pointerMove`**; `key`/`setSnapFlags`/`setViewport` без фактического изменения события не порождают.
- **Внешние события:** `view:changed` на вид ≠ `constructor` → `making-*`/`dragging-*` → `editing` (рисование/жест отменяется без коммита, **выделение сохраняется** — спека 08 «Смена вида во время drag»; уточнение спеки 08 «активный инструмент переносится» — парковка); `document:changed` → пересборка индекса кандидатов; `document.load`, undo/redo → `beforeReplace` → `interrupt()`; `dispose` — ничего.

### Snap-first пайплайн (E2)

- **Порядок на каждом `pointerMove`:** `snap = getSnapPoint(raw, candidates, params)` → переход состояния с результатом **значением** (аудит dd09 rework: без глобалов `snapPos/aligners`, без синглтона `snapTool` с `reset()`).
- **Чистые функции** `document/geometry/snap/`: `getSnapPoint`, `snapToNearest`, `snapX/snapY/snapPerpendicular`, `orthogonalSnap`, `bisectorSnap`, `findNearSegments` — формулы 1:1 с референсом (аудит dd09 keep) над `SnapCandidate[] = { id; x; y; prev?; next? }[]` (соседи по кольцу — для биссектрисы), без импорта `engine/`; предикаты — ADR 0017 C4.
- **Индекс кандидатов** — `engine/`, мемо по ссылке `document` (пересборка при `document:changed`); пул = все `layout.points` этажа (вершины контуров/полов/зон) + точки рисуемого контура; `exceptPoints` (перетаскиваемая точка — один id покрывает совладельцев) — параметр вызова.
- **Параметры:** `snapFlags` — состояние `tools` (не документ, не сохраняются: спека 10 их не перечисляет; дефолты `pointsSnap/pointsAlign/bisectorAlign` on, `orthoAlign` off; grid-снапа нет — Q18); куллинг кандидатов по `viewportBounds(viewport)` **всегда on**; Ctrl/Cmd при драге — снап выключен (`PointerInput.mods`); первая точка снапнута к моменту клика (Q31: `pointerDown` использует снап последнего `pointerMove`).
- **Пороги** — константы в px, в план делением на `viewport.scale` (верифицировано по исходнику, задача 0052: `WC.SNAP_DIST = 10`, `POINT_SIZE = 6`, `CLICK_SHIFT = 3`, 60604–60608): `SNAP_DIST = 10` (точечный снап и оси; хит-тест стороны — `/2`; радиус угла биссектрисы — ×10), `POINT_SIZE = 6` (хит-тест точки, хендл), `DRAG_THRESHOLD = 3` (одна константа вместо `POINT_SIZE/2` и `CLICK_SHIFT`), `pointsSnap = off` → радиус угла 2 см в плане (спека 01).
- **Метрики (Q34):** манхэттен — приём точечного снапа (угол, биссектриса), поиск угла для биссектрисы (радиус ×10), хит-тест точки, слияние; евклид — перпендикулярное расстояние до биссектрисы и замыкание «Стен» (толщина / `CLOSE_EPS`); оси — по одной координате. (Уточнено задачей 0062 по исходнику: `bisectorSnap` ищет угол через `snapToNearest` — манхэттен.)
- **Контракт результата** `SnapResult = { snapped (квантовано, = raw при промахе), alignerX, alignerY, bisAnchor, rawAlignersX: [M, P], rawAlignersY: [M, P], hit }` (аудит dd09 keep); лесенка 8 веток (спека 01 «Приоритет»), приоритет Y — явное правило; гайды и крест — часть `ToolState`, подавления гайдов (спека 01 «Визуальные подсказки») решает `guidesFor(snap, state)` в том же модуле, рисует вьювер.

### Инструменты рисования (E3)

| Инструмент                          | Постановка / завершение                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Коммит                                                           |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| «Стены» (`making-walls`)            | клик ставит точку в `snap.snapped`; лента `DEFAULT_WALL_WIDTH = 10`, `side` — `signSide` до третьей точки (рёбра < 5 см не участвуют), потом `sideFixed`; **завершение** — клик с `euclDist(последняя фикс.) ≤ width` **или** `≤ CLOSE_EPS` к первой; во втором случае контур замкнут, в первом коммитится **открытая полилиния** (свободностоящая стена с торцами; короткий последний сегмент отброшен гардом ленты ADR 0017 C5); dblClick — no-op; Esc — отмена всего | `addContours(floorId, N × outer-квадов ленты)` одной транзакцией |
| «Прямоугольник» (`making-rect`)     | два клика; обе стороны > 2 × width — полая (`outer` + `inner`), иначе один `outer`                                                                                                                                                                                                                                                                                                                                                                                      | `addContours` одной транзакцией                                  |
| «Комната по точкам» (`making-room`) | ≥ 4 точек — порог инструмента (команда принимает ≥ 3), замыкание по манхэттену к первой/последней ≤ `CLOSE_EPS`                                                                                                                                                                                                                                                                                                                                                         | `addContours(inner)`                                             |

- **Enter в live-инпуте длины = `commitPoint(point)`** тем же внутренним путём, что и клик (Q27; только абсолютная длина): точка от инпута ставится без снапа, правило замыкания — то же; клик = `commitPoint(snap.snapped)`. Расчёт точки по длине и направлению — чистая функция `document/geometry/`, вызывает оверлей инпута (задача 0060). Инпут длины при выделенной точке/стене в `editing` — `setEdgeLength` с `anchor` / `setWallWidth` (ADR 0018 D1).
- **Локальный стек:** Ctrl+Z в `making-walls`/`making-room` снимает предпоследнюю точку (последняя — живой курсор), Ctrl+Y возвращает; история документа о рисовании не знает; **undo до пустого холста → `editing`** (спека 09); disabled-состояние кнопок undo/redo в `making-*` — по локальным стекам из `ToolState` (0061).
- **Отказы молчаливые** (спека 01): `Result` команды (`contour-self-intersected`, `contour-degenerate`) инструмент не показывает, возвращается в `editing`, пишет `logger.debug`.

### Правка (E4)

- **Хит-тест** — чистая функция `hitTest(point, layout, derived, viewport)` по приоритету: точка (`POINT_SIZE/scale`, манхэттен) → сторона (`SNAP_DIST/2/scale`, `pointOnSegment` по рёбрам контуров) → комната (`pointInContour` по `inner`); результат — `HitTarget | null`, hover в `editing` на каждом `pointerMove`.
- **Драг точки:** после сдвига > `DRAG_THRESHOLD/scale` → `dragging-point`; на каждом `pointerMove` снап с `exceptPoints = [pointId]` → `pointOverrides[pointId] = snap.snapped`; **вьювер разрешает позицию как `overrides[id] ?? layout.points[id]`**, треугольники `DerivedFloor` ссылаются на id точек (ADR 0017 C1) — ретриангуляции на кадр нет. `pointerUp`: `dropTarget.kind === 'wall'` — точка проецируется на сегмент (`projectPointOnLine`), T-стык → разрез в `normalize` (`resplitSegments`/`clean-pslg`); `dropTarget.kind === 'point'` — координата = координата цели, слияние в `normalize` по тождеству квантованной координаты (аудит 01-walls keep: rebuild склеивает совпадающие точки в `manhDist < L_EPS`); команда `movePoints(floorId, [{ id, x, y }])`. Отдельных команд разреза/слияния нет (ADR 0018 D1).
- **Драг стены:** `dragging-wall`, дельта курсора проецируется на нормаль грани, обе точки едут одинаково, гайды подавлены (снап позиции учитывается) → `movePoints` двух концов.
- **dblClick по точке → `deletePoint`** (каскад — ADR 0018 D2). **Ctrl+клик по стороне → выделение комнаты.** Клик по пустому → `selection = null`. Любая смена `selection` (клик мимо, выбор другого, Esc) → `tools` зовёт внутренний `history.breakSeries()` — разрыв коалесинга (ADR 0018 D5).
- **Выделение конструктора живёт в `ToolState.editing.selection`**, не в неймспейсе `selection` (ADR I): спека 06 — мебель и конструктив в 2D — взаимоисключающие режимы; ADR I может переиспользовать форму `HitTarget`. Панель свойств читает его селектором `tools.get()`.
- **Нудж стрелками/WASD** — шаг 2 (задача 0059), как roomtodo (верифицировано по исходнику, задача 0052: `R2D.KeyboardInteractionHelper` 45816–45846 → `WC.SFK.state.moveElement`, `SelectedPoint` 70482, `SelectedWall` 70282, `SelectedRoom` 70558; без выделения `keyDownListener` 62429–62497 двигает камеру): `key({ kind: 'nudge', dx, dy, factor })` при `selection` точки — `movePoints` одной точки, стороны — обеих точек, с `coalesce: 'nudge:<ids>'` (серия нажатий — одна запись, спека 06); шаг — по `settings.units`: 1 см (см/м), 0.1 см (мм), 1.27 см (ftin), Shift ×10, Shift+Ctrl/Cmd ×0.1 (спека 01); Ctrl/Cmd на снап нуджа не влияет; **нудж комнаты — парковка** (в contour-first модели неясно, какие точки едут); без выделения — `{ handled: false }`, вьювер панорамирует.
- **Удаления стены/сегмента целиком в шаге 2 нет** (решение автора): у roomtodo Delete в конструкторе (`quickDelete` 60771–60826, вызов 62412–62417) удаляет выбранную комнату/точку/линейку/пол/зону, ветки «выбранная сторона» нет (верифицировано по исходнику, задача 0052); стена исчезает удалением её точек. Delete по выделенной комнате — парковка (семантика для `outer/inner` не очевидна, 2b/шаг 5).

### Ввод: pointer events, один владелец клавиатуры (E5)

- **Мышь/тач — только pointer events** (`pointerdown/move/up/cancel`, `dblclick`, `wheel`; `setPointerCapture` на `pointerdown` — драг не теряется за краем канваса), `blur` окна → `tools.blur()`, `pointercancel` → `tools.pointerCancel()`; вешает Canvas2D-проекция (ADR 0020), координаты → план через `viewToPlan`, в автомат — `PointerInput`; touch заложен pointer events, не реализуется.
- **Один владелец клавиатуры** — `projection/input/keyboard.ts` (создаётся в `createPlanner`, не в React; панель 0061 клавиш не вешает): `keydown` **и `keyup`** (Space+ЛКМ — пан) на `window`; guard «фокус в `input`/`textarea`/`contentEditable` → не перехватывать» (инпуты длины обрабатывают Enter/Esc/Tab сами — спека 07); чистый keymap `keyToAction(event): KeyAction | null` (Esc → `cancel`; Ctrl/Cmd+Z → `undo`; Ctrl/Cmd+Y, Ctrl/Cmd+Shift+Z → `redo`; стрелки/WASD → `nudge`); маршрут: `tools.key(action)` → при `{ handled: false }` (нет выделения) вьювер панорамирует.

### Canvas2D-проекция конструктора (E6)

Canvas2D-проекция конструктора — ADR 0020 (`./0020-canvas2d-proektsiya-konstruktora.md`).

### Раскладка скина (E7)

Не ADR-уровня: `<Planner />` — контейнер с двумя канвасами и оверлеями (`children`) внутри; подписи размеров, инпуты длины/ширины и подписи комнат — DOM-оверлей `ui/`, позиционируемый через `planToView` (детали — ADR 0020 и задача 0061).

### Тестовый контракт (E8)

- **Слой 1 (Jest node):** снап — все 8 веток лесенки, обе стороны каждого порога, приоритет Y, куллинг, `exceptPoints`, каждый флаг on/off, `pointsSnap = off` → 2 см, квантование; хит-тест — приоритет и пороги; `planToView/viewToPlan` round-trip; лента-превью — по фикстурам ADR 0017 C10; keymap + guard инпутов; `guidesFor` — все подавления.
- **Слой 2 (фасад как state-машина, headless):** все переходы — Esc, `blur`, `pointercancel`, смена инструмента посреди рисования, `view.setActive` посреди жеста (выделение сохраняется), `document.load`, undo до пустого холста → `editing`, программный `history.undo()` во время жеста → `interrupt()`, `history.get()` и `document.get()` не меняются до коммита, `tools:changed` ровно на каждое изменение и ни одного на no-op, `pointOverrides` сбрасываются при отмене, T-стык/слияние на дропе дают ожидаемый `layout` после `normalize`, нудж — coalescing по ключу и `breakSeries` при смене выделения.
- **Слой 3–4 (Playwright):** Canvas2D-гвард (ADR 0020); e2e через dev-ручку `onReady`: прямоугольник → комната → undo → redo; jsdom — pointer/keydown доходят до `tools` в координатах плана.

## Почему

Один автомат — README принцип 3 и аудит (01-walls drop «три параллельных FSM», 04 rework, 07 «состояния линеек — режимы одного автомата», Q10 — 2D-грипы мебели тоже в нём): у референса одна механика размазана по `WC.BaseState`, `R2D.MIH.State*` и зеркалу `WC.SFK` с ручной синхронизацией десятками коллсайтов; у нас смысл любого ввода (Ctrl+Z, Esc, стрелки, кнопки undo панели) определяет ровно одно состояние, а инпуты длины — производное `ToolState`. Каркас «idle-хаб + под-состояния» и порядок `findSnap → mouseMove` берём (аудит keep); состояния — plain-данные, потому что `ToolState` — payload шины и снимок для `useSyncExternalStore`. `xstate` отсекается: 6–8 плоских состояний без параллелизма и иерархии, чужой API в контракте фасада не нужен (та же логика, что `neverthrow` в ADR 0015). Отсекаются также: глобальный `snapTool` с `reset()` — индекс пересобирается по `document:changed`; глобалы `snapPos/aligners` — результат передаётся значением; `SubEditor` правки стен (dd06) — правка = `movePoints` в общем пайплайне; отдельные команды разреза/слияния — их делает `normalize` (ADR 0018 D1); DOM-листенеры в `engine/` — слой без DOM; хоткеи в React-панели — второй владелец клавиатуры.

Документ не трогается до коммита, потому что иначе каждый `pointerMove` — транзакция с `normalize` + `rebuild` + событие, а история нуждалась бы в `skip`-транзакциях и «тихом снятии» записей (спека 09); граница «превью — в `ToolState`, коммит — одна команда» выполняет гейт «мышь зажата — не пишем» по построению и совпадает с roomtodo «rebuild в конце каждого drag». Override позиций вместо мутации: `DerivedFloor` ссылается на id точек (ADR 0017 C1), поэтому вьювер подставляет `overrides[id]` при отрисовке без ретриангуляции, `rebuild` — только на коммит. Открытая полилиния коммитится, а не отменяется, потому что так у roomtodo (верифицировано по исходнику, задача 0052: `StateMakingWalls.mouseUp` 66048–66072 при клике у последней точки → `stateEditing` → `stop()` 65898–65939 строит блоки по оставшимся точкам, замкнутость — только если первая совпала с последней, 57977/58078; Esc 62379–62389 → `cancelMake` 60723 обнуляет контур без коммита) и спека 01 это предполагает («замыкание у последней точки», «короткий последний сегмент отбрасывается» — оба про открытую полилинию). `tools:changed` на каждое движение — потому что DOM-оверлей инпутов длины должен следовать за курсором, а второй канал «вьювер сам читает `tools.get()`» дублировал бы шину; цена компенсируется тем, что селекторы дёшевы (возвращают снимок), а Three-проекция при активном конструкторе приостановлена (ADR 0020) — реальный подписчик один.

Флаги снапа — состояние `tools`, а не документ и не `settings`: спека 10 их не сохраняет, тумблер не должен ставить dirty и порождать `document:changed`. Выделение конструктора — в `ToolState`, а не в неймспейсе `selection`: по спеке 06 конструктив в 2D и мебель — взаимоисключающие режимы, а «Esc снимает», «смена вида сохраняет», «undo снимает» для конструктора реализуются одним состоянием и одним `interrupt()`; ADR I добавит `selection` для мебели/конструктива в 3D. Нудж и Delete — по референсу: нудж у roomtodo есть (верифицировано) — берём в шаг 2 через `movePoints` с coalescing; удаления выбранной стороны нет (верифицировано), семантика Delete/нуджа комнаты для наших `outer/inner` не очевидна — парковка.

## Что важно знать

- **`tools:changed` дёргает wildcard-подписчиков на каждый `pointerMove`** — селекторы `usePlannerSelector` обязаны возвращать снимки/примитивы (ADR 0015), иначе бесконечный ре-рендер проявится на первом движении мыши; панели, которым нужен только `selection`, читают `state.kind === 'editing' ? state.selection : null` — ссылка стабильна между движениями.
- **`ToolState` — plain-данные:** превью ленты пересчитывается на каждый `pointerMove` чистой функцией ADR 0017 (десятки точек — микросекунды, мемоизировать не нужно); `pointOverrides` — новый объект на каждом переходе.
- **Разрез стены** зависит от точности проекции точки на сегмент + `resplitSegments`/`clean-pslg` в `normalize` (ADR 0017 C6): если на `pointerUp` хит-тест стороны не нашёл сегмента, точка ставится в снапнутую координату — разреза не будет, ошибки тоже. **Слияние** — только при тождестве квантованной координаты: снап к точке даёт её координату (спека 01 «в пределах эпсилона» = снап-радиус, финальная координата = координата цели); дроп «почти рядом» при выключенном снапе (Ctrl/Cmd) точки не склеит.
- **`interrupt()` во время рисования при программном undo теряет нарисованные точки** — осознанно (спека 09 «прерванные действия не оставляют записи»); из UI этот путь не достижим — кнопки панели идут через `tools.key`.
- **Смена вида не сбрасывает выделение конструктора** (спека 08), но `hover` пуст до первого `pointerMove`; жест/рисование при смене вида отменяется без коммита.
- **`commitPoint` из инпута ставит точку без снапа** — она может лечь рядом с существующей вершиной и не слиться (пользователь ввёл точную длину); замыкание проверяется тем же гардом, что клик.
- **`setPointerCapture` + `blur`:** при потере фокуса окна во время драга `pointercancel` приходит не всегда — `blur` окна слушается отдельно (спека 09 «blur во время drag»).
- **Отказ команды инструмент не показывает** (спека 01), но пишет `logger.debug` с `error.kind` — единственный канал диагностики «почему контур не появился».
- **Delete/Backspace в конструкторе шага 2 ничего не делает**; удаление комнаты, нудж комнаты — парковка. `making-area`/`making-cover`, состояния линеек и грипов мебели (2b/шаг 5/8) — режимы этого же автомата, второго не будет.
- **Уточнения реализации (задача 0057, в рамках E1–E3/E5):** `blur`/`pointercancel` в `making-*` рисование **не рвут** — зажатой кнопки в рисовании нет, точки остаются («прерванный жест» выше — про драг, спека 09 «Blur во время drag»; отмена рисования — только Esc, `interrupt()`, смена вида, смена инструмента). Точку ставит `pointerUp` основной кнопки (как `mouseUp` референса), `pointerDown` лишь обновляет снап; отсюда **второй `pointerUp` двойного клика — клик у последней точки, то есть завершение открытой ленты** (как у roomtodo), команда `doubleClick` при этом no-op; хочет ли продукт иного — решить до 0056 (фильтр `event.detail > 1` во вьювере). Гард входа: точка, дающая ребро короче `MIN_WALL_LENGTH` (в т.ч. замыкающее ребро петли) или совпавшая с поставленной, молча игнорируется (`commitPoint` возвращает `too-short`/`duplicate-point`), иначе валидация на завершении теряла бы весь контур; самопересечение/вырожденность — на завершении, как в спеке. Ctrl+Z при пустом локальном стеке — no-op (кнопка disabled), при снятии последней точки → `editing`. `start` вне конструктора/без этажа — `Result`-ошибка. Ctrl/Cmd выключает снап и при рисовании. `viewport` до первого `setViewport` — `DEFAULT_VIEWPORT` (1024×768, `scale = 1`, центр `(0, 0)`), чтобы headless-сценарии снапили и куллили осмысленно.
- **Уточнения реализации (задача 0058, в рамках E1–E3):** «Прямоугольник» — `preview: WallBlock[]` в форме ленты «Стен» (квады между `outer` и `inner`: полая — четыре, сплошная — один квад-прямоугольник, нулевой размер — пусто), строится по чистой `rectContours(a, b, width)` (`document/geometry/contours/`) — ровно то, что уходит в коммит; **полая только если полость проходит `contourValid`** (иначе `addContours` отверг бы пакет целиком из-за сливера при стороне 20–~22 см) — уточнение к правилу «обе стороны > 2 × width»; гард второго угла — угол в `origin` (`duplicate-point`) или сторона короче `MIN_WALL_LENGTH` (`too-short`) молча игнорируется; локальных стеков нет: Ctrl+Z при поставленном угле — «undo до пустого холста» → `editing`, без угла и Ctrl+Y — no-op (кнопки 0061: `canUndo = origin !== null`, `canRedo = false`). «Комната по точкам» — замыкание по манхэттену к первой/последней (`contourClosure`, `lastRadius = CLOSE_EPS`) **только от `POLYLINE_ROOM_MIN_POINTS = 4` вершин**; при меньшем числе клик в первую/последнюю — дубль (игнор), рисование продолжается (референс на этом выходил из рисования, теряя точки; треугольник комнатой не становится — спека 01); гард входа как у «Стен» (дубль проверяется первым, затем ребро < 15 см, в т.ч. замыкающее). `guides` в обоих состояниях без пунктира второй грани; у «Прямоугольника» — только основные (без расширенных с угловым фильтром: «последнего сегмента» у него нет, как `drawAligner` референса), у «Комнаты по точкам» — как у «Стен». Рёбра полости прямоугольника порогом 15 см не ограничены (23 × 300 → полость 3 × 280 валидна) — как у референса. Развилка двойного клика (выше) касается и «Комнаты по точкам»: второй `pointerUp` двойного клика у последней вершины от четырёх точек — замыкание; в «Прямоугольнике» — дубль угла (безопасно); решать один раз в 0056. Общий снап/сравнение кадров трёх инструментов — `engine/tools/drawingSnap.ts`.
