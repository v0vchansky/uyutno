# 0018. Мутации, транзакции и undo/redo планера

- Статус: Принято
- Дата: 2026-08-19

## Решение

Мутации документа и история живут в `packages/planner/src/engine/` (ADR 0015: без Three/DOM/React, Jest node) поверх единственной точки мутации `PlannerStore.transact` (задача 0048) и двух поддеревьев `floors[].layout` / `floors[].scene` (ADR 0016 B5); что делает `normalize`/`rebuild` внутри транзакции — ADR 0017 (шаг 2: фазы (1)–(2) `normalize`, `walls/rooms/axes` в `rebuild`). Продуктовые правила — [спека 09](../product/features/planner/09-undo-redo.md) целиком и [спека 01](../product/features/planner/01-walls-and-contours.md) «Транзакции undo/redo редактора стен»; вердикты — [аудит](../product/architecture/competitor-practices-audit.md), строки «Где = D» и решения автора Q14/Q23. Референс даёт memento «stack + pointer» и гейты, но не транзакции ([реверс 09](../product/reference/competitor-mechanics/09-undo-redo-history.md), «Чего не хватает для реализации») — формат транзакций наш. Граница с автоматом инструментов (ADR 0019): **документ не меняется до коммита жеста**; live-превью и live-драг — состояние инструмента.

### Команды планировки (D1)

Команды шага 2 — в неймспейсе `document` (один домен — документ, событие `document:changed`; файлы внутри `engine/` раскладываются по папкам, неймспейс один). `floorId` — явный параметр (форма на `floors[]`; активный этаж — состояние UI/инструмента, v0 — единственный). Каждая команда: валидация на границе → `quantize` координат (ADR 0016 B1) → **одна** транзакция с `history: { zone: 'layout' }` → `normalize` → `rebuild` → одно `document:changed`. Все — `Result<T, E>` (ADR 0015 A2), при ошибке документ не меняется, `undefined` в документ не попадает. Общая ошибка — `unknown-floor`.

### Удаление точки с общим id (D2)

Каскад, как roomtodo (верифицировано по исходнику, задача 0052: `WC.core.delPoint`, plannercore.js 59361–59434 — контур с ≤ 2 точками после удаления → `delRoom`, зона с ≤ 2 → `delArea`, дети-точки пола удаляются рекурсивно, две инцидентные стены сливаются в одну с данными более длинной (59410–59420); реверс 03-rooms этого не описывал — закрыто верификацией). Наше правило внутри транзакции: id снимается со всех владельцев (`contours/covers/areas`, `cuts` с этим концом удаляются); контур/пол/зона, у которых осталось < 3 точек, удаляются целиком (cuts зоны — вместе с ней); слияние двух смежных стен — следствие удаления вершины из петли, отдельной ветки нет (материалы слитой грани — ADR J); дальше `normalize` (пере-привязка комнат C7, GC точек без владельцев, в 2b — авто-полы). Отказ только `unknown-point`; порога «а не станет ли контур невалидным» на границе нет — невалидное вычищает каскад и `normalize`.

### Модель истории (D3)

Memento «stack + pointer» на контейнер (аудит 09 keep, `WallsCommander`): `states[0]` — baseline (создание/`load`), `pointer` — текущий; `canUndo = pointer ≥ 1`, `canRedo = pointer < states.length − 1`; новый коммит режет redo-хвост. Два контейнера — срезы одного документа, а не два графа (аудит 09 rework):

```ts
type HistoryZone = 'layout' | 'scene';
type HistoryRecord = { floorId: Id; layout: FloorLayout }[] | { floorId: Id; scene: FloorScene }[]; // ссылки на замороженные поддеревья всех этажей
type HistoryContainer = { states: HistoryRecord[]; pointer: number; lastCommitKey: string | null };
```

- **`layout`** — снимок берётся **после** `normalize` той же транзакции (спека 02 «Undo/redo для авто-производных объектов»: снимок содержит уже пересобранный документ). Восстановление — транзакция замены поддеревьев `floors[i].layout` по `floorId` с `history: 'none'` + обычный `normalize`/`rebuild` (двойной `normalize` идемпотентен — ADR 0017 C10) → одно `document:changed`.
- **`scene`** — то же для `floors[i].scene`. Пообъектный diff при restore (спека 09) — обязанность проекции по `document:changed` (ADR G), не истории: «что читаем при restore, то и пишем в snapshot» выполняется тем, что и снимок, и restore — одно и то же поддерево целиком.
- **Не в истории:** `Document.view` (не снапшотится и restore его не трогает); **`settings` (`units`, `wallHeight`) — вне истории в v0** (спека 09 их не перечисляет; dirty-флаг ставят); выделение, состояние инструментов, промежуточные кадры (спека 09 «Что НЕ попадает»).
- Baseline не откатывается; `document.load` — транзакция с `history: 'reset'` (D5): очистить оба контейнера, новый baseline из загруженного (нормализованного) документа, `lastCommitKey = null`, `activeZone` = зона вида; миграция формата — часть `load`, не запись (спека 09).

### Активная зона (D4)

`activeZone` — состояние истории: зона активного вида (`constructor` → `layout`, `plan`/`orbit`/`walk` → `scene`), **но последняя запись/undo/redo переключает её на свою зону** до следующей смены вида (`view.setActive` → зона вида). Так «Ctrl+Z откатывает то, что я только что сделал» верно и когда правка планировки придёт из 3D-панели (шаг 5/7); правило не переигрывается. `history.get(): { canUndo, canRedo }` — по активной зоне, стабильный замороженный снимок; `history:changed` — при изменении этих флагов, в том числе из-за смены вида (`view:changed` может повлечь `history:changed` без транзакции содержимого). `undo`/`redo` на пустом стеке — `err({ kind: 'nothing-to-undo' | 'nothing-to-redo' })` (0048), хук D9 не зовётся.

### API транзакции, коалесинг, точки коммита (D5)

```ts
type TransactionMeta = { history: 'none' | 'reset' | { zone: HistoryZone; coalesce?: string } };
transact(recipe: TransactionRecipe, meta: TransactionMeta): void;
```

- `history: { zone }` — после успешной транзакции содержимого (что-то кроме `view` изменилось) в контейнер зоны кладётся запись, `activeZone = zone`. `'none'` — `view.*`, `settings`, restore. `'reset'` — только `document.load`: оба контейнера очищаются, новый baseline, `lastCommitKey = null`, `activeZone` = зона загруженного вида (D3). Транзакция без изменений (immer вернул тот же объект) записи не порождает.
- **Коалесинг:** `coalesce: key` — если `lastCommitKey === key`, запись на `pointer` **заменяется** новой (одна запись на серию; undo возвращает к состоянию до серии), иначе обычный push. **Серию рвут:** любой другой коммит (без ключа или с другим), undo/redo, `load` и **смена выделения** (решение автора 2026-08-17, аудит 09): `tools` при смене `selection` (клик мимо, выбор другого объекта, Esc) зовёт внутренний метод контейнера `history.breakSeries()` (сброс `lastCommitKey`; внутренний движка, не публичный API фасада). Ключ формирует **команда, не UI**: `setEdgeLength`/`setWallWidth` (`'edge-length:<a>|<b>'`, `'wall-width:<a>|<b>'`) — серия правок одного поля = один шаг (спека 09 «Гранулярность»); нудж стрелками — `movePoints` с `'nudge:<ids>'` (ADR 0019 E4: серия нажатий = один шаг, спека 06); драги мышью, `addContours`, `deletePoint` — без ключа, каждый — отдельная запись.
- **Точки коммита** (порождает ADR 0019, фиксирует D): `pointerUp` драга точки/стены; завершение контура (клик у последней/первой точки или Enter в инпуте длины, давший замыкание/завершение); Enter/blur/Tab в инпуте длины/ширины. Гейт спеки 09 «пока мышь зажата — не пишем» выполняется по построению: на `pointerMove` транзакций нет. Прерванный жест (Esc, `blur` окна, `pointercancel`, смена вида, `document.load`, Ctrl+Z во время драга) — не транзакция: состояние инструмента возвращается к исходному, история и документ не тронуты; пути «тихо снять последнюю запись» (`removeUndoState`) нет за ненадобностью.

### Лимит (D6)

`MAX_HISTORY = 100` записей сверх baseline на контейнер (константа рядом с контейнером). На каждом push после среза redo-хвоста: если `states.length > MAX_HISTORY + 1` — `states.shift()`, самая старая запись становится новым baseline (спека 09 «жёсткий енфорс на каждом push»); замена по коалесингу длину не меняет и trim не зовёт.

### Dirty-флаг (D7)

Поле `PlannerStore` (Q14: отдельный флаг проекта, не «грязная история»): ставится любой транзакцией содержимого — командами планировки, `settings`, restore undo/redo, позже подложкой вне истории (ADR K); не ставится `view.*`. Наружу: `document.isDirty(): boolean`, `document.markSaved()` (заглушка до ADR F: сбрасывает флаг), событие `document:dirty-changed { dirty }` только при смене значения; `load` и создание — `false` (`load` сбрасывает флаг после своей транзакции). Гейт серверного автосейва (спека 10) — ADR F.

### Локальный стек рисования vs история — граница с ADR 0019 (D8)

Точки полилинии/контура в `MakingWalls/MakingRect/MakingRoom`, их локальные undo/redo (Ctrl+Z снимает предпоследнюю точку — спека 01), превью ленты `blocksFromContour` и live-драг через `pointOverrides` — состояние инструмента; история документа о рисовании не знает; контур попадает в документ **одной** транзакцией `addContours` на завершении. «Undo до пустого холста» — выход из рисования в `Editing`, записи нет. Ctrl+Z в `Editing` → `history.undo()`; программный `undo/redo` во время жеста — через хук D9.

### Снятие выделения перед restore (D9)

Внутренний хук движка, не событие шины: `StoreHooks { beforeReplace(): void }` — зовётся перед любой заменой поддерева/документа мимо команд инструментов: restore undo/redo и `document.load`. `PlannerManager` при сборке подключает к нему `tools.interrupt()` (отмена жеста без коммита + сброс hover/выделения конструктора → `Editing`, ADR 0019) и позже `selection.clear()` (ADR I). Хук зовётся синхронно **до** транзакции замены, только если замена состоится; хук не коммитит в историю. После undo/redo выделение не восстанавливается (спека 09).

### Тестовый контракт (D10)

Слой 2 ([testing-strategy](../product/architecture/testing-strategy.md), фасад как state-машина, Jest node): одна запись на команду и на `addContours` с N контурами; коалесинг — серия с одним ключом = одна запись, разрыв другим коммитом/undo/redo/`load`/сменой выделения (`breakSeries`); `load` = `'reset'` — оба контейнера пусты, `canUndo/canRedo = false`, `lastCommitKey = null`; лимит — 101-я запись вытесняет старейшую, baseline сдвигается, `canUndo` остаётся; `undo(redo(x)) == x` и `redo(undo(x)) == x` по ссылке поддерева (`fast-check`, случайные последовательности команд); `history:changed` ровно при смене флагов, включая смену вида без транзакции, и ни разу при no-op; undo не трогает `view` и `settings`; dirty по всем веткам (команда, `settings`, undo/redo, `view` — нет, `load` — сброс, `markSaved`, событие только при смене); `beforeReplace` вызывается до замены поддерева при undo/redo и при `load`, не вызывается при `nothing-to-undo`; `deletePoint` — все комбинации владельцев (контур/пол/зона/cut, общий id) и порог < 3 с каскадом; каждая ветка ошибки каждой команды — отдельный тест, документ после ошибки — тот же объект.

## Почему

**Снапшот по ссылке, а не command-модель.** Спека 09 выбрала snapshot; `immer` со структурным разделением (ADR 0016 B5) делает запись O(1) по памяти для неизменённых поддеревьев и O(1) по времени — «стоимость снапшота O(n) на коммит» референса (реверс 09, «Чего не хватает» п. 7) снимается разделением, а не командами. Command-модель отсекается: обратную операцию пришлось бы писать и для `normalize`, который переписывает `contours/points` результатом слияния (ADR 0017 C1) — обратимой команды там нет; «что читаем при restore, то и пишем в snapshot» с поддеревом выполняется автоматически, а не дисциплиной. Два контейнера — потому что спека 09 требует независимые истории планировки и сцены; но это срезы одного документа, поэтому «мостик» и условная починка baseline референса (аудит 09 drop) не нужны.

**Документ не трогается до коммита.** Rebuild — только на коммит, как roomtodo «rebuild в конце каждого drag» (аудит 01-walls keep; Q23 — полный синхронный recompute), поэтому `history: 'skip'`-транзакции для live-драга отсекаются: они дали бы rebuild с триангуляцией на каждый `pointerMove` и фильтр записей в истории ради того, что решается `pointOverrides` во вьювере (ADR 0019). `removeUndoState` («тихо снять») отсекается: если в историю ничего не писали, снимать нечего — путь спеки 09 выполняется вакуумно. Отдельные команды `splitSegment`/`mergePoints` **для жестов над существующими вершинами** отсекаются: тождество квантованной координаты и T-стык уже делает `normalize` (ADR 0017), спека 01 — «отдельного действия объединить не нужно». Пересмотрено 2026-08-21 (ручка деления грани, спека 01): этот аргумент работает, пока вершина, которой режут, уже есть, — тогда команда сводится к `movePoints`. У ручки деления вершины ещё нет, и создать её нечем: `addContours` заводит новый контур, а не вставляет точку в кольцо существующего. Поэтому `insertPoint` заведён — но ровно как «вставить вершину в кольцо между двумя соседями»: разрез соседних контуров, полов и зон, делящих ту же грань, по-прежнему делает `normalize`, а не команда. `mergePoints` командой не стал и не станет. Ручные `saveState` из инструментов и панелей отсекаются (аудит 09 drop, ~60 call sites у референса): запись — побочный эффект `transact` по `meta`, инструменты историю не трогают. Changed-флаги (аудит dd05/06 drop, Q23) отсекаются: инвалидация — факт `document:changed`, diff при restore — по значению в проекции (ADR G).

**Один хук `beforeReplace`, а не событие шины.** Правило ADR 0015 A5: события — свершившиеся факты в прошедшем времени; «сейчас заменю поддерево» — не факт, а запрос к двум конкретным подписчикам (`tools`, `selection`), порядок и синхронность которого важны; один хук покрывает и restore, и `load` — оба заменяют документ мимо инструментов. Паттерн референса «deselect на `STATE_UPDATE` до мутации» (аудит 09 keep) берём как хук. `settings` вне истории — потому что спека 09 их не перечисляет, `wallHeight` — дефолт для новых комнат (C7), а не правка планировки; откат единиц по Ctrl+Z удивил бы. Активная зона «по виду, но последняя запись побеждает» — роутинг Ctrl+Z в движке, а не в хосте (аудит 09 rework, реверс «Confidence & gaps» п. 3), и правило переживает правку планировки из 3D-панели без переигрывания.

## Что важно знать

- **Restore `layout` не откатывает изменения `scene`, сделанные `normalize` в той же транзакции** (шаг 6: проёмы без оси удаляются на rebuild — ADR 0016 «Принцип привязки»); отменяются они только undo в зоне `scene`, если попали в её запись. Осознанно: две зоны независимы по спеке 09.
- **Серию коалесинга рвут** другой коммит, undo/redo, `load` и смена выделения (`breakSeries` из `tools`, ADR 0019); две правки одного инпута через клик мимо и обратно — два шага.
- **Двойной `normalize` при restore идемпотентен** (ADR 0017 C10): снимок взят после `normalize`, поэтому после restore ссылка `floors[i].layout` совпадает с записью — на этом держится `undo(redo(x)) == x` по ссылке.
- **Запись держит все этажи** (`{ floorId, … }[]`): в v0 один этаж, несовпадение набора этажей между записью и документом невозможно (этажи добавляются только `load`, который чистит историю); политика для multi-floor — при его появлении.
- **Лимит считает записи сверх baseline**: в контейнере до 101 элемента; после вытеснения baseline — «то, что было 100 шагов назад», не состояние загрузки.
- **`history:changed` может прийти без изменения документа** (смена вида → смена активной зоны → другие флаги); подписчики не должны выводить из него «документ изменился».
- **`document:dirty-changed` — единственное событие с флагом**; `document:changed` подразумевает `dirty = true`, но не несёт его; `load` даёт `document:changed` + `view:changed` (0048) и при необходимости `dirty-changed { dirty: false }`.
- **Restore — обычная транзакция содержимого**: `document:changed` один, проекция Three не отличает undo от правки; пообъектный diff сцены при restore — обязанность проекции (ADR G), контракт зафиксирован здесь: снимок и restore — целое поддерево `scene`.
- **`beforeReplace` зовётся до транзакции**, поэтому `tools.interrupt()` внутри него видит ещё старый документ и не должен его читать для решений; отменённый жест не пишет в историю — рекурсии нет.
- **`setWallWidth` адресует ось парой граней** (осей без id, C8): если между инпутом и коммитом прошёл rebuild и такой пары больше нет — `unknown-axis`; UI перечитывает `getDerived()` по `document:changed`.
- **Уточнения реализации (задача 0055, аддитивно к D1/D2/D3):** ошибки `invalid-coordinate` (`addContours` — `{ index }`, `movePoints` — `{ id }`) для не-конечных координат (plain-JSON, B5) и `degenerate-edge` в `setEdgeLength` при совпадающих концах; `anchor` вне ребра → `unknown-point`; пороги `setWallWidth` — `too-short` < `MIN_WALL_WIDTH` = 1 см (пол 15 см к ширине неприменим: `DEFAULT_WALL_WIDTH` = 10), `out-of-range` — как у длины (> 100 000 / не конечное; `MAX_WALL_WIDTH` = 80 — порог детектора оси, не лимит ввода — спека 01); «cuts зоны» при удалении зоны (D2) — cuts с обоими концами среди её точек, которых не держит ни одна выжившая зона (у `Cut` нет ссылки на зону); `HistoryRecord` несёт дискриминант `zone` поверх скетча D3; транзакция содержимого с `history: 'none'` (`settings`) серию коалесинга не рвёт; `breakSeries()` — метод `PlannerStore`, не неймспейса `history`.
