## Описание

Второй шаг реализации планера по [planner-build-order.md](../../product/architecture/planner-build-order.md). После шага 1 (эпик 0043) движок стоит на ногах: пакет `@uyutno/planner`, документ по ADR 0016, фасад `PlannerManager` с транзакциями через `immer` и sync-`rebuild` (пока пустым), шина `mitt`, `history`-заглушка, проекция в Three с пустой сценой. Цель шага 2 — **первый полезный для пользователя результат**: в конструкторе (отдельный Canvas2D-вьювер того же документа, решение Q17) можно нарисовать контур со снапом, из него выводятся стены с толщиной и митрингом и комнаты, точки и сегменты правятся, всё это перерисовывается в 2D и откатывается undo/redo.

Как и в шаге 1, самое дорогое для отката фиксируется ADR **до** кода: **C** — геометрический пайплайн, **D** — мутации/транзакции и undo, **E** — автомат инструментов и пайплайн ввода/снапа (три ADR-кандидата строки шага 2 build-order). Кодовые задачи заведены сразу (см. таблицу в README доски), но их скоуп уточняется после принятия ADR — об этом пометка в «Заметках» каждой.

Скоуп эпика (по строке шага 2 build-order):

- **ADR C + D + E** — две задачи-брифа: 0051 (C) и 0052 (D + E), документация без кода.
- **Геометрическое ядро** (`document/geometry/`, чистые функции без Three/DOM): предикаты и примитивы, офсет ленты и митринг, обвязка триангуляции (`cdt2d` + `clean-pslg`), детекция комнат, оси стен, реальные `normalize()`/`rebuild()` → `DerivedState`; golden-фикстуры и property-тесты.
- **Мутации планировки и undo/redo**: команды фасада для контуров/точек/сегментов как транзакции, реальный неймспейс `history` (снапшоты, два контейнера, coalescing, лимит 100), dirty-флаг отдельно от истории.
- **Canvas2D-вьювер конструктора**: отрисовка документа и производного (стены, комнаты, хендлы углов, размеры сегментов), собственный зум/пан, render-on-demand, resize/dispose без утечек.
- **Снап** как чистые функции (лесенка приоритетов, гайды, индекс кандидатов).
- **Автомат инструментов и контракт ввода**: один FSM (`tools`), команды с координатами плана; инструменты «Стены», «Прямоугольная комната», «Комната по точкам»; DOM-ввод (pointer/keyboard) — у Canvas2D-вьювера.
- **Правка точек/сегментов**: хит-тест по приоритету, драг точки (с общими точками), драг стены по нормали, удаление точки двойным кликом со слиянием стен, разрез стены на дропе, слияние точек, Ctrl+клик — комната.
- **Live-инпуты длины** при рисовании и правка длины ребра / ширины стены (DOM-оверлей).
- **Минимальная интеграция в `<Planner />`**: панель инструментов конструктора, кнопки undo/redo, горячие клавиши, тумблеры снапа, переключение конструктор ↔ 2D-план.

Вне скоупа: save/load и автосейв (шаг 3, ADR F — здесь только dirty-флаг как факт движка); 3D-меши стен/полов и любая отрисовка стен в Three-видах (шаг 4, ADR G — 2D top-view в Three остаётся пустой сценой); проёмы (шаг 6); материалы и панель свойств (шаг 7, ADR J); зоны (areas), ручные полы (covers), cuts, плинтусы, потолки как **инструменты и отрисовка** — ADR C фиксирует для них место в пайплайне, реализация — вопрос автору о размещении в build-order (см. «Заметки»); мебель/каталог/выделение мебели (шаг 5, ADR H/I); измерения и единицы сверх инпутов длины (шаг 8); импорт подложки (шаг 10).

## Заметки

- Нарезка кодовых задач (0053–0062) — предварительная, заведена вместе с эпиком по принципу «задачи по одному шагу за раз»; после принятия ADR C/D/E скоуп и границы задач уточняются правкой файлов задач (не заведением новых номеров без нужды). Граф: 0051 → 0053 → 0054 → 0055; 0052 (черновики параллельно с 0051, принятие после C) → 0055/0056/0062; 0053 + 0052 → 0062 → 0057 (+0055) → {0058, 0059, 0056} → 0060 → 0061. Design-gated только 0056/0060/0061; весь движок (0053–0055, 0057–0059, 0062) проверяется headless и от макета не зависит.
- **Вопрос автору (размещение в build-order):** инструменты «Зона» (спека 01/02) и «рисование пола» (multi-material полы, спека 02), cuts, плинтусы и потолки нигде в таблице шагов не названы явно; шаг 2 берёт только детекцию комнат (`02 (детекция)`). Предложение: ADR C фиксирует их стадии пайплайна (`rebuildWallsAndCovers`-порядок аудита), реализацию вынести отдельной строкой build-order «шаг 2b: полы, зоны, cuts в 2D» между шагами 2 и 3 либо приклеить к шагу 4 (там появляются меши полов/потолков/плинтусов). Решить до закрытия 0051.
- **Вопрос автору (дизайн):** для конструктора (чертёжный вид: цвета стен/комнат, толщины линий, хендлы, гайды снапа/крест/превью, hover/выделение, подписи размеров), панели инструментов, кнопок undo/redo и live-инпутов длины в спеке есть только качественное описание (спека 08 «Конструктор стен», спека 01/07). Задачи 0056/0060/0061 заведены с `Нужен дизайн: да` и без ссылки — в работу не берутся, пока нет макета (handoff в `docs/ui/handoffs/planner/`) или явного решения «делаем по guidelines / как roomtodo временно». Движок и геометрия (0053–0055, 0057–0059, 0062) от макета не зависят.
- **Вопросы автору (скоуп, для ADR E / 0052):** (1) может ли контур «Стены» быть закоммичен незамкнутым (спека 01 «Крайние случаи» описывает завершение открытой полилинии, но не чем оно вызывается: Esc всегда отменяет?); (2) есть ли в шаге 2 удаление стены/сегмента целиком (спека 02/09 говорят «стёр стену», спека 01 — только удаление точки); (3) нудж выделенной точки стрелками — шаг 2 или шаг 8.
