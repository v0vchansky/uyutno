## Основание

ADR 0021 закрепляет: **golden-фикстуры хранятся в формате сейва с `format`/`version`, при смене версии мигрируются тем же кодом, что и пользовательские сейвы; детерминизм — через инжектируемый генератор id в `normalize`. Поднятие версии обязано включать переснятие фикстур — это пункт чек-листа задачи, которая двигает формат.**

Часть требования уже выполнена задачами шага 2: 23 фикстуры `document/geometry/fixtures/plan-*.json` лежат в виде `{ name, input: PlannerDocument, expected }`, поле `input` уже содержит `format: "uyutno.planner"` и `version: 1`, а `normalize` уже принимает `options.createId` — раннер подставляет `createSequentialIds` из `planBuilder`, поэтому новые id в эталонах выглядят как `n1, n2, …`. **Задача не переизобретает это, а достраивает недостающее**: связь фикстур с реальным кодом формата.

## Описание

Скоуп:

1. **Раннер читает фикстуру через код формата.** `engine/rebuild.golden.test.ts` сейчас берёт `input` как готовый объект. После задачи он прогоняет его через `parse` (и `migrate`) из `@uyutno/planner/format` — то есть фикстура входит в пайплайн ровно тем же путём, что пользовательский сейв. Ловит расхождение «фикстура написана руками так, как парсер бы её не принял».
2. **Round-trip на каждой фикстуре**: `parse(serialize(input))` равен `input`; `normalize` после `parse` неподвижен (идемпотентность пути загрузки, требование ADR 0021). Проверяется на всех 23 фикстурах, а не на выборке.
3. **Обновление эталонов миграцией, а не руками.** Механизм `UPDATE_GOLDEN=1` остаётся, но в него добавляется шаг: при смене версии формата фикстуры **прогоняются цепочкой миграций** и переписываются её результатом. В v0 цепочка пуста и шаг — тождество; ценность в том, что первая же смена формата не начинается с проектирования процедуры.
4. **Чек-лист «поднятие версии формата»** — короткий, в `packages/planner/CLAUDE.md` (или рядом с цепочкой миграций в `format/`), пунктами: добавить шаг в цепочку → версия поднимется сама → прогнать фикстуры миграцией → прочитать дифф глазами → обновить эталоны. Это тот самый «пункт чек-листа задачи, которая двигает формат», который ADR требует иметь заранее.
5. **Детерминированный генератор id — довести до пути загрузки.** Сейчас инжекция работает в раннере golden; убедиться, что тем же способом детерминизируется `normalize`, вызванный **после `parse`** (путь открытия проекта), и что фикстуры не зависят от `uuidv7`. Если где-то на пути загрузки генератор не прокинут — прокинуть.
6. **Фикстура с незнакомым полем.** Одна фикстура, в `input` которой лежит поле, которого схема не знает: она держит обещание forward-compat на уровне golden, а не только юнита (`0079` покрывает его юнит-тестом; здесь — что оно переживает полный круг `parse` → `normalize` → `serialize`).

Не в задаче: сам модуль формата (`0079`); серверная миграция (`0080`); новые геометрические фикстуры — набор шага 2b полон.

## Приёмка

- [x] Golden-раннер поднимает `input` через `parse`/`migrate` из `@uyutno/planner/format`; фикстура, которую парсер бы не принял, роняет тест.
- [x] На каждой из фикстур зелёные: `parse(serialize(input)) == input` и идемпотентность `normalize` после `parse`.
- [x] `UPDATE_GOLDEN=1` переписывает эталоны через цепочку миграций; на пустой цепочке результат байт в байт совпадает с текущими эталонами (дифф пустой — значит переход не поехал).
- [x] Чек-лист «поднятие версии формата» записан в репозиторий и содержит пункт про переснятие фикстур.
- [x] Ни один эталон не зависит от `uuidv7`: прогон дважды подряд даёт идентичный результат, id новых записей — из инжектированного генератора.
- [x] Заведена фикстура с незнакомым полем в `input`; поле переживает полный круг и присутствует в результате `serialize`.
- [x] Существующие 23 фикстуры остались зелёными **без правки эталонов**; если что-то поехало — дифф прочитан глазами и объяснён в «Заметках» (эталон меняется только осознанно).
- [x] `pnpm typecheck`, `pnpm lint`, `pnpm test` зелёные.
- [ ] Prettier чист; ровно один PR.

## Заметки

- **Почему это отдельная задача, а не строка в `0079`.** Идемпотентность `load(save(x)) == x` — условие приёмки задачи формата (ADR 0021 говорит об этом прямо), но привязка **эталонов** к коду формата — работа по тестовой инфраструктуре и трогает раннер, который используют все задачи геометрии. Разведены, чтобы `0079` не разрослась и чтобы дифф эталонов ревьюился отдельно.
- **Стоимость прогона.** Пакет `@uyutno/planner` сейчас идёт ~51–62 с, из них заметная доля — фазы (4)–(6) `normalize` (см. «Известное ограничение» эпика [0066](0066-EPIC-planner-step2b-covers-areas-cuts-core.md)). Добавляемый round-trip дешёвый (JSON + zod), но если прогон заметно вырастет — мерить и писать замер сюда, а не молча снижать `numRuns` property-тестов.
- **Записи-сироты `rooms[]`** в фикстурах остаются как есть: в v0 не чистим (ADR 0021, «Смежное»).
- **Содержимое фикстур не менялось — ни обёртка, ни эталоны.** 23 существующих `plan-*.json` уже лежали в формате сейва: `parse(input)` возвращает `input` дословно (ничего не дефолтится и не срезается), `parse(serialize(input)) == input`, `migrate` — тождество. Полный прогон `UPDATE_GOLDEN=1` (он теперь переписывает и `input` результатом цепочки миграций) оставляет рабочее дерево чистым: `git status` по каталогу фикстур пуст, добавлен только новый файл.
- **Генератор id прокинут в `PlannerStore`** (`createId?` в опциях, по умолчанию — `document/id.ts`): `normalize` зовётся не только раннером, но и стором — в конструкторе и в `load`, то есть на пути открытия проекта. Без инжекции туда «детерминизм фикстур» кончался бы на границе раннера; тест `engine/loadPathIdempotency.test.ts` («путь открытия проекта…») до правки видел в снимке `uuidv7`. Прод опцию не передаёт.
- **Forward-compat в фикстуре построен на неподвижной точке.** `plan-forward-compat-unknown-fields` собран из уже нормализованной раскладки `plan-area-in-room`, поэтому `normalize` её не пересобирает и тест говорит про незнакомые поля, а не про геометрию. Это существенно: записи, которые пересборка создаёт заново (новая комната без донора, вторая половинка разделённой), собираются из известных полей — незнакомые в них не переносятся. **Обещание forward-compat сужено под это решением автора 2026-08-21** — ADR 0021, «Что важно знать»: чинить не будем до появления второй версии формата. Уцелевшие уровни: корень, `settings`, `view`, камера, этаж, `layout`, `scene`, точка, контур, пол, зона, рез, комната.
- **Стоимость прогона не выросла**: golden-раннер — 0.46 с (24 фикстуры, по два прогона на каждую), пакет целиком — 61.7 с, в прежнем коридоре 51–62 с. Под `UPDATE_GOLDEN=1` — 2.8 с (по процессу Prettier на файл).
