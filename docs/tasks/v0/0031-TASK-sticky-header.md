## Описание

Сейчас `PublicHeader` (`apps/platform/src/client/common/components/PublicLayout/PublicHeader.tsx`) уходит вверх вместе с контентом при скролле — обычный поток, без `position: sticky`. Хочется, чтобы шапка «прилипала» к верхнему краю вьюпорта: скроллим страницу — шапка остаётся видимой. Это стандартное поведение шапок в web-приложениях: логотип, навигация и меню профиля всегда под рукой, не нужно скроллить наверх.

Правка касается всех трёх режимов `PublicLayout` (`landing` → `guest-landing`/`auth-landing`, `app`, `auth`) — шапка одна и та же, поведение унифицируем.

Побочный эффект от `sticky top: 0`: якорные переходы на лендинге (`#features`, `#how`, `#faq`) начнут прыгать «под шапку» — начало секции окажется скрыто. Компенсируем через `scroll-padding-top` на корневом `html`, равным высоте шапки. Высота шапки ~65px (то же значение уже используется в `MobileMenu.tsx:118` как `top-[65px]` для drawer'а).

Мобильный drawer `MobileMenu` уже позиционируется `fixed top-[65px]` — с липкой шапкой ничего не ломается: шапка остаётся видимой сверху, drawer растягивается ниже, скролл body заблокирован.

## Скоуп

**Клиент (`apps/platform/src/client/`):**

1. **`PublicLayout/PublicHeader.tsx`.** К корневому `<header>` добавить классы `sticky top-0 z-40`. Фон уже непрозрачный (`bg-[var(--surface)]`) — под ним не будет просвечивать контент. `z-40` совпадает с overlay мобильного меню (`MobileMenu.tsx:118`), чтобы drawer не перекрывал шапку.

2. **`global.css`.** Добавить `scroll-padding-top: 65px` на `html`, чтобы anchor-переходы (`#features`, `#how`, `#faq`) с плавным скроллом (задача 0030) останавливались под липкой шапкой, а не под ней.

3. **`ProfileMenu.tsx` — свой дропдаун вместо HeroUI Popover.** По ходу приёмки вылезли два регресса меню профиля:
   - клик вне меню больше не закрывает его;
   - повторный клик по триггеру-аватару «моргает» и не закрывает — только второй клик закрывает.

   Оба — следствие `isNonModal` на `Popover.Content` (введён коммитом e4e6611 в рамках 0030, чтобы React Aria не блокировал скролл страницы через `usePreventScroll`). В HeroUI Popover/Dropdown v3 пропс `isNonModal` пробрасывается в React Aria; non-modal режим ломает outside-dismiss и toggle-по-триггеру, а модальный — блокирует скролл страницы. Промежуточного варианта в v3-обёртке нет.

   Решение: заменить HeroUI Popover на собственный дропдаун. React state + `useEffect` с document/window-листенерами (`mousedown`, `scroll`, `keydown`). Меню — обычный `<div className='absolute right-0 top-full ...'>` под триггером, стили и разметка — как в макете (аватар+имя, разделитель, «Настройки», «Выйти»). Только для десктопа; на мобилке продолжает работать `MobileMenu`.

   Что получаем разом:
   - клик по триггеру открывает, повторный — закрывает (обычный `useState` toggle, никакого React Aria);
   - клик вне меню закрывает (`document.addEventListener('mousedown')` с проверкой `contains`);
   - скролл окна закрывает (`window.addEventListener('scroll')`);
   - Escape закрывает;
   - страница скроллится, когда меню открыто, — никаких `overflow: hidden` на `html`.
