## Описание

Мы не копируем roomtodo — берём паттерны и осознанно отбрасываем плохие практики. Сейчас вердикты разбросаны: «Что не копируем» есть только в секциях 00/14/15, у остальных — лишь блоки «Confidence & gaps» и таблица «стандарт/кастом» по deep-dives в 00-overview. Нужна **одна сводная таблица** — вход для всех ADR планера (A–K), чтобы каждый ADR ссылался на вердикт, а не переоткрывал его.

Результат — `docs/product/architecture/competitor-practices-audit.md`:

- Таблица по секциям `competitor-mechanics/01–15` и `deep-dives/01–10`: **практика** (одной строкой, со ссылкой на секцию/дайв) → **вердикт** `keep` / `rework` / `drop` → **почему** (одна-две строки) → **где решаем у нас** (буква ADR из build-order или «спека, раздел NN»).
- Отдельно вынести сквозные архитектурные практики (глобалы `WC/R2D/TR`, три параллельные state-машины, две системы истории, Redux-обвязка, render-on-demand, одна сцена — много камер, contour-first, `changed`-флаги, монолит без слоёв) — они влияют на ADR A/B в первую очередь.
- Практики, где вердикт зависит от нашего продуктового решения, уже принятого в `features/planner/*`, — просто ссылка на раздел спеки, не перерешивать.

Метод: оркестратор — по субагенту на группу секций (01–03+dd01–03/07–09; 04–05+dd10; 06+dd04–05; 07–08; 09–10; 11–12; 13–15) с одинаковым бланком таблицы; сводить самому, спорные вердикты помечать `?` и выносить в «Заметки» вопросом автору. Факты про конкурента брать только из наших доков (они провалидированы), в исходник не лезть — если дока не отвечает, писать «дока не раскрывает», а не догадываться.

Что не делаем: не пишем ADR, не правим спеку, не трогаем `competitor-mechanics/*` (аудит — новый файл, не правки внутри референса).
