## Описание

Страница регистрации email/пароль по макету `/register` из [`docs/ui/handoffs/auth/Auth Screens.dc.html`](../../ui/handoffs/auth/Auth%20Screens.dc.html) + серверный эндпоинт `POST /api/v1/auth/register`. Кнопки OAuth уже видимы, реализуются в 0015. Правовая строка ссылается на `/terms` и `/privacy`; страницы должны существовать (0017), константы `TERMS_URL/PRIVACY_URL` заводятся в этой задаче в `src/client/common/` — 0018 подхватит их для футера и остального сайта.

### Frontend (`src/client/landing/pages/RegisterPage/`)

- Свёрстать по макету на HeroUI v3 и токенах `theme-uyutno.css`. Три размера — desktop / tablet / mobile.
- Форма: поля email (`type=email`, `autocomplete=email`), пароль (`type=password`, `autocomplete=new-password`, плейсхолдер «Не менее 8 символов», подсказка под полем «Буквы и цифры, минимум 8 символов»).
- Под кнопкой «Создать аккаунт» — правовая строка «Создавая аккаунт, вы принимаете условия использования и политику конфиденциальности». Ссылки берутся из общей точки `src/client/common/` (константы `TERMS_URL`, `PRIVACY_URL`), которую заводит эта задача — не хардкодить пути прямо в JSX.
- Состояния: `idle`, `submitting` (кнопка disabled, текст «Создаём…»), `error` (плашка над кнопкой или подпись под полем — по типу ошибки).
- Валидация на клиенте до сабмита:
  - email: базовый regex + max 254 символа;
  - пароль: минимум 8 символов, обязательно буквы и цифры;
- Серверная валидация — авторитетная. Ошибка «email уже занят» — подпись под полем email («Этот email уже зарегистрирован»), курсор возвращается в поле email.
- **Логика `from`:**
  - При загрузке страницы читаем `?from`, валидируем.
  - Ссылка «Войти» → `/login?from=…` через `buildAuthUrl`.
  - После успешной регистрации — сессия уже установлена (автологин), редирект на `from` или на `/projects`.
- Свои `<title>` и `<meta name="description">`.
- Гард `redirectIfAuthenticated` (из 0011) уводит залогиненного пользователя автоматически.

### Backend (`src/server/auth/`)

- Zod-схема в `src/shared/auth/` — `RegisterRequest { email: string; password: string }`. Правила пароля (минимум 8, буквы + цифры) кодируются в схеме — используются и клиентом, и сервером.
- Контроллер `POST /api/v1/auth/register`:
  1. Валидация тела (Zod) → 400 при формате.
  2. Нормализация email (lowercase + trim).
  3. Проверка уникальности `usersRepository.findByEmail`; если занят — `ConflictError` (409) с кодом `email_taken` в теле ответа, чтобы клиент показал точную ошибку.
  4. `argon2.hash(password)`, `usersRepository.create`.
  5. `sessionService.issueSession(user.id)`, установка cookie.
  6. Ответ 200 без тела (симметрично 0012).
- Rate limit: 10 запросов / час на IP.
