# Задачи v0

Декомпозиция релиза [v0](../../product/release-v0.md) на исполнимые задачи.

## Правила ведения

- **Типы.** `EPIC` — крупная фича, объединяет несколько задач (например, «Аутентификация»). `TASK` — исполнимая единица работы, ровно один PR. Задача может существовать и вне эпика.
- **Файл на задачу.** Каждая — отдельный `NNNN-<TYPE>-<slug>.md` в этой папке. `NNNN` — сквозной номер по всем типам, начинается с `0001`, лидирующие нули для сортировки. `TYPE` — `EPIC` или `TASK`.
- **Индекс — эта страница.** Таблица ниже — единственный источник правды по статусам. При смене статуса обновляется и файл задачи, и строка в таблице.
- **1 PR = 1 задача (TASK).** Одна задача может затрагивать одновременно и бэк, и фронт — это норма. У EPIC своего PR нет: PR-ы висят на его подзадачах.
- **Порядок работы.** Задачи берутся по номерам с учётом графы «Зависит от». Приоритет разделов v0: инфраструктура → аутентификация → каркас редактора → каталог → фичи редактора → лендинг → SEO-обвязка.
- **Смена статуса.** `[ ]` todo → `[~]` in progress (в момент начала работы) → `[x]` done. Для TASK — done после мерджа PR и прохождения приёмки. Для EPIC — done, когда все его подзадачи `[x]`. При блокере — `[!]` + причина в разделе «Заметки» файла задачи, берём следующую по очереди; если следующей нет — останавливаемся и спрашиваем.
- **Приёмка UI-задач.** Любая задача, которая меняет UI (вёрстка, компонент, страница, стили), не сдаётся без визуальной проверки в браузере. Проверка выполняется через Playwright MCP: поднять dev-сервер, открыть страницу (`browser_navigate`), пройти golden path и ключевые состояния на десктопе/планшете/мобилке (`browser_resize` 1440 / 768 / 390), при необходимости — снять скриншот. TypeScript и SSR-HTML не заменяют этой проверки. Перекладывать визуальную проверку на автора задачи нельзя; если MCP-инструмент недоступен — сначала попытаться починить (установить браузер, поправить конфиг), и только при объективной невозможности — попросить проверить вручную.
- **Декомпозиция.** Задачи заводятся совместно перед началом каждого раздела/эпика, а не весь v0 сразу.

## Легенда статусов

| Символ | Значение    |
| ------ | ----------- |
| `[ ]`  | todo        |
| `[~]`  | in progress |
| `[x]`  | done        |
| `[!]`  | blocked     |

## Формат файла задачи

### TASK

```markdown
# 0002 · TASK · Миграция users + sessions

- Статус: [ ]
- Эпик: 0001
- Зависит от: —
- Спека: docs/product/features/auth.md#схема
- PR: —

## Описание

Что и зачем делаем. Развёрнуто, с контекстом — чтобы к задаче можно было приступить через месяц без восстановления по памяти.

## Приёмка

- [ ] критерий 1
- [ ] критерий 2

## Заметки

—
```

### EPIC

```markdown
# 0001 · EPIC · Аутентификация

- Статус: [ ]
- Зависит от: —
- Спека: docs/product/features/auth.md

## Описание

Высокоуровневое описание фичи: что в неё входит, какие пользовательские сценарии закрывает, границы скоупа.

## Приёмка

- [ ] критерий уровня фичи 1
- [ ] критерий уровня фичи 2

## Заметки

—
```
