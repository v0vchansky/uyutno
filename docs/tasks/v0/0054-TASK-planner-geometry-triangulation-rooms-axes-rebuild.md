## Описание

Вторая половина геометрического ядра по принятому ADR C и первое наполнение `rebuild` шага 1: из замороженного `FloorLayout` выводятся стены-тела, комнаты и оси, а `normalize` дописывает в хранимое то, что решил ADR C (как минимум `anchor` комнат; авто-полы/зоны — по решению автора о размещении, см. эпик 0050). После задачи `manager.document.getDerived()` отдаёт настоящий `DerivedState`, а `document:changed` после любой команды планировки несёт пересобранный документ.

Скоуп (границы уточняются по ADR C, см. «Заметки»):

1. **Библиотеки**: `cdt2d` + `clean-pslg` в deps пакета с зафиксированными версиями, свой `.d.ts` (`packages/planner/src/document/geometry/types/` или рядом), проверка импорта CJS в `type: module` под webpack (клиент + SSR-бандл) и Jest/SWC — записать в «Заметках», что потребовалось (по образцу 0047).
2. **Обвязка триангуляции** (dd01 с вердиктами аудита): `triangulateContours(outer, inner, bound, subtract, cutPairs)` — дедуп точек/рёбер hash-map по квантованной координате, `resplitSegments` (коллинеарные осевые T-стыки), `clean-pslg` в чистой обёртке (копии массивов), `cdt2d({ exterior: true })`, half-edge-lite структура (рёбра по отсортированной паре, `fixed`-флаг), центроид-классификация fill/hole/empty против четырёх наборов с sliver-safe выбором репрезентативного треугольника, `groupTriangles` flood-fill **с явным стеком**; плоские массивы на выходе, без глобального пула.
3. **Детекция комнат** (dd03): `rebuildContours` — boundary walk (старт min-X, виртуальная prev, экстремальный угол), `clearDict` (dead-end вершины), повторные обходы для дырок, нормализация ориентации по знаку площади, `clearContour` (слияние ближе 5 см, коллинеарные), `contourValid`; дырка → комната по членству в группе; guard runaway walk — soft-fail + `logger`? (чистая функция логгера не имеет — вернуть признак, логирует движок). Публичный контракт `rebuildContours` пригоден шагу 6 (Q2).
4. **Оси стен** (dd07): `findAxes` по парам граней (`parallelLines(0.05)` → `rightOriented` → `parallelBox` → `boxCenterSeg` с 80/15), детерминированное направление оси по ADR C, ось на каждую пару по участку перекрытия (Q19); индекс проём→ось — форма без потребителя (шаг 6). Если ADR C отложил оси — только тип в `DerivedFloor`.
5. **Пайплайн `normalize`/`rebuild`** в `engine/rebuild.ts` по порядку стадий ADR C (аналог `rebuildWallsAndCovers` без `roundAllPoints`/`connectAllPoints`): построение стен-тел для 2D-отрисовки (что это геометрически — по ADR C, см. 0051 п.1), комнат (полигоны с дырками + треугольники + площадь), осей; `normalize` — пере-привязка `rooms[]` по перекрытию площади (`compareContoursByArea`, первый донор того же outer/hole), запись `anchor`, высота проекта для комнаты без донора (Q20), удаление записей без комнаты (по ADR C); стадии полов/зон/cuts — по решению автора (форма стадий заложена, реализация — здесь или отдельной задачей). `DerivedState` заморожен, только plain-значения (0048).
6. **Golden-фикстуры планов** (testing-strategy, build-order «для шага 2 сразу golden-фикстуры»): вход — `PlannerDocument`/`FloorLayout` JSON, эталон — сериализованный `DerivedFloor` или его стата (по ADR C); стартовый набор spec-derived кейсов: 4 стены → 1 комната; самопересечение → нет комнаты; внутренняя стенка делит надвое; удалил стену — слились; комната в комнате → дырка + вложенная; висячая стена → нет ложных контуров; T-стык; вырожденная щель отбрасывается (`contourValid`); две коллинеарные короткие грани против длинной → две оси; сдвиг стены сохраняет запись комнаты (anchor переписан). **Property-тесты** `fast-check`: нет NaN, комнаты — валидные полигоны, `rebuild(rebuild(x)) == rebuild(x)`, инвариантность к порядку контуров.
7. **Слой 2**: транзакция `setSettings`/`load` с непустым `layout` → `document:changed` несёт пересобранный документ; `getDerived()` меняется только при изменении содержимого; ссылки неизменённых поддеревьев сохраняются.

Не в задаче: команды планировки и история (0055), снап (0057), отрисовка (0056), 3D-меши (шаг 4).
