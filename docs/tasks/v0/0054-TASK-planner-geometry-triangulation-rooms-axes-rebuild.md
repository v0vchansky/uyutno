## Описание

Вторая половина геометрического ядра по принятому ADR C и первое наполнение `rebuild` шага 1: из замороженного `FloorLayout` выводятся стены-тела, комнаты и оси, а `normalize` дописывает в хранимое то, что решил ADR C (как минимум `anchor` комнат; авто-полы/зоны — по решению автора о размещении, см. эпик 0050). После задачи `manager.document.getDerived()` отдаёт настоящий `DerivedState`, а `document:changed` после любой команды планировки несёт пересобранный документ.

Скоуп (границы уточняются по ADR C, см. «Заметки»):

1. **Библиотеки** (ADR 0017 C2, спайк 0051): `cdt2d@1.0.0` и `clean-pslg@1.1.2` **точными версиями** в deps пакета; свои `.d.ts` (`declare module 'cdt2d'`/`'clean-pslg'`, `@types/*` не существуют); default-импорт CJS в ESM работает под Node/Jest(@swc/jest)/webpack SSR без правок; **клиентский webpack**: `clean-pslg` тянет `buffer` (bn.js/typedarray-pool) → alias `buffer$` на стаб `{ Buffer: { isBuffer: () => false } }` в `webpack.client.js` (запасной вариант — полифилл `buffer`, +26 KiB); что реально потребовалось — в «Заметках» (по образцу 0047).
2. **Обвязка триангуляции** (ADR 0017 C6): `triangulateContours({ outer, inner, bound, subtract, cutPairs })` — дедуп точек/рёбер hash-map по квантованному ключу, `resplitSegments` (коллинеарные осевые перекрытия/T-стыки), `clean-pslg` в чистой обёртке (копии массивов, фильтр вырожденных рёбер `[i,i]`, маппинг индексов, координаты выхода квантуются до 0.001), `cdt2d({ exterior: true })`, half-edge-lite (рёбра по отсортированной паре, `fixed`-флаг), flood-fill групп по не-fixed рёбрам **явным стеком**, sliver-safe репрезентативный треугольник (all-sliver группы отбрасываются), центроид-классификация `fill = inside(outer) > inside(inner)` с bound∩/subtract-семантикой; плоские массивы на выходе, без глобального пула.
3. **Детекция комнат** (ADR 0017 C6): `rebuildContours` — публичная чистая функция: `filterContours` → триангуляция → boundary walk каждой группы (старт min-X, виртуальная prev `[x − 10, y]`, экстремальный угол; guard `res.length > n` — признак soft-fail в результате, логирует движок), `clearDict` (dead-end вершины), повторные обходы той же группы = дырки, **нормализация ориентации** (наш `contourArea`: `outer` и обводы комнат > 0, дырки < 0), `clearContour` (5 см, коллинеарные), `contourValid`. **Классы групп:** fill — тело стены; **комната** — не-fill группа без ребра на выпуклой оболочке (ребро с одним инцидентным треугольником); остальное — exterior; дырки комнаты — по членству в группе. Контракт пригоден шагу 6 (юнион луток + число внешних контуров, Q2) и полам (bound/subtract, `separateContacting`).
4. **Оси стен** (ADR 0017 C8, оси нужны в шаге 2): `findAxes` по парам граней всех контуров (`parallelLines(PARALLEL_EPS)` → `rightOriented` → `parallelBox` 4-case, `manhDist(E, F) < L_EPS` — отказ → `boxCenterSeg` с `MAX_WALL_WIDTH = 80`/`MIN_WALL_LENGTH = 15`), ось на каждую пару по участку перекрытия, слияния нет (Q19); **направление детерминировано**: `a` = конец с меньшим `x` (при равенстве — меньшим `y`), `faces[0]` — грань слева от `a→b` (y вверх), угол — `atan2(b − a)`; выход `{ a, b, depth, faces: [{ contourId, a, b }, …] }`; индекс проём→ось — шаг 6; коннекторы — шаг 4.
5. **Пайплайн `normalize`/`rebuild`** в `engine/rebuild.ts` по ADR 0017 C1/C6/C7 (скоуп шага 2 — фазы (1)–(2) normalize и `walls/rooms/axes` rebuild; полы/зоны/cuts — 2b, коннекторы — шаг 4, проёмы — шаг 6):
   - `normalize(draft, { createId })`: (1) `rebuildContours(outer, inner, cutPairs)` → **переписать `layout.contours`/`layout.points`** результатом слияния (`outer` = обводы fill-групп, `inner` = комнаты) с дисциплиной id: вершина → id существующей точки по тождеству квантованной координаты, иначе новый id из инжектированного генератора; контур сохраняет id при той же последовательности id точек с точностью до циклического сдвига; точки без владельцев удаляются; порядок — `sortByArea`; писать в draft только при фактическом изменении; (2) пере-привязка `rooms[]` (`compareContoursByArea`, старый контур = `anchor` по координатам черновика после мутации; первый донор в порядке `rooms[]`, донор не расходуется; без донора — новая запись `{ id, anchor, name: '', ceilingHeight: settings.wallHeight }`; **записи без комнаты остаются сиротами бессрочно** — спека 02, решение автора 2026-08-19), переписать `anchor`.
   - `rebuild(snapshot)`: триангуляция нормализованного `layout` → `DerivedFloor { id, walls: { contourId, triangles: [Id, Id, Id][] }[], rooms: { contourId, roomId, outline: Id[], holes: Id[][], triangles, area }[], axes }` (треугольники — по id точек layout: Steiner-точек нет; появление вершины без id — нарушение идемпотентности normalize, ловится property-тестом); `DerivedState` заморожен, только plain-значения (0048).
   - Добавить `Contour.kind: 'outer' | 'inner'` в `PlannerDocument.ts` (ADR 0016 B3, уточнено 2026-08-19) — здесь же; `createEmptyFloor`/тесты документа обновить.
6. **Golden-фикстуры планов** (ADR 0017 C10): `packages/planner/src/document/geometry/fixtures/<case>.json` формата `{ name, input: PlannerDocument (format/version), expected: { layout: нормализованный FloorLayout, derived: DerivedFloor } }`; id детерминированные (`p1`, `c1`… — генератор инжектирован), числа с округлением до 1e-6; обновление эталона — `UPDATE_GOLDEN=1 pnpm test` с ревью диффа; стартовый набор spec-derived кейсов: 4 стены → 1 комната; самопересечение → нет комнаты; внутренняя стенка делит надвое; удалил стену — слились; комната в комнате → дырка + вложенная; висячая стена → нет ложных контуров; T-стык; вырожденная щель отбрасывается (`contourValid`); две коллинеарные короткие грани против длинной → две оси; сдвиг стены сохраняет запись комнаты (anchor переписан). **Property-тесты** `fast-check` (фиксированный seed): нет NaN/Infinity, комнаты — валидные полигоны без самопересечений и `contourValid`, ориентация выхода по контракту, `normalize(normalize(x)) == normalize(x)`, `rebuild` детерминирован, инвариантность к порядку входных контуров с точностью до перестановки комнат (донор атрибутов при перестановке может смениться — фиксируется явно).
7. **Слой 2**: транзакция `setSettings`/`load` с непустым `layout` → `document:changed` несёт пересобранный документ; `getDerived()` меняется только при изменении содержимого; ссылки неизменённых поддеревьев сохраняются.

Не в задаче: команды планировки и история (0055), снап (0057), отрисовка (0056), 3D-меши (шаг 4).

**Решения по месту (в рамках ADR 0017; развилки для автора помечены ⚠):**

- ⚠ **Классификация центроида — счётчик референса `inside(outer) > inside(inner)` ИЛИ «ближайший объемлющий контур — `outer`»** (C6). Ближайший = наименьший по площади из строго содержащих центроид; при равной площади — `inner` (полость поверх сплошного тела вырезает его, как у референса). Почему одного счётчика мало при нашем «Комната по точкам = `inner`» (ADR 0019): (а) стены, нарисованные внутри нарисованной комнаты, он вырезает (1 outer против 1 inner → не fill) — квады превращались бы в «комнаты»; (б) счётчик теряет кратность после слияния — property-тест нашёл контрпример (два перекрывающихся квада внутри `inner`: 2 > 1 на сыром входе, 1 > 1 после нормализации → стены «проваливаются» на втором прогоне, идемпотентность нарушена). Почему одного «ближайшего контура» мало (нашёл критик): комната, нарисованная поперёк стены (`outer` + `inner` прямоугольника поверх кольца), вырезала бы кусок стены (наименьший содержащий — её `inner`) и давала 3 комнаты; счётчик (2 outer > 1 inner) стену сохраняет и режет комнату надвое — фикстура `plan-rect-room-over-wall`. Дизъюнкция даёт правильный ответ во всех разобранных случаях (кольца квадов, полилиние-комната со стенами внутри, комната в комнате, комната поперёк стены, перекрывающиеся квады); на вложенном (непересекающемся) наборе — а хранимые контуры после `normalize` всегда такие — все три правила совпадают. Референс с `inner` без слэба не сталкивается: его `StateMakingRoom` по умолчанию коммитит **outer**. Property-тесты (идемпотентность, детерминизм, инвариантность к порядку) зелёные на 800 прогонах. **Требует правки текста ADR 0017 C6.**
- ⚠ **Критерий комнаты** = не-fill группа **и** (нет ребра на выпуклой оболочке **или** ближайший объемлющий контур — `inner`). Второе условие — «объявленная полость»: без него одиночная «Комната по точкам» (все рёбра на оболочке) комнатой бы не стала, и `addContours(inner)` из ADR 0019 было бы пустым действием.
- ⚠ **Не-fill группы не сливаются через fixed-рёбра** (референс: `groupTriangles(holeTrs, false)`); группы разделены fixed-рёбрами (ADR C6 «flood-fill по не-fixed рёбрам»). Следствие: две «Комнаты по точкам» с общим ребром — две комнаты (иначе смежные полилиние-комнаты сливались бы в одну), **но** две полости, чьи грани стянуты драгом в нулевую толщину, тоже остаются двумя комнатами (у референса — сливаются: это его единственный способ «стереть стену»). В шаге 2 иного способа слить комнаты нет (удаления стены целиком нет; каскад `deletePoint` делает полость меньше, а не убирает перегородку). **Вопрос автору:** нужно ли «стереть перегородку → комнаты сливаются» в шаге 2 и как: слияние комнат через ребро нулевой толщины (потребует различать нарисованные `inner` от выведенных) либо отдельная команда позже. Совмещение с cut-парами зон — 2b (как в ADR).
- **`clearContour` не удаляет коллинеарные вершины вообще** — только схлопывает цепочки вершин ближе 5 см (коллинеарность решает, какой конец цепочки выживает) и удаляет «иглы» (соседи ближе 5 см); проходы до неподвижной точки (референс делал один проход и сравнивал индексы исходного массива с изменённым — исправлено). Так у референса и в реальности (`clearContour` там только на входе, коллинеарность вне цепочек не трогается — dd03 это переформулировал шире); общее удаление коллинеарных стирало бы точку пользователя между двумя прямыми стенами (три клика по прямой в «Стенах») и T-стыки — спека 01: стены сливаются только явным удалением точки. Это и есть «правило владельцев» из ADR «Что важно знать»: коллинеарная вершина сохраняется всегда. Цена: обвод после слияния перекрывающихся коллинеарных квадов держит вершины-концы перекрытия (как у референса).
- Обводы после boundary walk чистятся `clearContour` (по ADR; референс — только `contourValid`) и приводятся к канону: против часовой (обводы) / по часовой (дырки), старт с вершины min-X (при равенстве min-Y) — иначе `normalize∘normalize` менял бы порядок точек.
- **Идентичность контура — циклический сдвиг и обратный обход** (ADR: сдвиг): нормализация ориентации не должна менять id контура, нарисованного по часовой; ключ включает `kind`.
- **`matchRoomRecords`: сначала точное совпадение якоря по циклу id, потом `compareContoursByArea`** — сетка 10×10 промахивается на тонких/диагональных комнатах (узлы могут не попасть строго внутрь), и без точного матча запись комнаты на втором прогоне становилась бы сиротой — идемпотентность. Якорь < 3 живых точек — не донор по площади (ADR).
- Две точки в одной квантованной координате → выживает меньший по строковому сравнению id (для uuidv7 — старшая точка); остальные удаляются как безхозные. Совладение с полами/зонами (B4) при коллизии — 2b.
- `rooms[]` = записи новых комнат в порядке `inner`-контуров (sortByArea) + сироты в прежнем порядке; неизменённая запись сохраняет ссылку; вторая половинка разделённой комнаты — клон `{ name, ceilingHeight }` с новым id.
- `normalize` пишет в черновик только при фактическом изменении: `layout.contours`/`rooms` заменяются массивами с переиспользованием драфт-объектов неизменённых контуров/записей, `points` мутируется поимённо (добавить/удалить) — ссылки нетронутых узлов и `layout` при no-op сохраняются (тест PlannerStore: транзакция `settings` не трогает `layout`).
- Точки пересечений от `clean-pslg` квантуются **до** `cdt2d` (с повторным дедупом): normalize и rebuild триангулируют одну и ту же геометрию; иначе `rebuild` мог бы получить вершину без id.
- Soft-fail обхода в `normalize` — хранимое **не переписывается** (иначе оборвавшаяся группа исчезла бы из документа без следа, а снимок undo берётся после normalize), только `warn`; в `rebuild` soft-fail и нарушенные инварианты (вершина без id, контур без группы, комната без записи) — `warn(message)` в DI-логгер через `PlannerStore` (`@uyutno/planner: …`, тест с подменой `rebuild`), элемент пропускается, исключений нет; `rebuild` на ненормализованном снимке предупреждает, но не бросает.
- Оси: `faceRight` граней хранимых контуров = `(kind === 'inner') === (area > 0)` (тело справа от `a→b`, конвенция `rightOriented`; JSDoc `OrientedFace` из 0053 говорил «комната справа» — исправлен); **пары совпадающих граней (толщина < `L_EPS`, общее ребро двух комнат по точкам) осей не дают** — стены между ними нет, `depth = 0` для `setWallWidth` бессмыслен (замечание критика); угла в `WallAxis` нет (один источник — `atan2(b − a)`, считает потребитель).
- Формат golden: `expected` дополнен `warnings: string[]` (пусто во всех кейсах). Кейсы (14): 4 стены → комната; самопересекающийся outer (площадь ~0 → отбрасывается на входе; несимметричная «бабочка» — две fill-доли, комнаты нет); комната поперёк стены (стена цела, комната разрезана); перегородка делит (T-стыки); стена убрана → слились (r1 донор, r2 сирота с «пропавшими» id); комната в комнате; висячая стена + отдельный квад; T-стык снаружи; вырожденная щель; две оси против длинной грани; сдвиг стены сохраняет запись (якорь с пропавшим id); одиночная комната по точкам; прямоугольник одним outer. «Плоский торец ≥ 135°» / «короткий последний сегмент» — фикстуры ленты (0053, `band-*`), не пайплайна документа.

**Критики (два субагента: соответствие ADR/конвенциям и ревью тестов).** Blocker критика — классификация «ближайший контур» ломала «комнату поперёк стены» → правило заменено на дизъюнкцию со счётчиком (выше), добавлена фикстура. Should: нулевая толщина не сливает комнаты (оставлено, ⚠ выше); оси нулевой толщины — убраны; soft-fail стирал контуры — теперь хранимое не трогается; «удаление коллинеарных» — ADR неточен, референс тоже не удаляет (оставлено, ⚠ выше); `Contour.kind`/`rightOriented` JSDoc — поправлены. Nit: `matchRoomRecords` не принимает якорь < 3 точек и при точном совпадении id; новые точки без владельца не пишутся; `isDraft`-гард в `normalize`; недостижимая ветка `kind` убрана. Из ревью тестов добавлено: property — дырки по часовой и валидны, оси конечны, id контуров уникальны, все точки с владельцами, каждая комната с записью, число записей/производных при перестановке; `rebuild` «inner без группы»; тест DI-логгера с подменой `rebuild`. Не сделано (осознанно): тесты runaway-guard `contoursFromGroup` руками (обе ветки дают `null`), NaN на входе триангуляции (вход валидируют команды, ADR 0016 B5), property для `axes/`.

**Для правки ADR 0017 (по итогам, автору):** C6 — правило классификации (дизъюнкция) и критерий комнаты («или ближайший объемлющий — inner»); C6 «удаление коллинеарных» → «слияние цепочек < 5 см и игл, коллинеарные вершины сохраняются» (референс тоже); C1 — тождество контура «сдвиг и обратный обход»; C7 — точное совпадение якоря перед площадью; C8 — оси нулевой толщины не строятся; C10 — `expected.warnings`.
