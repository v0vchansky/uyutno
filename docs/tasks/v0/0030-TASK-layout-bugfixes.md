## Описание

По ходу использования обновлённого `PublicLayout` (задача 0026) вылезли три поведенческих бага. Все три — про то, как ведут себя меню и якорные ссылки, а не про статичную вёрстку.

**Баг 1. Нет плавного скролла к секциям лендинга.** В шапке и подвале лендинга нав-пункты — `<a href="#features">`, `<a href="#how">`, `<a href="#faq">`. Сейчас клик мгновенно «прыгает» к секции, без анимации. Хочется плавную прокрутку, как это принято на лендингах.

**Баг 2. `MobileMenu` продолжает блокировать скролл body на десктопе.** Кнопка-триггер и панель бургера скрыты через `lg:hidden` (`apps/platform/src/client/common/components/PublicLayout/MobileMenu.tsx:99` и `MobileMenu.tsx:105`), но `useEffect`, который ставит `document.body.style.overflow = 'hidden'`, срабатывает при любом `isMounted` — независимо от вьюпорта (`MobileMenu.tsx:53–60`). Если пользователь открыл меню на мобилке и растянул окно до десктопа — состояние `isMounted` остаётся `true`, панель невидима, а скролл body заблокирован. Так быть не должно. Скролл блокируется только в мобильном варианте.

**Баг 3. У пунктов меню профиля нет `cursor: pointer` при ховере.** Речь про меню профиля на десктопе (`ProfileMenu.tsx` — HeroUI Popover, «Настройки» и «Выйти») и про пункты в мобильном бургере (`MobileMenu.tsx` — «Настройки», «Выйти», а также нав-ссылки лендинга и «Войти» внутри бургера). Это `<button>` и `<a>`-элементы без явного `cursor-pointer` — Tailwind preflight не выставляет курсор на `<button>`, поэтому при ховере остаётся дефолтный. Добавляем `cursor-pointer` всем интерактивным строкам обоих меню.

## Скоуп

**Клиент (`apps/platform/src/client/`):**

1. **Smooth scroll (баг 1).** В `global.css` добавить:

   ```css
   @media (prefers-reduced-motion: no-preference) {
     html {
       scroll-behavior: smooth;
     }
   }
   ```

   Живёт под общим правилом `:root` в `global.css`. Уважаем `prefers-reduced-motion` — пользователям с включённой опцией «уменьшить движение» плавный скролл не навязываем.

2. **Скролл-лок только на мобилке (баг 2).** В `PublicLayout/MobileMenu.tsx`:

   - Завести `MOBILE_MEDIA_QUERY = '(max-width: 1023.98px)'` (константа рядом с `CLOSE_MS`).
   - Через `matchMedia` + `addEventListener('change', ...)` в отдельном `useEffect` закрывать меню, когда вьюпорт переходит в `min-width: 1024px` (т.е. `matches` становится `false`). Так `isMounted` уходит в `false`, и сработает cleanup существующего scroll-lock useEffect — тот сам вернёт исходный `overflow`. Не переусложнять: не нужно параллельно проверять вьюпорт внутри lock-эффекта, если меню на десктопе гарантированно закрывается.
   - Первичный SSR — на сервере `matchMedia` нет, поэтому обращаемся к нему только внутри useEffect (в браузере).

3. **`cursor-pointer` на пунктах меню (баг 3).**
   - `ProfileMenu.tsx`: добавить `cursor-pointer` к классам двух `<button>` («Настройки», «Выйти») внутри `Popover.Dialog`.
   - `MobileMenu.tsx`: добавить `cursor-pointer` к классам:
     - нав-ссылок лендинга (`<a>` внутри `.map` по `LANDING_NAV_ITEMS`),
     - ссылки «Войти» (`<Link to='/login'>`),
     - кнопки «Настройки» (`<button onClick={handleSettings}>`),
     - кнопки «Выйти» (`<button onClick={handleLogout}>`).
