## Описание

Снап как чистая математика, отдельно от автомата (0057) и от отрисовки (0056), чтобы влезть в один PR и покрыться слоем 1 целиком:

1. **`document/geometry/snap/`** — чистые функции над плоскими массивами кандидатов (без импорта `engine/`, ADR 0015 — слои), на предикатах 0053 (ADR 0017 C4: `manhDist`/`euclDist`, `pointOnSegment`, `projectPointOnLine`, `bisectorPoint`, `pointAtAngle`, `angleBetweenLines`, `lineIntersectLine`; предикат замыкания с `CLOSE_EPS` — тоже в ядре, снап только вызывает; выбор метрики — здесь/ADR E, не в ядре): `snapX`/`snapY` (по два кандидата на ось — полуплоскости, ключ по оси затем вдоль с `L_EPS`, отсечка `> snapDist`, взаимное отсечение в `B_EPS`, обе могут выжить), `snapPerpendicular` (представитель оси — ближний по манхэттену; координаты поосно; сырые пары для расширенных гайдов), `snapToNearest`/`findNearest` (манхэттен), `orthogonalSnap` (оси через предпоследнюю и первую точку контура, ≥ 2 точек), `bisectorSnap` (радиус ×10, соседи по кольцу, `bisectorPoint`, отказ по перпендикулярной дистанции), `findNearSegments`; лесенка `getSnapPoint` из 8 веток с приоритетом Y (спека 01 «Приоритет», README) и радиусом угла 2 см при `pointsSnap=off`; результат `{ snapped, alignerX, alignerY, bisAnchor, rawAlignersX, rawAlignersY }` + описание гайдов для отрисовки (правила подавления: совпадение с выравнивателем в `B_EPS`, точка на стене, угловой фильтр ≈ 135°, T-стык — только основной снап); квантование результата 0.001; **метрика** по спеке 01: манхэттен для приёма любого точечного снапа (угол, биссектриса), евклид — радиус поиска угла ×10; пороги — параметры функции в единицах плана (px → план делает вызывающий), `exceptPoints`, `viewport` — обязательный параметр (куллинг всегда on, спека 01).
2. **Индекс кандидатов в `engine/`** — производный от документа/`DerivedState`: пул = вершины комнат + точки рисуемого контура + вершины полов (аудит dd09 keep); пересборка по `document:changed`; глобалов/синглтонов нет; grid-снапа нет (Q18).
3. **Тесты слоя 1** («вся математика и все ветки»): каждая ветка лесенки, обе стороны каждого порога (`SNAP_DIST`, 2 см, ×10, `B_EPS`, `L_EPS`), приоритет Y при одновременных X/Y, куллинг (кандидат за вьюпортом не снапит), `exceptPoints`, все четыре флага on/off, вырожденные входы (пустой пул, совпадающие точки, `NaN`), tie-breaking `snapX/snapY` (оба выживают); property-тест: результат всегда квантован и внутри радиуса либо равен сырому курсору.

Не в задаче: автомат и коммиты (0057), отрисовка гайдов (0056), хит-тест правки (0059 — но `findNearest`/пороги переиспользуются).

**Решения по месту (в рамках ADR 0019 E2 / 0020 P4):**

- `SnapCandidate = { id, x, y, prev?, next? }` — соседи как координаты, не id (биссектрисе нужны только позиции); индекс даёт соседей из **первого** кольца, содержащего точку (`contours` → `covers` → `areas`), кольцо короче 3 вершин соседей не даёт; `segments` индекса — только рёбра `contours` (спека 01 «на существующей стене»); один кандидат на точку без дублей по кольцам.
- Draft-кандидаты (`draftCandidates`) — концы открытой полилинии без соседей (референс замыкал кольцо через живой курсор — «угол» с самим курсором); внутренние вершины — с соседями по полилинии.
- Орто-якоря — `contour` = зафиксированные точки **без** живого курсора: оси через последнюю и первую (референс — `points[len−2]` и `points[0]` при курсоре в контуре, эквивалентно); при одной точке — только она. В орто-ветках 5/7 `alignerX/alignerY` и сырые пары — якоря `ortho:*` (осей точек там заведомо нет), чтобы гайд вёл к точке контура (референс орто-гайдов не рисовал).
- Приоритет Y в ветке 5 — явный (`ortho.alignerY ?? ortho.alignerX`); тест с биссектрисой `y = x + 4`, где X- и Y-варианты равноудалены.
- Куллинг — по `viewportBounds` ко всему пулу до любой ветки, включая угол, биссектрису и орто-якоря; **белого списка `farNodes` нет** (спека 01: «никаких режимов, где куллинг выключается»). **Развилка автору:** референс не куллил точки собственного рисуемого контура (`farNodes = rawCont.points`), а строка аудита dd09 говорит «farNodes — явный белый список»; при зуме внутрь длинной стены осевое выравнивание к первой/предыдущей точке своего контура за кадром пропадёт. Если это нежелательно — добавить `SnapParams.keepIds` (не куллить draft-кандидатов) — изменение локальное, тесты куллинга дописать.
- Метрика радиуса поиска угла для биссектрисы — **манхэттен** (через `snapToNearest`, как референс 57525 и факты Q34); евклид — только перпендикуляр к биссектрисе. ADR 0019 E2 «Метрики» писал «евклид — радиус поиска угла» — уточнён по исходнику одной фразой (пометка «уточнено задачей 0062»); формулировка п.1 этого файла («евклид — радиус поиска угла ×10») тем самым тоже устарела — верна версия ADR.
- `getSnapPoint`: неконечный курсор → детерминированный промах (`hit: none`, `snapped` как есть); NaN-кандидаты отсекаются куллингом и гардами (`snapAxis` — гард по вторичной координате, у референса такой кандидат прошёл бы в сторону P). `snapped` — всегда новый объект, квантован; `hit` — discriminated union (`point {id}` — цель слияния/дропа для 0057/0059, `cross`, `bisector-axis {axis}`, `ortho-bisector {axis}`, `axis {axis}`, `ortho`, `bisector`, `none`).
- `guidesFor`: основные гайды к `alignerX/alignerY/bisAnchor` (нулевой длины не рисуются; **осевой гайд — только если снап-точка лежит на оси источника** — иначе победил угол, и наклонный пунктир референса подавлен); расширенные гайды к «проигравшим» из сырых пар и `face` (параллель второй грани `offsetSegment(snapped→источник, width, side)`) — только при `lastPoint` и не при совпадении с выравнивателем / точке на стене (T-стык, спека 01), угловой фильтр `GUIDE_TURN_LIMIT` = `RE_MITER_ANGLE` (0.75π), «lastPoint на одной оси с выравнивателем» — с допуском `B_EPS` (референс — точное `!=`); проигравший сравнивается с основным по `id`. Гайд для орто-якоря отличим только по префиксу id `ortho:` — если вьюверу понадобится явный `source`, добавить поле.
- `pixelsToPlan(viewport, px)` добавлен к тройке ADR 0020 (одна строка, чтобы 0057/0059 не дублировали `/scale`); `boundsContain` — включительно, как `pointInFrame` референса. Предусловие `scale > 0` — валидирует `tools.setViewport` (0057), чистые функции не проверяют.
- Индекс: `SnapCandidateIndex` — экземпляр на менеджер (создаёт `tools` в 0057), ленивый, WeakMap по ссылке `floor.layout` (смена `view`/`settings`/undo на прежний снимок — кеш-хит); битые id в кольцах молча пропускаются (инвариант `normalize`).

**Критик (соответствие ADR 0019 E2/0020, конвенции; refute-by-default) — blocker'ов нет; сделано:** сравнение проигравшего с основным по `id` вместо ссылки; ключ кеша индекса — `floor.layout` вместо `document` (+ убран вложенный `Map` по этажу); `NeighbourSegments` заменён на `StartNeighbourSegments` ленты (дубль типа); `NO_ALIGNERS`/`NO_PERPENDICULAR` заморожены, индекс — глубоко (`immer.freeze`); убран неиспользуемый параметр `closed` у `draftCandidates`; JSDoc про сырые пары в орто-ветках исправлен; JSDoc `ringSegments` про кольцо из 2 точек (у референса два встречных ребра); ADR 0019 E2 метрика поиска угла; развилка `farNodes` — выше. Ревью тестов (второй субагент писал тесты по JSDoc и три расхождения зафиксировал `it.failing`): NaN во вторичной координате в `snapAxis` — добавлен гард, тесты переведены в обычные `it`; JSDoc `bisectorSnap` уточнён («ближайший без соседей → null, следующий не ищется — как референс»). Не сделано (nit, осознанно): `boundsContain` не заменён на `pointInBounds(p, {min}, {max}, 0)` (читаемость); `SnapHit 'ortho'` без `axis`; `pickAligner` экспортирован (тестируется отдельно).

**Осталось на 0057/0059/0056/0061:** `tools` создаёт `SnapCandidateIndex`, на `pointerMove` зовёт `getSnapPoint(raw, [...index.candidates, ...draftCandidates(points)], { snapDist: pixelsToPlan(viewport, SNAP_DIST), viewport, flags, exceptIds, contour: points })` и `guidesFor(snap, { lastPoint, segments: index.segments, face: { width, side } })`; `findNearSegments(start, index.segments)` → `autoOffsetSide`/`blocksFromContour`; хит-тест — `document/geometry/hittest/` на `findNearest` и `pixelsToPlan(viewport, POINT_SIZE)`; экспорт типов `SnapFlags`/`SnapResult`/`Viewport` из `index.ts` — вместе с `ToolState`.
