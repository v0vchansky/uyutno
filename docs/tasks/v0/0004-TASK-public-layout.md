## Описание

Свёрстать переиспользуемый layout-компонент — обёртку с Header и Footer, которая принимает произвольный контент через `children`. Триггер — лендинг (0002), но layout будет использоваться на большинстве публичных страниц v0 (`/`, `/login`, `/register`, `/forgot-password`, `/reset-password`, `/projects` и т.п.), поэтому вынесен в отдельную задачу и живёт вне эпика лендинга.

**Адаптивная вёрстка обязательна.** Layout — фундамент всех публичных страниц v0, включая точку входа `/`, которая влияет на SEO-ранжирование и отказы (см. `docs/product/release-v0.md` «Технические ограничения»). Header и Footer в макете `Landing Simple.dc.html` отрисованы в **трёх размерах — десктоп, планшет, телефон** (см. `docs/ui/handoffs/auth/README.md` → таблица Files); все три реализуем по макету, а не изобретаем собственную адаптацию.

Скоуп задачи:

- компоненты Header и Footer по макету `docs/ui/handoffs/auth/Landing Simple.dc.html`;
- layout-обёртка, прокидывающая `children` между ними;
- реализация на HeroUI v3 и токенах `apps/platform/src/client/theme-uyutno.css`, без переноса инлайн-CSS из `.dc.html`;
- адаптивность desktop + mobile;
- никакой auth-логики в Header (кнопки/ссылки статичные из макета) — варианты «залогинен/не залогинен» появятся отдельно вместе с аутентификацией, здесь не предвосхищаем.

Вне скоупа: сама страница `/` (она в 0002), любые доменные состояния (пользователь, проекты, уведомления).

## Приёмка

- [ ] Есть переиспользуемый layout-компонент с Header и Footer; контент передаётся через `children`.
- [ ] Header и Footer визуально совпадают с макетом на desktop и mobile.
- [ ] Используются компоненты HeroUI v3 и переменные из `theme-uyutno.css`; инлайн-CSS из `.dc.html` не перенесён.
- [ ] Компонент лежит там, где его смогут импортировать все будущие публичные страницы (не внутри папки лендинга).

## Заметки

Сверх заявленного скоупа перестроили SSR-обвязку под нативный metadata hoisting React 19: ввели компонент `Document` (`src/client/application/components/Document/`), который рендерит `<html>/<body>` и «инфраструктурный» `<head>` (charset, viewport, theme-color, favicons, CSS, bundle) одним деревом; `page.ts` схлопнулся до одного `renderToString` вокруг `Document → StaticRouter → Application`. Благодаря этому любая страница может сама рендерить свои `<title>` и `<meta name="description">` прямо в JSX — React поднимает их в `<head>`. Правило «каждая страница обязана иметь свои `<title>` и `description`» зафиксировано в `apps/platform/src/client/CLAUDE.md`. Формально это шире layout-задачи, но без этого рефакторинга мета из 0002 работать бы не смогла.
