## Описание

Полный флоу восстановления пароля по email: страница запроса ссылки, отправка письма, страница установки нового пароля, обработка истёкшего/неизвестного токена. Оба экрана — по макету из [`docs/ui/handoffs/auth/Auth Screens.dc.html`](../../ui/handoffs/auth/Auth%20Screens.dc.html).

### Frontend

**`src/client/landing/pages/ForgotPasswordPage/`:**

- Форма с одним полем email + кнопка «Отправить ссылку».
- После успеха: форма остаётся, под кнопкой появляется плашка «Если такая почта у нас есть, письмо придёт в течение минуты. Ссылка действует час.» Формулировка нейтральная (не раскрывает, зарегистрирован ли email) — по спеке.
- Кнопка блокируется на 60 секунд с обратным отсчётом («Отправить ещё раз через 45 с»). Счётчик — клиентский `setInterval`, при перезагрузке страницы сбрасывается (это ок в v0).
- Ссылка «Вернуться ко входу» → `/login?from=…` (проброс `from`).
- Свои `<title>` и `<meta name="description">`.

**`src/client/landing/pages/ResetPasswordPage/`:**

- При SSR/при загрузке страницы делаем запрос `GET /api/v1/auth/password-reset/verify?token=…`:
  - 200 → показываем форму «Новый пароль» + «Повторите пароль» + подпись «Для аккаунта {email}» (email отдаётся эндпоинтом в теле).
  - 404/410 → вместо формы показываем сообщение «Ссылка недействительна» + кнопка «Запросить новую ссылку» → `/forgot-password`.
- Форма: правила пароля — как в 0013 (минимум 8, буквы + цифры), поле «Повторите пароль» с проверкой совпадения. Ошибка «Пароли не совпадают» — красная рамка на втором поле + подпись 12px `oklch(48% 0.16 27)` (по макету).
- После успеха: редирект на `/login?from=…` (`from` сохраняется на будущий логин).
- Ссылка «Вернуться ко входу» → `/login?from=…`.

### Backend (`src/server/auth/`)

**Схема `password_reset_tokens`** уже в 0007. Здесь — только сервис + контроллеры + email-шаблон.

- Сервис `PasswordResetService`:
  - `requestReset(email)`: нормализация email, `usersRepository.findByEmail`; если юзер найден — генерируем raw token (≥32 байта, hex/base64url), сохраняем `sha256(raw)` в `password_reset_tokens` с TTL 1 час, отправляем письмо со ссылкой `https://<домен>/reset-password?token=<raw>`. Если юзера нет — ничего не делаем (не раскрываем). Ответ 200 в обоих случаях.
  - `verifyToken(rawToken)`: ищет по `sha256(raw)`, проверяет `expires_at > now()`, `used_at IS NULL`. Возвращает `{ email }` или `NotFoundError`.
  - `confirmReset(rawToken, newPassword)`: та же проверка, хеширует новый пароль, `usersRepository.updatePasswordHash`, помечает токен `used_at = now()`, вызывает `sessionService.revokeAllForUser(userId)` (инвалидация всех сессий по ADR 0005), инвалидирует все остальные `password_reset_tokens` того же юзера.
- Контроллеры:
  - `POST /api/v1/auth/password-reset/request` — тело `{ email }`, всегда 200.
  - `GET /api/v1/auth/password-reset/verify?token=…` — 200 `{ email }` или 404.
  - `POST /api/v1/auth/password-reset/confirm` — тело `{ token, password }`, 200 при успехе, 404 при плохом токене, 400 при слабом пароле.
- Rate limit:
  - request: 3 запроса / час на email + 10 / час на IP;
  - confirm: 10 запросов / час на IP.

**Email-шаблон** (в `src/server/auth/mail/` или `src/server/mail/`):

- Простой текст + минимальный HTML: приветствие, ссылка «Установить новый пароль» (URL из `RESET_PASSWORD_URL` = `https://<домен>/reset-password?token=…`), фраза «Ссылка действует час», подпись. Никакой сложной вёрстки в v0.

### Приёмка UI (Playwright MCP)

- `/forgot-password`: ввести email, увидеть плашку успеха, кнопка disabled на 60с.
- `/reset-password?token=<valid>`: форма показывается, установка нового пароля → редирект на `/login`.
- `/reset-password?token=<expired>`: форма не показывается, сообщение «Ссылка недействительна» + кнопка «Запросить новую».
- Проверить полный флоу: request → письмо (в dev-транспорт из 0009) → извлечь URL → verify → confirm → login с новым паролем.
- Прогон на 1440 / 768 / 390.

## Приёмка

- [ ] `/forgot-password` рендерится по макету, плашка успеха и обратный отсчёт работают.
- [ ] `/reset-password` рендерится по макету, показывает форму при валидном токене и сообщение об ошибке — при истёкшем/неизвестном.
- [ ] `POST /password-reset/request` отправляет письмо (в dev — попадает в заглушку из 0009), возвращает 200 для существующих и несуществующих email.
- [ ] `GET /password-reset/verify` возвращает `{ email }` для валидного токена и 404 иначе.
- [ ] `POST /password-reset/confirm` меняет пароль, помечает токен использованным, инвалидирует **все** активные сессии этого юзера (проверить: сессия из другого браузера ломается).
- [ ] Rate limit: 4-й запрос на восстановление того же email в час → 429.
- [ ] Проброс `?from` работает на ссылках «Вернуться ко входу» и на редиректе после `confirm`.
- [ ] Обе страницы рендерят свои `<title>` и `<meta name="description">`.
