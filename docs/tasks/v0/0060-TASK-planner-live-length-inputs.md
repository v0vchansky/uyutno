## Описание

Активные подписи длин над рёбрами по спеке 01 «Ввод размеров с клавиатуры»:

- **При рисовании** («Стены», «Прямоугольник» — 0058): поверх каждого ребра — длина; если ребро на экране ≥ 45 px (полилиния) / ≥ 70 px (прямоугольник) — это инпут (26 px, повёрнут под углом ребра — спека 07); при > 2 точках — второй инпут для первой точки («отращивать контур с обратной стороны»), у прямоугольника — два инпута W/H (спека 07); появляются/исчезают по видимости (пересчёт при зуме/пане через `planToView` 0056), значение переживает скрытие; Tab — по кругу между видимыми инпутами; **Enter = постановка точки** тем же `commitPoint()`, что и клик, с тем же правилом замыкания (Q27); формат — только абсолютная длина; Esc в инпуте — отмена ввода (спека 07).
- **При правке** (выбрано ребро/стена из 0059): инпут длины ребра (`N`, `+N`, `−N`; оба конца симметрично ±дельта/2) и инпут ширины стены (оба конца перпендикулярно ±дельта); отказ при самопересечении или < 15 см, `0` — «слишком мало»; коммит через команды 0055 (одна запись истории на Enter/blur/Tab — coalescing по спеке 09).
- **Парсинг/ошибки**: пустое, отрицательное где нельзя, мусор, > 100 000 см — отклоняются с локализованным сообщением; `toFixed` без научной нотации; единицы документа (`settings.units`) — форматирование/парсинг по спеке 07 в объёме, нужном инпуту. **Единицы — только `см / м / мм`: имперская система из продукта убрана** (решение автора 2026-08-19, ADR 0016 «Что важно знать»), имперского парсера/форматтера и кодов ошибок `too-many-primes` / `bare-number` нет. **Разделитель**: на показ — запятая, на вводе принимаются и точка, и запятая (спека 07 «Единицы измерения»).
- **Фокус и клавиши**: пока фокус в инпуте — глобальные клавиши редактора (Esc/Ctrl+Z/стрелки) не перехватываются; **стрелки в инпуте — браузерные (курсор в тексте), переключение полей только Tab** (решение автора 2026-08-19, спека 07 приведена).
- **Две подписи и два инпута на сегмент** (решения автора 23/24, 2026-08-19): у сегмента показываются **две** длины, и каждая — ребро **своего кольца контура** (`outer` / `inner`), а не две грани одного ребра. Контракт `setEdgeLength` не меняется — обе правятся той же командой, каждая на своём контуре; добавляется реестр видимых инпутов по обоим кольцам, и Tab ходит по нему. **Оба поля редактируемые**, фокус в каждый момент один, **пассивное поле пересчитывается на лету** при вводе в активное. Тестовые фикстуры обязаны включать **полую комнату** — на одиночной линии без толщины пары полей не существует. Это снимает парковку build-order «Две длины у одного сегмента».
- **Ошибка ввода — поле плюс плашка** (решение 5): кольцо danger на самом инпуте и отдельная плашка с текстом рядом; **плашка не наследует поворот инпута**, всегда горизонтальна — иначе на вертикальной стене текст ошибки нечитаем. Тостов в редакторе нет.
- **Отдать состояние «фокус в поле длины» наружу** (решение 3): контекстная подсказка клавиш живёт в 0061 и слушает `tools:changed`, но `ToolState` про фокус в инпуте не знает — а это ровно тот случай, ради которого подсказку заводят («Tab — другое поле», «Enter — поставить точку»). Здесь нужно отдать этот факт наружу (второе событие шины или проп в оверлей — решается вместе с 0061); свою локальную плашку у поля не рисовать.

Скоуп: React-компонент оверлея в `ui/` (что из спеки 07 «Правка размера по клику»/«Автоматические размеры на стенах» входит сюда, а что — в шаг 8, решает ADR E; по умолчанию здесь — всё, что относится к рисованию/правке рёбер конструктора) (позиционирование по `planToView` + поворот к ребру, `z-index` над канвасами), состояние инпутов (`ToolState` или локально в `ui` — по ADR E), парсер/форматтер как чистые функции с тестами (обе стороны каждого порога 45/70 px, лимит 1 км, `+N/−N`, `0`, дробные, единицы), тесты слоя 2 на Enter = `commitPoint` с замыканием и на отказы, jsdom-тест компонента (показ/скрытие по порогу, Tab по кругу), визуальная приёмка через Playwright MCP.

Не в задаче: линейки (шаг 8); **сам контрол переключения единиц — в 0061** (решение автора 15: он живёт в группе контролов холста), здесь только чтение `settings.units` для форматирования и перерисовка инпутов при их смене; панель свойств.

## Заметки

- Скоуп заведён до принятия ADR E (0052); после принятия — сверить, где живёт состояние инпутов и как оверлей позиционируется, поправить файл.
- **`Нужен дизайн: да` без ссылки — в работу не берётся.** Инпут над ребром (шрифт, состояние ошибки, суффикс единиц, подсказка «Tab/Enter», стрелка направления) — новый компонент; спека даёт только пороги показа, высоту 26 px и поворот. Нужен макет/handoff или явное решение автора «по guidelines» (тогда переопределить строку с причиной).
- **Нужно от дизайна/автора (по итогам реализации 2026-08-20).** Ни одно из перечисленного не блокирует сдачу: остальное сделано, а здесь взяты рабочие значения, помеченные в коде комментариями.
  1. **Перпендикулярный отступ подписи от ребра.** Handoff говорит только «сдвинута перпендикулярно наружу», числа нет. Взято `LABEL_OFFSET = 16` px (половина высоты поля 26 плюс зазор, по шкале 4) — `document/geometry/measure/labelPlacement.ts`.
  2. **Сторона, куда уходит подпись у пары.** Правило выведено из сцены 13 прототипа, а не из текста: обе подписи сегмента уходят **от тела стены** (внешняя — наружу здания, внутренняя — внутрь комнаты). Если двигать обе «наружу своего кольца», при 100% зума они налезают друг на друга (стена 10 см = 10 px, поле 26 px). Просьба подтвердить.
  3. **Позиция и порог поля ширины стены.** Handoff их не задаёт. Сделано: середина оси, без офсета (ложится в тело стены, где подписей нет), порог показа — общий 30/45 px.
  4. **Тексты ошибок, которых нет в handoff'е:** `empty` → «Введите длину», `negative-not-allowed` → «Здесь только точная длина», `ambiguous-decimal` → «Оставьте один разделитель», `width-too-small` → «Стена тоньше 1 см», `rejected` → «Так изменить размер не получится». Три заданных текста взяты дословно. Отдельно: аудит handoff'а (пункт 9 «Что осталось») уже отметил, что «Стена короче 15 см» констатирует факт вместо того, чтобы сказать, что делать, — правка тоже за дизайном.
  5. **Подсказка-стрелка направления** (handoff «Поле ввода длины», спека 07) — **не сделана**: в поставке нет ни геометрии стрелки на повёрнутом поле, ни правил анимации. TODO в `ui/LengthInputs/LengthField.tsx`.
  6. **Правило коллизии подписей комнаты и сторон** (handoff «Подписи» → «Коллизия») — **не сделано**: требует измерения фактических текстовых боксов обеих подписей. Реализовано только «текст с запасом 30 px не влезает в сегмент — подпись гаснет», причём ширина текста **оценивается** по числу знаков (метрик шрифта в поставке нет). Побочный эффект оценки: у типичных подписей «текст + 30 px» больше порога инпута 45 px, поэтому состояние «ниже 45 px остаётся подпись» на практике почти недостижимо — подпись гаснет раньше. Нужно решение, что здесь верно.
  7. **Живой пересчёт пассивного поля пары на готовой комнате вырождается.** Решение 24 требует пересчёта на лету; он реально виден на паре прямоугольника (оба кольца выводятся из одного угла). У **готового** контура рёбра колец геометрически независимы: `setEdgeLength` двигает только точки своего контура (ADR 0018 D1), поэтому пассивное поле показывает своё значение и до Enter не меняется. Механизм пересчёта общий и работает; вопрос в том, ожидал ли автор решения 24 именно такого поведения.
  8. **`blur` не применяет там, где применение ставит точку.** Handoff говорит «Потеря фокуса применяет», но у поля текущего ребра и у полей прямоугольника применение = постановка точки/завершение прямоугольника, а `blur` случается на каждом клике по холсту. Поэтому им оставлен только Enter; поля правки готовой геометрии (`edge`, `wall-width`, «первое ребро») применяют по Enter/blur/Tab, как в спеке 09.
  9. **Порог 45 px применён и к правке готовой геометрии.** Спека 07/01 задают 45/70 px для рисования; для правки спека говорит «клик по подписи превращает её в поле» без своего порога. Взята формулировка эталона холста («поле ввода показывается на сегменте от ~45 px, ниже остаётся подпись»).
  10. **Тумблеры подписей** («Размеры», «Имя комнаты», «Площадь») хранятся в контексте скина `ui/PlannerOverlayContext.tsx`, а не в документе: полей под них в `DocumentSettings` нет, а спека 07 «Персистентность» обещает их сохранение. Нужен ADR/шаг, который заведёт хранение.
  11. **Центроид подписи комнаты** — площадной; у U/П-образной комнаты он попадает в вырез, и подпись сядет вне комнаты. Для v0 принято, запасной вариант — центр bbox — срабатывает только при вырожденной площади.
- **Найдено при прогоне e2e, чужая зона (0061).** `apps/platform/e2e/planner-constructor-canvas.spec.ts` (спека 0056) падал на шаге «увести курсор в пустоту»: рейл видов 60 px из 0061 лежит поверх холста, и точка `(40, 40)` холста теперь под кнопкой рейла — `pointermove` до канваса не доходит, hover остаётся прежним. Проверено `document.elementFromPoint`: там `<button>` внутри `div.w-[60px]`, а не канвас. Оверлей 0060 к этому отношения не имеет (его контейнер — `pointer-events: none`, статические подписи — тоже). Правится в 0061; на момент сдачи 0060 их спека уже поправлена.
- **Стык 0060/0061 закрыт (2026-08-20).** В `Canvas2dProjection` заведена безопасная область кадра: `setViewportInsets({left, right, top, bottom})` / `getViewportInsets()`, числа сообщает сам скин (`ui/ConstructorSkin`: рейл 60 + 12 + панель 224 + 12 = 308 слева, 12 + сводка 36 + 8 + контролы 36 = 92 снизу; на чужом виде — только рейл 60). `fitToContent()`, `resetCamera()` и шаг зума кнопками считают по видимой части, а не по всему кадру, — план больше не уезжает под панели. Пересчёт экран ↔ план не изменился (канвас по-прежнему полноразмерный), поэтому позиционирование оверлея 0060 через `planToView` осталось прежним. Оба e2e теперь берут свободную область у самого скина (`getViewportInsets`), а не кликают по угаданным координатам.
- **Уточнено по ADR 0020/0019/0018 (2026-08-19):** оверлей — компонент `ui/` пакета внутри контейнера `<Planner />` (не `children` платформы), позиционирование через чистый `planToView(viewport, p)` из `document/geometry/viewport.ts`, viewport — селектором `m => m.tools.get().viewport` (обновляется по `tools:changed` на каждый move/зум/пан), геометрия — `document.get()`/`getDerived()` (+ `pointOverrides` из `ToolState` при драге); сюда же — статические подписи длины всех сегментов и подписи комнат (спека 07/08 — DOM-оверлей), не только инпуты; Enter при рисовании → `tools.commitPoint(point)` (точку по длине/направлению считает оверлей чистой функцией, автомат ставит без снапа с общим правилом замыкания); при правке → `document.setEdgeLength(…, { anchor })` (выделена точка — вся Δ на другой конец) / `setWallWidth(…, faces)`; одна запись истории на Enter/blur/Tab — коалесинг делает команда. Второй инпут «отращивать контур с первой точки» (спека 07) — парковка build-order, решить здесь при реализации.
