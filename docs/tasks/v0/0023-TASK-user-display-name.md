## Описание

Заводим у пользователя обязательное имя (`display_name`) — просим его при регистрации email/паролем и вытаскиваем из OAuth-профиля. Понадобится в UI (шапка, будущий профиль, авторская подпись под планировками).

**Одна колонка `users.display_name`** — короткое имя для отображения. Не ФИО, не логин. Nullable — потому что старые пользователи заведены без него (см. миграцию-бэкфилл ниже) и потому что не каждый OAuth-провайдер обязан вернуть имя. В UI при `NULL` показываем часть email до `@` (defensive-фолбэк, чтобы шапка не сломалась).

### Backend

- Миграция `dbmate` — добавить `display_name text` в `users`.
- **Backfill для существующих строк**: `UPDATE users SET display_name = 'Владимир' WHERE display_name IS NULL;` в теле up-миграции. Существующих пользователей в БД сейчас двое (сид из `docs/testing.md` и локальный аккаунт @v0vchansky) — оба «Владимир», можно жёстко.
- Обновить `UserRow` в `usersRepository` (`displayName: string | null`).
- `usersRepository.create` — принимает `displayName: string | null` (для password-flow — обязательное строковое значение; для OAuth — nullable).
- Zod-схема `RegisterRequest` в `src/shared/auth/` — добавить `displayName: z.string().trim().min(1).max(64)`. Обязательное.
- Контроллер `POST /api/v1/auth/register` — принимает `displayName`, прокидывает в `usersRepository.create`.
- Type `OAuthProfile` → добавить `displayName: string | null`.
- `YandexProvider.fetchProfile` — читать `display_name`, fallback `first_name`, fallback `login`; результат `trim()`, при пустой строке — `null`. Тесты на все три ветки.
- `OAuthManager.signInOrRegister` — при создании нового юзера через OAuth пробрасывать `profile.displayName` в `usersRepository.create`. Тест обновить.

## Заметки

- Обновление имени из провайдера при **повторном** входе OAuth — сознательно вне скоупа (изменение имени должно быть явным действием пользователя, не сайд-эффектом входа).
- Редактирование имени в UI (страница профиля / модалка) — отдельная задача, появится когда будет профиль.
- «Полное» меню пользователя в шапке (аватар, дропдаун с выходом) — отдельно, здесь только текстовая метка.
