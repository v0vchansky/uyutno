## Описание

Внешняя работа — зарегистрировать приложение на стороне VK ID, получить `client_id` и `client_secret`, настроить redirect URI. Без этих кредов задача 0022 (OAuth-flow VK ID) заблокирована.

Аналог 0010 (Yandex), но для VK. Разнесены в отдельные задачи, чтобы Yandex-часть можно было раскатить, не дожидаясь регистрации VK-приложения.

Скоуп:

- Зарегистрировать приложение в кабинете VK, указать redirect URI `https://<домен>/auth/callback/vk` (и локальный `http://localhost:<port>/auth/callback/vk` для dev), выбрать scopes для получения email и `provider_user_id`, сохранить креды.
- Секреты в `process.env`: `VK_OAUTH_CLIENT_ID`, `VK_OAUTH_CLIENT_SECRET`. Дев-значения — из тестового приложения на localhost (если VK такое позволяет) или пустые с фича-флагом «VK OAuth в dev выключен».
- Актуальные URL-эндпоинтов VK (authorize / token / userinfo), scope-строки и особенности (например, у VK email возвращается отдельным полем в access_token response, и у части пользователей его может не быть) — зафиксировать в комментарии к задаче или коротким разделом в `docs/product/features/auth.md`.
- Иконка VK ID: заменить монограмму в макете на официальный SVG из брендбука (см. `docs/ui/handoffs/auth/README.md`, «Assets» — «Иконки Yandex ID и VK ID … Перед релизом взять официальные SVG»). SVG-ассет положить в `apps/platform/public/` или `src/client/common/`.

Вне скоупа:

- Сам код OAuth-flow (в 0022).
- Всё, что касается Yandex ID (в 0010 / 0015).
