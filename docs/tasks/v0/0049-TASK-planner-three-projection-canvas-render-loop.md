## Описание

Завершающая задача шага 1: ядро из 0048 получает **проекцию в Three** — единственный слой пакета, который трогает `three` и DOM. После неё эпик 0043 «стоит на ногах»: `/project/:id` открывает планер с канвасом на весь контейнер, ортокамерой сверху и пустой сценой; рендер только по требованию (в покое ни одного `requestAnimationFrame`); resize и unmount не текут. Здесь же закрываются обязательные пункты приёмки эпика 0043 (канвас на весь контейнер, нет RAF в покое, unmount освобождает renderer/геометрии/материалы).

Ровно один PR. Инструментов, геометрии, мешей стен — нет (шаги 2 и 4).

### Скоуп (что делаем)

1. **`projection/three/ThreeProjection`** (A7): один `WebGLRenderer` на переданный `canvas`; одна `Scene` (пустая; фон/свет — минимум, чтобы «пустая сцена» была видна как фон); **ортокамера сверху** из `Document.view` (`activeView`, камера вида `plan`): центр/зум → фрустум камеры; **маппинг план→мир `(x, y) → (x, h, −y)` — в одном месте** проекции (B1; ADR G позже расширяет, не переносит). Проекция подписана на шину через `manager.on/subscribe`, документ читает через фасад, в документ не пишет; `view:changed` → перестроить камеру и `invalidate()`; `document:changed` → в шаге 1 просто `invalidate()` (сцена пустая).
2. **`RenderLoop`** (A7): `invalidate()` выставляет бюджет кадров, дефолт `FRAME_BUDGET = 5` (константа рядом с классом), переопределяется параметром `createPlanner({ frameBudget })`; луп через `requestAnimationFrame` декрементирует бюджет и **самозавершается** — в покое `rAF` не планируется; повторный `invalidate()` во время лупа только пополняет бюджет (без второго лупа). Инвалидируют: любое событие шины, resize.
3. **Resize**: `ResizeObserver` на контейнер канваса (родителя) → `renderer.setSize` с `devicePixelRatio`, пересчёт фрустума ортокамеры под aspect, `invalidate()`. Канвас занимает контейнер целиком (стили — задача страницы; проекция не пишет `style` кроме размеров, необходимых three).
4. **`dispose()`** в обратном порядке (A7): `off` подписок на шину, `ResizeObserver.disconnect()`, `cancelAnimationFrame` активного лупа, обход сцены с `dispose()` геометрий/материалов/текстур, `renderer.dispose()` + `forceContextLoss()`. Повторный `dispose()` — no-op.
5. **`getStats()`** для гварда (A7): `{ frame: renderer.info.render.frame, geometries: renderer.info.memory.geometries, textures: renderer.info.memory.textures }`. Как Playwright достаёт результат фабрики: **dev-only проп** `<Planner onReady={(planner) => …} />` (или аналог), **не** `window.__*`; в проде проп не передаётся, глобалов нет.
6. **`createPlanner`** реально поднимает `ThreeProjection(manager, canvas, { frameBudget })`, `<Planner />` монтирует полноценно (canvas → фабрика → контекст → dispose на unmount) — как в 0048, без второй точки создания.
7. **Тесты**:
   - Jest (без Three, где возможно): `RenderLoop` с фейковым `requestAnimationFrame` (бюджет, самозавершение, повторный `invalidate`, отмена при dispose), маппинг `(x,y,h)→(x,h,−y)` и расчёт фрустума ортокамеры из камеры вида (чистые функции, вынесены из класса).
   - **Playwright-гвард** (testing-strategy, слой 3): открыть `/project/:id`, дождаться `onReady`, ассертить «idle FPS ≈ 0» (за секунду покоя `getStats().frame` не растёт), после resize/событий и unmount (навигация со страницы) `renderer.info.memory.geometries/textures` не растут и после `dispose()` — 0. Расположение и запуск Playwright-тестов — по текущей практике репозитория (если инфраструктуры Playwright-тестов ещё нет — завести минимальную в этой задаче и записать в «Заметках», как запускать).
8. **Приёмка через Playwright MCP** по протоколу доски (UI-задача → визуальная проверка на 1440 / 768 / 390): канвас на весь контейнер, консоль без ошибок и WebGL-предупреждений, после ухода со страницы и возврата — новый планер без утечек.

- Интеракция камеры (pan/zoom мышью), кнопки видов, orbit/walk — шаги 2/4/9; здесь камера только читает `Document.view`.

## Заметки

Решения в рамках ADR (установка автора: «правильно, надолго, не на один раз»):

- **Раскладка `projection/three/`:** `ThreeProjection.ts` (класс), `RenderLoop.ts` (луп + `FRAME_BUDGET = 5` рядом), `planToWorld.ts` (единственное место маппинга `(x, y) → (x, h, −y)`, обратный `worldToPlan`, `PLAN_UP_IN_WORLD` — up-вектор ортокамеры выводится из того же маппинга: `planToWorld({x:0,y:1}) = (0,0,−1)`), `planCamera.ts` (чистые `planZoomToViewHeight`, `computePlanFrustum`, константы глубины камеры), `disposeSceneGraph.ts` (обход сцены). Чистые функции вынесены из класса и тестируются в Jest без `three`; ориентация проверена по базису `lookAt` three: экранное «вправо» = `+x` плана, «вверх» = `+y` плана.
- **`ThreeProjection(manager, canvas, { frameBudget, logger })`:** логгер приходит опцией (менеджер свой не отдаёт). Один `WebGLRenderer({ canvas, antialias: true })`, одна пустая `Scene` с фоном-цветом, `OrthographicCamera` из `Document.view.cameras.plan` (центр `(x, y)` → мир через `planToWorld`, фрустум по зуму и aspect); подписки: `on('view:changed')` → перестроить камеру, `subscribe('*')` → `invalidate()`. **Порядок инициализации:** `RenderLoop` (валидация `frameBudget`) — до создания GL-контекста; всё после `new WebGLRenderer` — в `try/catch` с `renderer.dispose()+forceContextLoss()`, чтобы неудачная инициализация не оставляла контекст (замечание критика). Исключение из `renderer.render` — в `logger.error`, не наружу из `rAF`. Наружу: `scene` (readonly — для гвардов на scene-graph), `canvas`, `manager`, `invalidate()`, `isRendering`, `isDisposed`, `getStats()`, `dispose()`; `renderer`/`camera` — приватные, пока нет потребителя.
- **Resize:** `ResizeObserver` на `canvas.parentElement` (фолбэк — сам canvas) с `box: 'device-pixel-content-box'` (Chromium/Firefox: будит observer при смене DPR без смены CSS-размера; где не поддерживается — обычный `observe(el)`). Размер — `entry.contentRect` (CSS px), DPR — `defaultView.devicePixelRatio` при каждом колбэке, `setPixelRatio` → `setSize(w, h, false)` — стили канвасу проекция не пишет, CSS-размер задаёт страница (`block h-full w-full`). DPR не капится (desktop-only планер). **Не проверено:** смена DPR под CDP-эмуляцией (`Emulation.setDeviceMetricsOverride`) не будит ни RO, ни `matchMedia` — артефакт эмуляции; реальный перенос окна между мониторами документирован Chromium; `matchMedia`-страховку не добавлял.
- **`RenderLoop`:** `invalidate()` = пополнить бюджет до `frameBudget` (не суммировать) и запланировать кадр, если луп спит; `tick` обнуляет handle до `render()` (реентерабельный `invalidate` из рендера не создаёт второго кадра); после `dispose()` — no-op; невалидный `frameBudget` — `RangeError` при создании. Планировщик (`requestAnimationFrame`/`cancelAnimationFrame`) — параметр: в проекции — `defaultView` канваса, в тестах — фейк.
- **`dispose()`** — ровно по A7: off подписок → `RO.disconnect()` → `loop.dispose()` (cancel rAF) → `disposeSceneGraph` (геометрии/материалы/текстуры **всех** объектов с `geometry`+`material`: `Mesh`, `Line`, `Points`, `Sprite`; текстуры из свойств материала и из `ShaderMaterial.uniforms`; фон/окружение сцены-текстуры; общие ресурсы — по одному разу) → `scene.clear()` → `renderer.dispose()` + `forceContextLoss()`. Повторный — no-op на всех уровнях (loop, projection, `createPlanner`).
- **`createPlanner`:** документ → менеджер → проекция; если проекция бросила (нет WebGL) — менеджер освобождается, ошибка пробрасывается (полуживого планера нет). **`<Planner />`:** ловит ошибку фабрики → `logger.error('failed to start planner')`, контекст пуст, дети не рендерятся, `onReady` не зовётся, хост не падает; UI-фолбэк «WebGL недоступен» — отдельная задача. **`<canvas key={projectId}>`:** после `forceContextLoss` контекст канваса потерян, второй рендерер на нём ничего не нарисует — при смене `projectId` React создаёт новый элемент (замечание критика). `frameBudget` читается при монтировании (ref), не в deps: его смена не пересоздаёт движок. **StrictMode** (двойной эффект на одном канвасе) в приложении не включён; при включении понадобится канвас-на-эффект — записано вопросом.
- **Dev-only ручка для Playwright:** проп `onReady?: (planner: PlannerInstance) => void` у `<Planner />` (в ref, смена не пересоздаёт планер). Платформа: `project/lib/plannerReadyEvent.ts` — `announcePlannerReady` = `undefined` при `process.env.NODE_ENV === 'production'` (DefinePlugin), иначе `window.dispatchEvent(new CustomEvent('planner:ready', { detail: planner }))` — тот же паттерн, что `auth:unauthorized` в `common`. Глобал `window.__uyutnoE2E` заводит **тест** через `addInitScript`, не приложение; в prod-бандле строки `planner:ready` нет (проверено grep по `dist/client`).
- **Playwright-инфраструктура (заведена в этой задаче):** `apps/platform/playwright.config.ts`, тесты `apps/platform/e2e/*.spec.ts` (не `*.test.ts` — вне Jest), `e2e/tsconfig.json` включён в `typecheck` платформы, скрипты `test:e2e` (платформа и корень), devDep `@playwright/test ^1.62.1`, `.gitignore`: `test-results/`, `playwright-report/`. В CI нужны `.env` (`--env-file`) и Postgres — как для `pnpm dev`. Как запускать: `pnpm exec playwright install chromium` один раз → `pnpm test:e2e` (поднятый `pnpm dev` переиспользуется).
