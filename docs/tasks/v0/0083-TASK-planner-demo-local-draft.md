## Описание

Единственное место в v0, где документ планера живёт в браузере. **В обычном проекте локальной копии нет** (ADR 0021): серверный автосейв её дублирует, а взамен приносит развилку «локальное против серверного» при каждом открытии. На демо-роуте сервера нет вовсе — сохранять некуда, поэтому черновик там нужен.

Задача реализует draft-половину пропа `storage` (`loadDraft`/`saveDraft`/`clearDraft`, заведён в `0081`) и подключает её к таймеру черновика в `persistence`.

Скоуп:

1. **Ключ `planner_demo_draft`** — один на гостевую сессию, **без идентификатора пользователя**. У обычного проекта черновика нет, различать владельцев незачем. Имя ключа — решение ADR 0021, опоры в репозитории у него нет: не искать «как было», брать отсюда.
2. **Периодичность — 30 секунд**, старт с той же задержкой **5 секунд** после старта редактора, что и серверный автосейв (спека 10). Активный drag гасит тик так же, как у серверного автосейва (механика — `0081`).
3. **Diff-guard**: реальный `setItem` идёт только если сериализованный JSON отличается от прошлого — при простое запись пропускается. Опирается на детерминированность `serialize` из `0079` (одинаковый документ даёт байт в байт одинаковую строку), иначе guard не сработает никогда.
4. **Формат записи** — документ в формате сейва (`serialize` из `@uyutno/planner/format`) плюс метка времени (решение автора 2026-08-20, зафиксировано в задаче [0064](0064-TASK-planner-demo-route-and-guest-draft.md)). Версия формата уже внутри конверта, отдельным полем её не дублировать.
5. **Клиентский `migrate` при чтении.** Черновик гостевой сессии сервера не видит, поэтому миграцию формата там выполняет клиент: `loadDraft` прогоняет `migrate` и, если тот что-то изменил, **кладёт результат обратно в тот же ключ**. Код тот же, что на сервере (`@uyutno/planner/format`), точек вызова две.
6. **`QuotaExceededError`** (и любой отказ `localStorage` — приватный режим, отключённое хранилище) — **та же тихая иконка, что и ошибка автосейва**; редактор не падает и работу не теряет. Никаких модалок и тостов. Поведение при квоте — решение ADR 0021, опоры в репозитории у него нет.
7. **Очистка.** `clearDraft` — обязанность платформы, зовётся: при успешном переносе демо-проекта в аккаунт (`0065`) и при удалении проекта из галереи, если демо-ключ ещё жив. Ключ у черновика один и `projectId` в нём нет, поэтому «очистка при удалении проекта» из ADR сводится к безусловному снятию демо-ключа — сопоставлять его с удаляемым проектом нечем и не надо.
8. **Возврат на демо-роут** молча загружает черновик, если он есть, — **без модалки «восстановить?»** (принято по reference, спека 10).
9. Реализация — на стороне платформы (`client/project/lib/`), по конвенциям `src/client/CLAUDE.md`; планер знает только про методы пропа.

Не в задаче: сам демо-роут `/demo`, заготовленный проект и шапка в состоянии «демо» — задача [0064](0064-TASK-planner-demo-route-and-guest-draft.md); гейт Save, модалка «Войдите, чтобы сохранить проект» и её состояние «хранилище недоступно», копия проекта в аккаунт — задача [0065](0065-TASK-planner-demo-save-gate-and-project-copy.md). Здесь — механизм и его тесты; подключение к живому роуту делает `0064`.

## Приёмка

- [ ] `saveDraft` пишет в `localStorage` под ключом **`planner_demo_draft`**; идентификатора пользователя в ключе нет.
- [ ] Запись идёт раз в **30 с**, первая — не раньше **5 с** после старта редактора.
- [ ] **Diff-guard работает**: при неизменном документе `setItem` не вызывается вовсе — тест со счётчиком вызовов на фейковом хранилище.
- [ ] `loadDraft` читает черновик, прогоняет `migrate` и при `changed: true` **записывает мигрированный результат обратно** в тот же ключ — отдельный тест с фиктивным шагом миграции.
- [ ] Битый/нечитаемый черновик не роняет редактор: `loadDraft` возвращает «нет черновика», ключ не остаётся источником вечной ошибки.
- [ ] `QuotaExceededError` при записи не роняет редактор и даёт **то же тихое состояние ошибки**, что и неудачный автосейв; модалки не появляется.
- [ ] Недоступный `localStorage` (обращение бросает синхронно) обрабатывается там же и той же веткой — тест на «хранилище недоступно вообще».
- [ ] `clearDraft` снимает ключ; повторный вызов на пустом ключе безопасен.
- [ ] Серверного автосейва в режиме черновика нет (гаситель из `0082`), и наоборот: в обычном проекте `saveDraft` не зовётся ни разу — тест на обе стороны.
- [ ] `pnpm typecheck`, `pnpm lint`, `pnpm test` зелёные.
- [ ] Prettier чист; ровно один PR.

## Заметки

- **Черновик обязан пережить редирект к OAuth-провайдеру и обратно** — иначе попытка сохраниться уничтожает то, ради чего сохранялись. Механика ухода со страницы и возврата описана в задаче `0064` (решение автора 2026-08-20); этой задаче достаточно того, что запись синхронная и лежит в `localStorage`, а не в памяти. Сквозной сценарий проверяет `0064`.
- **План — десятки килобайт JSON при лимите порядка 5 МБ**: запас огромный, ужимать и резать нечего. IndexedDB в v0 не используется.
- **Цикл «демо → логин → работа → логаут»** (спека 10): при логине копия демо-проекта уезжает на сервер отдельным проектом, гостевой ключ очищается, дальнейшая работа пишется только на сервер; после логаута новый демо-сеанс стартует с заготовленного проекта. История не теряется — она лежит в проектах аккаунта.
- **Превью при записи черновика не пересчитывается** (спека 10). В v0 превью нет вовсе — шаг 9.
