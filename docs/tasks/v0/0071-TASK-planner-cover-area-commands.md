## Описание

Инструментов «Зона» и «Рисование пола» на 2b нет (перенесены на шаг 7), поэтому наполнить документ зонами и ручными полами нечем — а без этого стадии 2b не проверяются ни фикстурами, ни тестами. Задача заводит **команды ядра**, которыми это делается напрямую, по образцу существующих `document.addContours` / `deletePoint`: валидация на границе → квантование → одна транзакция `history: { zone: 'layout' }` → `normalize`/`rebuild` → одно `document:changed`; `Result<T, E>`, при ошибке документ — тот же объект.

Состав (минимальный набор, достаточный для фикстур и тестов; жесты, диалоги и панели — шаг 7):

- **`addCover(floorId, points)`** — ручной пол одним контуром. Валидация: конечные координаты, ≥ 3 точки, `contourSelfIntersected`, `contourValid`. Слияние с существующими полами — по правилам спеки 02: `intersect` → автоматическое объединение; `contact` → **отдельный пол** (диалог «Объединить?» — авторинг шага 7, команда его не показывает и по умолчанию не сливает); поведение зафиксировать явным параметром или явным дефолтом и записать в «Заметки».
- **`addArea(floorId, points, height)`** — зона. Валидация по спеке 02: самопересечение, пересечение стен комнаты (касание допустимо), пересечение существующей зоны (касание допустимо), опора точек. **Отказ молчаливый** для пользователя (модалок и тостов в v0 нет) — но команда обязана вернуть типизированную ошибку, иначе тест не отличит отказ от no-op.
- **`deleteCover(floorId, id)` / `deleteArea(floorId, id)`** — явное удаление; зона забирает свои записи `cuts[]` по правилу владения (решение (1), 0068). Спека 02: «Пользователь может явно удалить пол и оставить комнату без покрытия».
- **`setAreaHeight(floorId, id, height)`** — высота зоны, конечное число > 0; коалесинг-ключ формирует команда (`'area-height:<id>'`), как у `setEdgeLength`.

Требования:

- Коды ошибок — говорящие и по одной ветке на правило отказа (`unknown-floor`, `unknown-cover`/`unknown-area`, `invalid-coordinate`, `contour-self-intersected`, `contour-degenerate`, `area-crosses-walls`, `area-overlaps-area`, `area-unsupported`, `invalid-height`). Каждая ветка — отдельный тест (ADR 0018 D10).
- Команды идут в **существующий неймспейс `document`**, нового неймспейса не заводить (`engine/README.md`).
- Публичный экспорт типов ошибок/входов — через `src/index.ts`, как у прочих команд.

Не в задаче: инструменты, диалог высоты, модалка «Объединить?», подписи и ручки — шаг 7; отрисовка — шаг 4.

## Заметки

**Реализация 2026-08-20.** `engine/commands/`: `loopAccess.ts` (общий доступ — `resolveCover`/`resolveArea`, `quantizeLoop`, `resolveLoopIds` с дисциплиной id как в `addContours`), `addCover.ts`, `addArea.ts`, `deleteCover.ts`, `deleteArea.ts`, `setAreaHeight.ts` + тесты (50 тестов). Пять методов дописаны в **существующий** неймспейс `document`, нового неймспейса не заводилось.

```ts
addCover(floorId, points, options?: { kind?: ContourKind }): Result<void, AddCoverError>
addArea(floorId, points, height): Result<void, AddAreaError>
deleteCover(floorId, id): Result<void, DeleteCoverError>
deleteArea(floorId, id): Result<void, DeleteAreaError>
setAreaHeight(floorId, id, height): Result<void, SetAreaHeightError>
areaHeightCoalesceKey = (id) => `area-height:${id}`   // ключ формирует команда, не UI (ADR 0018 D5)
```

Коды ошибок: `unknown-floor`, `unknown-cover`, `unknown-area`, `invalid-coordinate`, `contour-self-intersected`, `contour-degenerate`, `invalid-height`, `area-crosses-walls`, `area-overlaps-area`, `area-unsupported` — каждая ветка отдельным тестом; при отказе документ остаётся тем же объектом, событий ноль.

**Опора зоны проверяется и при создании** (`validateArea` с `requireSupport: true`) — тем же предикатом и допуском, что в `normalize`. Зона мимо углов комнаты не пережила бы ближайшую пересборку, принять её значит молча потерять данные пользователя. Побочный эффект (зафиксирован тестом): вершины зоны получают id углов комнаты, новых точек не заводится, записи `cuts[]` строятся на общих id.

**Фактическое поведение `addCover` — пересечение и касание неразличимы.** Фаза (5) `normalizeCovers` зовёт `mergeCovers(..., { contact: true })` безусловно, поэтому и `intersect`, и `contact` дают слияние. Более того, на 2b сценарии различить **нечем**: `findAutoCovers` застилает всю свободную площадь комнаты до слияния, поэтому новый ручной пол внутри комнаты всегда пересекает авто-пол. Замер: комната 380×280 под авто-полом + `addCover` левой половины → **одна** запись на всю комнату (вершины ручного пола остались в петле). Слияние идёт по отношению контуров, а не «всё в одно»: разнесённые комнаты дают две записи. `ceilingHidden` первого пола-донора переживает слияние. Явного параметра «сливать / не сливать» у команды нет — слияние является правилом `normalize`, и параметр не мог бы на него повлиять.

**Нужно от автора:**

1. **Слияние при касании делает multi-material полы невозможными — спека 02 противоречит себе.** Фаза (5) склеивает все касающиеся полы, поэтому «несколько полов бок о бок в одной комнате» («Multi-material пол», «каждый со своим материалом», «„Нет“ — новый пол остаётся отдельным») сейчас недостижимо **в принципе** — не только для команды, но и для будущего инструмента шага 7. Противоположное требование той же спеки — «соприкоснулись косвенно из-за правки стен — объединяются автоматически». Пока материалов нет (ADR J), это безвредно; к шагу 7 нужно либо звать `mergeCovers` с `contact: false` для ручных полов, либо хранить признак «нарисован вручную, по касанию не сливать». **Решение за автором, кандидат в «спека ← код».**
2. **«Комната без покрытия» не моделируется.** Спека 02: «пользователь может явно удалить пол и оставить комнату без покрытия — тогда пола просто не будет в 3D». На 2b это недостижимо: сразу после `deleteCover` фаза (5) заводит дефолтный пол на той же площади (новый id, `ceilingHidden` сброшен). Признака «покрытия нет намеренно» модель не хранит. Осмысленно удаляется только вырез (`kind: 'inner'`) — он исчезает, обвод хозяина остаётся целым. Оба случая покрыты тестами. Нужен либо флаг в модели, либо правка спеки.
3. Контракта геометрии (`validateArea`, `validateContour`, `normalizeCovers`, `reconcileCuts`) хватило полностью — доработок ядра не потребовалось.
