## Описание

Достраиваем интерактив карточки: контекстное меню и три действия — переименовать, дублировать, удалить. К этому моменту готов каркас страницы, карточка с ссылкой и кнопкой «…»-заглушкой (задача 0038) и REST-ручки бэкенда (задача 0037).

Читать перед стартом — то же, что в 0038 (`projects-screen.md`, `guidelines.md`, `layout.md`, `client/CLAUDE.md`).

### Меню карточки — десктоп

`ProjectCardMenu` — Popover на HeroUI (или React Aria Menu из HeroUI v3, см. канон MCP heroui-react).

- Триггер — кнопка «…» из карточки (нужно перекинуть её в `role="button"` с `aria-haspopup="menu"`, вместо заглушечного `onOpenMenu`).
- Ширина 200px, белый, radius 12px, padding 4px, тень `0 2px 8px rgb(0 0 0 / 0.10)`, рамка 1px `--separator`. Прижат к правому краю карточки, открывается ниже кнопки.
- Пункты 36px, radius 8px, иконка 16px + текст 14px, gap 8px:
  1. «Переименовать»
  2. «Дублировать»
  3. разделитель 1px `--separator`
  4. «Удалить» (цвет danger `#C63C2E`, ховер `#9F3226`)
     Ховер пунктов — `--surface-secondary`.
- Закрывается по Escape, клику вне и выбору пункта. Фокус возвращается на кнопку «…» карточки.
- Клик по «…» не должен всплывать до ссылки-карточки (`preventDefault` + `stopPropagation`).
- `role="menu"`, стрелки вверх/вниз перемещают фокус между пунктами.

### Меню карточки — мобилка (до 1024px)

Bottom sheet во всю ширину экрана:

- radius 24px только сверху, ручка 36×4 `--separator` по центру.
- Над пунктами — название проекта 15px/500 (padding 12px 16px, снизу разделитель).
- Пункты 44px с иконками 20px.
- Плавная анимация появления снизу (translate + fade, ~200ms). При `prefers-reduced-motion: reduce` — мгновенно.
- Закрытие по свайпу вниз необязательно; достаточно тапа вне, кнопки закрытия и выбора пункта.

### Модал «Переименовать»

`RenameProjectModal` — по геометрии клон `NewProjectModal` (задача 0038); можно завести общий `<ProjectFormModal>`-компонент, если он естественно вырисовывается, но не форсировать абстракцию.

- Ширина 344px, radius 24px, padding 24px, gap 16px. Мобильно — прижат к низу, кнопки 44px в ряд по 50% ширины.
- Заголовок «Переименовать» 22px/600.
- Поле «Название» с текущим именем проекта; при открытии — фокус + `select()`.
- Валидация: `trim().length > 0` и `length <= 60`; проверяется только на отправке. Пустое имя дизейблит «Сохранить».
- Состояние ошибки: кольцо 2px danger, подпись 12px под полем — «Введите название» / «Максимум 60 символов» / серверная ошибка.
- Кнопки: «Отмена» (`--surface-secondary`) + «Сохранить» (`--accent`), обе 40px.
- Enter сохраняет, Escape закрывает без сохранения.
- Сабмит: `PATCH /api/v1/projects/:id`. Успех → закрыть модал, инвалидировать/обновить query списка (карточка ползёт наверх, потому что `updated_at`).

### Модал «Удалить проект?»

`DeleteProjectModal` — та же геометрия.

- Заголовок «Удалить проект?» 22px/600.
- Текст 14px: `"{название}" удалится вместе с планировкой. Восстановить не получится.` (кавычки-ёлочки не обязательны; используем то же, что в спеке).
- Кнопки: «Отмена» (`--surface-secondary`) + «Удалить» (`#C63C2E`, ховер `#9F3226`, текст белый), обе 40px.
- Enter подтверждает удаление, Escape закрывает без действия.
- Сабмит: `DELETE /api/v1/projects/:id`. Успех → закрыть модал, убрать карточку из списка. Ошибка → строчка ошибки под кнопками; модал остаётся открытым.

### Дублирование

Один клик по пункту меню:

- `POST /api/v1/projects/:id/duplicate` → новая карточка появляется первой в списке (её `updated_at` свежее).
- Никаких модалов и подтверждений. Меню закрывается.
- Пользователь остаётся на `/projects`, редактор не открываем (в отличие от «Новый проект»).
- Ошибка сервера — тост/строчка в углу карточки не обязательны; в v0 достаточно `console.error` и no-op. Если это уже не соответствует принятой практике в других модулях — сделать так же, как там (см. LoginPage, где показывается инлайновая плашка).

### Query-инвалидация

- После rename и duplicate — инвалидировать `getProjectsQuery` (react-query invalidateQueries) — простой и достаточный подход в v0.
- После delete — можно ту же инвалидацию либо `setQueryData` с локальным `filter(p => p.id !== id)`. На выбор автора; главное — карточка исчезает без ручного refetch на UI-стороне.

### Что не делаем

- Оптимистичный UI (rollback на ошибке и т.п.) — не нужно.
- Undo для удаления — не нужно (в v0 корзины нет, см. спеку).
- Клавиатурные шорткаты глобального уровня (F2 для rename и т.п.) — нет.
- Изменения в модальном каркасе `NewProjectModal` из 0038 — только если естественно вытекает переиспользуемый компонент.
