## Описание

Слой `engine/` получает то, что нужно инструментам шага 2 и спеке 09: **команды планировки** как транзакции `PlannerStore` и **настоящий неймспейс `history`** вместо заглушки 0048. UI визуально не меняется (кнопки undo/redo — 0061); после задачи движок headless в Jest умеет: добавить контур → комната выведена → `undo` вернул пустой этаж → `redo` вернул комнату; серия `movePoint` под одним coalescing-ключом = одна запись.

Скоуп (по ADR D, границы уточняются — «Заметки»):

1. **Команды планировки** (неймспейс `document`, ADR 0018 D1; `floorId` явный): `addContours(floorId, { kind, points: PlanPosition[] }[])` (сырой результат инструмента; id вершин по квантованной координате — сварка с существующими; валидация ≥ 3 точек / самопересечение / вырожденность), `movePoints(floorId, moves, { coalesce? })` (без геометрической валидации; драг стены — два конца; **разрез стены и слияние точек — не команды**: T-стык и тождество координат делает `normalize` ADR 0017), `deletePoint(floorId, id)` (каскад D2: id снимается со всех владельцев, контур/пол/зона с < 3 точками удаляются, cuts — с зоной), `setEdgeLength(floorId, edge, length, { anchor? })` (симметрично ±Δ/2 или вся Δ на конец, противоположный `anchor`; отказ `too-short` < 15 / самопересечение / `out-of-range`), `setWallWidth(floorId, faces: [FaceRef, FaceRef], width)` (сдвиг `faces[0]` на Δ по нормали; `unknown-axis`); коалесинг-ключи `'edge-length:…'`/`'wall-width:…'` формируют сами команды. Валидация на границе (`Result` с ветками отказа спеки 01), квантование координат (B1), `undefined` в документ не попадает; каждая команда — одна транзакция → `normalize`/`rebuild` (0054) → одно `document:changed`.
2. **API транзакции для истории** (ADR 0018 D5): `store.transact(recipe, meta)` с `meta.history: 'none' | 'reset' | { zone: 'layout' | 'scene'; coalesce?: string }`; коалесинг — замена записи на `pointer` при `lastCommitKey === key`, серия рвётся другим коммитом/undo/redo/`load`/сменой выделения (внутренний `history.breakSeries()`, зовёт `tools`); гейта «мышь зажата» и `removeUndoState` нет — документ не меняется до коммита (граница D↔E), live-драг/превью — в `ToolState` (0057/0059).
3. **`HistoryNamespace` реальный** (ADR 0018 D3–D6, D9): два контейнера memento «stack + pointer» (записи — ссылки на замороженные `floors[i].layout` / `floors[i].scene` всех этажей, снимок после `normalize`); активная зона = зона активного вида, но последняя запись/undo/redo переключает её до следующей смены вида (D4) — `history:changed` и при смене вида; baseline при создании/`load` (`history: 'reset'`), не откатывается; restore = транзакция замены поддеревьев с `history: 'none'` + обычный rebuild; `MAX_HISTORY = 100` сверх baseline, `shift()` на переполнении; redo-хвост сбрасывается новой записью; `undo`/`redo` не трогают `view` и `settings` (`settings` вне истории); хук **`StoreHooks.beforeReplace()`** перед restore и перед `load` — `PlannerManager` подключает `tools.interrupt()` (0057) — имя не переименовывать.
4. **Dirty-флаг** (ADR 0018 D7): поле `PlannerStore`, ставится любой транзакцией содержимого (команды, `settings`, restore), не `view`; наружу `document.isDirty()`, `document.markSaved()` (заглушка до ADR F), событие `document:dirty-changed { dirty }` только при смене; `load`/создание — `false`.
5. **Тесты слоя 2** (все ветки): каждая команда — успех и каждая ветка отказа; удаление точки с общим id по всем комбинациям владельцев; ровно одна запись на коммит, coalescing по ключу, транзакции без изменений и `history: 'none'` не пишут; лимит: 101-й push вытесняет самый старый, baseline не откатывается; `undo(redo(x)) == x` и `redo(undo(x)) == x` property-тестом (`fast-check`); `history:changed` только при изменении; `view` не меняется на undo; dirty-флаг по всем веткам; `dispose` снимает подписчиков.

Не в задаче: инструменты и ввод (0057), отрисовка (0056), UI-кнопки (0061), сохранение (шаг 3).

## Заметки

- Скоуп заведён до принятия ADR D (0052); после принятия — сверить состав команд, форму API транзакции (коммит/коалесинг/гейт), правило удаления общей точки, форму dirty-флага и поправить этот файл. Если ADR D решит, что live-драг всё же идёт через документ (`skip`-транзакции), сюда добавляется гарантия «rebuild на каждый кадр не эмитит историю» и перф-оговорка. Если после ADR D объём (7 команд со всеми ветками отказа + история + dirty + property) не влезает в один PR — резать по границе «команды планировки» / «history + dirty», правкой этого файла и одним дополнительным номером.
- **Уточнено по ADR 0018 (2026-08-19):** состав команд, форма `TransactionMeta` (`'none' | 'reset' | { zone, coalesce }`), хук `StoreHooks.beforeReplace`, внутренний `history.breakSeries()`, правило активной зоны D4, dirty-флаг D7 — вписаны в скоуп выше; `splitSegment`/`mergePoints` из скоупа убраны (делает `normalize`). Live-драг документ не трогает — гарантия «rebuild на каждый кадр» не нужна. Если объём не влезает в один PR — резать по границе «команды планировки» / «history + dirty».
- **Реализовано (2026-08-19).** Раскладка: `engine/history/HistoryLog.ts` — два контейнера memento «stack + pointer», `MAX_HISTORY = 100`, `captureRecord`/`applyRecord` (запись = ссылки на `floors[i].layout` / `.scene` всех этажей), активная зона D4; `PlannerStore` — `transact(recipe, meta: TransactionMeta)`, `restore('undo' | 'redo')`, `StoreHooks.beforeReplace`, dirty-флаг, эмит `history:changed` (при смене флагов активной зоны, в т.ч. от смены вида) и `document:dirty-changed`; `HistoryNamespace` — тонкая обёртка над store (`get/undo/redo`); внутренний `breakSeries()` живёт на `PlannerStore` (D5: не публичный API фасада — `tools` в 0057 собирается в `PlannerManager` с доступом к store); команды — `engine/commands/{addContours,movePoints,deletePoint,setEdgeLength,setWallWidth}.ts`, подключены методами `DocumentNamespace` (неймспейс один, D1); `document.isDirty()/markSaved()`; `document.load` → `store.load()` (единственный путь к `'reset'`: хук → транзакция → dirty снят). `PlannerManager` передаёт хук `beforeReplace` как no-op — 0057 заменит на `tools.interrupt()`.
- **Решения в рамках/сверх ADR (для сверки при 0057/0060):**
  - Порядок событий одной транзакции: `document:changed` → `view:changed` → `history:changed` → `document:dirty-changed`. При `load` другого объекта документа `view:changed` приходит всегда (новая ссылка `view`, как в 0048).
  - Транзакция содержимого с `history: 'none'` (`settings`) серию коалесинга **не рвёт**: `settings` вне истории (D3), в D5 перечислены только коммиты в историю, undo/redo, `load` и смена выделения. `view` тем более не рвёт.
  - `'reset'` того же снимка (`load` уже загруженного объекта) — документ и события документа не меняются, но история сбрасывается и dirty снимается (load = reset по смыслу); хук `beforeReplace` при этом не зовётся (замена не состоится, D9).
  - Restore ставит dirty всегда, даже если запись совпала с текущим снимком по ссылке (D7: «ставится restore undo/redo»); хук `beforeReplace` в этом (штатно недостижимом) случае не зовётся — замена не состоится (D9).
  - Ошибки сверх таблицы D1 (аддитивно, без изменения перечисленных): `invalid-coordinate` (`addContours` — `index` контура, `movePoints` — `id`) для не-конечных координат — plain-JSON документ (B5) не должен получить `NaN`; `degenerate-edge` в `setEdgeLength`, если концы совпадают (направление сдвига не определено; после `normalize` не встречается — только у полов/зон с дублями точек). Все ошибки несут контекст (`floorId`, `id`, `index`, `min/max`).
  - `setWallWidth`: нижний порог `MIN_WALL_WIDTH = 1` см (`too-short`) — пол длины 15 см к ширине неприменим (`DEFAULT_WALL_WIDTH = 10`); верх — как у длины (`MAX_EDGE_LENGTH = 100 000`, `out-of-range`), `MAX_WALL_WIDTH = 80` — порог детектора оси, «не пользовательский лимит ввода» (спека 01): стена шире просто теряет ось, следующая правка — `unknown-axis`; пара граней принимается в любом порядке (`faces[0]` — сдвигаемая), нормаль считается от середины `faces[1]` к середине `faces[0]`.
  - `setEdgeLength` не проверяет, что `a–b` — ребро контура (ADR не требует; UI передаёт ребро из выделения); порядок проверок: `unknown-floor` → `unknown-point` (концы, затем `anchor` вне ребра) → `out-of-range` → `too-short` → `degenerate-edge` → `contour-self-intersected`. Проверка самопересечения — по всем петлям-владельцам сдвигаемых точек (`contours`, `covers`, `areas`).
  - `deletePoint`: сама точка из `layout.points` командой не удаляется — её, оставшуюся без владельцев, снимает `normalize` (GC), который до этого пере-привязывает комнаты по координатам ещё живой точки. «Cuts зоны» при удалении зоны — cuts с обоими концами среди точек зоны на момент удаления (у `Cut` нет ссылки на зону в модели B).
  - `addContours`: пустой пакет — `ok` без транзакции; порог длины ребра не проверяется (торцы квадов ленты короче `MIN_WALL_LENGTH` по построению — длину рёбер контролирует инструмент на завершении); возвращает `void` — id контуров после `normalize` не стабильны (C1), а id точек можно взять из снимка по координате.
  - `TransactionMeta.coalesce` — по контейнеру, но любой коммит (в любую зону) сбрасывает ключи обоих контейнеров: «серию рвёт любой другой коммит» (D5).
- **Критики (субагенты, 2026-08-19):** по ADR — блокеров нет (замечание «нет property-теста» — ложное, файл `history/undoRedo.property.test.ts`); учтено: `breakSeries` убран из публичного `HistoryNamespace`, `load` собран в `PlannerStore.load`, `HistoryError` один (в `HistoryLog`), `invalid-coordinate` разбит на два дискриминанта (`index` / `id`), `HistoryZone` не экспортируется, JSDoc про серию и `'none'`, `emitHistoryChanged`; аддитивные решения (ошибки, пороги ширины, «cuts зоны», форма `HistoryRecord`) вписаны в ADR 0018 «Что важно знать». По тестам — блокеров нет; учтено: явные проверки записей в `setEdgeLength`/`addContours`, хук через `document.load`, ветки `unknown-point` для `a`, `invalid-coordinate` с `index: 1`, порог/сливер `MIN_CONTOUR_AREA`, сварка после квантования, `outer` из 3 точек, cut выжившей зоны (реализация уточнена: cut удалённой зоны остаётся, если его держит выжившая зона), тавтология в property убрана, арбитрарий расширен `setEdgeLength`/`setWallWidth`, dirty-свойство стало двусторонним. Не сделано (осознанно): `unknown-point` в `setWallWidth` — недостижимо (ось из `getDerived()` того же снимка), ветка защитная.
