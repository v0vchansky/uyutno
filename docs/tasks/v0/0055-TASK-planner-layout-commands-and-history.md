## Описание

Слой `engine/` получает то, что нужно инструментам шага 2 и спеке 09: **команды планировки** как транзакции `PlannerStore` и **настоящий неймспейс `history`** вместо заглушки 0048. UI визуально не меняется (кнопки undo/redo — 0061); после задачи движок headless в Jest умеет: добавить контур → комната выведена → `undo` вернул пустой этаж → `redo` вернул комнату; серия `movePoint` под одним coalescing-ключом = одна запись.

Скоуп (по ADR D, границы уточняются — «Заметки»):

1. **Команды планировки** (неймспейс по ADR D — `document` или `layout`): добавить контур(ы) (результат инструмента: пара контуров граней от ленты / polyline room / rectangle), переместить точки (набор id → новые координаты), переместить сегмент по нормали, удалить точку (слияние двух смежных стен; проверка всех владельцев общего id — контур/пол/зона; правило ADR D), разрезать сегмент точкой (дроп на стену), слить точки (дроп на точку), задать длину ребра / ширину стены (симметрично ±дельта/2 / ±дельта по нормали; отказ при самопересечении или < 15 см). Валидация на границе (`Result` с ветками отказа спеки 01), квантование координат (B1), `undefined` в документ не попадает; каждая команда — одна транзакция → `normalize`/`rebuild` (0054) → одно `document:changed`.
2. **API транзакции для истории** по ADR D: пометка коммита (`commit` / `coalesce:<key>` / `skip`) — как параметр `transact` или отдельные методы; гейт «пока жест не завершён — не пишем» (кто его держит — движок по флагу от `tools` или инструмент вызывает коммит только на mouseUp — по ADR D/E); «тихо снять последнее состояние без записи в redo» для прерванных жестов (если ADR D оставил).
3. **`HistoryNamespace` реальный**: два контейнера (`floors[].layout` / `floors[].scene`) со снапшотами по ссылке на замороженные поддеревья; активная зона по ADR D; baseline при создании/`load` (не откатывается; `load` = `clear` + baseline); undo планировки = полная замена поддерева + обычный rebuild; сцена — контракт пообъектного восстановления (реализация — когда появится сцена, шаг 5); лимит 100 с явным trim (FIFO головы) на каждый push; redo-хвост сбрасывается новой правкой; `history:changed { canUndo, canRedo }` — ровно при изменении факта; `undo`/`redo` не трогают `Document.view`; выделение снимается перед применением снапшота — имя события/метода фиксирует ADR D, 0057 его не переименовывает.
4. **Dirty-флаг** (Q14, ADR D): ставят транзакции содержимого и undo/redo, не ставит `view`; форма наружу — по ADR D (`history.get()`/отдельный геттер/событие); сброс — заглушка `markSaved()` до ADR F.
5. **Тесты слоя 2** (все ветки): каждая команда — успех и каждая ветка отказа; удаление точки с общим id по всем комбинациям владельцев; ровно одна запись на коммит, coalescing по ключу, `skip` не пишет; лимит: 101-й push вытесняет самый старый, baseline не откатывается; `undo(redo(x)) == x` и `redo(undo(x)) == x` property-тестом (`fast-check`); `history:changed` только при изменении; `view` не меняется на undo; dirty-флаг по всем веткам; `dispose` снимает подписчиков.

Не в задаче: инструменты и ввод (0057), отрисовка (0056), UI-кнопки (0061), сохранение (шаг 3).
