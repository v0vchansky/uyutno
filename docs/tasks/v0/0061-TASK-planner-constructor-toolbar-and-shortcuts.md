## Описание

Минимальный UI-скин шага 2, чтобы пользователь мог пользоваться всем, что сделано в 0055–0060, без dev-ручки:

- **Панель инструментов** конструктора: «Стены», «Прямоугольная комната», «Комната по точкам» (активный инструмент подсвечен из `tools.get().kind`), кнопки **undo/redo** — зовут `tools.key({ kind: 'undo' | 'redo' })` (тот же маршрут, что клавиши, ADR 0019: в рисовании — локальный стек, в `editing` — история); disabled: в `editing` — по `history.get()` (`history:changed`), в `making-*` — по локальным стекам из `tools.get()`, тумблеры снапа `pointsSnap` / `pointsAlign` / `orthoAlign` / `bisectorAlign` (дефолты on/on/off/on), переключатель вида **конструктор ↔ 2D-план** (`view.setActive`; клик по уже активной кнопке вида — сброс камеры этого вида к дефолту, спека 08 «Смена вида» → `view.resetCamera`; в шаге 2 2D-план в Three — пустая сцена, это ожидаемо и записано в эпике).
- **Горячие клавиши здесь не вешаются**: единственный владелец клавиатуры — DOM-ввод вьювера (0056) с keymap из ADR E; панель только показывает подсказки шорткатов в тултипах кнопок (Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z, ⌘ на macOS; Esc).
- **Решения автора по дизайн-брифу (2026-08-19), входящие в скоуп:**
  - **Переключатель вида — в рейле/панели, не в шапке** (решение 8): вариант «в шапке» закрыт, монтировать сюда.
  - **Инструменты — списком «иконка + название»** (решение 6); иконки — свои SVG в метрике Lucide (24×24, та же толщина, `currentColor`), не второй icon-набор.
  - **Тумблеры снапа — иконки плюс тултип бытовой формулировкой** (решение 9); тултип `pointsSnap` обязан сказать, что выключение **сжимает радиус притяжения до 2 см**, а не отключает притяжение (спека 01 «Снап»), иначе тумблер читается как сломанный.
  - **Группа контролов холста** (решение 7) — одна полоска внизу справа поверх холста; по брифу в неё входят линейка, зум «− % +», «в центр», переключатель единиц и полноэкранный режим. **В шаге 2 наполняются зум, «в центр» и единицы; место под линейку и полноэкранный режим закладывается пустым** (линейка — шаг 8). Зум наполняется публичным шагом шкалы, который выводит наружу 0056; «в центр» — `fitToContent()` проекции.
  - **Переключатель единиц `см / м / мм`** (решение 15) — здесь, а не в отложенных «Настройках проекта»; пишет `document.setSettings({ units })`. **Имперской системы нет** (решение 18): в `UNITS` её больше не существует.
  - **Контекстная подсказка горячих клавиш** (решение 3) — отдельный компонент оболочки, узкая полоса по нижнему краю холста, источник — `tools:changed { state: ToolState }`; монтируется здесь, 0060 её не дублирует. Состояния автомата: `editing` (в т.ч. «подсказки нет»), `making-walls`, `making-rect`, `making-room`, `dragging-point`, `dragging-wall`. **Два случая автомат не различает — «фокус в поле длины» (ключевой, ради которого компонент и вводится: «Tab — другое поле», «Enter — поставить точку») и «выделено ребро/стена»: их источник — оверлей инпутов 0060.** Значит компонент принимает подсказку из двух источников, а не только из `tools:changed`; конкретный механизм (второе событие шины vs проп от оверлея) решается вместе с 0060 при реализации — состояние инпутов там ещё открыто («`ToolState` или локально в `ui` — по ADR E»). Не больше трёх пар «действие → клавиша» одновременно, переполнение — обрезка по приоритету, не перенос строки. Это снимает парковку build-order «Контекстная подсказка горячих клавиш».
  - **Место под панель статистики** (решение 11) — угол холста зарезервировать в раскладке, содержимое не наполнять.
  - **Переключатели видимости подписей** «Размеры» / «Имя комнаты» / «Площадь» (спека 07, handoff «Панель инструментов»; все три включены по умолчанию) — **добавлены в скоуп 2026-08-20**. Изначально их не делали: в документе под них нет ни поля, ни команды (`DocumentSettings` = `{ units, wallHeight }`). Хранилище появилось у параллельной 0060 — общий контекст скина `ui/PlannerOverlayContext.tsx`, который и читает оверлей подписей. Флаги живут в UI и **с проектом не сохраняются**: персистентность ждёт своего шага (спека 07 «Персистентность»), поля в документе и команды в фасаде для них по-прежнему нет.
- **Раскладка** в `<Planner />` по ADR E (панели как `children` рядом с канвасами или оверлеи в контейнере) и монтирование на `/project/:id` без изменений `ProjectPage` сверх раскладки; SSR — панели рендерятся только после подъёма движка (0048: дети — внутри контекста).
- Все действия — только через фасад (ADR 0015 A2); React состояние документа не хранит.

Тесты: jsdom — кнопки зовут команды фасада, disabled по `history.get()`, активный инструмент по `tools.get()`, повторный клик по активному виду → `resetCamera`; Playwright: e2e-смоук шага 2 **через UI** (кнопка «Прямоугольная комната» → два клика → комната → Ctrl+Z → Ctrl+Y) и визуальная приёмка на 1440 по макету (планер desktop-only; 768 / 390 — только что панель не ломает вёрстку страницы).

Не в задаче: панель свойств комнаты, каталог, инспектор (шаги 5/7); кнопки 3D/walk (шаги 4/9).

### Решения реализации, которые стоит знать

- **Tailwind не видел пакет.** Автодетект источников стартует от cwd сборки (`apps/platform`) и `packages/` не сканирует — проверено, до правки классы скина в бандл не попадали вовсе. Добавлена одна строка `@source '../../../../packages/planner/src/ui'` в `global.css`; ниже `ui/` не спускаемся, чтобы строковые литералы геометрии не давали мусорных утилит.
- **`lucide-react` добавлен в зависимости пакета** — один icon-набор на продукт (гайдлайн). Свои SVG рисуются только для того, чего в наборе нет.
- **HeroUI v3 в пакете не используется.** `@heroui/react` объявляет в `exports` только ESM-условие, поэтому CJS-резолвер Jest (ADR 0014) его не резолвит — ни один jsdom-тест скина не поднялся бы. Тултипов как готового компонента в проекте и так нет (бриф, разд. 3: «их нужно спроектировать»), меню и поповеры на платформе тоже написаны вручную. `PanelTooltip` — свой, по геометрии handoff'а.
- **Рейл — оверлей-колонка внутри контейнера `<Planner />`, а не колонка страницы**: панели обязаны быть внутри `PlannerContext` (ADR 0020 P6), а handoff описывает рейл колонкой строки («рейл 60px, затем холст»). Совместить не получилось — см. открытый вопрос ниже.
- **Второй источник полосы подсказок — общий контекст скина `ui/PlannerOverlayContext.tsx`** (заведён параллельной 0060): `usePlannerLengthFocus()` даёт «фокус в поле длины» и «правка длины ребра». Собственный канал переопределений был заведён и удалён как мёртвый — 0060 пользуется штатным.
- **Тумблеры подписей** («Размеры», «Имя комнаты», «Площадь») сделаны — хранилище дал тот же контекст скина. Флаги живут в UI и с проектом **не сохраняются**: полей в `DocumentSettings` и команды в фасаде нет.

### Стык 0060/0061 закрыт (2026-08-20)

Общий прогон 0060 + 0061 и открытый вопрос 0 выше закрыты одной правкой — **безопасной областью кадра у камеры конструктора**. Раскладка не менялась: панели остаются оверлеями поверх холста (решение 13), холст ширину не теряет.

- `Canvas2dProjection` получил `setViewportInsets({ left, right, top, bottom })` и `getViewportInsets()`; `camera.ts` — `ViewportInsets`, `NO_INSETS`, `safeFrameOf()` и `centeredCamera()`. `fitCamera()` считает и масштаб, и центр по видимой части (поля `FIT_PADDING_RATIO` — тоже от неё); `resetCamera()` кладёт начало координат в центр видимой части; шаг зума кнопками держит её центр, а не центр кадра. Пересчёт экран ↔ план от insets не зависит — канвас полноразмерный, поэтому ни ввод указателя, ни DOM-оверлей 0060 не тронуты.
- **Числа приходят снаружи, проекция их не знает**: их сообщает скин из `useEffect` (`CONSTRUCTOR_SKIN_INSETS` = рейл 60 + 12 + панель 224 + 12 = 308 слева и 12 + сводка 36 + 8 + контролы 36 = 92 снизу; на чужом виде — `RAIL_ONLY_INSETS`, один рейл 60; при размонтировании — нули). Каждый размер объявлен рядом со своим компонентом (`VIEW_RAIL_WIDTH`, `TOOL_PANEL_WIDTH`, `CANVAS_CONTROLS_HEIGHT`, `STATS_SLOT_HEIGHT`, `KEY_HINTS_HEIGHT`) — из головы не взято ни одного.
- **Правой полосы нет**: колонка со сводкой и контролами целиком лежит внутри нижней. **Верхней тоже нет** — шапки редактора в этой поставке не существует; появится (P1.1) — добавится сюда одной строкой.
- **Смена insets камеру не двигает** — это факт раскладки, а не жест пользователя: иначе монтирование панели или уход на чужой вид уводили бы план из-под курсора. Следствие: сразу после загрузки начало координат стоит в центре **кадра** (автофита при открытии проекта нет вовсе), а в центр видимой части приходит после первого «в центр» или сброса камеры.
- Тесты: `camera.test.ts` — `safeFrameOf`/`centeredCamera` и `fitCamera` с ненулевыми insets (план целиком в видимой части, поля от неё, вырожденные insets); `Canvas2dProjection.test.ts` — insets приходят снаружи и по умолчанию нулевые, санитайз мусора, снимок-копия; `ConstructorSkin.test.tsx` — скин сообщает проекции свои полосы. E2E: оба спека берут свободную область у скина через `getViewportInsets()`, плюс новый сценарий «в центр» в `planner-toolbar.spec.ts` (проверен на отказ: без insets левый край плана садится на 215 px при полосе 308).
- **Осталось автору**: ADR 0020 P3 про insets ещё не знает — раздел про камеру конструктора стоит дополнить отдельным коммитом «ADR ← код».
