## Описание

`rebuild(snapshot)` начинает отдавать всё, что 2b выводит из хранимого. Здесь же принимается и записывается **решение (2) эпика** — точная форма производного для плинтусов и потолков.

Скоуп:

1. **Полы и зоны** в `DerivedFloor`: треугольники и обводы полов (с дырками), треугольники зон, привязка пола к комнате. Формы — по образцу `DerivedRoom` (`Triangle = [Id, Id, Id]`, id точек `layout`, без стабильных id производного).
2. **Вертикальные грани вырезов**: на каждую запись `cuts[]` — грань с высотами «от» и «до». Высота = max высот соседних зон / высота стен комнаты (ADR 0017 C9). Материал — ADR J (шаг 7), здесь только геометрия и высоты.
3. **Производные высоты граней**: стена, попавшая под зону, укорачивается до её высоты (спека 02 «Что видит пользователь»); стены, целиком лежащие внутри зоны, — только укорачиваются. Форма — высота на грань, чтобы шаг 4 строил меши «как будто зоны уже есть» (build-order, «Осознанные переносы»).
4. **Потолки**: форма 1-в-1 повторяет форму пола, включая дырки; у каждого multi-material пола — свой кусок потолка; высота — с комнаты (`Room.ceilingHeight`), не с пола; флаг «скрыть потолок» — на полу, не на комнате (спека 02 «Видимость потолка»; хранение флага — модель, см. решение (2)). Камерная авто-логика скрытия — проекция (шаг 4), не производное; крышка зоны ей не подчиняется.
5. **Плинтусы**: «бортик вдоль всех стен комнаты на уровне пола», нижний и верхний; 16 профилей — встроенные константы редактора (нормализованные полилинии + дефолтные глубина/высота, у верхних — отступ до потолка), а не каталожные ассеты (решение 2026-08-17). Форма производного обязана пережить приход разрывов под проёмами (шаг 6) и выбор профиля из панели (шаг 7) без смены формы. Стены, совпадающие с ребром зоны, теряют верхний плинтус (спека 02).
6. **Решение (2)** — что именно отдаёт `DerivedFloor` для плинтусов и потолков (набор полей, единица адресации, кто владеет высотой и профилем, что из этого хранится, а что выводится) — обосновать по спеке 02 и реверсу конкурента, записать в «Заметки» задачи и строкой в ADR 0017 «Что важно знать»; при необходимости — правка ADR 0016 по месту (если решение требует нового хранимого поля, например флага видимости потолка на `Cover`).

Не в задаче: меши, UV, материалы, свет (шаг 4/7); разрывы плинтуса под проёмами (шаг 6); отрисовка зон (шаг 4).

## Заметки

**Реализация 2026-08-20.** `document/geometry/skirting/plinthQuad.ts` (осевой квад свипа + константы), `engine/derivedCovers.ts` (полы и потолки), `engine/derivedAreas.ts` (крышки зон и вертикальные грани вырезов), `engine/derivedFaces.ts` (высоты граней и плинтусы), `engine/derivedRegions.ts` (раздача треугольников по областям) + тесты; сборка — в `rebuild.ts`.

**Решение (2) эпика — форма производного.** `DerivedFloor` шага 2b:

```ts
covers:    { coverId, roomId, outline, holes, triangles, area }[]
ceilings:  { coverId, height, hidden }[]        // ровно один на пол, в том же порядке
areas:     { areaId, roomId, outline, triangles, height }[]
cuts:      { cutId, a, b, low, height }[]
faces:     { roomId, contourId, a, b, top, underArea }[]
skirtings: { roomId, contourId, a, b, kind, points: [B, C, Bx, Cx], gaps }[]
```

Обоснования:

- **Потолок не дублирует геометрию пола, а ссылается на него** `coverId`: спека 02 — «форма 1-в-1 повторяет форму пола, включая дырки», значит второй копии треугольников не нужно, и рассинхрона формы быть не может по построению.
- **Высота потолка — с комнаты** (`Room.ceilingHeight`: «несколько multi-material полов внутри одной комнаты не могут иметь разные высоты потолка»), **флаг видимости — с пола** (`Cover.ceilingHidden`: спека 02 хранит его на полу и наследует по перекрытию площади независимо от атрибутов комнаты). У референса оба поля лежат на полу (`plannercore.js:61804`) — расхождение осознанное, продиктовано нашей моделью. Камерная авто-логика скрытия — проекция (шаг 4), не производное; крышка зоны ей не подчиняется.
- **`low`/`height` выреза** — дословно по референсу (`plannercore.js:54009–54018`): две соседние зоны → `height = max`, `low = min` их высот; одна → `low` от зоны, `height` от высоты стен. У нас «высота стен» — `Room.ceilingHeight` комнаты, содержащей вырез (спека 02: высота комнаты влияет и на потолок, и на верхнюю границу стен), фолбэк `settings.wallHeight`; у референса там глобальный `cap.wallsHeight` — расхождение осознанное.
- **`faces` разводит два случая, которые спека 02 различает явно** (и ровно так делает референс, `plannercore.js:61833–61864`): грань, **совпавшая** с ребром зоны, получает `top = area.height` и `underArea = true` (верхнего плинтуса нет); грань **целиком внутри** зоны получает `top = area.height`, но `underArea = false` — молдинг сохраняется.
- **Плинтус — осевой квад свипа** `[B, C, Bx, Cx]` (порядок аргументов `setPoints` референса), константы `PLINTH_OFFSET = 1` и `PLINTH_MAX_MITER = 2` — `d` и `maxDist` из `createPlinths` (`plannercore.js:55411–55474`). Митра — пересечение **прямых** (не отрезков: у тупого угла точка митры лежит за концами обоих смещённых отрезков); нет пересечения или вынос дальше порога → плоский торец. Нижний плинтус всегда, верхний — только при `underArea = false`.
- **`gaps` заведён пустым** — разрывы под проёмами приходят на шаге 6 и не должны менять форму производного.
- **Банк из 16 профилей плинтуса на 2b не заводится** — см. эпик 0066, «Решения автора (2026-08-20)», п. 9 — закрыт задачей [0074](0074-TASK-plinth-profiles-reverse.md). Производное отдаёт осевой квад и `kind`; профиль и его `elevation` приходят на шаге 4/7. Значения на глаз не подбирались.

**Golden.** Набор фикстур расширен до 19; в существующих `layout` и прежние `derived.walls/rooms/axes` остались байт в байт, добавились только новые поля производного.
