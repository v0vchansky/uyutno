## Описание

Отдельный пункт DoD шага 2b (build-order, строка «2b»): **golden-фикстура с уже существующей зоной + тесты, зовущие команды напрямую, без интерфейса** — иначе до шага 7 стадии зон никто не проверит и баги всплывут поздно.

Скоуп:

1. **Golden-фикстуры планов** `document/geometry/fixtures/plan-*.json` в существующем формате (`{ name, input, expected: { layout, derived, warnings } }`, раннер `engine/rebuild.golden.test.ts`, `UPDATE_GOLDEN=1`): комната с авто-полом; комната с ручным полом меньше комнаты (авто-пол занимает остаток); ручной пол с дыркой-вычитанием; комната в комнате (пол внешней получает вырез); зона внутри комнаты (крышка, вертикальные грани, укороченные стены); зона, касающаяся стены одной стороной (это ребро — не cut); две касающиеся зоны с общим ребром (одна запись `cuts[]`); зона, потерявшая опору после сдвига стены (исчезает вместе с cuts); пол, разрезанный новой перегородкой надвое; осиротевшая дырка удаляется.
2. **Property-тесты** (`fast-check`, фиксированный seed, рядом со стадиями): `normalize(normalize(x)) == normalize(x)` на документах с полами и зонами; нет NaN/Infinity в производном; полы — валидные полигоны с ориентацией по контракту, дырки — по часовой; каждая комната покрыта полом без нахлёстов авто-полов; каждая запись `cuts[]` принадлежит хотя бы одной живой зоне; высоты граней и вырезов конечны и упорядочены (`low <= height`).
3. **Тесты команд** (слой 2, headless, без UI): сценарии спеки 02 через `manager.document.*` — нарисовать комнату → авто-пол появился; добавить ручной пол → авто-пол ужался; добавить зону → cuts и укороченные стены; подвинуть стену → зона исчезла; undo → всё вернулось (снимок берётся после `normalize`, значит содержит авто-полы).
4. **Обновление существующих фикстур**: приход авто-полов меняет `expected` всех планов с комнатами — дифф читается глазами и объясняется в «Заметках» (это ровно тот случай, когда `UPDATE_GOLDEN` допустим).

## Заметки

**Реализация 2026-08-20.** Набор golden-фикстур доведён до 23; восемь из них — 2b:

| фикстура                         | какое правило держит                                                                   |
| -------------------------------- | -------------------------------------------------------------------------------------- |
| `plan-area-in-room`              | зона внутри комнаты: крышка, интерьерные рёбра → записи `cuts[]`, укороченные грани    |
| `plan-area-touching-wall`        | ребро зоны по стене — `wall`, записи `cuts[]` на нём нет, грань теряет верхний плинтус |

| `plan-two-areas-share-edge`      | общее ребро двух касающихся зон — **одна** запись `cuts[]`                             |

**Сквозные сценарные тесты** — `engine/coversAreas.scenario.test.ts`: комната → авто-пол; ручной пол меняет состав `covers`; зона → `cuts` и укороченные грани (`faces[].top`, `underArea`); сдвиг стены → зона исчезает вместе с `cuts`; `undo`/`redo` возвращают всё (снимок берётся после `normalize`, поэтому содержит авто-полы). Всё через `manager.document.*`, без интерфейса — ровно то, ради чего в 2b заведены команды ядра.
