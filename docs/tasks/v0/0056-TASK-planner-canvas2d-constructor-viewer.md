## Описание

Второй вьювер планера — `projection/canvas2d/`: отдельный `<canvas>` с 2D-контекстом в `<Planner />`, активный при `view.activeView === 'constructor'` (новый проект открывается именно в нём — ADR 0016 B7). Читает документ, `DerivedState` (0054) и `tools.get()` (0057), в документ не пишет; рисует чертёжный вид: стены-тела (плоские серые), контуры/грани, комнаты (заливка/штриховка), кружки-хендлы углов, размеры сегментов, **и всё из `ToolState`**: гайды снапа (зелёный пунктир к источнику, параллельный пунктир второй грани, крест курсора — спека 01 «Визуальные подсказки»), live-превью ленты/прямоугольника, hover/выделение точки/стены/комнаты; **владеет DOM-вводом канваса**: pointer events (+ `pointercancel`, `blur` окна) и `keydown` → пересчёт экран → план `viewToPlan` → команды `tools` (0057), с guard'ом «фокус в DOM-инпуте — не перехватывать» — единственный владелец слушателей, панель 0061 клавиши не вешает; свой дискретный зум и пан по ADR E; render-on-demand на общем `RenderLoop` (0049 — тогда он переезжает из `projection/three/` в `projection/`) или своём — по ADR E; DPR/resize/dispose как у Three-проекции; гвард слоя 3.

Скоуп (по ADR E, границы уточняются — «Заметки»):

1. `projection/canvas2d/Canvas2dProjection` (имя — по ADR E): подписки `on('document:changed')`, `on('view:changed')`, `on('tools:changed')` (или чтение `tools.get()` по `invalidate()` — по ADR E), `invalidate()`; `viewToPlan`/`planToView` — единственное место пересчёта экран ↔ план (см, ось `y` плана вверх/вниз на экране — зафиксировать); зум — дискретная шкала и пан (колесо, ПКМ / Space+ЛКМ — по спеке 08 и ADR E), где хранятся (`Document.view` или локально) — по ADR E; `ResizeObserver` на родителя, DPR как в 0049; `dispose()`; `getStats()` для гварда (счётчик кадров).
2. Отрисовка из `DerivedState`/документа и `ToolState`: стены-тела, грани, комнаты (полигоны с дырками), хендлы углов, размеры сегментов (подписи на канвасе или DOM-оверлей — по ADR E), гайды/крест/превью, hover/выделение; при `hidden` — пропуск. Стили (цвета, толщины, пунктир `[2,4]`, шрифты) — по макету, константы в одном месте.
   2a. DOM-ввод канваса → `tools` (pointer, клавиатура, guard инпутов) — по ADR E; keymap как чистая функция (Esc, Ctrl+Z/Y/Shift+Z, ⌘, Delete если решено, стрелки-нудж если решено).
3. `createPlanner`/`<Planner />`: второй канвас, переключение видимости/активности по `view.activeView` (Three-проекция при активном конструкторе — по ADR E), порядок dispose; `onReady` отдаёт обе проекции.
4. Тесты: Jest — `viewToPlan`/`planToView` (round-trip, DPR, зум-шкала — обе стороны границ шкалы), keymap и guard инпутов, функции подготовки примитивов рисования (чистые, без `CanvasRenderingContext2D`), `RenderLoop`-интеграция с фейковым планировщиком; jsdom — pointer/keydown на канвасе доходят до `tools` в координатах плана; Playwright-гвард (расширение `planner-render-guard.spec.ts`): в покое кадров нет, resize/переключение вида → конечное число кадров, unmount — оба канваса сняты, утечек нет; e2e-смоук **мышью**: рисование контура «Стены» через реальные клики (инструмент включается dev-ручкой до 0061); визуальная приёмка через Playwright MCP на 1440 (планер desktop-only; 768 / 390 — только что вёрстка страницы не ломается) с фикстурой-планом через dev-ручку.

Не в задаче: панель инструментов (0061); live-инпуты (0060); отрисовка в Three (шаг 4); сам автомат/снап (0057/0062 — здесь только их отрисовка и DOM-привязка).

## Заметки

- Скоуп заведён до принятия ADR E (0052); после принятия — сверить, где живут зум/пан, свой или общий `RenderLoop`, судьбу Three-канваса при активном конструкторе, канвас vs DOM для подписей размеров, кто владеет DOM-слушателями — и поправить этот файл. Задача зависит от 0057 намеренно: вьювер — единственная design-gated вершина графа, движок (0053–0055, 0057–0059, 0062) от макета не зависит и проверяется headless.
- **`Нужен дизайн: да` без ссылки — в работу не берётся.** В спеке 08 конструктор описан качественно («плоские серые стены, штриховка полов, приглушённая мебель, кружки-хендлы, размеры на всех сегментах»), чисел (цвета, толщины линий, размер хендла, шрифт размеров, фон/сетка) нет. Макет должен покрывать и гайды снапа/крест/превью ленты, hover и выделение точки/стены/комнаты, хендлы, подписи размеров (это всё рисует этот вьювер). Нужен либо макет/handoff чертёжного вида, либо явное решение автора «делаем по guidelines / временно как roomtodo» — тогда строку `Нужен дизайн` переопределить с причиной в скобках.
- **Уточнено по ADR 0020/0019 (2026-08-19):** `projection/canvas2d/Canvas2dProjection(manager, canvas, { frameBudget, logger })`; **камера конструктора — локальное состояние проекции** (`scale` px/см, база 1.0, дискретная шкала 41 шаг 0.05×…10.11×, центр 1.0×; колесо вокруг курсора; ПКМ / Space+ЛКМ — пан; стрелки — пан, если `tools.key` вернул `handled: false`; `fitToContent()`/`resetCamera()`), в `Document.view` не пишется; тип `Viewport` и `planToView/viewToPlan/viewportBounds` — `document/geometry/viewport.ts` (0062), проекция единственный писатель `tools.setViewport`; общий `RenderLoop` **переезжает** `projection/three/RenderLoop.ts` → `projection/RenderLoop.ts`; Three-проекция при активном конструкторе приостановлена (`invalidate` только помечает, один кадр при возврате), неактивный канвас — `hidden` из `<Planner />` по `usePlannerSelector`; **подписи размеров/инпуты/подписи комнат — не на канвасе, а DOM-оверлей `ui/`** (0060), канвас рисует геометрию/хендлы/гайды/крест/превью/hover/выделение с `pointOverrides`; DOM-ввод: pointer events + `setPointerCapture`, `dblclick`, `wheel`, `blur` окна → `tools.*(PointerInput)`; **клавиатура — `projection/input/keyboard.ts`** (один `keydown`/`keyup` на `window`, guard инпутов, keymap → `KeyAction`), создаётся в `createPlanner`; `createPlanner({ canvas: { three, canvas2d }, … }) → { manager, projections: { three, canvas2d }, dispose }` (dispose: canvas2d → three → manager), `PlannerContext` несёт `PlannerInstance` (`usePlannerManager` без изменений, новый `usePlannerProjections`); `getStats(): { frame }`; в Jest 2D-контекст — через DI/фабрику `getContext` или мок; гвард слоя 3 расширяется на второй канвас и «переключение вида — конечное число кадров».
