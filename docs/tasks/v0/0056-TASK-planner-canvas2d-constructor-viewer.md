## Описание

Второй вьювер планера — `projection/canvas2d/`: отдельный `<canvas>` с 2D-контекстом в `<Planner />`, активный при `view.activeView === 'constructor'` (новый проект открывается именно в нём — ADR 0016 B7). Читает документ, `DerivedState` (0054) и `tools.get()` (0057), в документ не пишет; рисует чертёжный вид: стены-тела (плоские серые), контуры/грани, комнаты (заливка/штриховка), кружки-хендлы углов, размеры сегментов, **и всё из `ToolState`**: гайды снапа (**терракотовый** пунктир к источнику — решение автора 4 от 2026-08-19, не зелёный, как было в спеке 01 по поведению конкурента; параллельный пунктир второй грани, крест курсора — спека 01 «Визуальные подсказки», см. п. 2b), live-превью ленты/прямоугольника, hover/выделение точки/стены/комнаты; **владеет DOM-вводом канваса**: pointer events (+ `pointercancel`, `blur` окна) и `keydown` → пересчёт экран → план `viewToPlan` → команды `tools` (0057), с guard'ом «фокус в DOM-инпуте — не перехватывать» — единственный владелец слушателей, панель 0061 клавиши не вешает; свой дискретный зум и пан по ADR E; render-on-demand на общем `RenderLoop` (0049 — тогда он переезжает из `projection/three/` в `projection/`) или своём — по ADR E; DPR/resize/dispose как у Three-проекции; гвард слоя 3.

Скоуп (по ADR E, границы уточняются — «Заметки»):

1. `projection/canvas2d/Canvas2dProjection` (имя — по ADR E): подписки `on('document:changed')`, `on('view:changed')`, `on('tools:changed')` (или чтение `tools.get()` по `invalidate()` — по ADR E), `invalidate()`; `viewToPlan`/`planToView` — единственное место пересчёта экран ↔ план (см, ось `y` плана вверх/вниз на экране — зафиксировать); зум — дискретная шкала и пан (колесо, ПКМ / Space+ЛКМ — по спеке 08 и ADR E), где хранятся (`Document.view` или локально) — по ADR E; `ResizeObserver` на родителя, DPR как в 0049; `dispose()`; `getStats()` для гварда (счётчик кадров).
2. Отрисовка из `DerivedState`/документа и `ToolState`: стены-тела, грани, комнаты (полигоны с дырками), хендлы углов, размеры сегментов (подписи на канвасе или DOM-оверлей — по ADR E), гайды/крест/превью, hover/выделение; при `hidden` — пропуск. Стили (цвета, толщины, пунктир `[2,4]`, шрифты) — по макету, константы в одном месте.
   2a. DOM-ввод канваса → `tools` (pointer, клавиатура, guard инпутов) — по ADR E; keymap как чистая функция (Esc, Ctrl+Z/Y/Shift+Z, ⌘, Delete если решено, стрелки-нудж если решено).
   2b. **Решения автора по дизайн-брифу (2026-08-19), обязательные для этой задачи:** **сетки на холсте конструктора нет** (решение 1) — слоя сетки не заводить вовсе, на пустом холсте канвас рисует только фон (строка первого шага — DOM, задача 0061); **гайды снапа рисуются терракотой, не зелёным** (решение 4), все семь веток одним стилем, различие только в количестве гайдов, а гайд и выделение разводятся формой и весом (тонкий пунктир против сплошной с ручками), не цветом; **у хендла точки два дополнительных состояния-цели** — «замкнуть контур» (курсор у первой точки) и «завершить открытую стену» (курсор у последней), значит `ToolState` при рисовании обязан различать двух целевых кандидатов, а не просто «рядом с точкой» (решение 2); **шаг зума выводится наружу из проекции** (решение 7) — публичный геттер текущего шага дискретной шкалы плюс уведомление о его изменении, чтобы контрол «− % +» в группе контролов холста (0061) было чем наполнять; сейчас камера конструктора локальна и наружу не видна.
3. `createPlanner`/`<Planner />`: второй канвас, переключение видимости/активности по `view.activeView` (Three-проекция при активном конструкторе — по ADR E), порядок dispose; `onReady` отдаёт обе проекции.
4. Тесты: Jest — `viewToPlan`/`planToView` (round-trip, DPR, зум-шкала — обе стороны границ шкалы), keymap и guard инпутов, функции подготовки примитивов рисования (чистые, без `CanvasRenderingContext2D`), `RenderLoop`-интеграция с фейковым планировщиком; jsdom — pointer/keydown на канвасе доходят до `tools` в координатах плана; Playwright-гвард (расширение `planner-render-guard.spec.ts`): в покое кадров нет, resize/переключение вида → конечное число кадров, unmount — оба канваса сняты, утечек нет; e2e-смоук **мышью**: рисование контура «Стены» через реальные клики (инструмент включается dev-ручкой до 0061); визуальная приёмка через Playwright MCP на 1440 (планер desktop-only; 768 / 390 — только что вёрстка страницы не ломается) с фикстурой-планом через dev-ручку.

Не в задаче: панель инструментов (0061); live-инпуты (0060); отрисовка в Three (шаг 4); сам автомат/снап (0057/0062 — здесь только их отрисовка и DOM-привязка).

## Заметки

- **Два целевых кандидата в `ToolState` (решение 2) — правки автомата не потребовалось.** Различие «курсор у первой точки» / «курсор у последней» выводится вьювером из уже существующих полей тем же чистым предикатом, которым его считает сам автомат в момент постановки точки: `contourClosure(cursor, points, { lastRadius: DEFAULT_WALL_WIDTH, distance: euclDist })` для «Стен» и `contourClosure(cursor, points, { lastRadius: CLOSE_EPS, distance: manhDist })` от `POLYLINE_ROOM_MIN_POINTS` вершин для «Комнаты по точкам» (`drawFrame.ts`, `closureTarget`). Те же радиусы и та же метрика — иначе подсветка обещала бы не то, что произойдёт по клику. `engine/tools` в этой задаче **не менялся**.
- **Итог по реализации (2026-08-20).** Переезд `projection/three/RenderLoop.ts` → `projection/RenderLoop.ts` (ADR 0020 P5) сделан в этой задаче, но уехал в чужой коммит `d845029` параллельной сессии — в диффе этой задачи его нет. Файлы: `projection/ProjectionGate.ts` — взаимная приостановка проекций по активному виду (ADR 0020 P5), подключён и к Three; `projection/canvas2d/` — `Canvas2dProjection.ts` (жизненный цикл, DOM-ввод указателя, локальная камера, `getStats`/`getViewport`/`getZoom`/`onZoomChanged`/`fitToContent`/`resetCamera`), `camera.ts` (шкала зума, зум вокруг курсора, пан, fit), `drawFrame.ts` (кадр), `draftStyle.ts` (все чертёжные константы и чтение токенов `--draft-*`), `cursorFor.ts`; `projection/input/` — `keymap.ts` (чистая раскладка) и `keyboard.ts` (единственный владелец клавиатуры); `createPlanner.ts` — два канваса и клавиатура; `ui/PlannerContext.ts` — контекст несёт `PlannerInstance`, добавлен `usePlannerProjections`; `ui/Planner/Planner.tsx` — контейнер с двумя канвасами, `role="img"` + `aria-label` (решение 22) из `ui/Planner/planDescription.ts`; восемь токенов `--draft-*` заведены в `apps/platform/src/client/theme-uyutno.css` по значениям эталона.
- **Что намеренно не рисуется** (это не пробелы реализации): сетки нет вовсе — слоя не заведено (решение 1); подписи длин, имя комнаты и площадь — DOM-оверлей задачи 0060; строка первого шага — DOM задачи 0061; приглушённая мебель — у `SceneItem` в модели шага 2 нет 2D-габаритов, отрисовка отложена (ADR 0020 P2, шаг 5+); растровая подложка — P2 (решение 17); **оси стен (`DerivedFloor.axes`) не рисуются** — в таблице слоёв ADR 0020 P2 их нет, а `planner-editor-ui.md` прямо говорит «Ось стены пользователю не показывается и не редактируется» (расхождение с формулировкой скоупа выше закрыто в пользу handoff).
- **Расхождения с прототипом — намеренные, по приоритету источников** (раздел 9 брифа > `planner-canvas-reference.md` > прототип): (1) сцена 8 рисует тело стены во время драга с `fill-opacity: 0.5`, но строки «стена во время жеста» в нормативной таблице нет — рисуем сплошным `--draft-wall-body`; (1а) тело стены заливается правилом **nonzero**, хотя таблица говорит «even-odd (полость комнаты вычитается)»: полость вычитает сама триангуляция (`DerivedFloor.walls[].triangles`, ADR 0017 C1), картинка совпадает, а even-odd на случайном перекрытии треугольников пробил бы в стене дыру; (2) известные дефекты поставки — штрих собственных иконок 1.5 вместо гайдлайновых 2, разъехавшиеся формулировки второго и третьего тумблеров снапа, скопированные `aria-label` пяти кнопок группы контролов холста — **не воспроизведены**; всё это в скоупе 0061, здесь только зафиксировано.
- **Приёмка (2026-08-20).** Прогоны: `pnpm typecheck` — Done по обоим воркспейсам; `pnpm lint` — без замечаний; `pnpm test` — planner 94 сьюта / 1457 тестов, platform 14 / 108, все зелёные; `pnpm build` — client и server compiled successfully; `pnpm test:e2e` — 17 passed (23.0s). Визуальная приёмка Playwright MCP на 1440: новый проект открывается в конструкторе (два канваса, Three скрыта и кадров не рисует), «Стены» → контур реальными кликами → цель «замкнуть контур» на первой точке → комната с заливкой и штриховкой, `aria-label` «план: 1 комната, 12,6 м²»; наведение на угол — `grab` и хендл с ореолом, клик — выделение, драг — `grabbing` и live-геометрия без ретриангуляции, история пишется; колесо — шаг шкалы 20 → 21, точка плана под курсором осталась под курсором; в покое счётчики кадров обеих проекций стоят. На 768 и 390 вёрстка страницы не ломается: канвас занимает контейнер, буфер = CSS × DPR, горизонтальной прокрутки нет.
- **Что нашли субагенты и починили по ходу.** (1) `projection/input/keymap.ts`: общий гард «Ctrl/Cmd или Alt → не наше» стоял до ветки нуджа, из-за чего точный шаг `Shift + Ctrl/Cmd + стрелка` (ADR 0019 E4) не работал вовсе, а множитель `NUDGE_FACTOR_FINE` был мёртвым кодом; теперь Ctrl/Cmd режет только WASD и Delete/Backspace, у стрелок это часть множителя. (2) `drawFrame.ts`: штриховка комнаты отсчитывалась от края экрана и при пане стояла на месте, пока комната уезжала (эталон относит штриховку к масштабируемому вместе с планом) — фаза привязана к началу координат плана. (3) «Комната по точкам» подсвечивала последнюю вершину как «завершить открытую стену», хотя открытого исхода у неё нет (`makingRoom.finish` всегда коммитит замкнутый контур) — обе цели теперь «замкнуть контур», квадратная рамка осталась только у «Стен». (4) Цель замыкания адресуется индексом вершины, а не совпадением координат. (5) Остаток бюджета кадров, начатый до ухода на чужой вид, больше не рисуется в скрытый канвас; `dispose()` снимает захват указателя, если пришёл посреди пана.
- **Нужно от дизайна/автора (значения, которых нет ни в эталоне холста, ни в `planner-editor-ui.md`, ни в решениях, ни в ADR).** Не подбирались «на глаз»: там, где без числа не собирался связный кусок, взято выводимое из зафиксированных якорей значение и помечено комментарием в коде; каждый пункт — вопрос, а не решение.
  1. **Точная таблица 41 значения шкалы зума.** ADR 0020 P3 даёт только края (`0.05×`, `10.11×`), длину (41) и центр (индекс 20 = `1.0×`); промежуточные значения таблицы roomtodo в наши документы не переносились. Сейчас — две геометрические прогрессии между якорями (`camera.ts`, `CONSTRUCTOR_ZOOM_SCALES`). Влияет на ощущение шага зума и на индикатор «− % +» (0061). Замена — правка одной константы.
  2. **Шаг пана стрелками.** ADR 0020 P3: «проекция панорамирует шагом (константа в px)» — числа нет. Сейчас `KEYBOARD_PAN_STEP = 40` CSS px (`Canvas2dProjection.ts`), Shift/Ctrl умножают его тем же `factor`, что и нудж.
  3. **Толщина линии штриховки при зуме — подтвердить или отклонить.** Эталон относит «штриховку комнат» и «шаг штриховки» к масштабируемому, «толщину линий сторон и гайдов» — к фиксированному; толщина самой линии штриховки не отнесена никуда. Прототип отвечает в пользу масштабирования: штриховка задана паттерном в user space (`rect width="1"` внутри `pattern … patternUnits="userSpaceOnUse"`), то есть 1 единица плана, а не экрана. Сейчас сделан **фиксированный 1 CSS px**: при масштабировании линия была бы 0.05 px на минимуме шкалы и 10 px на максимуме, то есть на краях шкалы штриховка либо исчезала бы, либо превращалась в заливку. Нужно решение автора, чьё чтение верно.
  4. **Нижний порог видимости штриховки.** На мелких шагах шкалы шаг 8 см даёт доли пикселя — штриховка сливается в заливку и стоит тысячи `stroke` на комнату. Сейчас — инженерный порог `HATCH_MIN_STEP_PX = 2` CSS px, ниже штриховка не рисуется. Нужно правило (гасить? сливать в сплошную `--draft-room-hatch`?).
  5. **В каких состояниях рисуется крестик курсора.** Эталон даёт только его вид. Сейчас — в трёх состояниях рисования (по `cursor`) и в `dragging-point` (по live-позиции точки), как на сценах 2, 3a, 3b, 8, 13; в `dragging-wall` не рисуется — там и гайды подавлены по ADR 0019 E4.
  6. **Тянется ли параллельный пунктир второй грани через весь кадр** вместе со своим гайдом. Про гайд сказано «через весь кадр, за пределы геометрии» (и это видно на сценах 2 и 7), про его пунктирную пару — нет. Сейчас читаем буквально: через кадр тянется только сам гайд, вторая грань рисуется тем отрезком, который вернул `guidesFor`. Пара при этом выглядит рассогласованно по длине — если задумано иначе, это правка одной строки.
  7. **Курсор при наведении на комнату.** Таблица курсоров перечисляет точку и сторону. Сейчас — `default`.
  8. **`aria-label` пустого плана.** Решение 22 даёт шаблон «план: 3 комнаты, 45 м²», формулировки для пустого холста нет. Сейчас — тот же шаблон: «план: 0 комнат, 0,0 м²».
  9. **Сплошная сторона превью ленты и превью «Комнаты по точкам» нормой не описаны.** В таблице есть «превью ленты» (заливка 12% + пунктирная вторая грань), «живой сегмент к курсору» и «поставленные, не закоммиченные точки», но не сказано, чем рисуется уже поставленная часть ломаной. Сейчас — как обычная сторона контура (1.4px `--draft-contour-line`), это же видно на сцене 2; у «Комнаты по точкам» ленты нет вовсе, рисуется только сам полигон.
  10. **`hidden` из таблицы слоёв ADR 0020 P2 («`hidden` — пропуск» у комнат) не реализован**: в модели документа шага 2 такого поля у комнат нет (единственный `hidden` — `FloorScene.hidden`, это скрытые предметы обстановки). Либо строка в ADR, либо появится вместе со слоем видимости.
