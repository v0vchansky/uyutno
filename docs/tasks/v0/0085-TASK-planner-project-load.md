## Описание

Обратная сторона сохранения: `/project/:id` перестаёт открываться пустым холстом.

Сейчас `ProjectPage` монтирует `<Planner />`, и тот заводит пустой документ внутри. После этой задачи страница проходит **две фазы**, ровно те, что требует бриф оболочки и что задал ADR 0021 формой API:

1. **«Загружаем проект»** — карточка проекта: `GET /api/v1/projects/:id` (имя, даты). Лёгкий запрос, он же даёт 404 на чужой и несуществующий проект.
2. **«Подгружаем модели и материалы»** — документ: `GET /api/v1/projects/:id/document` (эндпоинт из `0080`), `parse` из `@uyutno/planner/format`, `document.load()` в движок.

Скоуп:

1. **Реализация `storage.load` в платформе** — обе фазы, через HTTP-клиент из `core`, по конвенциям `client/project/api/`.
2. **Прогресс-индикатор поверх canvas** с двумя фазами; **редактор становится интерактивным только после того, как сцена полностью восстановлена** (спека 10). Ввод до этого момента не принимается — не «выглядит неактивным», а действительно не доходит до автомата инструментов.
3. **Восстановление вида и камер.** Из документа поднимаются `activeView` и камеры `plan`/`orbit`/`walk`; редактор открывается **в том виде, в каком проект закрыли**, а не всегда в конструкторе.
4. **Камера конструктора — исключение.** В документ она не пишется (ADR 0020), поэтому при открытии выполняется **авто-fit «в центр»** по содержимому плана: `fitToContent()` уже есть (задачи `0056`/`0060`) и считает по видимой части холста с учётом полос под панелями скина (`setViewportInsets`). **Пустой документ** получает не fit, а дефолтный зум — вписывать нечего.
5. **Пустая колонка документа.** Сервер отдаёт `{ document: null }` (`0080`) — это новый проект, который ни разу не сохраняли. Ошибкой не считается: поднимается пустой документ, редактор открывается в конструкторе.
6. **Ошибочные ветки** (спека 10, «Ошибочные сценарии»):
   - **Битый проект** (нечитаемый JSON или отсутствие обязательных секций формата) → модалка «Не удалось открыть проект» с кнопками «Попробовать ещё раз» и «Вернуться в галерею». **Редактор не остаётся в наполовину загруженном состоянии.**
   - **Версия формата новее поддерживаемой** → отдельное сообщение: проект не открывается, предлагается **перезагрузить страницу**. Формулировка «обновите редактор» из спеки 10 буквально неприменима — у нас веб, обновлять пользователю нечего, у него просто устаревший бандл во вкладке (решение ADR 0021).
   - **Битые ссылки между элементами** (стена → отсутствующая точка, комната/пол → отсутствующая точка или стена контура) битым проектом **не считаются**: элемент молча пропускается, остальной план загружается. Ветка обеспечена парсером (`0079`) — здесь проверяется, что она доходит до экрана без модалки.
   - **404** (проект чужой, не существует или удалён) → страница 404, а не модалка редактора.
7. **Стык с демо.** После входа из демо модалка B4 держит «Сохраняем ваш проект…» до перехода на `/project/:newId`, дальше отрабатывает этот же прогресс-индикатор — отдельного экрана на переезд нет (решение брифа 2026-08-20). Сам переход делает `0065`; здесь важно, чтобы индикатор был переиспользуем и стык читался как одно движение.

Не в задаче: индикатор сохранения и модалки ошибок сохранения (`0084`); подгрузка моделей и материалов каталога (каталога ещё нет — шаг 5, вторая фаза прогресса пока проходит мгновенно); превью (шаг 9); плашка «N объектов не удалось загрузить» из спеки 10 — она про каталожные объекты и заводится вместе с каталогом.

## Приёмка

- [ ] Открытие `/project/:id` проходит две фазы: карточка проекта → документ; тексты фаз совпадают с принятым макетом.
- [ ] Сохранённый план восстанавливается: нарисовать → Save → F5 → на экране тот же документ.
- [ ] Восстанавливаются активный вид и камеры `plan`/`orbit`/`walk`; проект открывается в том виде, в каком его закрыли, а не всегда в конструкторе.
- [ ] Камера конструктора не берётся из документа: непустой план получает авто-fit «в центр» с учётом полос под панелями скина, пустой — дефолтный зум.
- [ ] Редактор интерактивен только после полного восстановления сцены: ввод, поданный во время загрузки, до автомата инструментов не доходит.
- [ ] `{ document: null }` (новый проект) открывается пустым холстом без единой ошибки.
- [ ] Битый документ даёт модалку «Не удалось открыть проект» с двумя кнопками; «Попробовать ещё раз» повторяет загрузку; редактор не остаётся полузагруженным.
- [ ] Версия новее поддерживаемой даёт своё сообщение с предложением **перезагрузить страницу**.
- [ ] Битые id-ссылки внутри документа модалку **не** поднимают: план грузится, дефектные элементы пропущены молча.
- [ ] Чужой/несуществующий проект даёт 404-страницу, а не модалку редактора.
- [ ] **Визуальная проверка через Playwright MCP**: обе фазы прогресса, восстановленный план, модалка битого проекта, ветка «версия новее» — на 1440 (планер desktop-only) плюс проверка, что вёрстка не ломается на 768 / 390.
- [ ] e2e-смоук: «открыть сохранённый проект → план на экране → редактор интерактивен» (слой 4 testing-strategy, критический маршрут).
- [ ] `pnpm typecheck`, `pnpm lint`, `pnpm test` зелёные.
- [ ] Prettier чист; ровно один PR.

## Заметки

- **Задача ждёт приёмки макета оболочки и в работу не берётся, пока в строке «Дизайн» нет ссылки.** Заказ — [`docs/ui/briefs/planner-editor-shell.md`](../../ui/briefs/planner-editor-shell.md): блоки **B3**/**B4** (индикатор сохранения и модалка демо — ими живёт соседняя `0084` и стык с `0065`), состояния экрана загрузки — **B6** того же брифа. Перевести задачу в `[~]` без ссылки нельзя; альтернатива — явное переопределение `Нужен дизайн: нет (согласовано, по guidelines)` в диалоге с автором спеки.
- **Вторая фаза прогресса пока формальна**: каталога моделей и материалов в v0 ещё нет (шаг 5), подгружать нечего. Фазу всё равно заводим — она заказана брифом и понадобится без переделки, когда каталог появится.
- **Undo/redo после загрузки пуст** (спека 10: стек истории не сохраняется). `document.load()` уже делает `history: 'reset'` — оба контейнера чистятся, новый baseline, dirty снимается (ADR 0018 D5). Отдельной работы не требует, но в приёмке проверить, что после открытия проекта «Отменить» неактивно.
- **Проёмы, мебель, материалы** в документ ещё не пишутся — их шаги 5–7. Порядок восстановления сцены из спеки 10 (пункты 2–5) в v0 сводится к геометрии плана; остальное вешается сюда же по мере появления.
- **Новых страниц задача не заводит** — `/project/:id` существует, мета на месте.
