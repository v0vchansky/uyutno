## Описание

Видимая часть шага 3. `0082` довёл `persistence` до полного набора состояний; здесь они становятся тем, что человек видит в шапке редактора.

Состояния — по списку «Формат поставки» брифа оболочки (B3) и спеке 10:

1. **Покой** — ничего не происходит, изменений нет.
2. **Идёт запись** — кнопка «Save» в состоянии «идёт запись» (спиннер / disabled). Единый статус и для ручного Save, и для автосейва: пока один запрос в полёте, второй ждёт (очередь из `0081`).
3. **Сохранено, HH:MM** — короткое подтверждение после ручного Save.
4. **Автосохранено, HH:MM** — ненавязчивый статус рядом с кнопкой «Save».
5. **Ошибка фонового сохранения** — **тихая иконка** предупреждения рядом с кнопкой, по hover тултип «Не удалось сохранить на сервер, HH:MM». Без модалок и тостов. Иконка снимается при первом успешном сохранении.
6. **Офлайн** — постоянный статус в шапке «нет сети, изменения не сохранены», держится, пока сети нет, снимается сам. Плюс модалка на **каждое** ручное сохранение с тем же смыслом.
7. **Ошибка ручного Save** — модалка с текстом ошибки (не тост).
8. **Частный случай «Проект удалён»** — та же модалка с кнопкой «В галерею» (проект удалили во второй вкладке, сервер ответил 404).
9. **Демо — индикатора нет вовсе**: серверного автосейва там не бывает, показывать нечего. Кнопка «Save» при этом на месте и активна — её поведение делает [0065](0065-TASK-planner-demo-save-gate-and-project-copy.md).

Ключевое требование к текстам: **обещания «изменения сохранены локально» нет ни в одном из них** — локальной копии у обычного проекта не существует, обещать нечего (решение 2026-08-21, спека 10 приведена к нему).

Скоуп по коду: компоненты живут в клиенте платформы (`client/project/components/`), состояние читается из `persistence` планера через `usePlannerSelector` / событие шины. Пакет планера собственного индикатора не заводит — шапка принадлежит платформе.

Не в задаче: механика сохранения и таймеры (`0082`); модалка «Войдите, чтобы сохранить проект» и её состояния (`0065`, макет B4); экраны загрузки проекта и модалка «Не удалось открыть проект» (`0085`); имя проекта в шапке (B2) и слот каталога (B5) — вне шага 3.

## Приёмка

- [ ] Все девять состояний из списка выше реализованы и совпадают с принятым макетом (B3), включая тексты.
- [ ] Кнопка «Save» на время записи показывает «идёт запись» и не даёт запустить второй запрос; ручной Save и автосейв дают **один** визуальный статус.
- [ ] Ошибка фонового сохранения — только иконка с тултипом; модалки не появляется ни при каких обстоятельствах.
- [ ] Ошибка ручного Save — модалка с текстом; ветка «Проект удалён» имеет кнопку «В галерею», которая ведёт на `/projects`.
- [ ] Офлайн: статус в шапке держится всё время отсутствия сети и снимается сам; ручное сохранение дополнительно поднимает модалку.
- [ ] Ни в одном тексте нет обещания «изменения сохранены локально» — проверено по всем состояниям.
- [ ] В режиме демо индикатора нет, кнопка «Save» на месте и активна.
- [ ] Тексты времени (`HH:MM`) берутся из состояния `persistence`, а не считаются в компоненте заново.
- [ ] **Визуальная проверка через Playwright MCP**: dev-сервер, `/project/:id` под сессией, проход по состояниям (покой → запись → сохранено → ошибка фонового → офлайн → ошибка ручного), на 1440 (планер desktop-only) и проверка, что вёрстка шапки не ломается на 768 / 390.
- [ ] `pnpm typecheck`, `pnpm lint`, `pnpm test` зелёные.
- [ ] Prettier чист; ровно один PR.
