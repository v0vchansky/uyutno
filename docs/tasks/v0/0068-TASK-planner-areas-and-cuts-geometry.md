## Описание

Вторая геометрическая половина 2b: чистые функции зон и вырезов в `packages/planner/src/document/geometry/areas/`. Здесь же принимается и записывается **решение (1) эпика** — кому принадлежит запись `cuts[]` на ребре, общем для двух касающихся зон, и что с ней происходит, когда одна зона исчезает.

Скоуп:

1. **Опора зоны.** Точка зоны считается опёртой, если существует точка комнаты с **той же координатой**; допуск — шаг квантования координат (0.001 см), а не 10-см снап (спека 02, решение 2026-08-17; 10-см снап «точка к углу» работает только при рисовании зоны — шаг 7). Достаточно одной неопёртой точки, чтобы зона удалялась целиком: частичной подгонки не бывает.
2. **Отбраковка зоны** — предикаты валидности: самопересечение (`contourSelfIntersected`), пересечение стен (граница зоны обязана целиком лежать внутри комнаты; касание стен допустимо, пересечение — нет), пересечение другой зоны (`compareContours`: `contact` допустим, `intersect` — нет). Две разных ситуации по спеке: при рисовании — мгновенный молчаливый отказ (команда, 0071), при авто-пересборке — удаление уже сохранённой зоны (стадия (3), 0069). Предикаты одни и те же, разная реакция.
3. **Cut-пары.** Рёбра зоны, идущие **через интерьер комнаты** (не совпадающие со стеной), — вертикальные грани; рёбра, лежащие по стене, — нет (спека 02 «Вертикальные грани зоны»). Функция различения ребра «по стене» / «через интерьер» — по граням хранимых контуров (`layoutFaces`, `segmentsOverlay`), с явным порогом. Все рёбра зоны идут в триангуляцию как `cutPairs` (fixed-рёбра), различение нужно для того, какие рёбра порождают запись `cuts[]` и вертикальную грань.
4. **Совмещение cut-пар с критерием комнаты** (открытый вопрос парковки build-order, шаг 2b): fixed-рёбра зоны делят треугольники комнаты на группы, но новых записей комнат порождать не должны. Решить здесь явно и закрепить юнитом + фикстурой в 0072; правило записать в ADR 0017 C6.
5. **Владение записью `cuts[]`** (решение (1)): запись адресуется **неупорядоченной парой id точек** (ADR 0017 C9); ребро, общее для двух касающихся зон, — одна запись; правило владельца и судьба записи при исчезновении одной из зон — обосновать по спеке 02 и реверсу конкурента, записать в «Заметки» этой задачи и строкой в ADR 0017 «Что важно знать». Чистая функция «набор зон → набор нужных записей `cuts[]`» с сохранением id уже существующих записей (материал записи переживает пересборку — спека 02: «У грани собственный материал… он сохраняется вместе с зоной и переживает пересборку»).

Не в задаче: стадии `normalize` (0069), высоты граней и производное (0070), команды и их коды ошибок (0071), фикстуры пайплайна (0072).

## Заметки

**Реализация 2026-08-20.** `document/geometry/areas/`: `areaSupport.ts` (опора по тождеству квантованной координаты), `areaEdges.ts` (`areaPairs`, `contourFaces`, `classifyAreaEdges`, `FACE_COLLINEAR_EPS`), `validateArea.ts`, `cutEdges.ts` (`interiorCutEdges`), `cutRecords.ts` (`requiredCuts`, `reconcileCuts`, `cutKey`). Правки ядра: `contours/rebuildContours.ts` — `detectRooms` (склейка не-fill групп через интерьерные cut-рёбра) и вычисление набора cut-рёбер (ленивое: без зон грани контуров не собираются — горячий путь); `contours/contoursFromGroup.ts` — параметр `ignored` (хорда снимается из графа обхода).

**Решение (1) эпика — владение записью `cuts[]`.** У записи **нет хранимого владельца, владение вычисляется**: запись адресуется неупорядоченной парой id точек, ребро двух касающихся зон даёт одну запись (вторая переиспользует — это и есть «владелец = записавшая первой» ADR 0017 C9), запись жива, пока хотя бы одна зона держит это ребро как интерьерное. При исчезновении одной из двух касающихся зон запись переживает пересборку вместе с id и материалом, если ребро осталось интерьерным у выжившей; высота грани пересчитывается — она производная. Это поведение референса (полная регенерация из рёбер зон с переносом данных по совпадению концов) в нашей модели хранимых записей. Записано в ADR 0017 «Что важно знать». Осознанное расхождение: у референса ребро без старого донора записи не порождает вовсе, а два старых cut'а на одну сторону дают дубль (нет `break`); у нас новая пара получает новую запись, дубли ключа схлопываются.

**Решение — cut-пары и критерий комнаты** (закрывает строку парковки build-order): интерьерное cut-ребро — не граница комнаты и не барьер группировки; не-fill группы, разделённые только им, склеиваются обратно, и склейка — комната, лишь когда критерий проходит **каждая** часть (иначе кусок экстерьера, отрезанный зоной, вылезшей за комнату, дал бы фантомную комнату); в обводе такие рёбра игнорируются; ребро зоны «по стене» остаётся барьером. Без зон правило тождественно прежнему `groups.filter(isRoom)` — по составу и по порядку. Записано в ADR 0017 C6.

**Прочие решения по месту:**

- `FACE_COLLINEAR_EPS = COORDINATE_QUANTUM` (0.001) — **не третий эпсилон**, а шаг квантования: точка, лежащая на грани по построению, после квантования отходит от прямой до ≈0.0007 см, то есть дальше `B_EPS`. Проверено фаззингом (50 000 диагональных граней, максимум 0.000699). Внесено в ADR 0017 C3.
- **Зона в толще свободностоящей стены отбраковывается:** вложенность зоны в тело стены безопасна, только если это тело само объемлет комнату-хозяйку; зона в толще колонны внутри комнаты — `crosses-walls`.
- **Классификация рёбер зоны — под-рёберная:** ребро режется по концам граней, поэтому интерьерный кусок частично-стенового ребра (L-образная комната) получает свою запись `cuts[]`. **Публичный контракт изменён:** длина результата больше не равна числу рёбер зоны, `AreaEdgeSet` = `{ interior: readonly CutEdge[] }`; `classifyAreaEdges` — дженерик по типу точки, id доезжают без поиска по координате.

**Критики (два субагента: ADR/конвенции и ревью тестов).** Ревью тестов гоняло мутационный прогон (40+ одиночных мутаций реализации, каждая закрывающая проверка проверена эмпирически): из первой партии 27 мутантов были убиты сразу, 13 выжили. По итогам добора **11 из 11 оставшихся содержательных мутантов убиты**, правок реализации не потребовалось: три property-теста (`requiredCuts` без дублей и идемпотентен, `reconcileCuts` ссылочно стабилен поэлементно, «зона внутри комнаты не меняет числа комнат и обвода» — property не вакуумен, мутант «DSU не склеивает» его роняет); кейс «кольцо + отдельный прямоугольник» на правило `every` (`rooms.length === 1`, `softFail === false`); порог `FACE_COLLINEAR_EPS` больше не самореферентен (сверяется с `COORDINATE_QUANTUM` и с литералом, `1e-4` явно мал); плюс порядок стадий `validateArea`, синтетические фикстуры `interiorCutEdges` (ветка `!edge.fixed`, перпендикуляр против серединного теста), `inner`-грани, разделитель в `cutKey`, сортировка участков вдоль ребра, знак/ориентация и отрицательный квадрант, NaN/±Infinity. Оставлены как поведенчески эквивалентные три мутанта-перфа (early-return при пустых `cutPairs` / `cuts.size === 0`, отсев участков нулевой длины в одиночку). Из первого раунда ADR-критики закрыты: зона в толще свободностоящей колонны, под-рёберная классификация для L-образной комнаты, четыре неточности JSDoc про референс.
