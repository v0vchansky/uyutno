## Описание

ADR 0015 (принят 2026-08-18) решил: планер — **отдельный воркспейс-пакет `packages/planner`** с npm-именем `@uyutno/planner`, без собственной сборки/`dist` — платформа потребляет исходники `.ts/.tsx` напрямую в оба webpack-бандла (клиент + SSR), Jest платформы гоняет тесты пакета, ESLint энфорсит слои внутри пакета. Сейчас директории `packages/` в репозитории нет (`ls packages` → нет), хотя `pnpm-workspace.yaml` уже содержит `packages/*`. Эта задача заводит **инфраструктуру пакета без движка**: чтобы следующие задачи шага 1 (документ, фасад, шина, проекция, монтирование в `ProjectPage`) писали код в готовый, собирающийся, тестируемый и линтуемый пакет, а не настраивали тулинг по дороге.

Ровно один PR. Кода движка в нём нет — только заглушки слоёв, чтобы граф импортов собирался и один smoke-тест проходил.

### Факты конфигов на момент постановки (проверено, на них опираться)

- Корень: `pnpm-workspace.yaml` — `packages: [apps/*, packages/*]` (**`packages/*` уже включён**, менять не надо). `package.json` корня: `typecheck` = `pnpm -r typecheck` (значит у пакета нужен свой скрипт `typecheck`, иначе он не проверяется), `lint` = `eslint .` (пакет попадёт в линт автоматически), TypeScript `^6`, ESLint `^9` flat config `eslint.config.mjs`, Prettier 3.
- `tsconfig.base.json`: `module: esnext`, `moduleResolution: bundler`, `jsx: react-jsx`, `lib: [es2022]`, `strict`, `verbatimModuleSyntax`, `isolatedModules`, `incremental` + `tsBuildInfoFile: .tsbuildinfo`. Клиентский `apps/platform/src/client/tsconfig.json`: `extends` базовый, `lib: [dom, dom.iterable, es2022]`, `types: [node, jest]`, `paths: { "@app/*": ["./*"] }`, `noEmit`, `include` — только `src/client` и `src/shared` (файлы пакета попадут в программу только через импорты).
- `apps/platform/package.json`: `type: module`; `uuidv7 ^1.2.1` уже в deps; `three`/`immer`/`mitt` — **нет** ни в платформе, ни в корне. `typecheck` = два `tsc -p` (client, server). `test` = `jest`. Актуальные версии на npm (2026-08-18): `three` 0.185.1 (`@types/three` 0.185.4 — три не шипает свои типы), `immer` 11.x, `mitt` 3.x. ADR 0003 фиксирует **r185**, не «последнюю» — ставить `three@~0.185.1` (или `^0.185.0`, но не выше 0.185).
- pnpm strict layout: в `apps/platform/node_modules` лежат только прямые зависимости платформы. Следствия: (а) зависимости пакета (`three`, `immer`, `mitt`, `@swc/helpers`, `react` для `ui/`) должны быть объявлены **в `packages/planner/package.json`**, иначе не резолвятся из его файлов; (б) `webpack-node-externals` в `webpack.server.js` определяет «внешние» модули по листингу `node_modules` **cwd платформы** — `three`/`immer`/`mitt` там не будет, и они **забандлятся в SSR-бандл** (не сломает, но заметить: SSR-бандл потяжелеет на three; `uuidv7` — внешний, т.к. есть в платформе).
- `apps/platform/webpack/webpack.client.js`: `swc-loader` для `.ts/.tsx` с `exclude: /node_modules/`, `resolve.extensions [.tsx,.ts,.js]`, `TsconfigPathsPlugin` по клиентскому tsconfig, `resolve.symlinks` — дефолт (true → воркспейс-симлинк резолвится в реальный `packages/planner/...`, `exclude` его не отсекает). **Опции SWC берутся из `apps/platform/.swcrc`** (`syntax: typescript, tsx: true`, `react.runtime: automatic`, `externalHelpers: true`); SWC ищет `.swcrc` от директории файла вверх — для файлов в `packages/planner/**` его **не найдёт** → TS-синтаксис не распарсится. Нужно решить: инлайн `options` в правиле `swc-loader` (клиент и сервер), либо `.swcrc` в `packages/planner/`, либо корневой `.swcrc`. `externalHelpers: true` требует `@swc/helpers` резолвимым из пакета (devDep пакета).
- `apps/platform/webpack/webpack.server.js`: `target: node`, `output.module: true`, `externals: [nodeExternals({ allowlist: [/^@heroui\//], importType: 'module' })]`, тот же `swc-loader` с `exclude: /node_modules/`, alias `@server`/`@app`.
- `apps/platform/jest.config.mjs`: `testEnvironment: node`, `roots: ['<rootDir>/src']`, `testMatch **/*.test.ts(x)`, `moduleNameMapper` для `@app/*`, `@server/*` и `^(\.{1,2}/.*)\.js$`, `transform` — `@swc/jest` с инлайн-опциями (парсер ts+tsx, react automatic, target es2022 — **не** читает `.swcrc`, значит для тестов пакета отдельной настройки SWC не нужно). Файлы вне `roots` не находятся.
- `eslint.config.mjs`: массив `clientModuleBoundaries` с override `apps/platform/src/client/planner/**` (+ `core/**`) и запретами `@app/planner`, `@app/planner/*` в override `auth/**`; правила react/react-hooks навешаны только на `apps/platform/src/client/**/*.{ts,tsx}`; `ignores` — `dist/build/node_modules/coverage`.
- Точка монтирования: `apps/platform/src/client/project/pages/ProjectPage/ProjectPage.tsx` — заглушка `<h1>Проект {id}</h1>` с `<title>`/`<meta>`.

### Скоуп (что делаем)

1. **`packages/planner/package.json`** — `name: @uyutno/planner`, `private: true`, `version: 0.0.0`, `type: module`, вход на исходник (`main`/`exports` → `./src/index.ts`; убедиться, что TS `moduleResolution: bundler`, webpack и Jest резолвят `.ts` через этот вход, иначе — `moduleNameMapper`/`resolve.alias`), скрипты `typecheck` (`tsc -p tsconfig.json`) и, при желании, `test` (прокси на Jest платформы или свой конфиг — см. п. 6). Зависимости: `three@~0.185.1`, `immer`, `mitt`, `uuidv7` (та же версия, что в платформе); `react` — `peerDependencies` (+ devDep для typecheck) с той же мажорной, что у платформы (`^19`); devDeps: `@types/three`, `@types/react`, `@types/jest`, `@swc/helpers` (если остаётся `externalHelpers`), `typescript` не дублировать — из корня.
2. **`packages/planner/tsconfig.json`** — `extends: ../../tsconfig.base.json`, `lib: [dom, dom.iterable, es2022]` (проекция и `ui/` трогают DOM; `document/`/`engine/` без DOM энфорсятся линтом, не tsconfig), `types: ["jest"]` (co-located `*.test.ts` внутри пакета — ADR 0014 «первые Jest-тесты вне `apps/platform`»), `noEmit`, `include: ["src/**/*.ts", "src/**/*.tsx"]`, свой `tsBuildInfoFile`. Корневой `pnpm typecheck` (`pnpm -r`) должен подхватывать пакет.
3. **Подключение в платформу** — `"@uyutno/planner": "workspace:^"` в `apps/platform/package.json` (deps), `pnpm install`, обновлённый `pnpm-lock.yaml`.
4. **Webpack клиента** — исходники пакета `.ts/.tsx` резолвятся и транспилируются как свои: проверить, что `swc-loader` их обрабатывает (см. факт про `.swcrc`), что `exclude: /node_modules/` не отсекает реальный путь пакета, при необходимости — `resolve.alias`/`TsconfigPathsPlugin` не нужны (пакет — обычная зависимость воркспейса). Отдельного билда/`dist` у пакета нет.
5. **Webpack SSR** — allowlist в `nodeExternals`: `/^@uyutno\/planner$/` (или `/^@uyutno\//` на все воркспейс-пакеты — выбрать и записать в ADR 0015 «Что важно знать» как факт), чтобы исходники пакета бандлились в SSR-бандл, а не резолвились из `node_modules` в рантайме; `swc-loader` для файлов пакета — та же оговорка про `.swcrc`. SSR-бандл после этого должен собираться и стартовать (`pnpm --filter platform build && pnpm --filter platform start` или `dev`), страница `/project/:id` рендерится.
6. **Jest** — тесты пакета исполняются командой `pnpm --filter platform test`: добавить в `roots` `<rootDir>/../../packages/planner/src` (и `moduleNameMapper` `^@uyutno/planner$` → `packages/planner/src/index.ts`, если платформенным тестам понадобится импорт пакета); альтернатива — свой `packages/planner/jest.config.mjs` с тем же transform и запуск через `pnpm -r test` — выбрать одно, обосновать в «Заметках» одной строкой. Не забыть `^(\.{1,2}/.*)\.js$` для ESM-импортов внутри пакета, если они будут.
7. **ESLint** — override для `packages/planner/**/*.{ts,tsx}` с per-directory `no-restricted-imports` по слоям ADR 0015:
   - `packages/planner/src/document/**` — запрещены `three`, `three/*`, `react`, `react-dom`, `react/*` и импорты вышележащих слоёв (`../engine`, `../projection`, `../ui`, а также любые `**/engine/**`, `**/projection/**`, `**/ui/**` через относительные пути);
   - `packages/planner/src/engine/**` — то же (`three`, `react*`, `../projection`, `../ui`);
   - `packages/planner/src/projection/**` — запрещён `react*` и `../ui`;
   - `packages/planner/src/**` — запрещены `@app`, `@app/*`, `@server`, `@server/*` (граница с платформой физическая — алиасов у пакета нет, но правило дешёвое и даёт понятное сообщение);
   - react/react-hooks правила распространить на `packages/planner/src/ui/**/*.tsx` (сейчас они только для `apps/platform/src/client/**`);
   - в override платформенных модулей заменить нынешние `@app/planner`, `@app/planner/*` и `files: apps/platform/src/client/planner/**` (в паре с `core/**`) на актуальное: `core/**` остаётся, `planner` из клиентских модулей исчезает; кто может импортировать `@uyutno/planner` — по графу ADR 0007 (`landing`, `project`, `common`, `application`; `auth`, `core` — нет) — если это дёшево выразить `no-restricted-imports` для `auth/**` и `core/**`, добавить; иначе оставить только замену старых правил и записать в «Заметках».
   - Проверить намеренным нарушением (например, `import * as THREE from 'three'` в `document/`), что ESLint падает; нарушение **не коммитить**.
8. **Заглушки слоёв** — `packages/planner/src/{document,engine,projection,ui}/` + `src/index.ts`. Минимум, чтобы граф собирался: `index.ts` экспортирует `createPlanner` (заглушка-фабрика с сигнатурой из ADR 0015 A7/A8 в объёме шага 1: `{ canvas, projectId, logger, frameBudget? } → { manager, projection, dispose }` — можно с телом-заглушкой, без Three-логики) и `Planner: React.FC` (рендерит `<canvas>` и ничего больше). Тип `PlannerLogger` `{ debug, info, warn, error }` — в пакете (A8). Один smoke-тест `src/index.test.ts` (или `engine/*.test.ts`) — например, `createPlanner` возвращает объект с `dispose`, `dispose()` не бросает; проверяет, что Jest видит пакет и SWC его транспилирует. Каждая папка-слой — хотя бы один файл (пустой `index.ts` с комментарием-ссылкой на ADR 0015 допустим), чтобы ESLint-override было чем проверять. Реализация слоёв — **следующие задачи** (не здесь).
9. **ADR 0007 / 0010 — правка по месту** (не новый ADR): в 0007 строку таблицы модулей `planner` («В v1 переезжает в отдельный пакет») и пункт «Что важно знать» → «пакет `@uyutno/planner` (`packages/planner`) с шага 1 планера, ADR 0015»; граф импортов **не меняется** (`planner ──► —`, потребители `landing`/`project`/`common`), меняется физическое место и способ импорта (`@uyutno/planner` вместо `@app/planner`); в «Симметрия на сервере» уточнить: пакет попадает в SSR-бандл через allowlist, но серверные модули его не импортируют. В 0010 — упоминание алиасов не трогать по смыслу, только зафиксировать, что у `packages/planner` алиаса `@app/*` нет и быть не должно (импорт из платформы — `@uyutno/planner`). В ADR 0015 «Что важно знать» пункты «при реализации шага 1 …» / «решается в задаче шага 1» заменить на факты (какой allowlist, как настроен Jest, где `.swcrc`).
10. **Монтирование заглушки `<Planner />` в `ProjectPage`** — только если дёшево (импорт + `<Planner projectId={id} logger={…} />` вместо `<h1>`; `logger` — временно `console`-обёртка в `project/`, т.к. клиентского модуля `core`/логгера нет — парковка build-order). Если упирается в вёрстку/лэйаут страницы или SSR-проблемы с `three` — оставить `ProjectPage` как есть и явно записать в «Заметках», что монтирование уходит в следующую задачу шага 1 (проекция + монтирование).

### Что НЕ в задаче

- Сам движок: `PlannerManager`, команды/транзакции, шина `mitt` с картой событий, `useSyncExternalStore`-мост, `RenderLoop`/render-on-demand, `ThreeProjection`, ортокамера, resize/dispose — следующие задачи шага 1 по build-order (после этой). Здесь зависимости только **объявлены**, использовать их в коде заглушек не обязательно.
- Модель документа (типы `Document`/`Floor`, `immer`-транзакции) — отдельная задача шага 1 по ADR 0016.
- Тесты слоёв 1–2 из testing-strategy сверх одного smoke-теста; perf/leak-гвард Playwright.
- Правки спеки `features/planner/*` (задача 0046).
- Playwright/визуальная приёмка: UI не меняется (кроме, возможно, пустого `<canvas>` вместо `<h1>` — если монтируем заглушку, достаточно открыть страницу в браузере через Playwright MCP и убедиться, что SSR/гидрация без ошибок в консоли).

## Заметки

Открытые вопросы автору / решения, которые нужно принять по ходу (записать сюда результат):

- `.swcrc`: инлайн-опции в обоих webpack-конфигах vs корневой `.swcrc` vs копия в пакете — предпочтительно **одно место** (например, вынести опции в `webpack/common.js` и передавать в `swc-loader`), чтобы не разъезжались клиент/сервер/пакет. Подтвердить у автора, если решение выходит за рамки «дёшево».
- Allowlist SSR: `/^@uyutno\/planner$/` (точечно) или `/^@uyutno\//` (все будущие воркспейс-пакеты) — предложение: широкий, т.к. по ADR 0002 все `@uyutno/*` — исходники без сборки; финал записать в ADR 0015.
- `three` в SSR-бандле: из-за pnpm-layout `nodeExternals` не увидит `three`/`immer`/`mitt` как внешние и забандлит их в `dist/server/server.js`. Приемлемо для v0 (SSR только рендерит `<canvas>`), но если хочется держать SSR-бандл лёгким — либо добавить их в `externals` явно (`importType: 'module'` + hoist/дубль в платформе), либо не импортировать `three` на уровне модуля из `index.ts` (ленивый импорт в `createPlanner`). Решить при реализации, зафиксировать здесь.
- Jest: `roots` платформы vs свой `jest.config.mjs` в пакете — предложение: расширить `roots` платформы (один раннер, одна команда, как в ADR 0014 «единый конфиг»); отдельный конфиг — когда появится второй потребитель пакета.
- Монтирование `<Planner />` в `ProjectPage` — см. п. 10 скоупа; критерий «дёшево»: без правок лэйаута/стилей и без обходных путей для SSR.
