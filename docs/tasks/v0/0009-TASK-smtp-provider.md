## Описание

Выбрать и подключить внешний SMTP-провайдер для транзакционных писем. В v0 единственный сценарий — письмо со ссылкой на восстановление пароля (`/forgot-password` → `/reset-password`). Без этой задачи заблокирована 0014 (восстановление пароля).

Скоуп:

- Выбор провайдера. Требования: российский или доступный из РФ, поддержка SMTP, есть free tier для v0-объёмов (несколько десятков писем в сутки). Кандидаты — SendPulse, Unisender Go, Mailopost, Notisend — сравнить и зафиксировать выбор в **`docs/adr/`** (новый ADR «Выбор SMTP-провайдера»).
- Регистрация аккаунта, подтверждение отправителя (DKIM/SPF на домене), получение SMTP-креденшлов.
- Настройка dev/staging/prod окружений: dev использует локальную заглушку (`nodemailer` `stream`-transport или Mailhog), staging/prod — реальный SMTP. Как переключается — по `process.env` без формального env-слоя (см. ADR 0007).
- Хранение секретов: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` — через `process.env`, дев-дефолты для локальной заглушки хардкодятся в коде.
- В `src/server/core/mail/` — фабрика транспорта `nodemailer` (singleton), контракт `sendMail({ to, subject, html, text })`. Без бизнес-логики писем — она в 0014.
- Ручная проверка: отправить тестовое письмо на реальный ящик через staging.

Вне скоупа:

- Сами письма (шаблон password-reset, вёрстка) — в 0014.
- Мониторинг доставки / бэкап-провайдер — v1+.

## Приёмка

- [ ] Провайдер выбран, решение зафиксировано отдельным ADR.
- [ ] SMTP-аккаунт зарегистрирован, отправитель подтверждён (DKIM/SPF настроены на домене).
- [ ] Креды лежат в `process.env` (production), инструкция по локальному запуску — в `apps/platform/README.md`.
- [ ] В `src/server/core/mail/` есть транспорт и функция `sendMail`. Dev использует локальную заглушку без реальной отправки.
- [ ] Ручная проверка: тестовое письмо доходит на реальный ящик через staging.
