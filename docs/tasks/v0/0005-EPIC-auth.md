# 0005 · EPIC · Аутентификация

- Статус: [ ]
- Зависит от: —
- Спека: docs/product/features/auth.md

## Описание

Полный auth-контур v0: вход, регистрация, восстановление и смена пароля по email, вход через Yandex ID и VK ID, серверные сессии в cookie. Основа для всех защищённых страниц (в первую очередь `/projects` и `/project/:id` в будущих эпиках). Кроме продуктовых сценариев эпик закрывает и всю необходимую инфру: подключение PostgreSQL + Kysely + миграций, Registry, error-middleware, регистрацию OAuth-приложений и выбор SMTP-провайдера.

Скоуп подзадач:

- Инфра: БД-слой, миграции auth-таблиц, Registry + error-middleware.
- Внешние блокеры: настройка SMTP-провайдера, регистрация OAuth-приложений Yandex ID + VK ID.
- Backend + frontend: `auth`-модуль с `AuthService`, session middleware, гарды на защищённые роуты (SSR + API + axios-interceptor), логика `?from`.
- UI: `/login`, `/register`, `/forgot-password`, `/reset-password`, OAuth-flow.

Вне скоупа эпика:

- Кнопка выхода и залогиненный Header (нет макетов, откладываем).
- Личный кабинет и настройки безопасности.
- Импорт демо-проекта после регистрации — относится к фиче демо.
- Подтверждение email (`email_verified_at` в схеме есть, но не заполняется в v0).

Продуктовая спека — [`docs/product/features/auth.md`](../../product/features/auth.md). Технические решения — ADR [0005](../../adr/0005-model-autentifikatsii.md), [0006](../../adr/0006-shema-bd-v0.md), [0007](../../adr/0007-arhitektura-proekta-moduli.md). Макеты — [`docs/ui/handoffs/auth/`](../../ui/handoffs/auth/).

## Приёмка

- [ ] Незалогиненный пользователь может зарегистрироваться (email/пароль) и попасть в приложение с созданной сессией.
- [ ] Зарегистрированный пользователь может войти паролем и получить сессию.
- [ ] Пользователь может запросить восстановление пароля, получить письмо со ссылкой и установить новый пароль; все ранее активные сессии инвалидированы.
- [ ] Работает вход/регистрация через Yandex ID и VK ID; коллизия email обрабатывается по ADR 0005.
- [ ] Защищённые роуты недоступны без сессии: SSR редиректит на `/login?from=…`, API отвечает `401`; axios-interceptor превращает `401` в клиентский редирект на `/login?from=…`.
- [ ] Параметр `from` корректно сохраняется при переключении между `/login`, `/register`, `/forgot-password`, `/reset-password` и при OAuth-flow; после успешного входа/регистрации пользователь редиректится на `from` (если валиден) или на `/projects`.
- [ ] Все auth-экраны визуально совпадают с [макетом](../../ui/handoffs/auth/Auth%20Screens.dc.html) на desktop / tablet / mobile.
