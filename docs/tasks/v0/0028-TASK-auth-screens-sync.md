## Описание

Сверяем существующие экраны `/login` и `/register` с обновлённым `Auth Screens.dc.html` и подтягиваем всё, что разошлось: композиция карточки, ширина колонки (360px, центр), радиусы, отступы, оформление полей и кнопок, ссылки-переходы под карточкой, тексты. Шапка/подвал уже переключаются на `mode="auth"` из 0026 — эту логику не трогаем, только контент `<main>`.

Экраны `/forgot-password` и `/reset-password` **не входят в скоуп** — они появятся в рамках [0014](0014-TASK-password-reset.md) вместе с бэком.

## Приёмка

- [x] `/login` визуально сходится с макетом на 1440 / 768 / 390.
- [x] `/register` визуально сходится с макетом на 1440 / 768 / 390.
- [x] Переход между входом и регистрацией стоит под карточкой; ссылка «Забыли пароль?» ведёт на `/forgot-password` (пусть даже страницы ещё нет — задача 0014).
- [x] Отступы, шрифты, цвета — из `docs/ui/guidelines.md`.
- [x] Playwright MCP: `/login` и `/register` на 1440 / 768 / 390.

## Заметки

- Ширина колонки формы — 360px (по гайдлайну «формы: колонка 360px по центру», см. `docs/ui/guidelines.md#компоновка`). Handoff-HTML нарисован под 400px, но задача и гайдлайн явно фиксируют 360px — идём по спеке.
- OAuth-блок пока держит одну кнопку Yandex ID на всю ширину. VK ID (двухколоночная сетка из макета) появится вместе с бэком в [0022](0022-TASK-oauth-flow-vk.md); поднимать кнопку-заглушку раньше нет смысла — по гайдлайну «уберите элемент, прежде чем добавить новый».
- Красная `*` у required-полей от HeroUI выключена глобально в `theme-uyutno.css`: в наших макетах required не помечается, все поля формы обязательные и звёздочка визуально лишняя.
