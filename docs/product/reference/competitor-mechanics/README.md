# Реверс механики roomtodo — индекс

> **Это реверс чужого продукта, а не наша спека.** Здесь описано, как устроен roomtodo.com — источник паттернов и анти-паттернов для нашего планера. **Код не копируем**: берём алгоритмы, пороги и уроки, а форму и побочные эффекты решаем сами.

Как этим пользоваться:

- **Вердикты «берём / переделываем / не делаем» — не здесь.** Они в [`docs/product/architecture/competitor-practices-audit.md`](../../architecture/competitor-practices-audit.md): таблицы `keep` / `rework` / `drop` с колонкой «Где» (буква ADR или раздел спеки). ADR обязан ссылаться на строку аудита, а не переоткрывать вопрос заново. Файл отсюда, на который аудит не сослался, — просто описание чужого продукта, а не наше решение.
- **Спорный факт проверяется по исходнику отдельной верификацией**, а не пересказом этой доки. Исходники — снапшот в [`../roomtodo-src/`](../roomtodo-src/README.md) (на его строки указывают все якоря вида `plannercore.js:59361`); перезаписывать снапшот нельзя без пересверки доков. Верификация ведётся refute-by-default: дословная цитата из исходника или факт не считается подтверждённым.
- **Сводный отчёт валидации** — [`VALIDATION-REPORT.md`](./VALIDATION-REPORT.md) (1276 утверждений, ~91% подтверждено построчно, ноль оставшихся WRONG). Точка входа с общей картиной и константами — [`00-overview.md`](./00-overview.md).
- **Продуктовые решения** — в [спеке планера](../../features/planner/README.md); шаг, на котором файл понадобится, — в [build-order](../../architecture/planner-build-order.md).
