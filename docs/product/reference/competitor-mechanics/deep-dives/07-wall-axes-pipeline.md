# Deep-dive 07 — Пайплайн осей стен (`WC.Axis`)

Реверс-анализ неминифицированного `plannercore.js` конкурента. Все номера строк —
по этому файлу. Док сшивает то, что разорвано между 01-walls (draw-time), 02-doors-windows
(проёмы) и 03-rooms (rebuild): **как оси строятся, когда пересоздаются, кто их
потребляет и как двери/окна переживают полную пересборку сцены**.

Ключевая рамка: в движке два «мира».

- **Редактор конструктора** (`WC.core` + `WC.SubEditor`): `CPoint`/`CRoom`/`CWall` —
  2D-модель, которую пользователь правит. Осей здесь **нет вообще**.
- **Data/3D-слой** (`WC.WallsData`, конструктор на 55010): `DataPoint`/`DataWall`/
  `DataRoom` + `me.axes` (55029), `me.dictModelAxis` (55033), `me.newModelsData`
  (55034). Оси живут только здесь.

`DataWall` в этой модели — **одна грань** физической стены (сегмент контура одной
комнаты). Ось = центральная линия физической стены, восстановленная из **пары
смотрящих друг на друга граней**. Оси — производные и одноразовые: каждый полный
rebuild их выбрасывает и находит заново; переживают rebuild только модели
(двери/окна), и то через отдельный механизм пере-дропа (§4).

## 1. Модель данных

`WC.Axis(wall1, wall2)` (52086–52104):

| Поле                                  | Что хранит                                                                                 |
| ------------------------------------- | ------------------------------------------------------------------------------------------ |
| `wall1`, `wall2`                      | две грани-`DataWall`, породившие ось                                                       |
| `point1`, `point2`                    | концы центрального сегмента (середины торцов бокса)                                        |
| `box`                                 | прямоугольник перекрытия `[E,F,G,H]` из `parallelBox`                                      |
| `depth`                               | толщина стены = `euclDist(box[1], box[2])` (55383)                                         |
| `angle`                               | угол для ротации дропнутой модели, со свопом для outer (55389–55406)                       |
| `models[] / modelIDs[] / positions[]` | параллельные массивы проёмов: данные модели, id, **нормализованная** позиция 0..1          |
| `frames[]`                            | 3D-меши лутки/рамы (`createFrame3D`), пересобираются `createFramesForAxis`                 |
| `finalContours[]`                     | сдвинутые в осевые координаты силуэты моделей — вход для разрывов плинтуса (55728 → 53287) |

Обратные ссылки: `DataWall.axes = []` в конструкторе грани (52784), заполняется в
`findAxes` (55386–55387). Глобальный словарь `dictModelAxis[modelID] → axis`
(55033, запись 55211) — единственный способ найти ось по проёму.

## 2. `findAxes` построчно (55362–55407)

Вызывается ровно из одного места — `WallsData.setStructure` (55098), т.е. только
при полной пересборке data-слоя.

```
for i in 0..walls.length-2:                       // 55364
  for j in i+1..walls.length-1:                   // 55366
    box = WC.boxFromWalls(walls[i], walls[j])     // 55371; null → continue
    pts = WC.boxCenterSeg(box[0..3])              // 55374; null → continue
    axis = new WC.Axis(DW1, DW2)                  // 55377
    axis.point1 = pts[0]; axis.point2 = pts[1]    // 55380–55381
    axis.box = box
    axis.depth = euclDist(box[1], box[2])         // 55383 — поперёк бокса
    me.axes.push(axis)                            // 55384
    DW1.axes.push(axis); DW2.axes.push(axis)      // 55386–55387
    axis.angle = ...                              // 55389–55406, см. ниже
```

**Критерии пары** — три последовательных фильтра в `boxFromWalls` (54822–54831):

1. `TR.parallelLines(p1,p2, q1,q2)` (54826) — почти-параллельность, дефолтный
   допуск `maxAngle = 0.05` рад (~2.9°) из самого `parallelLines` (50252–50254).
2. `WC.rightOriented(DW1, DW2)` (54922–54941) — parity-фильтр «грани смотрят друг
   на друга»: XOR-таблица из `parallel` (сонаправленность, 54927), `LR`
   (знак векторного произведения — с какой стороны лежит вторая грань, 54929) и
   флагов `faceRight` обеих граней (таблица 54933–54939). `faceRight` проставлен
   раньше, при конверсии контуров: `faceRight = roomOuter ^ roomCW ^ parallel`
   (54140 в `shortToStructure`; идентичная формула 61739 в editor-`getStructure`).
3. `parallelBox(A,B,C,D, 0.05)` (54833–54908) — четырёхвариантный разбор
   проекций концов второй грани на первую (`insC`/`insD`, 54840–54842):
   строит прямоугольник перекрытия `[E,F,G,H]`, отклоняет пары без настоящего
   перекрытия (ветка `!insC && !insD` с обеими проекциями по одну сторону →
   `return null`, 54873) и вырожденное перекрытие `manhDist(E,F) < L_EPS` (54903).

**Построение сегмента** — `boxCenterSeg` (54911–54920): два порога
`euclDist(B,C) > WC.MAX_WALL_WIDTH (80)` → null (54913, слишком толстая «стена»),
`euclDist(A,B) < WC.MIN_WALL_LENGTH (15)` → null (54914, слишком короткая);
иначе `point1 = mid(D,A)`, `point2 = mid(B,C)` — середины торцов бокса.

**`axis.angle`** (55389–55406): базово `-atan2(point2−point1)` (экранная ось Y
вниз), но если `DW1.outer` и векторное произведение (направление оси × вектор к
`DW1.point1`) > 0 — концы для расчёта угла свопаются (55395–55404), т.е. для
наружных стен угол разворачивается на π, чтобы дропнутая дверь «смотрела» внутрь
консистентно. Сами `point1/point2` при этом **не** свопаются — только угол.

**Дедупликация**: отдельного шага нет. Перебор `i < j` сам по себе не даёт
дубликатов пары; фильтр `rightOriented` отсекает пары «в спину». При этом одна
грань может законно попасть в **несколько** осей (длинная грань напротив двух
коллинеарных коротких → два бокса, две оси) — потребители (`getHoles` 52994,
`findPlinthGaps` 53291) это учитывают, итерируя `wall.axes[]` целиком.
Слияния/фильтрации перекрывающихся осей не найдено.

Сложность — честный O(n²) по всем граням всех комнат, без пространственного
индекса.

## 3. Полный порядок стадий одной правки

Правка стен проходит **два независимых цикла**: быстрый 2D-цикл внутри
редактора и полный data/3D-rebuild при синхронизации.

### 3.1. 2D-цикл (на каждый коммит правки в конструкторе)

`WC.core.rebuildWallsAndCovers()` (59533) — вызывается из десятков мест
редактора (удаление комнаты/точки 60776/60798, конец драга 64037/64224/64326,
рисование 65625/65935, и т.д.):

```
delIntersectedAreas()            // 59535
roundAllPoints()                 // 59537 — округление координат точек
rebuildWalls()                   // 59539 → 59582
rebuildCovers()                  // 59540 → 59909
findAutoCovers()                 // 59542
connectAllPoints()               // 59544
findCoverHoles()                 // 59545
findAllCoverTriangles()          // 59546
WC.snapTool.reset(); draw()      // 59548–59549
```

`rebuildWalls` (59582): чистка плохих областей → сбор outer/inner контуров →
`TR.rebuildContours(...)` (59630) → новые `CRoom`/`CPoint`, перенос данных со
старых комнат матчингом (цикл 59690–59701, проверка `compareContoursByArea` на
59695). **Осей здесь нет** — это чисто
контурная перестройка 2D-модели.

### 3.2. Полный rebuild data/3D (при выходе из конструктора / сохранении / смене вью)

Триггер — `SubEditor.setStructureToWallsData()` (62325–62328) либо тот же вызов
внутри `disable()` (62344). Внешние точки входа: `disable` при выходе из
режима конструктора (62344 → `dispatchModelsReset` 62348), сохранение на сервер
(15645–15646), экспорт данных (15739), показ 2D/3D-вью (62766, 39925).

```
wallsData.setStructure( subEditor.getStructure() )        // 62327
```

Порядок существенен: **сначала** выполняется `getStructure()` (61611) — он ещё
видит СТАРЫЕ оси и готовит `newModelsData` (§4), — и только потом тело
`setStructure` (55088) их уничтожает:

```
me.removeAll()          // 55091 → 55107: ELEMENT_DELETE на все стены/каты/
                        //   полы/потолки/области/плаги/плинтусы (55109–55115),
                        //   ELEMENT_DELETE на все frames осей (55117–55120),
                        //   me.axes = [] (55138), me.dictModelAxis = {} (55142)
copy struct fields      // 55093–55096: walls/rooms/conts... из getStructure
findAxes()              // 55098 — §2, оси с нуля, models[] у всех пустые
createPlinths()         // 55100 → 55411: офсет контура комнаты на d=1 внутрь,
                        //   митры через lineIntersectLine, maxDist=2 fallback
build3D()               // 55102 → 55475, см. ниже
findRoomsForCovers()    // 55104 → 55324: привязка cover.room по pointInContour
```

`build3D` (55475–55636) по шагам:

1. `createWall3D` на каждую грань + `ELEMENT_CREATE` (55477–55481). Внутри
   `DataWall.build3D` дырки берутся из `getHoles()` (53119 → 52990), но в этот
   момент `axis.models` пусты — **стены сначала строятся сплошными**.
2. `createCut3D` (55483–55487).
3. `findPlinthGaps` на каждую грань (55489–55492) — тоже пока пусто.
4. `createPlinth3D` + события (55494–55498).
5. Полы/потолки: `createCover3D` (55500–55509).
6. Cap и areas: триангуляция внешних контуров (55521), раскладка треугольников
   по областям, `cap.build3D` (55571).
7. Служебная разводка: `cut.walls` (высшая стена на каждом конце ката,
   55589–55610), `wall.neighbours` (по общим точкам, 55615–55631).
8. `me.plugs = WC.createConnectors(me.axes, me.walls, me.cuts)` (55633) —
   гэп-филлеры по осям (§5.4), затем `plug.walls` разводка и `ELEMENT_CREATE`.

### 3.3. Пере-дроп моделей (замыкает цикл)

После `setStructure` вызывающий код дёргает `dispatchModelsReset()` (62348;
15646; 39927) → событие `WC.RESET_MODELS` с `me.newModelsData` (55797–55800) →
обработчик сцены `updatePositionObjectsForWall` (13189, подписка 14298). Каждый
успешный `dropElement` пересобирает рамы оси, обе грани и оба плинтуса
(55219–55236) — стены из шага 3.2.1 перестраиваются уже с дырками.

Итоговая цепочка одной правки:

```
edit commit → WC.core.rebuildWallsAndCovers (2D, 59533)
   … (мгновенно, много раз за сессию правки)
exit constructor / save / switch view
   → SubEditor.getStructure (61611): DataWalls + faceRight (61739)
                                     + newModelsData из СТАРЫХ осей (61972–1999)
   → WallsData.setStructure (55088): removeAll → findAxes → createPlinths
                                     → build3D (…→ createConnectors 55633)
                                     → findRoomsForCovers
   → dispatchModelsReset (62348) → RESET_MODELS
   → updatePositionObjectsForWall (13189): dropElement по каждому проёму
   → каждый drop: createFramesForAxis + createWall3D×2 + плинтусы (55219–55236)
```

Загрузка сохранённого плана — тот же хвост: `setData` (55043) →
`WC.convert.shortToStructure` (53828, `faceRight` на 54140) → тот же
`setStructure`; модели приходят сценой и дропаются в `scene.add`
(14033–14044, `dropElement` на 14038).

## 4. Идентичность осей между ребилдами и пере-дроп моделей

Оси **не имеют идентичности** — ни id, ни матчинга «старая ↔ новая». Каждый
`setStructure` создаёт новый набор. Непрерывность проёмов обеспечивается
пересчётом **мировых координат** каждой модели по старой оси и повторным дропом
на новые оси.

Механизм (`getStructure`, регион 61629–61999):

1. **`savedWalls`** (61629, push 61682): при конверсии каждой новой грани
   `DW(DP1,DP2)` ищется `CWall` редактора с совпадающими концами
   (`p1.match(DP1) && p2.match(DP2)` или наоборот, 61669); у найденного
   `cwall.data` — это **старый `DataWall`** из прошлого rebuild'а (identity
   протянута через `CWall.data`). Он попадает в `savedWalls`, и — ключевая
   тонкость — его точки **перепривязываются на текущие координаты редактора**:
   `cwall.data.point1 = p1; cwall.data.point2 = p2` (61683–61684).
2. **`wallsData.newModelsData = []`** (61972); цикл по СТАРЫМ `wallsData.axes`
   (61974):
   - скип, если хотя бы одна из двух граней оси не выжила
     (`savedWalls.indexOf(...) == -1`, 61978) или на оси нет моделей (61980);
   - бокс и центральный сегмент пересчитываются по старым граням с уже НОВЫМИ
     координатами: `boxFromWalls` → `boxCenterSeg` (61982–61986), `axis.point1/2`
     обновляются in-place (61986–61987 у сегмента; сам угол `ang = +atan2(...)`
     на 61989 — без минуса, это мировая проекция, не экранный `axis.angle`);
   - для каждой модели: **если `model.axisPos > длинаНовойОси − 5` — скип**
     (61995): модель, «не влезающая» в укоротившуюся стену (с запасом 5 см от
     конца), в `newModelsData` не попадает;
   - иначе пушится `{id, x: point1.x + axisPos·cos(ang), y: point1.y +
axisPos·sin(ang)}` (61997–61998) — мировая точка на новой геометрии оси,
     на том же **абсолютном** расстоянии от `point1`.
3. **`updatePositionObjectsForWall(newModelsData)`** (13189–13252),
   `radiusDropElement = 10` (13092):
   - для каждого элемента `newModelsData` находится sceneObject по id (13211),
     ему подменяются x/y (13215–13216) и вызывается `constructor.dropElement`
     (13218) — обычный дроп: `getAxis` в радиусе 10, проекция на сегмент,
     регистрация в новых `axis.models/positions/dictModelAxis`;
   - неуспех дропа → `scope.remove(sceneObject)` (13221–13226) — **проём
     удаляется из сцены**;
   - оставшиеся forWall-объекты сцены, которых в `newModelsData` не было
     (стена удалена/разрезана/модель за краем), передрапываются **по своим
     старым мировым координатам** (13242–13245); если рядом (≤10) есть любая
     ось — модель прилипнет к ней (возможно, к чужой стене), иначе —
     удаляется (13249).

Что при этом теряется/пересчитывается: `positions[]` (нормализованные 0..1) не
переносятся — пересчитываются в `dropElement` (55215–55217); `axisPos`
пересчитывается от нового `point1` (55209); `depth` модели обновляется на
толщину новой оси (55197: `modelData.depth = axis.depth`). Единственный
носитель непрерывности — мировые `x,y` из шага 2 (или старые мировые x/y в
fallback-ветке).

## 5. Потребители осей

### 5.1. Дроп/драг проёмов — `getAxis` / `dropElement` / `moveElement` / `pickElement`

- `getAxis(center, snapDist)` (55338–55360): линейный перебор `me.axes`,
  кандидат только если `projectionPointOnLine(center, p1, p2, true)` попадает
  **на сегмент** (55345–55346), берётся минимальная перпендикулярная дистанция
  (55348), отказ при `minDist > snapDist` (55357). Дефолт `snapDist = 10`
  (55156, 55174; и `radiusDropElement = 10` на 13092).
- `dropElement` (55172–55240): проекция на ось, `rotation = axis.angle`
  (55186), `depth = axis.depth` (55197), `axisPos` (55209), `dictModelAxis`
  (55211), `positions.push(axisPos/axisLength)` (55215–55217), затем
  `createFramesForAxis` + rebuild обеих граней + плинтусы (55219–55236).
- `moveElement` (55154–55170): live-драг; считает угол сам, без outer-свопа:
  `rotation = π + (−atan2(...))` (55164, 55168) — отличается от
  `dropElement`-ового `axis.angle`.
- `pickElement(id)` (55241–55274): снятие модели с оси через `dictModelAxis` +
  та же пересборка рам/граней/плинтусов.

### 5.2. Дырки в гранях — `DataWall.getHoles` (52990–53050)

Для каждой оси, касающейся грани (`me.axes`, 52994), ориентация грани
относительно оси определяется сравнением расстояний `point1` грани до концов
оси (`parallel`, 52997–52998). Силуэт каждой модели проецируется в локальные
координаты грани: `x = contourX·scaleX·(±flip) + positions[i]·axisLength +
axisShift` (53020 / 53037, `axisShift` — проекция конца оси на грань,
53014–53015 / 53030–53031), `y = elevation − contourY·scaleY` (53022–53023).
Дырки уходят внутренними контурами в триангуляцию грани (53119 →
`triangulateContours` 53185) — **не CSG** (детали в 02-doors-windows §окна).

### 5.3. Рамы и плинтусы

- `createFramesForAxis(axis)` (55677–55729): удаляет старые frames оси,
  сдвигает силуэты моделей в осевые координаты (55692–55705, round до сотых),
  сливает пересекающиеся силуэты `compareAndRebuildContours` (55707) — поэтому
  два наложенных проёма дают одну общую раму, — и строит `createFrame3D` с
  `axis.point1/point2/depth` (55714). `axis.finalContours = shiftedContours`
  (55728) — сырые (не слитые) контуры.
- `findPlinthGaps` (53287–53334): по каждой оси грани и каждому
  `finalContours[j]` берётся AABB силуэта (53300); если низ проёма выше высоты
  плинтуса — пропуск (53301: `if (-bounds.maxY >= bottomPlinth.h) continue`);
  иначе minX/maxX силуэта разворачиваются вдоль оси через `WC.azimuth`
  (53304–53307), проецируются на грань (53309–53310), клампятся к сегменту и
  пушатся как `gaps` нижнего плинтуса (53321–53327); далее sweep-слияние
  перекрывающихся гэпов (53336+). Т.е. ось влияет на плинтус **только** через
  `finalContours` — плинтус рвётся под дверьми.

### 5.4. Connectors (гэп-филлеры) — `WC.createConnectors(axes, walls, cuts)` (54382)

Работает **по осям**: для каждой оси канонически сопоставляет концы граней
(своп-тест 54398–54403), кандидаты — поперечные пары `[P11,P21]`, `[P12,P22]`
(54405–54407); фильтры: длина > `maxConnectorLength = 40` (54384, 54408),
совпадение со стеной (54413–54418), чужая точка на линии (54420–54432),
пересечение стены (54434–54440), дубль ката равной высоты (54443–54454).
Выжившие → `WC.DataPlug(pt1, pt2, axis, height = axis.wall1.height)`
(54480–54484, класс 52053: `type:'plug'`) → плоский вертикальный квад
`createPlug3D` (54495). Подробности — deep-dive 02 §Connectors.

### 5.5. Прочее

- Запись материалов рамы обратно в модель: `getCurModelDataFromAxis` в
  `DataFrame` через `dictModelAxis` (52003–52010).
- `me.frames` getter собирает рамы со всех осей (55866–55869); механика
  показать/скрыть стены гасит **пару** граней оси разом
  (`currentConstructorElementData.axes[0].wall1/wall2`, 13305–13319) и рамы по
  `axis.visible` (55922–55965).

## 6. Судьба `models[]` при изменениях стены

Всё сводится к механизму §4; поведение по сценариям:

| Правка                                    | Что происходит с проёмом                                                                                                                                                                                                                                                                                          |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Сдвиг/удлинение стены                     | Грань матчится в `savedWalls` (по концам), ось пересчитывается, модель встаёт на **то же абсолютное** `axisPos` от `point1` (61997). Нормализованный `pos` пересчитывается заново при дропе (55215–55217) — он живёт только между ребилдами (рендер дырок/рам), а переживает rebuild именно абсолютный `axisPos`. |
| Укорочение стены, модель у дальнего конца | `axisPos > len−5` (61995) → модели нет в `newModelsData` → fallback-передроп по старым мировым координатам (13241–13245): либо прилипнет к ближайшей оси в радиусе 10 (возможно, не к «своей»), либо удалится (13249).                                                                                            |

## 7. Confidence & gaps

**Высокая уверенность** (читано построчно): `findAxes` и все три фильтра пары
(0.05 рад / parity `rightOriented` / четырёхвариантный `parallelBox`), пороги
80/15 в `boxCenterSeg`, отсутствие явной дедупликации осей, полное разрушение и
пересоздание осей в каждом `setStructure` (`removeAll` 55117–55142), механизм
`savedWalls`+`newModelsData`+`RESET_MODELS` с порогом `len−5` (61995) и
fallback-передропом (13241–13251), порядок стадий `setStructure`/`build3D`,
двойная стройка стен (сплошными → с дырками после дропов), все перечисленные
потребители с якорями.

**Gaps / ниже уверенность:**

1. **Стабильность направления `point1→point2` между ребилдами** не доказана:
   `parallelBox` строит `E/F` от геометрии первой грани пары, а порядок граней в
   `me.walls` и направление обхода контура могут смениться после
   `rebuildContours`. Если направление оси флипнется, «то же абсолютное
   `axisPos`» отмерится от противоположного конца. В коде компенсации не нашёл;
   на практике артефакт, видимо, маскируется тем, что мировая точка (61997)
   считается по той же (старой) оси, где `axisPos` был записан, — рассинхрон
   возможен только между записью и чтением в одном `getStructure`, а там ось
   одна и та же. Формально не проверено на кейсе зеркалирования комнаты.
2. Полный список триггеров `setStructureToWallsData` (62327/62344/15645/15739/
   62766/39925) собран grep'ом; мог пропустить экзотические (undo/redo-пути
   истории дёргают `dropElement` напрямую через `sceneObjectHistoryUpdate`,
   13259–13269, — этот путь прочитан, но вся история за рамками дока, см. 09).
3. Поведение при **нескольких осях на одной грани** для передропа: модель
   числится на одной оси; если выжила «не та» пара граней, кейс уходит в
   fallback — специальной обработки не видел, но исчерпывающе не гонял.
4. `WC.azimuth` (используется в `findPlinthGaps`, 53304) не читал — принял как
   «угол направления»; на выводы не влияет.
5. Закомментированный блок в `createConnectors` (54466–54478, подбор
   минимальной высоты плага по соседним стенам) — мёртвый код; упоминаю, чтобы
   не приняли за действующий.
