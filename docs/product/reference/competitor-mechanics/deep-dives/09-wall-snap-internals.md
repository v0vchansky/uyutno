# Deep-dive 09 — Внутренности снапа 2D-конструктора стен (WC.SnapTool)

Реверс по неминифицированному `plannercore.js`; все номера строк — по нему.
Верхнеуровневая «лесенка приоритетов» описана в `01-walls.md` (§Snapping &
constraints); здесь — недостающие внутренности: `snapX`/`snapY` до формул,
полный разбор `getSnapPoint`, направляющие-гайды, округление и дубликаты
полигонного снапа.

Класс: `WC.SnapTool` (57221), единственный инстанс `WC.snapTool = new
WC.SnapTool()` (60585). Работает в **мировых координатах** (см); экранные
пороги переводятся в мир делением на `WC.wallsEditor.scale` (px/см:
`realToView` умножает на scale, 61394). Все дистанции точечного снапа —
**манхэттенские** (`TR.manhDist = |dx|+|dy|`, 49490).

Ключевые константы:

| Константа | Значение | Где |
|---|---|---|
| `WC.SNAP_DIST` | 10 px | 60604 |
| `TR.L_EPS` | 1e-8 | 49482 |
| `TR.B_EPS` | 1e-4 | 49483 |
| fallback-радиус углового снапа при `pointsSnap=off` | 2 (мировых ед., см) | 57594 |
| радиус поиска угла для биссектрисы | `snapDist × 10` | 57525 |
| округление результата | 0.001 мировой ед. (`TR.roundCoord`, `Math.round(x*1000)/1000`) | 50554, вызов 57698 |
| точность хит-теста стороны стены (смежное) | `WC.SNAP_DIST / 2 / scale` | 60352 |

Флаги (defaults 57563–57566, тумблеры в панели настроек 59179–59191, иконки
59131–59134):

- `pointsSnap = true` — притяжение к существующим углам;
- `pointsAlign = true` — выравнивание по X/Y-координатам точек («align by points»);
- `orthoAlign = false` — H/V-выравнивание относительно точек текущего контура («align by axes»);
- `bisectorAlign = true` — выравнивание по биссектрисе угла («align by bisector/mediana»).

## 1. База кандидатов: `allPoints`, кадр, исключения

`me.reset()` (57276) пересобирает пул кандидатов: `WC.core.roomPoints`
(вершины всех комнатных контуров) + `WC.core.rawCont.points` (точки контура,
который сейчас рисуют, если есть) + `WC.core.coverPoints` (вершины полов).
`reset()` дёргается почти на каждом изменении геометрии и при смене
состояний (`changeState` → `WC.snapTool.reset()`, 61310; плюс десятки
call-site'ов 65356…68558).

Фильтры кандидатов **только в snapX/snapY** (в угловом `snapToNearest` их
нет — он смотрит все точки без кадра):

- `exceptPoints` — точки, к которым нельзя выравниваться (обычно
  перетаскиваемая/текущая точка): `exceptPoints?.indexOf(Q) >= 0 → skip`
  (57366);
- **кадр-куллинг**: `pointInFrame(Q)` (57336) — AABB видимой области
  (`WC.framePointLT/RB` = `viewToReal` углов канваса, обновляются при
  пане/зуме, 60865–60866). Точка вне кадра пропускается, **если** она не в
  `farPoints`: условие `(! pointInFrame(Q) && farPoints?.indexOf(Q) == -1)`
  (57366).

Тонкость (важно для порта): при `farPoints === undefined`
`farPoints?.indexOf(Q)` даёт `undefined`, `undefined == -1` — false, т.е.
**куллинг полностью отключается**. Куллинг реально работает только когда
`farNodes` передан массивом (пусть даже пустым `[]`, как в
`BaseState.findSnap`, 63136). Состояния черчения передают
`currentPt.contour?.points` (65945 и др.) — свой контур снапится даже за
экраном, но если контура ещё нет (`?.` → undefined), выключается и куллинг
чужих точек.

## 2. `snapX` / `snapY` построчно — по два кандидата на ось

`snapX(P, snapDist, allPoints, exceptPoints, farPoints)` (57346–57401).
Ищет точку Q, на чью **вертикаль** (`x = Q.x`) стоит притянуть `P.x`.
Симметричный `snapY` (57403–57458) — та же логика с обменом осей (ищет
горизонталь `y = Q.y`).

Источник точек: явный `allPoints`, если непустой, иначе `me.allPoints`
(57348–57357). Оба выравнивателя ищутся **раздельно по полуплоскостям**
вторичной оси:

- `alignerM` («minus») — среди Q с `Q.y < P.y` (кандидаты выше курсора);
- `alignerP` («plus») — среди Q с `Q.y >= P.y` (ниже, включая ту же высоту)
  (57369–57391; в `snapY` деление по `Q.x < P.x` / `Q.x >= P.x`, 57431).

Для каждой стороны два аккумулятора: `minDist*` — первичный ключ `dx =
|P.x − Q.x|` (расстояние до вертикали) и `minSideDist*` — вторичный ключ
`dy = |P.y − Q.y|` (насколько близко сама точка вдоль вертикали). Обновление
кандидата (57376, зеркально 57384):

```js
if ((dx < minDistM - TR.L_EPS) ||                       // строго лучше по оси
    (dx < minDistM + TR.L_EPS && dy < minSideDistM - TR.L_EPS)) {  // равен по оси (±1e-8),
    alignerM = Q; minDistM = dx; minSideDistM = dy;                // но сама точка ближе
}
```

То есть tie-breaking: при равенстве `dx` в пределах `L_EPS` выигрывает точка
с меньшей вторичной дистанцией `minSideDist` — из нескольких точек на одной
вертикали гайд ведёт к **ближайшей** к курсору. Обе величины — по одной
координате, не манхэттен.

Пост-фильтры (57394–57398):

```js
if (minDistM > snapDist) alignerM = null;   // вне радиуса — долой
if (minDistP > snapDist) alignerP = null;
if (minDistM > minDistP + TR.B_EPS) alignerM = null;  // взаимное отсечение:
if (minDistP > minDistM + TR.B_EPS) alignerP = null;  // остаётся строго лучшая сторона,
return [alignerM, alignerP];                          // либо ОБЕ, если dx равны в ±1e-4
```

Итог: `[alignerM, alignerP]` — 0, 1 или 2 точки. Обе выживают только когда
их вертикали совпадают с точностью `B_EPS` (типичный случай — две вершины
одной стены строго друг над другом): тогда гайды рисуются в обе стороны
(см. §5).

### `snapPerpendicular` — свод осей в точку

`me.snapPerpendicular(P, snapDist, allPoints, exceptPoints, farPoints)`
(57460–57505): зовёт `snapX` + `snapY`, из каждой пары выбирает одного
представителя:

- один не-null — берём его (57471–57478);
- оба — берём того, кто ближе к `P` по **манхэттену всей точки**
  (`TR.manhDistP`, 57480–57482 / 57494–57496).

Затем `newX = alignerX.x`, `newY = alignerY.y` (57499–57500) — координаты
подменяются **по осям независимо**; если нет ни одного выравнивателя —
`[null, null, null]` (57502). Возврат (57504):

```
[ new WC.CPoint(newX, newY),  // P с притянутыми осями (одной или обеими)
  alignerX, alignerY,         // победители по осям (для гайдов)
  alignersX, alignersY ]      // сырые пары [M, P] (для расширенных гайдов StateMakingWalls)
```

## 3. Остальные примитивы

- **`snapToNearest(P, snapDist, exceptPoints)`** (57314) — ближайшая точка
  `allPoints` по манхэттену в радиусе `snapDist`, без кадр-куллинга. Угловой
  снап.
- **`findNearest(P, points, maxDist)`** (57290) — то же по явному списку;
  в снапе не участвует, это хит-тест точек (`WC.POINT_SIZE/scale`, 64564).
- **`orthogonalSnap(P, snapDist)`** (57507) — только при черчении
  (`WC.core.rawCont` длиной ≥ 2): выравнивание через `snapPerpendicular` по
  **двум** точкам — предпоследней зафиксированной `points[len-2]` и первой
  `points[0]` (57515–57517). H/V-лок относительно предыдущей точки и
  замыкания. `farPoints=[]` ⇒ обе точки должны быть в кадре.
- **`bisectorSnap(P, snapDist, exceptPoints)`** (57523–57561):
  1. ближайший угол в радиусе `snapDist × 10` (`snapToNearest`, 57525–57526);
  2. у угла должен быть `.contour` (57530; `CPoint.contour` ставят
     `CContour.addPoint`/`CRawContour.addPoint`, 56900/57172);
  3. соседи `A`, `B` по кольцу контура (57536–57551);
  4. `Q = TR.bisectorPoint(nearPt, A, B)` (57553; 50175 — середина между
     единичными ортами `nearPt→A` и `nearPt→B`, null если они противоположны);
  5. отказ, если **перпендикулярное** (тут — евклидово со знаком, модуль)
     расстояние от `P` до прямой `nearPt→Q` больше `snapDist`
     (`TR.distanceBetweenPointAndLine`, 57557; 49567);
  6. возврат `[nearPt, Q]` — опорная точка + направление биссектрисы.
- **`findNearSegments(P)`** (57227) — не снап курсора, а поиск пары соседей
  для точки, посаженной на существующую стену: сначала ищет вершину,
  совпадающую с `P` в `TR.B_EPS` (57242–57249 — тогда возвращает вторые
  концы двух инцидентных рёбер), иначе ребро, на котором `P` лежит
  (`TR.pointOnLine` с `B_EPS`, 57264) — возвращает его концы. Ровно 2 точки
  или `[]`. Используется в `StateMakingWalls.calcStart` (66027) для
  автовыбора стороны офсета `signSide` при старте от чужой стены и для
  T-стыка в `blocksFromContour` (см. deep-dive 02).

## 4. `getSnapPoint` — полная лесенка

`me.getSnapPoint(P, exceptNodes, snapDist, farNodes)` (57568–57701).
Все реальные вызовы передают `snapDist = WC.SNAP_DIST / WC.wallsEditor.scale`
= 10 px в мире (63136, 63976, 64073, 64347, 64463, 65362, 65945, 66406,
66690, 68477).

**Фаза сбора** (независимо от лесенки):

1. `nearPt = snapToNearest(P, pointsSnap ? snapDist : 2, exceptNodes)`
   (57588–57595). При выключенном `pointsSnap` угловой снап не исчезает —
   радиус жёстко сжимается до 2 мировых единиц (см).
2. `pointsAlign` → `snapPerpendicular(P, snapDist, [], exceptNodes,
   farNodes)` → `pointPt, alignerX, alignerY, alignersX, alignersY`
   (57597–57606).
3. `orthoAlign` → `orthogonalSnap` → `orthoPt, orthoX, orthoY` (57608–57617).
4. `bisectorAlign` → `bisectorSnap` → `bisCenter, bisDirect` (57619–57626).

**Лесенка приоритетов** (первое совпадение выигрывает):

| # | Условие | Результат |
|---|---|---|
| 1 | `nearPt && manhDist(P, nearPt) < snapDist` (57629) | сам угол `nearPt`. Эффективный радиус при `pointsSnap=off`: `min(2, snapDist)` |
| 2 | `pointsAlign && pointPt && alignerX && alignerY` (57633) | `pointPt` — пересечение вертикали и горизонтали двух точек («крест») |
| 3 | `pointsAlign && bisCenter && bisDirect && alignerX` (57637) | `A = lineIntersectLine(bisCenter→bisDirect, вертикаль через alignerX)` (вторая точка вертикали — `(x, y+10)`, 57639); принимается, если `manhDist(P,A) < snapDist`, иначе откат на `pointPt` (57640–57648) |
| 4 | то же с `alignerY` (57650) | пересечение биссектрисы с горизонталью `(x+10, y)` (57652–57661) |
| 5 | `orthoAlign && orthoPt && bisCenter && bisDirect` (57663) | биссектриса ∩ орто-ось (вертикаль через `orthoX` или горизонталь через `orthoY`, 57665–57667); принятие/откат на `orthoPt` как выше |
| 6 | `pointsAlign && pointPt` (57679) | одноосевое выравнивание (`pointPt` с одной притянутой осью) |
| 7 | `orthoAlign && orthoPt` (57683) | чистый H/V-лок |
| 8 | `bisectorAlign && bisCenter && bisDirect` (57687) | `A = projectionPointOnLine(P, bisCenter, bisDirect, as_seg=false)` (57689); принимается при `manhDist < snapDist` |
| — | иначе | `resTarget = P` — сырой курсор |

В ветках 3–5 и 8 попутно ставится `alignerD = bisCenter` — опорная точка для
отрисовки биссектрисного гайда.

**Финал** (57698–57700):

```js
resTarget = TR.roundCoord(resTarget);   // 0.001 мировой ед. (см), 50554
return [resTarget, alignerX, alignerY, alignerD, alignersX, alignersY];
```

Округляется **любой** исход, включая сырой курсор и снап на существующий
угол (координаты угла уже округлены прошлыми снапами, так что визуального
сдвига нет). `roundCoord` создаёт новый `TR.Point` — исходная вершина не
мутируется. Дальше округлённые координаты становятся вершинами контура:
`mouseUp` черчения делает `new WC.CPoint(WC.snapPos.x, WC.snapPos.y)`
(66072) — т.е. вся геометрия конструктора квантована на сетку 0.001.

**Пайплайн вызова**: `onCanvasMouseMove` → `me.state.findSnap()` (61218; и
touch-путь 61295) до `state.mouseMove`. Каждый state кладёт `WC.snapPos =
snapRes[0]` и `WC.aligners = [snapRes[1], snapRes[2], snapRes[3]]`
(= alignerX, alignerY, bisCenter; 63137–63138, 63977–63978, 64074–64075,
65363–65364, 66407–66408, 66691–66692, 68483–68484). `StateMakingWalls`
дополнительно сохраняет сырые пары: `WC.aligners = [.., snapRes[4],
snapRes[5]]` (65947). В `start()` состояния снап не применяется — первая
точка ставится в сырой `WC.realPos` (65885) и подтягивается уже первым
`mouseMove` (65962–65963).

Особые потребители: `StateDraggingWall`/`StateDraggingCoverSide` берут
`snapRes[0]` и **проецируют его на перпендикуляр к стене**
(`projectionPointOnLine(snapRes[0], ptDir1, ptDir2, false)`, 64349/64470),
гайды глушат (`WC.aligners = [null,null,null]`, 64350/64471) — стена ездит
только по нормали, но чувствует чужие выравниватели.

## 5. Alignment-гайды: что видит пользователь

**Базовая отрисовка** — `BaseState.drawAligner` (63472–63497): зелёные
(`#00aa00`) пунктирные (`setLineDash([2,4])`) отрезки **от `WC.snapPos` до
каждой из точек `WC.aligners[0..2]`** (alignerX, alignerY, bisCenter) в
экранных координатах. Концы гайда — это буквально снап-точка и сама
точка-выравниватель (для биссектрисы — вершина угла), никакого клипа по
экрану.

**Расширенная версия в `StateMakingWalls.drawAligner`** (66088–66210+):

1. те же три базовых гайда (66101–66107);
2. затем гайды к «проигравшим» кандидатам из сырых пар `alignersX =
   WC.aligners[3]`, `alignersY = WC.aligners[4]` (66117–66118) — чтобы при
   двух точках на одной вертикали пунктир шёл в обе стороны;
3. подавление: если снап-точка уже совпала с одним из выравнивателей
   (`manhDistP < B_EPS`, 66120–66123) или лежит на существующей стене
   (`pointOnLine` по всем рёбрам, 66127–66145) — дополнительные гайды не
   рисуются;
4. угловой фильтр: гайд к `alignersX[k]`/`alignersY[k]` рисуется только если
   угол между последним зафиксированным сегментом (`lastPt→snapPos`) и
   направлением на выравниватель не острее `recalcAng = 0.75π` (66147,
   66152–66157) — та же константа, что и лимит миттера;
5. к каждому такому гайду рисуется **параллельный офсетный пунктир** на
   расстоянии `signSide * wallsWidth * scale` (экранных px) через
   `TR.perpendicularPoint` (66162–66164 и зеркальные блоки) — предпросмотр
   того, куда ляжет **вторая грань** будущей стены, а не только её осевая.

Плюс сам курсор: `drawCross` рисует чёрный крест в `WC.snapPos` (63520).

## 6. Дубликаты `snapPolygonToNearestLine*` @57704/57771

Это **не** вариации snapX/snapY, а полигонный снап (перетаскивание
фигуры к линиям), скопированный из движка мебельной 2D-сцены:

- Оригиналы: `SNAP.Snap2D.prototype.snapPolygonToNearestLine` (9742) и
  `...InOneDirection` (9807) — методы `SNAP.Snap2D` (9476), инстанс
  `R2D.mouseInteractionHelper._snap2d` (41576), дистанция 15 (41668);
  используются при драге объектов/групп в основной 2D-сцене (44013, 44450,
  44537, 45679).
- Копии в `WC.SnapTool`: `me.snapPolygonToNearestLineInOneDirection` (57704)
  и `me.snapPolygonToNearestLine` (57771). **Тела побайтово идентичны
  оригиналам** (проверено diff'ом нормализованного текста; отличается только
  обёртка `prototype.f = function` vs стрелочное поле).
- Отличаются **оркестраторы** `snapPolygon`:
  - `Snap2D.snapPolygon` (10007): линии/боксы из своих `_lines`/`_boxes`
    (`updateLines`/`updateBoxes`), с fallback на `snapPolygonToBox`;
  - `WC.snapTool.snapPolygon` (57838): линии тянет из
    `R2D.mouseInteractionHelper._constructor.getLines()` (57841) — это рёбра
    внутренних+внешних комнатных контуров `WallsData` (55832); боксов и
    точек нет. Алгоритм: сначала снап к ближайшей линии по проекции
    (`snapPolygonToNearestLine`), затем добор вторым снапом **вдоль
    найденной линии** к перпендикулярным линиям
    (`snapPolygonToNearestLineInOneDirection` с углом найденной линии,
    57850–57859; отбраковка почти-параллельных по `deltaAng ±0.2 рад`,
    57744–57748).
- **Кто жив в конструкторе**: `WC.snapTool.snapPolygon` вызывается только из
  рулеточных состояний — `StateMakingRuler.findSnap` (68723, состояние
  68648) и `StateDraggingRuler.findSnap` (68886, состояние 68823): концы
  рулетки снапятся к граням стен, радиус тот же `WC.SNAP_DIST/scale`.
  Обе строки содержат баг: `snapPolygon` возвращает `GEOM.Point`, а код
  делает `WC.aligners = [snapRes[1], snapRes[2], snapRes[3]]` (68725,
  68888) — индексация точки даёт `undefined`, т.е. гайды у рулетки не
  рисуются никогда.
- Не путать с однофамильцем `TConf.Snap.getSnapPoint` (79481) — это снап
  плиток в редакторе раскладки покрытий, к стеновому конструктору отношения
  не имеет (79477, инстанс 79174).

Ещё один клон вне `WC`: `snapPolygonToIntersectLine[InOneDirection]`
(9578/9667) — версия для 3D-вида; конструктором не используется.

## 7. Сводная спека для порта

**Вход**: `P` (мировые см), `exceptNodes: CPoint[]`, `snapDist` (мир; в
оригинале всегда `10 px / scale`), `farNodes: CPoint[] | undefined`
(белый список внекадровых точек; `undefined` = куллинг выключен — в порте
лучше сделать куллинг всегда-on и не тащить этот баг).

**Пул кандидатов**: все вершины комнат + пола + текущего рисуемого контура;
пересборка на каждом изменении геометрии (`reset`).

**Выход**: `{ snapped: Point (округлён до 0.001), alignerX?, alignerY?,
bisAnchor?, rawAlignersX: [M,P], rawAlignersY: [M,P] }`.

**Алгоритм**:

1. Угловой снап: ближайший по манхэттену кандидат в `snapDist`
   (радиус 2 см при выключенном флаге) — побеждает всё.
2. По каждой оси независимо: два кандидата (с каждой стороны по вторичной
   оси); ключ сортировки `(осевое расстояние, затем вторичное)` с
   допусками `L_EPS=1e-8`; выжившие ≤ `snapDist` по оси; стороны
   отсекают друг друга с допуском `B_EPS=1e-4` (могут выжить обе).
   Представитель оси — ближний по манхэттену. Снап подменяет координаты
   поосно.
3. Биссектриса: угол ищется в `10 × snapDist`, линия = биссектриса угла
   контура; комбинации «биссектриса ∩ ось» приоритетнее одиночной оси;
   любой биссектрисный результат принимается только при манхэттен-дистанции
   `< snapDist`.
4. Орто-лок (по умолчанию off): оси через предыдущую и первую точку
   рисуемого контура; в лесенке ниже точечного выравнивания.
5. Всегда: округление результата до 0.001 — геометрия квантована на
   этой сетке, слияние вершин дальше по пайплайну сравнивается через
   `L_EPS`/`B_EPS` и на неё опирается.

**Гайды**: пунктир от снап-точки до каждой точки-источника (X, Y,
вершина биссектрисы + «проигравшие» дубли осей), плюс при черчении стены —
параллельный пунктир на толщине стены (предпросмотр второй грани); гайды
прячутся, когда снап-точка совпала с источником или лежит на стене; гайд
не рисуется при угле к последнему сегменту острее 135°.

**Пороги px vs мир**: единственный экранный порог — `SNAP_DIST = 10 px`;
всё остальное — производные в мире. Мировые абсолюты: 2 (fallback угла),
0.1 (`eps` замыкания контура, 66033), 5 (мин. длина сегмента для
`calcStart`, 66031), `wallsWidth = 10` (порог «клик рядом с предыдущей
точкой = закончить», 66038–66040).

## Confidence & gaps

- **Высокая уверенность**: тела `snapX`/`snapY`/`snapPerpendicular`/
  `bisectorSnap`/`getSnapPoint` прочитаны построчно (57346–57701); лесенка,
  формулы tie-breaking и все пороги взяты из кода, не из наблюдений.
  Идентичность дубликатов 57704/57771 оригиналам 9807/9742 подтверждена
  диффом нормализованного текста.
- **Семантика единиц**: «см» для мировых единиц — вывод из
  `R2D.DimensionSystem` и `wallsWidth = 10` (65864); сам код единиц не
  называет. Если мировая единица иная, все «см» в доке масштабируются, но
  соотношения px/мир не меняются.
- **`WC.snapData` из комментария** (61218 «updates WC.snapData») в коде не
  существует — фактически пишутся `WC.snapPos` и `WC.aligners`; комментарий
  устарел.
- Не прослежено до конца, в каких сценариях реально выживают **оба**
  кандидата пары M/P (нужно `dx` равное в `1e-4`): по построению это
  вертикально/горизонтально совпадающие вершины, что после квантования на
  0.001 достижимо, но частотность не проверялась в рантайме.
- Хвост `StateMakingWalls.drawAligner` после 66210 (зеркальные блоки для
  `alignersY[1]`) прочитан не полностью — по началу блока он симметричен
  предыдущим трём; риск пропущенной особенности низкий.
- Поведение `snapPolygon`-бага у рулетки (68725) описано по коду; в
  рантайме не воспроизводилось.
- `orthoAlign`-ветки лесенки (5, 7) и `orthogonalSnap` по умолчанию мертвы
  (флаг off) и активируются только кнопкой «align by axes»; их
  взаимодействие с биссектрисой (ветка 5: перезапись `A` при обоих
  `orthoX`+`orthoY`, 57665–57667 — берётся Y-вариант) выглядит как баг
  «последний выигрывает», но подтверждено только чтением.
