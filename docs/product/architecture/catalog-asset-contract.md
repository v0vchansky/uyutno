# Контракт 3D-ассета каталога (v0)

> Часть каркаса планера. Что обязан из себя представлять файл модели и её карточка, чтобы редактор мог сделать с ней всё, что описано в feature-spec ([04 — Мебель](../features/planner/04-furniture.md), [03 — Проёмы](../features/planner/03-openings.md), [05 — Материалы](../features/planner/05-materials.md), [08 — Свет](../features/planner/08-cameras-views.md), [12 — Каталог](../features/planner/12-catalog-uploads.md)). Каждый пункт выведен из уже принятого поведения редактора — ссылка на раздел спеки указана. Контракт исполняется **полностью**, упрощённых «уровней соответствия» нет (решение 2026-08-17): модель либо проходит валидацию публикации, либо в каталог не попадает.
>
> Источник паттернов — реверс roomtodo (`docs/product/reference/competitor-mechanics/04, 02, 06, 12`); их бинарный формат `ROOMTODO` не переносим, берём glTF 2.0 / GLB.

## 0. Термины

- **Ассет** — один каталожный продукт: GLB-файл + карточка (JSON) + превью. Один продукт = один GLB. Цветовые варианты — отдельные записи-варианты внутри карточки, каждый со своим GLB или (предпочтительно) с тем же GLB и другим набором дефолтных материалов слотов.
- **Слот материала** — окрашиваемая часть модели (обивка, каркас, ножки…), которую юзер перекрашивает через панель свойств ([05](../features/planner/05-materials.md), «Применение к мебели»).
- **Класс ассета** — `furniture` (мебель/декор/техника), `light` (светильник = мебель + источник света), `opening` (дверь/окно/арка), `image` (постер/ковёр — из картинки, без GLB; см. §9).
- **Пайплайн публикации** — наш серверный шаг: валидирует контракт, считает хэш, генерирует превью, при необходимости сжимает (Draco/meshopt/KTX2). Автор ассета сжатие не делает.

## 2. Единицы, оси, origin, ориентация

Выводится из [04](../features/planner/04-furniture.md) «Опорная точка (origin) объекта» и стекинга ([dd10](../reference/competitor-mechanics/deep-dives/10-furniture-stacking.md)): посадка считается по 8 углам OBB относительно origin в **центре подошвы**.

- **Единицы в файле — метры** (стандарт glTF). Импортёр умножает на 100 → внутренние см. Автор не «подгоняет» единицы под см внутри GLB.
- **Ось вверх — +Y**, правая система координат (стандарт glTF).
- **Origin (0,0,0) — центр footprint по X/Z, самая нижняя точка модели по Y** (`minY = 0` с допуском ±0.5 см). Для настенных (WALL) — то же: центр по X, `minY = 0`; посадка «на высоту» задаётся `elevation` в сцене, не смещением в файле.
- **Ориентация: лицо объекта смотрит в +Z, спина в −Z.** Для настенных объектов прижимаемая к стене плоскость — задняя, `z = minZ`; редактор ставит объект «лицом от стены» ([04](../features/planner/04-furniture.md)) поворотом вокруг Y, поэтому в файле поворот нулевой.
- **Все трансформации узлов запечены в вершины**: матрицы всех `node` — identity (позиция 0, поворот 0, масштаб 1). Иерархия узлов допускается только как группировка. Причина: параметрический ресайз (§6) и посадка работают по вершинам мешей, как в reference (`ParametricScaler` читает геометрию мешей напрямую; их лоадер принудительно обнуляет `position.y` у всех узлов).
- **Bounding box модели = габариты карточки** (`sizes.width/height/depth`, см) с допуском ±0.5 см; никаких «висящих» вершин/пустых мешей, раздувающих bbox — bbox и есть footprint для снапа/линеек ([04](../features/planner/04-furniture.md), «Snap-логика»).

## 3. Геометрия

- Только треугольники (`mode = 4 TRIANGLES`), индексированные буферы, `float32` позиции (или квантизация через `KHR_mesh_quantization`, если её сделал пайплайн).
- Нормали обязательны и корректны (сглаживание по группам сглаживания, hard edges через дублирование вершин). Вершинные цвета как единственный источник цвета — запрещены.
- Один набор UV (`TEXCOORD_0`) обязателен на каждом меше с текстурой; UV в диапазоне 0..1 без наложений для запечённых карт (атлас допустим); второй набор (`TEXCOORD_1`) — только под AO.
- Без вырожденных треугольников, дублей вершин сверх необходимого, «внутренней» невидимой геометрии (внутренности мягкой мебели, полости), пересекающихся оболочек, которые дают z-fighting.
- Замкнутость (watertight) не требуется. Двусторонние материалы (`doubleSided`) — только там, где реально нужны (тонкие листы: абажур, полотно шторы).
- **Бюджет треугольников (жёсткий, на весь продукт):**

| Класс                                                                                           | Лимит    | Ориентир                           |
| ----------------------------------------------------------------------------------------------- | -------- | ---------------------------------- |
| декор/малые предметы (smart-стекинг, ≈ куб < 31 см — [04](../features/planner/04-furniture.md)) | ≤ 6 000  | ваза, книга, светильник настольный |
| стулья, столы, тумбы, техника                                                                   | ≤ 15 000 |                                    |
| диваны, кровати, шкафы, кухни                                                                   | ≤ 30 000 |                                    |
| проёмы (дверь/окно с рамой и створкой)                                                          | ≤ 8 000  |                                    |

Проверяется валидатором. Сцена из 50 предметов должна укладываться в ~1 М треугольников.

## 4. Структура мешей и слоты материалов

Из [05](../features/planner/05-materials.md): «модель имеет несколько окрашиваемых частей … каждая часть — отдельный слот»; и [04](../features/planner/04-furniture.md): reference объединяет меши с одинаковым материалом в один набор для перекраски.

- **Слот = glTF-материал.** Все примитивы, ссылающиеся на один `material`, — один слот. Число слотов на модель: **1–6**.
- **Имя материала = имя слота**, latin snake_case из словаря: `upholstery`, `frame`, `legs`, `top`, `body`, `front` (фасады), `handles`, `cushion`, `mattress`, `glass`, `mirror`, `metal`, `wood`, `fabric`, `shade` (абажур), `lamp` (светящаяся часть, §7), `leaf` (створка проёма, §8), `casing` (рама/наличник проёма). Расширение словаря — через этот документ. Валидатор отклоняет материалы с именами вне словаря или пустыми (`Material.001`).
- **Непере­крашиваемые слоты** помечаются в карточке (`slots[].paintable=false`) — стекло, экраны, зеркала: юзер их в списке частей не видит. Всё остальное перекрашивается каталожным материалом; при перекраске редактор заменяет `baseColorTexture`/цвет и tiling слота, сохраняя нормали/roughness модели, если каталожный материал их не несёт.
- Каждый слот несёт **дефолтный материал** двумя способами: (а) собственная запечённая PBR-текстура в GLB (то, что видно «как есть», [05](../features/planner/05-materials.md) «Материалы GLB-моделей каталога»), (б) опционально `slots[].defaultMaterialId` — ссылка на каталожный материал, чтобы «вернуть заводской» и чтобы цветовые варианты продукта задавались без второго GLB.
- Меши именуются `<slot>[_<n>]` (`legs_1`, `legs_2`) — имя меша информационно; связь со слотом идёт через материал.

## 5. PBR-материалы и текстуры в GLB

- Модель — только `pbrMetallicRoughness`. Разрешённые карты: `baseColorTexture` (**sRGB**), `metallicRoughnessTexture`, `normalTexture`, `occlusionTexture` (линейные). `emissiveTexture`/`emissiveFactor` — только у слота `lamp` (§7).
- **Цветовое пространство**: baseColor — sRGB, всё остальное — linear; ничего не пре-линеаризовать (см. [threejs-r185-migration.md](threejs-r185-migration.md) §1; в reference был legacy force-linear — не воспроизводим, [05](../features/planner/05-materials.md)).
- Разрешение текстур: степень двойки, **≤ 2048** на сторону в файле; целевое 1024 для мебели, 512 для декора; пайплайн может даунскейлить. Суммарный объём текстур продукта — в пределах лимита файла §1.
- Прозрачность: `alphaMode = BLEND` только для стекла/тюля/абажуров, `MASK` — для вырезов (листва); всё остальное `OPAQUE`. Прозрачные слоты — `paintable=false` или отдельный набор материалов «стекло» (решение каталога).
- Без «запечённого света» в baseColor (тени/блики в альбедо): сцена освещается своим светом ([08](../features/planner/08-cameras-views.md)); генераторы с опцией «remove lighting» — включать.
- Один атлас на всю модель **допустим** при условии, что слоты всё равно разделены материалами (материалы могут ссылаться на одну текстуру с разными UV-регионами). Один материал на всю модель = один слот; для мебели с очевидно разными частями (диван: обивка/ножки) валидатор публикации не пропустит одно-слотовую модель, если в карточке заявлено `slots > 1`.

## 6. Параметрический ресайз (per-mesh разметка)

Из [04](../features/planner/04-furniture.md) «Параметрический ресайз»: «у каждого меша модели прописано, по каким осям он тянется и какой край является якорем». В reference разметка лежит в glTF `extras` каждого меша (`userData.scale/fix`, [04-furniture-placement §7.1](../reference/competitor-mechanics/04-furniture-placement.md)) — берём тот же механизм.

- Модель **параметрична**, если у **каждого** меша в `mesh.extras` (или `node.extras`) есть оба поля:
  - `scale ∈ {"no","horizontal","vertical","all"}` — по каким осям меш тянется при изменении width/height (глубина `depth` масштабируется у всех мешей всегда);
  - `fix ∈ {"left","right","top","bottom","topLeft","topRight","bottomLeft","bottomRight","axis","topAxis","bottomAxis","no"}` — якорь: что остаётся на месте.
- Если разметка есть не у всех мешей — валидатор **отклоняет** файл (нет «полупараметрических» моделей: reference трактует такую модель как непараметрическую молча — мы этого не хотим).
- Модель без разметки — **непараметрическая**: ресайз = масштабирование целиком (`scaleX/Y/Z` к дефолтным габаритам), UV перекладываются по направлению растяжения, чтобы текстура не тянулась ([04](../features/planner/04-furniture.md)).
- **Какие продукты обязаны быть параметрическими** (валидатор проверяет по категории карточки): шкафы, стеллажи, комоды, кухонные модули, столы, кровати, диваны, окна и двери (рама тянется, створка/наличник — по правилам). Декор, стулья, техника, светильники — непараметрические.
- Требования к геометрии параметрических моделей: детали, которые не должны тянуться (ножки, ручки, фурнитура), — отдельными мешами с `scale:"no"`; «швы» между смежными мешами — вершины **точно совпадают** по координатам (движок находит общие вершины смежных мешей и двигает их синхронно — [04](../features/planner/04-furniture.md) «шовные вершины»); UV корректируются пропорционально приросту.
- Карточка дублирует флаг `parametric` (валидатор сверяет с содержимым GLB) и задаёт диапазон допустимых размеров `sizes.min/max` внутри общего клампа редактора [1 см, 10 м] ([06](../features/planner/06-selection-transform.md)).

## 7. Светильники

Из [08](../features/planner/08-cameras-views.md) «Освещение» и reference `LightViewer3D`: три типа ламп, включение/цвет/яркость 0–100, лимит 9 источников на сцену, «стекло плафона» светится и становится полупрозрачным.

- Класс `light` = обычная модель по §1–6 плюс:
  - слот `lamp` (glTF-материал с именем `lamp`) — светящаяся часть (плафон/колба); при включении редактор даёт ей emissive цвета света и подменяет на полупрозрачное стекло; `paintable=false`.
  - в карточке блок `light.sources[]` — 1–3 источника: `{type: "spot"|"point"|"area", offset:[x,y,z] см от origin, angleDeg? (spot), size:[w,h]? (area), direction? (spot/area, по умолчанию вниз)}`, плюс `light.defaultColor` (hex) и `light.defaultPower` (0–100). Источники в самом glTF (`KHR_lights_punctual`) не используются, чтобы схема была наша и лимит 9 считался по карточке.
  - позиции источников масштабируются вместе с моделью (reference `update`), поэтому `offset` — в координатах немасштабированной модели.

## 8. Проёмы (двери, окна, арки)

Из [03](../features/planner/03-openings.md): проём = каталожная модель на оси стены; дырка режется по 2D-контуру; ширина/высота — `scaleX/scaleY`, подоконник — `elevation`, зеркала — `flipX/flipY`; толщина обналички = толщине стены; 3D-модель получает напуск +1 см поверх толщины стены; арка = дверь с пустой створкой; дефолты хранятся в карточке (`scaleX/scaleY/elevation/flipX/flipY/contour`).

- Класс `opening`, подтип `kind ∈ {door, window, arch}` — только для UI-категории ([12](../features/planner/12-catalog-uploads.md)); механика у всех одна.
- **Контур выреза** (`opening.contour`) — в карточке, не в GLB: замкнутый полигон в плоскости стены, координаты в **см**, `x` вдоль стены (0 = центр проёма), `y` вверх (0 = нижний край проёма; `elevation` добавляет редактор), обход против часовой, без самопересечений, 4–64 точки. Прямоугольник — 4 точки; арка — дуга полилинией. Правило зеркалирования `flipX` — `x → −x` (как в reference).
- **Геометрия GLB проёма**: origin — центр проёма по X на уровне низа проёма (`minY = 0`), плоскость стены — `z = 0`; модель симметрична по глубине вокруг `z = 0` и авторится на **номинальной глубине 10 см**; редактор растягивает по Z до `толщина стены + 1 см`. Всё, что не должно тянуться по глубине (ручка, выступ подоконника), — не поддерживается в v0: авторить проёмы «плоскими по глубине».
- Обязательные слоты: `casing` (рама/коробка/наличник — параметрична: `scale:"all"`, якоря по краям), `leaf` (створка/полотно/стёкла — тянется вместе с рамой). Арка: только `casing` (или вообще пустой GLB — тогда в 3D видна лишь обналичка, которую строит сам редактор). Материалы верхней/нижней обналички редактор строит сам ([03](../features/planner/03-openings.md), «Обналичка») — они не часть модели.
- Габариты по умолчанию и допустимые диапазоны — `opening.defaults {width, height, elevation}` и `sizes.min/max`; ширина/высота меняют модель параметрически (§6), поэтому все проёмы обязаны быть параметрическими.
- Створка в v0 всегда закрыта; анимации открывания нет.
- 2D-символ проёма на плане (условное обозначение со створкой) — **не часть этого контракта**: решается UI-спекой 2D-плана; если понадобится, добавится поле `symbol2d` (SVG вид сверху).

## 9. Постеры и ковры (image-based)

Из [04](../features/planner/04-furniture.md) («постер — гибрид smart») и reference (poster/carpet = картинка + размеры, `carpetType` square/round).

- Класс `image`: без GLB. Ассет = растр (PNG/JPEG, ≤ 2048, sRGB) + `sizes {width,height}` см + `image.kind ∈ {poster, carpet}` + для ковра `shape ∈ {rect, round}`; толщина фиксирована редактором (постер ~2 см с рамой, ковёр ~1 см). Редактор строит меш сам.
- Постер, поставленный как glTF-модель (картина в объёмной раме), — обычный `furniture` с `appointment: wall` ([04](../features/planner/04-furniture.md), «Постер как glTF-пакет»).

## 10. Карточка продукта (JSON) — поля

Хранится на сервере, отдаётся каталогом; в проект сохраняется только `id` (+ вариант) ([10](../features/planner/10-save-load.md)).

```jsonc
{
  "id": "sofa-oslo-3", // стабильный, только [a-z0-9-]
  "version": 3, // растёт при любой замене GLB/карточки
  "class": "furniture", // furniture | light | opening | image
  "name": { "ru": "Диван Осло 3-местный", "en": "…" },
  "category": "furniture/sofas", // путь в дереве категорий (12)
  "tags": ["диван", "скандинавский", "3-местный"],
  "appointment": "floor", // floor | wall | universal (04); ceiling — производное smart-логики
  "sizes": {
    // см; равны bbox GLB ±0.5
    "width": 210,
    "height": 84,
    "depth": 92,
    "min": { "width": 160, "height": 84, "depth": 92 }, // только если parametric
    "max": { "width": 320, "height": 84, "depth": 92 },
  },
  "fixedSize": false, // true → ресайз-грипы и числовой ресайз недоступны (06)
  "keepRatio": false, // пропорциональный ресайз по умолчанию (04)
  "parametric": true, // сверяется с extras в GLB (§6)
  "slots": [
    // порядок = порядок в панели свойств

  ],
```

## 12. Валидатор публикации (чеклист)

Автоматическая проверка на сервере при `draft → published`. Любой пункт «нет» = отказ с кодом ошибки.

1. GLB парсится, glTF 2.0, нет внешних `uri`, расширения — только из белого списка §1, нет анимаций/скинов/морфов/камер/`KHR_lights_punctual`/`KHR_materials_variants`.
2. Размер файла ≤ 8 МБ; текстуры ≤ 2048, степень двойки, baseColor sRGB.
3. Все узлы — identity-трансформы; `minY = 0 ± 0.5 см`; центр bbox по X/Z в 0 ± 0.5 см; bbox = `sizes` ± 0.5 см (после ×100).
4. Треугольники в бюджете класса §3; нормали и `TEXCOORD_0` присутствуют; нет вырожденных треугольников; нет пустых мешей.
5. Имена всех материалов — из словаря §4, число слотов 1–6, `slots[]` карточки ↔ материалы GLB совпадают 1:1; `emissive` только у `lamp`.
6. Параметрика: либо у всех мешей есть валидные `extras.scale`+`extras.fix`, либо ни у одного; `parametric` в карточке совпадает; категории из обязательного списка §6 — параметричны; при параметрике `sizes.min/max` заданы и лежат в [1 см, 10 м].
7. `light`: 1–3 источника, типы/поля валидны, есть слот `lamp`.
8. `opening`: контур замкнут, без самопересечений, 4–64 точки, обход CCW; `defaults` внутри `min/max`; слоты `casing` (+`leaf` для door/window); модель параметрична; глубина bbox = 10 см ± 0.5.
9. `variants[]` уникальны, `slotDefaults` ссылаются на существующие слоты и опубликованные материалы.
10. md5 совпадает с уже опубликованным ассетом → отказ «дубликат» (паттерн reference).
11. Превью 240×240 сгенерировано.

## 13. Пайплайн v0: AI-генерация → нормализация → публикация

Решение 2026-08-17: источник моделей — топ каталога roomtodo, генерируем через AI (Meshy как первый кандидат); упрощать контракт под возможности генератора **не будем** — недостающее закрывается ручным шагом в Blender.

Матрица «что даёт Meshy из коробки vs что нужно доделать» — по публичным докам Meshy (Image-to-3D API, авг. 2026); пометка «проверить» = уточнить на реальном тесте:

| Требование контракта                                                          | Meshy                                                                                                              | Ручной/скриптовый шаг                                                                                                     |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| GLB, встроенные текстуры                                                      | ✅ `model_urls.glb`                                                                                                | —                                                                                                                         |
| PBR (baseColor/metallic/roughness/normal)                                     | ✅ `enable_pbr: true`; `remove_lighting` убирает запечённый свет                                                   | проверить, что baseColor без бликов                                                                                       |
| Полигонаж в бюджете                                                           | ✅ `target_polycount` 100–300k, `topology: triangle`; `should_remesh`                                              | decimate в Blender, если результат выше бюджета                                                                           |
| Текстуры ≤ 2048                                                               | ✅ `texture_resolution: 2k`                                                                                        | —                                                                                                                         |
| Единицы/масштаб                                                               | ⚠️ `auto_size` — AI-оценка реального размера, точности контракта (±0.5 см к карточке) не даёт                      | Blender: масштаб к `sizes` карточки                                                                                       |
| Origin в центре подошвы, identity-трансформы, лицо в +Z                       | ❌ не управляется                                                                                                  | Blender: apply transforms, origin to bottom-center, поворот                                                               |
| **Слоты материалов (несколько glTF-материалов по именам словаря)**            | ❌ один атлас/один материал на модель; Auto Split режет только нетекстурированные модели и предназначен для печати | Blender: разделить меш по частям, назначить материалы `upholstery/legs/…`, перепечь/перерезать UV по слотам               |
| **Параметрическая разметка `extras.scale/fix`, совпадающие «шовные» вершины** | ❌                                                                                                                 | Blender: разбить на меши по правилам §6, проставить custom properties (glTF-экспортёр пишет их в `extras`), выровнять швы |
| Проёмы: контур, слоты `casing`/`leaf`, глубина 10 см, параметрика             | ❌ (генерировать дверь как «объект» бессмысленно)                                                                  | ручное моделирование в Blender по шаблону (рама + полотно), контур — из шаблона                                           |
| Светильники: слот `lamp`, `light.sources`                                     | ❌                                                                                                                 | Blender: выделить плафон в материал `lamp`; источники — в карточке руками                                                 |
| Отсутствие внутренней геометрии, чистые нормали                               | ⚠️ генераторы дают «оболочку», внутренностей обычно нет, но нормали/дубли — проверить                              | Blender: cleanup, recalc normals                                                                                          |
| Превью 240×240                                                                | ⚠️ у Meshy есть `thumbnail_url`/`multi_view_thumbnails`, но не наш ракурс/фон                                      | наш пайплайн рендерит сам                                                                                                 |

Вывод: Meshy закрывает **сырую форму и текстуру** (пункты 1–4 чеклиста, частично 2–3), но не структуру (слоты, параметрика, origin, проёмы, свет). Реалистичный пайплайн v0 на один предмет: Meshy → Blender-шаблон (скрипт: масштаб/origin/apply transforms + ручная разбивка на слоты и параметрическая разметка) → экспорт GLB → валидатор → публикация. Проёмы и светильники — Blender с нуля по шаблонам. Ориентир трудозатрат на «якорный» параметрический предмет (диван/шкаф) — часы, не минуты; на декор — минуты.
