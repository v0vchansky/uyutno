# Скоуп v0

- Статус: В работе
- Дата: 2026-08-08
- Автор: @v0vchansky

## Цель релиза

Вывести в прод работающий 2D/3D-редактор с минимальным каталогом мебели, начать индексацию домена в поисковиках и получить первые 100-500 уникальных органических пользователей в месяц для валидации базового UX перед вложениями в killer features v1.

Killer features из [vision.md](./vision.md) (AI-каталог, каталог планировок ЖК, загрузка своей мебели) в v0 отсутствуют — цель v0 в базе, на которую v1 будет наслаиваться.

## Основной пользовательский сценарий

1. Пользователь заходит на главную страницу.
2. Жмёт «Собрать свою планировку» (или сначала «Посмотреть пример» → потом «Собрать свою»).
3. Регистрируется через email/пароль, Yandex ID или VK ID.
4. Создаёт проект.
5. Рисует стены в 2D-режиме.
6. Расставляет мебель из каталога.
7. Переключается в 3D посмотреть, как это выглядит.
8. Проект сохраняется автоматически.

## Скоуп

### Аутентификация

- Регистрация и вход через **email/пароль**, **Yandex ID**, **VK ID**.
- Без гостевого режима: свой проект = только через регистрацию.
- Обычные пути восстановления: сброс пароля по email для email/пароль-регистрации.

### Проекты

- У одного пользователя может быть несколько проектов.
- У каждого проекта: название, дата создания, дата последнего изменения, thumbnail (скриншот 3D-вида).
- Действия: создать, открыть, переименовать, удалить, дублировать.
- Автосохранение при изменениях (короткий debounce) + явная кнопка «Сохранить».
- Личный кабинет со списком проектов на странице `/projects`.

### Редактор

2D/3D-редактор со стенами, дверями, окнами, расстановкой мебели из каталога, переключением 2D↔3D, undo/redo, snap-системой. Детальный скоуп — в `features/editor.md` перед началом работы над редактором.

### Каталог мебели

- Гибкая система каталога, готовая принять произвольное число моделей без изменений редактора.
- Категоризация только по типу мебели (диваны, столы, стулья, шкафы, кровати и т.п.). Стилевые теги и фильтры не вводятся.
- Конкретное наполнение и источник моделей — открытый вопрос (см. ниже).

### Демо-проект

- Кнопка «Посмотреть пример» на главной открывает готовую планировку в редакторе.
- В демо доступны все действия редактора: двигать, добавлять, удалять мебель, крутить камеру, переключать 2D/3D. Это полноценная песочница.
- Сохранение недоступно: клик по «Сохранить» ведёт на регистрацию, изменения демо-проекта не переносятся в новый проект пользователя.

### Лендинг и страницы

- `/` — главная. Один экран: заголовок, короткое описание, две кнопки («Посмотреть пример», «Собрать свою планировку»), 2-3 скриншота редактора.
- `/login`, `/register` — аутентификация.
- `/projects` — список проектов пользователя (после логина).
- `/project/:projectId` — сам редактор.
- `/demo` — демо-проект (редактор в режиме песочницы).

### SEO-техническая база

- SSR лендинга.
- Корректные meta- и OG-теги на всех публичных страницах.
- `sitemap.xml`, `robots.txt`.
- Structured data (schema.org).
- Семантичный HTML.
- Тексты на главной — 500-1000 знаков, написанные вручную.

Активная SEO-стратегия и производство контента откладываются на неопределённый срок за пределы v0.

### Инфраструктура и Ops

- Хостинг — российский, конкретный провайдер выбирается отдельно.
- База данных — собственный PostgreSQL.
- Файловое хранилище (модели мебели, thumbnails) — конкретный провайдер выбирается отдельно.
- SSL через Let's Encrypt.
- Деплой и ролбэк — bash-скрипты, без CI-платформ.
- Продуктовая аналитика — Яндекс.Метрика.
- Приложенческие логи и ошибки — собственный self-hosted стек.
- Мониторинг доступности — внешний бесплатный сервис.
- Бэкапы БД — ежедневный дамп в файловое хранилище, retention 7 дней.

## Технические ограничения на уровне продукта

- Только веб (без нативных приложений — см. [vision.md](./vision.md)).
- Редактор работает **только на десктопе**. На мобильных устройствах — экран-заглушка с сообщением «редактор доступен только с компьютера». Лендинг и статические страницы адаптивны.
- Поддерживаемые браузеры — последние стабильные версии основных браузеров. Более старые — best effort.
- **WebGL2 обязателен** (без него 3D-редактор не запускается).

## Out-of-scope v0

Перечислено то, что явно решено не делать в v0:

- **Killer features v1** — AI-каталог, каталог планировок ЖК, загрузка своей мебели. Обоснование — в [vision.md](./vision.md).
- **Экспорт скриншота 3D-вида в PNG**.
- **Экспорт 2D-плана в PDF**.
- **Шеринг проекта по публичной ссылке**. Может быть рассмотрено в v1+.
- **Печать 2D-плана** — не планируется никогда, целевая аудитория не строители.
- **Блог и контент-маркетинг** — не планируется никогда.
- **Стилевые фильтры каталога** — вводятся в v1 вместе с наполнением, дающим критическую массу моделей по стилям.
- **Активная SEO-стратегия и производство контента** — только техническая база в v0.

Всё остальное, что не упомянуто здесь и в vision.md — не решено и не отвергнуто, обсуждается по мере возникновения.

## Метрики выхода в v1

Переход в v1 определяется по продуктовому ощущению: базовый редактор стабилен и не глючит на основных сценариях, есть первые органические пользователи, есть готовность вкладываться в killer features.

Метрики из [vision.md](./vision.md) — активация, Retention D7, органический трафик — отслеживаются со дня релиза для наблюдения тренда, но не служат жёсткими воротами перехода.

## Риски и mitigation

- **Сложность привлечения первых пользователей.**
  Mitigation: посты в соцсети, комьюнити по интерьеру и обстановке жилья, при необходимости небольшой рекламный бюджет.

- **Слабая SEO-экспертиза автора.**
  Mitigation: активная SEO-работа откладывается за пределы v0 (в v0 закрывается только техническая база). Программатический SEO становится возможным в v1 через каталог планировок ЖК — тысячи страниц с точными названиями ЖК, что естественно ищется в поисковиках.

## Открытые вопросы

- **Домен.** `uyutno.ru` занят, рассматриваются `uyutno.design`, `uyutno.app`, `uyutno.io`. Финальный выбор до релиза v0.
- **Источник моделей для первого каталога.** Из [vision.md](./vision.md): open-source (Sketchfab CC0, Poly Haven), ручное моделирование, готовые платные библиотеки, смешанное. Решается до релиза v0.
- **Минимальный объём каталога v0.** Точное число моделей не критично, важна готовность системы каталога принять любой объём. Конкретное наполнение определяется по выбранному источнику.
