# 10 — Сохранение и загрузка проекта (v0)

> Раздел feature-spec planner-v0. Единицы: 1 см = 1 юнит. Экспорт (GLTF/OBJ/PDF) — вне области v0.

## Что это

Пользователь работает в редакторе над проектом квартиры. В любой момент он может сохранить текущее состояние, а позже открыть его — сцена восстановится ровно в том виде, в каком её оставили: стены, комнаты, полы и потолки, мебель, назначенные материалы, последний ракурс камеры. Список своих проектов пользователь видит в галерее — каждая карточка показывает миниатюру плана и имя, оттуда же открывает проект в редакторе.

## Save проекта

- Триггеры:
  - Ручное сохранение: кнопка «Save» в верхней панели, шорткат Ctrl+S / Cmd+S. Дополнительно в меню «Projects» доступны «Save As» (дублирование с новым id/hash) и «Дублировать»; см. «Множественные проекты и галерея».
  - Автосохранение (см. отдельный раздел ниже).
- Индикация процесса:
  - На время сохранения кнопка «Save» переходит в состояние «идёт запись» (спиннер / disabled).
  - По завершении — короткое подтверждение («Сохранено, HH:MM») либо ошибка с человекочитаемым текстом.
- Модель конфликтов при параллельной записи из двух вкладок/устройств: **last-write-wins без предупреждения**. Save отправляется без revision/ETag; вторая запись поверх первой молча перезаписывает. Optimistic locking с revision-номером — не в v0.
- Что сохраняется:
  - Геометрия плана: стены, проёмы (окна/двери), комнаты, полы, потолки, плинтусы (верхние и нижние).
  - Все размещённые объекты: мебель, декор, светильники, ковры, постеры.
  - Материалы: назначенные на стены, полы, потолки, плинтусы, слоты мебели; их поворот и смещение текстуры.
  - Группы объектов (сохраняется факт группировки и трансформации группы).
  - Состояния камер: последняя позиция/наклон/зум для 2D-плана, 3D-orbit и режима «прогулка».
  - Скрытые элементы (что пользователь спрятал через видимость).
  - Скайбокс / фон 3D-сцены.
  - Миниатюра проекта — JPEG-превью текущего 3D-вида для галереи.
  - Импортированная подложка плана (если загружалась — см. 11), с её позицией и масштабом.
  - Пользовательские линейки/размеры, нарисованные поверх плана.
- Что НЕ сохраняется:
  - Стек undo/redo — после повторного открытия история пустая.
  - UI-состояние: какая панель раскрыта, что выделено, положение сплиттеров.
  - Сами 3D-модели и текстуры материалов — только их идентификаторы из каталога; при загрузке подтягиваются заново.
- «Save As» / «Скопировать себе» сохраняет копию из того состояния, в котором пользователь сейчас смотрит проект: в копию попадают все скрытые/показанные элементы, положения камер, видимости — ровно как на экране, а не последний серверный снимок. Это относится и к режиму «только просмотр»: если пользователь открыл чужой проект, что-то отключил или покрутил камеру, и нажал «Скопировать себе» — копия сохранится в этом виде.

## Load проекта

- Триггеры:
  - Клик по карточке проекта в галерее.
  - Открытие ссылки на проект (собственный или расшаренный, см. «Шаринг»).
- Индикация:
  - Прогресс-индикатор поверх canvas: сначала «загружаем проект», затем «подгружаем модели и материалы».
  - Редактор становится интерактивным только после того, как сцена полностью восстановлена.
- Порядок восстановления сцены:
  1. Геометрия плана (стены, проёмы, комнаты, полы, потолки).
  2. Материалы стен, полов, потолков и плинтусов.
  3. Размещённые объекты (мебель, декор, свет), затем группы.
  4. Материалы слотов мебели.
  5. Импортированная подложка плана (если была).
  6. Последний ракурс камеры пользователя.
- Ошибочные сценарии:
  - Проект битый / не удалось разобрать — модалка «Не удалось открыть проект», кнопки «Попробовать ещё раз» и «Вернуться в галерею». Редактор не остаётся в наполовину загруженном состоянии.
  - Часть моделей/материалов не подтянулась из каталога — плейсхолдер на месте объекта + плашка «N объектов не удалось загрузить», с возможностью повторить.
  - Проект сохранён более новой версией формата, чем поддерживает текущий клиент — сообщение «Обновите редактор, чтобы открыть этот проект».

## Версионирование формата

- В файл проекта пишется идентификатор формата и его версия.
- При загрузке клиент выбирает нужную процедуру разбора по версии; неизвестные/новые версии пытаются открыться в режиме совместимости, а если ключевые поля не совпадают — показывают ошибку из раздела выше.
- В v0 существует одна версия формата; миграций между версиями пока нет — как только появится вторая, добавляется явный шаг миграции при открытии старых проектов.
- Миграция формата — silent side-effect на load, **не пушится в undo/redo**. Пользователь не должен «откатить» миграцию через Ctrl+Z (см. 09-undo-redo).

## Превью проекта

- Каждое ручное сохранение генерирует JPEG-миниатюру текущего активного вьюпорта: 3D-orbit, 2D-план, режим прогулки или конструктор — что было на экране, то и снимается.
- Разрешение: **1280×720** для обычных вьюпортов, **265×150** для режима прогулки (walk).
- Снимается через `toDataURL("image/jpeg")` активного канваса, с отключённым SSAO ради ускорения.
- Автосохранение превью **не пересчитывает** — обновляется только ручным Save.
- Миниатюра хранится внутри самого файла проекта — отдельного файла для превью нет.
- Отображается на карточке в галерее проектов и в списках «недавние».
- Если пользователь ни разу не заходил в 3D до первого сохранения (сохранение из чистого 2D) — карточка показывает 2D-снимок; нейтральный плейсхолдер — только если снимок не удалось получить вовсе.

## Множественные проекты и галерея

- Пользователь может иметь произвольное количество проектов.
- Галерея проектов — отдельный экран вне редактора: сетка карточек с превью, именем, датой изменения.
- Действия над проектом:
  - Создать новый (пустая сцена).
  - Открыть в редакторе.
  - Переименовать.
  - Дублировать (создаётся копия со своим идентификатором и своим именем). Тот же сценарий доступен из меню редактора как «Save As» — сервер минтит новую пару id + hash.
  - Удалить (с подтверждением; если удаляют открытый проект — редактор возвращается к пустой новой сцене). Удаление — soft-delete, см. «Корзина» ниже.
- У каждого проекта есть два вида ссылок:
  - Приватная — для самого владельца, требует авторизации. Внутри системы проект адресуется числовым `id`.
  - Публичная share-ссылка — режим «только просмотр»: URL строится вокруг случайного `hash` (не человекочитаемого имени). Получатель открывает проект в редакторе, но не может сохранять изменения поверх оригинала. Владелец включает/выключает шаринг явно. Механизм revoke ранее выданной ссылки (перевыпуск hash) — в бэклоге, в v0 достаточно тумблера «шаринг on/off».

## Корзина и удаление проектов

> **Осознанное отклонение.** Удаление проекта идёт через soft-delete + 30-дневную «Корзину» с возможностью восстановления. Типовой отраслевой паттерн интерьер-редакторов — hard-delete сразу; мы даём пользователю окно на «передумать», потому что потеря планировки квартиры болезненнее, чем чуть более сложная модель хранения.

- Удаление проекта из галереи — **soft-delete**. Проект помечается флагом `deleted_at` и уходит в отдельный раздел «Корзина» на 30 дней.
- В «Корзине»: список удалённых проектов с превью, именем и датой удаления; кнопка «Восстановить» возвращает проект в основную галерею с исходным id.
- Через 30 дней с момента удаления проект автоматически hard-delete'ится cron-задачей на бэке. Ручного «Удалить навсегда» из UI в v0 нет — пользователь всегда знает, что у него есть 30 дней, чтобы передумать.

## Автосохранение

В v0 автосохранение работает на двух уровнях, независимо от ручного «Save». Оба таймера запускаются с задержкой 5 секунд после старта редактора (чтобы не молотить сохранения сразу на инициализации):

- Локальный черновик (localStorage):
  - Периодичность: каждые **30 секунд**.
  - Diff-guarded: реальный `setItem` идёт только если сериализованный JSON отличается от прошлого — при простое запись пропускается.
  - Ключ вида `planner_project_<hash>_<userKey>`; для гостя используется отдельный ключ гостевой сессии. Цикл «гость → логин → работа → логаут»: при логине гостевой черновик уже уехал на сервер отдельным проектом (см. «Мёрдж черновика после логина»), гостевой ключ очищен; дальнейшая работа пишется под ключом аккаунта; после логаута новый гостевой сеанс стартует пустым — история не теряется, она лежит в проектах аккаунта. (У reference ключ черновика от пользователя не зависит и логин/логаут его не трогают — там этой развилки просто нет; у нас она разрешена переносом на сервер.)
  - Назначение: не потерять работу при случайном закрытии вкладки, обрыве связи, перезагрузке. При следующем открытии того же проекта, если для него есть локальный черновик, редактор молча загружает **черновик**, а серверную загрузку пропускает — без сравнения содержимого и без модалки «восстановить?» (принято по reference). Серверная версия догоняет черновик при следующем сохранении.
  - Превью при таком автосохранении не пересчитывается.
- Серверное автосохранение:
  - Периодичность: **раз в 60 секунд**.
  - Срабатывает только если: проект уже сохранён на сервере хотя бы раз (есть `projectId`), стек истории «грязный» (были изменения с последнего save), и текущий пользователь — владелец проекта (просмотр чужого расшаренного проекта никогда не автосохраняется).
  - Ошибка серверного автосохранения: без модалок и тостов — рядом с кнопкой Save появляется тихая иконка предупреждения, по hover — тултип «Не удалось сохранить на сервер, HH:MM; изменения сохранены локально». Ретрая по таймеру нет — следующий тик через 60 с при наличии изменений повторит попытку сам; иконка снимается при первом успешном сохранении. Ошибка **ручного** Save — модалка с текстом ошибки (как в reference; там автосейв при ошибке молчит вовсе, только консоль — наша иконка это минимальное расширение).
  - Явное ручное сохранение не заменяется автосохранением — только оно обновляет превью.
- Индикация:
  - Ненавязчивая — статус «Автосохранено, HH:MM» рядом с кнопкой «Save».
  - При ошибке автосохранения — тихая иконка предупреждения; ручное «Save» остаётся основным способом гарантированно закрепить состояние.

## Storage backend и авторизация

- **Гибридное хранение**: localStorage для черновика + сервер для канонической версии проекта. IndexedDB в v0 не используется — объём проекта укладывается в localStorage-квоты.
- **Guest-режим разрешён**: можно редактировать без аккаунта. Гостевой проект живёт только в localStorage под отдельным ключом (`planner_project_guest`).
- **Сохранение на сервер — жёсткий гейт логина**. Кнопка «Save» и серверный автосейв недоступны гостю; при попытке сохранить показывается модалка «Войдите, чтобы сохранить проект».
- **Мёрдж черновика после логина**: если у гостя был локальный проект и он залогинился/зарегистрировался — черновик автоматически переносится на сервер как новый проект под этим аккаунтом, гостевой ключ очищается. Merge с уже существующими проектами не делаем — гостевой черновик всегда становится отдельным проектом, чтобы ничего не затереть. Юзер видит: сразу после логина в галерее появляется новая карточка с именем черновика (по умолчанию «Без имени») и превью 2D-плана. Отдельного диалога «Оставить черновик? / Отбросить?» нет — перенос молчаливый, юзер потом сам может удалить лишнее из галереи.

## Крайние случаи

- Ручное «Save» во время активного drag/трансформации — сохранение откладывается до отпускания мыши, чтобы не писать промежуточную геометрию.
- Одновременный ручной save и серверное автосохранение — работает очередь: пока один запрос в полёте, второй ждёт; в UI это единый статус «идёт сохранение».
- Пользователь закрыл вкладку до завершения сохранения — локальный черновик страхует; при следующем открытии загружается черновик (см. «Локальный черновик»).
- Пользователь сохранил проект во второй вкладке и вернулся в первую с более старым черновиком — при следующем открытии проекта локальный черновик всё равно побеждает молча (следствие правила «локальный без сравнения»); принято по reference, пересмотреть, если сценарий проявится на юзер-сессиях.
- Оффлайн — ручное «Save» показывает ошибку «нет сети, изменения сохранены локально»; черновик продолжает писаться, серверная синхронизация возобновляется автоматически при восстановлении сети.
- Очень большой проект (много мебели/высокополигональные модели) — операция сохранения может занять больше секунды. В v0 клиент не проверяет размер payload перед отправкой (POST уходит как есть), а лимит на число проектов и предупреждения по квотам приходят с сервера в ответе на save/create.
- Открытие расшаренной ссылки без авторизации — режим «только просмотр», кнопка «Save» скрыта, «Save As» / «Скопировать себе» доступна авторизованным.

## Режим «только просмотр» — что можно и чего нельзя

При открытии расшаренной ссылки владельцем-другим пользователем (или самим владельцем в анонимном браузере):

- Что доступно: смотреть 2D-план, вращать 3D-orbit, ходить по walk-режиму (все три вида камеры), переключать вид, менять локальный зум/pan, скрывать/показывать отдельные элементы для собственного удобства просмотра.
- Что недоступно: любые редактирующие инструменты (стены, мебель, материалы), Ctrl+Z/Y (нечего откатывать — истории не ведётся), кнопки Save/Save As для гостя (для авторизованного — доступна только «Save As / Скопировать себе»), удаление проекта.
- Локальные изменения (передвинутая камера, скрытые элементы «для себя») не сохраняются и сбрасываются при перезагрузке страницы.

## Крайние случаи (продолжение)

- Save во время активного drag/трансформации откладывается до отпускания мыши. Если юзер держит мышь дольше следующего цикла таймера (30/60 сек), таймер тихо пропускает свой тик; при отпускании — save запускается на ближайшем тике, не сразу. Ручной Ctrl+S во время drag — та же логика (ожидает отпускания).

## Открытые вопросы

- **Soft-delete + прямая ссылка на удалённый проект (нужно продуктовое решение)** — reference не различает soft/hard. Наше предложение: прямая ссылка на soft-deleted проект → показать «Проект в корзине, восстановить?» (кнопка); на hard-deleted → 404.
