# Planner — feature spec

> Продуктовое описание 3D-редактора планировок uyutno. Живой документ — правится по мере развития фичи, без v0/v1 разделения. Feature-spec, не архитектура (см. ADR отдельно). Планировочная механика унаследована из провалидированного реверса roomtodo.com (см. `docs/product/reference/competitor-mechanics/`).

## Что это

Веб-редактор, в котором пользователь может нарисовать план квартиры/дома, расставить мебель, покрасить стены/полы, походить внутри в 3D и сохранить проект. Планер живёт в контексте платформы uyutno (авторизация, БД проектов — уже есть в платформе).

## Вне скоупа планера

- **Экспорт в файлы:** GLTF, OBJ, FBX, PDF, PNG-снапшоты сцены, 360°-панорамы, IFC.
- **AI-рендер:** фотореалистичные превью через нейросети, upload-model-AI, tour360°.
- **Платные функции:** платные пресеты рендера, платные пакеты моделей, кредиты, подписки, чекаут.
- **Аккаунты и биллинг:** живут в платформе, не в планере. Планер получает контекст текущего пользователя от платформы.
- **Share/collaboration:** публичные read-only ссылки на проекты, совместное редактирование, комментарии. В v0 проект открывает только владелец в полном режиме редактирования; read-only режима планера нет (см. [backlog.md](backlog.md)).
- **Аналитика (GA/GTM/метрика):** живёт в платформе. Планер в v0 событий использования инструментов не шлёт; тонкий хук-эмиттер событий инструментов — бэклог (решение 2026-08-17).

## Единицы и координаты

- **Внутренняя единица (модель, все константы):** 1 см = 1 юнит. Все геометрические расчёты — в см. Не меняется. Константы: `SNAP_DIST=10`, `MIN_WALL_LENGTH=15`, `DEFAULT_WALL_WIDTH=10` (офсет при рисовании), `MAX_WALL_WIDTH=80` (порог детектора оси стены), `DEFAULT_WALL_HEIGHT=280`, `radiusDropElement=10`.
- **Длины в UI:** см по умолчанию. Пользователь может переключить в **м / мм** — переключателем в редакторе, в группе контролов холста (решение автора 2026-08-19; см. раздел 07 «Измерения»). Переключение — глобально для документа, ре-парсит все инпуты и лейблы. **Имперской системы (футы+дюймы) в продукте нет.**
- **Площади в UI:** всегда м². Не переключается. Пользователь никогда не видит «450000 см²» — только «45 м²» (как в roomtodo).
- **Объёмы в UI:** всегда м³ (по аналогии, если появятся).
- **Углы:** градусы.

Смысл: базовая единица `см` безопасна для геометрии (целые числа, нет накопления ошибок округления), но derived-величины (площадь, объём) автоматически форматируются в человекочитаемое. Пользователь не думает о сантиметрах в контексте площади.

## Принципы

1. **Контур-first.** Стены не самостоятельны — пользователь рисует замкнутые контуры, стены и комнаты выводятся автоматически. Все правки — на контуре.
2. **Одна модель.** Один источник правды — контур + прикреплённые к нему сущности (полы, потолки, мебель, проёмы). 3D-сцена — memoized-проекция, не отдельная модель.
3. **Один автомат.** Редактор в каждый момент находится в одном режиме. Никаких трёх параллельных стейт-машин, как у roomtodo.
4. **Snap-first UX.** Магнитное выравнивание — базовое поведение всех инструментов, а не отдельная кнопка.
5. **Реалтайм-rebuild.** После любой правки — комнаты/полы/потолки/плинтусы/проёмы пересобираются мгновенно.
6. **Три вида — один документ.** 2D top / 3D orbit / walk-through — одна модель, разные проекции. Состояние камер сохраняется между переключениями.

## Зафиксированные продуктовые решения

- **Multi-floor:** data-model поддерживает `floors: [Floor]`, но в UI показываем только один этаж — переключатель этажей и лестницы вынесены в бэклог. Задел на будущее без breaking change в save-формате.
- **Undo:** in-memory stack глубиной 100. Сбрасывается при закрытии проекта — как в Figma, Sketch, roomtodo. Автоверсии проекта (Figma-style version history) — в бэклоге, не блокер.
- **Storage:** облако (наш API). Никакого IndexedDB. Планер расширяет схему проекта в БД планировочными данными.
- **Save-стратегия:** `Ctrl+S` + два независимых автотаймера — **локальный черновик в localStorage раз в 30 сек** (страховка от закрытия вкладки, diff-guarded, обновляется всегда при наличии изменений) и **серверное автосохранение раз в 60 сек** (только когда история «грязная», проект уже был сохранён на сервере хотя бы раз, и юзер — владелец проекта). Не dirty — сеть не гоняем. Ручной Ctrl+S — единственный триггер, который обновляет превью проекта. Детали — в [10-save-load.md](10-save-load.md).
- **Толщина стен:** не хранимый атрибут (как в reference) — стена есть «мясо» между гранями контуров; при рисовании лента откладывается на константу `DEFAULT_WALL_WIDTH=10`; «ширина» выбранной стены = сдвиг её стороны. Явное поле толщины и настраиваемый дефолт — в [backlog.md](backlog.md). Детали — в [01](01-walls-and-contours.md) и [07](07-measurements.md).
- **Custom uploads (моделей и текстур):** не в MVP планера. Каталог из коробки — только наш контент. Uploads вынесены в [backlog.md](backlog.md) как отдельная фича L-размерности.
- **Units:** см как база (см. раздел «Единицы и координаты»), площадь всегда м².
- **Устройства:** планер работает только на desktop. На touch-устройствах — заглушка «откройте на компьютере». Просмотр с планшета/телефона и полная touch-поддержка редактирования — в [backlog.md](backlog.md) как две отдельные фичи. **При выборе технических решений стоит закладываться на будущее touch-поддержку, если это не сложно и не значительно** (например: pointer events вместо MouseEvent, размеры UI через CSS-переменные — стоят копейки, экономят месяцы потом; переверстка mobile-layout — не сейчас).
- **Multi-material поверхности:**
  - **Полы:** как в roomtodo — пол можно нарезать на «tiles» с разными материалами (кухня-плитка + гостиная-ламинат в одной студии).
  - **Стены:** в v0 одна сторона стены несёт один материал на всю плоскость — «база» (цвет) + «финиш» (текстура), как в roomtodo. Многозонная раскладка стены (несколько прямоугольных материальных зон на одной стороне: панель снизу, полоса других обоев, акцент по центру) и roomtodo-вский «тайл-конфигуратор» стен — **не в v0**, вынесены в [backlog.md](backlog.md#rect-zones-многозонная-раскладка-стены) (решение 2026-08-17).
- **Multi-select мебели:** Ctrl/Cmd+клик выделяет несколько объектов (как в reference; Shift-клик мультивыделения нет), transform (move/rotate/scale) применяется ко всей выборке как к временной «группе». Клик мимо — выборка сбрасывается. Двойной клик по одному объекту в выборке — descend to single-select (остаётся выделенным только этот объект). Так как Ctrl/Cmd во время драга — выключатель снапа, драг **не стартует, пока зажат Ctrl/Cmd** (Ctrl-нажатие всегда трактуется как клик добавления/исключения, а не начало перемещения без снапа). **Persistent-группы (Ctrl+G с сохранением в проекте) — в [backlog.md](backlog.md).**
- **Floorplan import:** остаётся в MVP, но реализуем **под конец** разработки MVP. Механика — как в roomtodo (см. раздел [11-floorplan-import.md](11-floorplan-import.md)) + добавляем drag & drop файла прямо в 2D-канвас (у roomtodo нет). **Подложка живёт только в 2D top-view** — в 3D и walk мы её не показываем (у roomtodo это опция «текстура на полу», у нас — сознательное упрощение: подложка нужна как aid для обводки, не как декоративный ассет).
- **Walk-through 3D-режим:** в MVP как в roomtodo (см. раздел [08-cameras-views.md](08-cameras-views.md)).
- **Материалы — только через свойства объекта.** Юзер выделяет объект (стену, пол, потолок, плинтус, мебель) → в панели свойств кликает «выбрать материал» → каталог → применение. **Никакого drag & drop материалов из каталога на грань** — значительное отклонение от roomtodo, но проще и предсказуемее. Copy-paste материала между гранями (Ctrl+C/V на выделенной грани) — есть, как в reference; инструмент «пипетка» — в [backlog.md](backlog.md).
- **Удаление проекта:** безвозвратное, сразу (hard-delete, как roomtodo и как зафиксировано в [features/projects.md](../projects.md)). Корзины и восстановления в v0 нет; прямая ссылка на удалённый проект → 404. Корзина/soft-delete — в [backlog.md](backlog.md#корзина-проектов-soft-delete-и-восстановление).
- **Конфликты save:** last-write-wins без warning (как roomtodo). Optimistic locking с revision — если появятся жалобы, добавим миграцией схемы.
- **Undo стратегия:** in-memory (см. выше), coalescing по mouseUp/blur для drag/slider (один шаг на завершённое действие). Миграция save-формата — silent side-effect, не пушится в history. Undo калибровки подложки не делаем, undo удаления подложки — делаем.
- **Линейки (custom rulers):** независимые пары координат (как roomtodo), без магнита к точкам стен после постановки. Если стена сдвинулась — юзер пере-тащит конец руками.
- **Каталог проёмов:** три категории — Двери, Окна, **Проёмы** (арки без створок). Технически проём = дверь с пустой моделью створки.
- **UI истории:** только кнопки undo/redo (как roomtodo). Дерево транзакций / галерея превью — не в MVP.
- **Полупрозрачные материалы в 2D-виде:** alpha 0.5, простая полупрозрачная заливка. ГОСТ-штриховка — в бэклоге.
- **Форматирование длин:** стандартный toFixed без научной нотации. Лимит парсера ввода — 1 км (100 000 см), выше — ошибка «слишком большое значение».
- **Drag & drop мебели из каталога:** Native HTML5 Drag & Drop через `dataTransfer` (не своя event-шина, не библиотека).
- **Цветовое пространство albedo-карт — sRGB.** В reference-реализации есть известный legacy-подвох (force-linear на диффузе каталожных моделей) — мы его сознательно не воспроизводим. Юзер видит правильные цвета из каталога без дополнительных настроек рендера. Детали — в [05-materials.md](05-materials.md).
- **Приоритет Y-оси в осевом снапе стен.** При одновременном срабатывании горизонтального и вертикального выравнивателей выигрывает Y-вариант. В reference-реализации это побочный эффект порядка присваиваний; у нас — явно зафиксированное детерминированное поведение. Детали — в [01-walls-and-contours.md](01-walls-and-contours.md).
- **Один Ctrl+Z для юзера, одна очередь undo.** Внутренне история хранится как два независимых снапшот-контейнера (планировка и обстановка), но интерфейсно это невидимо — split-view 2D+3D не поддерживается, значит активна ровно одна зона, значит очередь для юзера линейная. Детали — в [09-undo-redo.md](09-undo-redo.md).
- **Custom uploads (свои GLB-модели, свои текстуры) — не в v0.** Кнопки «Upload», вкладки «My uploads» в UI не появляются. Полная задача — в [backlog.md](backlog.md#custom-uploads-пользовательские-модели-и-текстуры).

## Ограничения текущей реализации

- Один проект = одна квартира/дом на одном этаже (multi-floor — в бэклоге).
- Каталог — только наш контент (custom uploads — в бэклоге).
- Desktop only. Tablet/mobile — в бэклоге (просмотр и полное редактирование — как две отдельные фичи).
- Undo глубина 100, in-memory.
- Один пользователь редактирует один проект в одну единицу времени.

## Формат разделов

Каждый раздел (01-12) имеет одинаковую структуру:

- **Что это** — одно-два предложения контекста.
- **Инструменты / режимы / действия** — что пользователь делает.
- **Визуальная обратная связь** — что он видит.
- **Клавиатура и мышь** — таблица shortcuts.
- **Ограничения и пороги** — численные константы UX.
- **Крайние случаи** — как ведёт себя редактор в углах.
- **Открытые вопросы** — (если есть) что в reference-документации не раскрыто и ждёт продуктового решения. На 2026-08-17 все вопросы разделов 01-12 закрыты — решения внесены в текст разделов с пометкой «решение 2026-08-17».
