# 05 — Материалы и текстуры (v0)

> Раздел feature-spec planner-v0. Единицы: 1 см = 1 юнит.

## Что это

> **Осознанное отклонение.** Материалы применяются **только через свойства выделенного объекта** — никакого drag & drop материалов из каталога на грань в 3D. Типовой паттерн интерьерных редакторов — тянуть свотч из каталога прямо на поверхность; мы этот сценарий сознательно не поддерживаем ради простоты и предсказуемости UX. Пипетка / copy-paste материала между гранями — в бэклоге.

Материалы и текстуры — это отделка сцены: то, чем пользователь «одевает» стены, полы, потолки, плинтусы и мебель. Материал — это либо каталожная текстура (обои, плитка, ламинат, дерево, металл), либо чистый цвет (задаётся hex-значением). Пользователь выделяет поверхность (стену, пол, потолок, плинтус, мебель или конкретную часть мебели), в панели свойств нажимает «выбрать материал», в открывшейся модалке каталога находит нужный и подтверждает выбор — выбранная грань меняет вид немедленно, история действий фиксирует изменение. Одна поверхность может нести базовый материал и дополнительный финиш поверх (например, текстуру плюс цветовой тонировщик), а сложные поверхности (мебель, комбинированные стены) — разные материалы для разных частей одной модели.

## Каталог материалов (модалка выбора)

- Каталог материалов открывается из панели свойств выделенного объекта по клику «выбрать материал» — как модальное окно поверх сцены.
- Категории поверхностей на уровне продукта: стена (wall), пол (cover), потолок (ceiling), крышка/зона пола (cap), плинтус (plinth), молдинг (molding). Каждая категория имеет свой реестр дефолтных материалов.
- Внутренняя разбивка по стилю/бренду/типу отделки (обои, покраска, плитка, ламинат, ковролин, дерево, металл, стекло) — задача каталожного слоя (фильтры, поиск, разделы), не самого планера.
- Каждая карточка материала показывает превью-миниатюру (текстура или цветовой свотч).
- Отдельный тип элемента в каталоге — материал-как-цвет: карточка с цветным свотчем без текстуры.
- Комбинированные карточки: базовая текстура с наложенным цветом (например, «обои под покраску + цвет») — на превью видны оба слоя.
- Клик по карточке в модалке применяет материал к выделенной поверхности и закрывает модалку. Отдельного жеста drag'а из каталога нет.
- Пользовательские (частные) материалы моделируются как ownership-флаг на каталожной карточке, а не как отдельный тип: в каталоге они лежат в одной сетке с прочими и помечаются «моё».

## Применение к стенам

> **Осознанное отклонение.** Одна сторона стены может нести несколько материалов, разделённых **произвольными прямоугольными зонами** (например, панель/вагонка снизу, вертикальная полоса других обоев, акцент по центру). Reference поддерживает многозонные стены только через отдельный саб-редактор «тайл-конфигуратор» (пользователь заходит в него, режет плоскость перегородками, выходит) — у нас же это должен быть родной интерактивный слой поверх выделенной грани стены, без переключения контекста.

- Пользователь выделяет сторону стены (внутреннюю или внешнюю) → в панели свойств выбирает материал через модалку каталога → материал накатывается на всю плоскость этой стороны стены целиком.
- Основной материал стены и дополнительный финиш поверх: у каждой стороны стены два независимых слота — «база» (цвет) и «финиш» (текстура). Финиш всегда рисуется поверх базы, порядок фиксирован. Если в модалке выбрана каталожная карточка «текстура + цвет», цвет автоматически уходит в базу, текстура — в финиш; чистый цвет заменяет базу, чистая текстура — финиш.
- Поворот и смещение текстуры на выделенной поверхности задаются в панели свойств числовыми полями (угол в градусах, смещение по осям в сантиметрах); поворот выполняется вокруг центра поверхности. Значения этих полей — часть текущего слота материала.
- Разные материалы на разных сторонах одной стены: внутренняя сторона (со стороны комнаты) и внешняя сторона (снаружи) независимы. Каждая сторона хранит свою ориентацию текстуры, чтобы рисунок читался правильно, а не был «зеркальным».
- Стены с составной раскладкой (панели, вставки, бордюр из плитки) поддерживают несколько частей — каждая часть выделяется отдельно, у каждой в свойствах свой материал; неиспользованная площадь стены заливается «остаточным» материалом.
- Для новой стены материал не задаётся вручную — используется дефолт из глобального реестра по ключу `wall`. Пользовательская настройка дефолтов «в настройках проекта» в MVP не реализуется.

## Применение к полам

- Пользователь выделяет пол комнаты (или конкретную зону многозонного пола) → в панели свойств выбирает материал через модалку каталога.
- Multi-material пол: пол одной комнаты может быть разделён на несколько зон (плитка в кухонной части, ламинат в жилой части) — каждая зона несёт свой материал и свои параметры раскладки, выделяется и настраивается независимо.
- Плитка/ламинат: у каждой зоны — масштаб (плотность повтора), поворот сетки, смещение начала укладки, толщина шва между плитками, флаг случайного поворота/отражения плиток внутри зоны. Все параметры правятся в панели свойств выделенной зоны.
- Раскладка плиток строится автоматически: сетка выравнивается по границе зоны, лишние плитки за пределами контура обрезаются.
- Разделение пола на зоны выполняется отдельным инструментом «разделить активную зону» с параметром направления (горизонтально/вертикально). Один жест инструмента создаёт делимитер и вторую зону с наследуемым материалом; обратная операция — удаление делимитера сливает две зоны. Порог: рез отклоняется, если любая из двух _получающихся_ зон оказалась бы тоньше 5 см (проверка после реза, не до). Свободного «рисования границ» между зонами нет.
- Для нового пола материал не задаётся вручную — используется дефолт из глобального реестра по ключу `cover`.

## Применение к потолкам

- Работает аналогично полу: выделение потолка комнаты → выбор материала в панели свойств. Поддерживаются те же параметры укладки (масштаб/поворот/смещение).
- Дефолт для нового потолка — материал из глобального реестра по ключу `ceiling`; отдельного per-project override в MVP нет.

## Применение к плинтусам

- Материал плинтуса задаётся на уровне комнаты (выделяется комната → в панели свойств секция «плинтус») и применяется ко всему периметру одновременно.
- Дефолт плинтуса — из глобального реестра по ключу `plinth` (отличен от стенового).
- Отдельного разделения «материалы только для плинтуса» в каталоге нет: пользователь видит общий каталог и подтверждает выбор.

## Применение к мебели

- Многие каталожные модели мебели имеют несколько окрашиваемых частей: обивка дивана, столешница, каркас, ножки — каждая часть считается отдельным слотом материала.
- Пользователь выделяет объект целиком, в панели свойств видит список окрашиваемых частей модели и для каждой части выбирает материал через модалку каталога. Прямого клика по конкретной части в 3D-виде для назначения материала не предусмотрено.
- У модели есть два независимых укрупнённых слота — «верх/каркас» и «низ» — каждый со своим материалом, поворотом и смещением текстуры; оба доступны из панели свойств.
- Импортированные пользовательские GLTF-модели тоже поддерживают пер-часть материалы; список частей строится по геометрии самой модели и показывается в панели свойств так же, как у каталожных моделей.
- Глобального дефолта «материал для новой мебели» нет: каждый каталожный продукт приходит со своим набором частей и заранее назначенными для них материалами; при размещении в сцене они читаются из карточки продукта и, при желании, переопределяются пользователем в панели свойств.

## Touch-поведение

Планер на десктопе, специализированных touch-жестов в MVP нет. Так как материал применяется исключительно через панель свойств выделенного объекта, отдельного touchEnd-пути с валидацией «куда можно класть материал» не возникает: любые нажатия на карточку в модалке применяют материал к уже выделенному объекту одинаково для мыши и тач-устройства. Полноценные touch-жесты (long-press, двухпальцевые) вводятся вместе с общей touch-фичей из бэклога.

## GLTF materials

- Импортированные пользовательские GLTF/GLB-модели приходят с собственными материалами и текстурами; редактор отрисовывает их «как есть» и позволяет пере-натянуть материал из каталога на любую часть через панель свойств.
- Цветовое пространство albedo-карт — sRGB. Форсирование linear-пространства на диффузе каталожных моделей — известный legacy-подвох; мы его не воспроизводим.
- Крупные текстуры автоматически даунскейлятся, чтобы не выжирать видеопамять; на мобильных устройствах предел ниже, чем на десктопе.

## Копирование материала между поверхностями

- В MVP отдельного инструмента «пипетка» и Ctrl+C/Ctrl+V материала между гранями нет — фича вынесена в бэклог.
- Текущий рабочий процесс: пользователь выделяет целевую поверхность, открывает модалку каталога и выбирает тот же материал заново. Каталог должен обеспечивать быстрый повторный доступ (недавно применённые / избранное) для комфорта.

## Клавиатура и мышь

| Действие                          | Клавиша/жест                                                                              |
| --------------------------------- | ----------------------------------------------------------------------------------------- |
| Выбрать материал для поверхности  | Выделить объект → в панели свойств нажать «выбрать материал» → клик по карточке в модалке |
| Правка поворота/смещения текстуры | Числовые поля в панели свойств выделенной поверхности                                     |
| Отменить назначение материала     | Ctrl+Z (общий undo)                                                                       |
| Пипетка / копипаст материала      | Не в MVP (бэклог)                                                                         |

## Ограничения

- Смещение текстуры хранится внутри в пикселях при плотности 100 пикселей на метр; поворот — в радианах. Пользователь видит и правит эти значения в панели свойств в человекопонятных единицах (сантиметры для смещения, градусы для угла).
- Поворот применяется вокруг центра поверхности (для стены — центра стены).
- Каталожные материалы делятся на «масштабируемые» (плотность повтора правится в панели свойств) и «немасштабируемые» (плотность повтора фиксирована и показана read-only).
- Текстуры автоматически даунскейлятся до предела 512 px, умноженного на множитель устройства; на телефонах множитель меньше.
- Материалы с прозрачностью (стекло, тюль) корректно отрисовываются в 3D; в 2D применяется простая alpha-заливка.
- Пустой материал (значение «нет материала») — валидное состояние поверхности, обрабатывается отдельной веткой рендера.

## Крайние случаи

- Материал не подходит для типа поверхности (ковёр на стену, обои на пол): запрета нет — модалка каталога показывает один и тот же набор материалов для любой выделенной поверхности, любой материал может быть применён к любой грани. Продуктовая ответственность за «здравый выбор» лежит на пользователе; каталог помогает сортировкой/фильтрами.
- Материал с прозрачностью (стекло, тюль): в 3D-виде поверхность становится полупрозрачной; в 2D-виде рисуется простой alpha-заливкой (~0.5). Правильная ГОСТ-штриховка (штриховка для стекла, точки для тюля) — в бэклог (для профи-архитекторов, печатающих план).
- Комбинация «база + финиш»: если пользователь выбирает материал-с-цветом, цвет уходит в базу, а текстура — в финиш; чистый цвет заменяет базу, чистая текстура — финиш. Итоговый визуальный порядок наложения фиксирован (финиш поверх базы), взаимозамена — переназначением в разные слоты.
- Стена с составной раскладкой: перекраска «фоном» затрагивает только «остаточную» часть стены, не трогая вставки; чтобы сменить материал вставки, её нужно выделить отдельно.
- Импортированная GLTF-модель без назначенного материала: часть отрисовывается со встроенным материалом модели, пока пользователь не перекроет его каталожным.
- Каталожная модель мебели без назначенных материалов (или пришедшая из каталога без них): редактор автоматически подставляет дефолтный материал на все материальные слоты предмета — модель появляется в сцене и не ломает её, пользователь при желании переопределяет материалы вручную через панель свойств.
- «Немасштабируемые» материалы (`scalability=false`): в панели свойств поля масштаба/повтора показываются как read-only с сохранёнными значениями каталога, а не скрываются — так пользователь видит фактическую плотность.
- Undo/redo материалов: восстанавливает поля материала и параметры UV каждой затронутой поверхности целиком (материал, финиш, поворот, смещение) — без затрагивания геометрии сцены. Единичное применение материала — отдельный шаг истории; правки числовых полей поворота/смещения слайдером/drag'ом коалесятся в один шаг на blur/release.

## Открытые вопросы

- **UI для многозонной раскладки стен (rect zones).** Осознанное расширение над reference-реализацией — «одна сторона стены несёт несколько прямоугольных материальных зон». Не решено: как именно пользователь их рисует и правит. Кандидаты: (а) отдельный вид «в фас на стену» с рисованием прямоугольников поверх, (б) drag прямоугольника прямо на грани стены в 3D, (в) числовой ввод координат зон в панели свойств. Дизайн-решение — до перед реализацией фичи. См. также [README.md#зафиксированные-продуктовые-решения](README.md).
- **Undo для rect zones на стене (нужно продуктовое решение)** — rect zones это наша продуктовая формулировка. В reference многозонная раскладка стены существует, но живёт через отдельный «тайл-конфигуратор» (пользователь заходит в него, режет плоскость перегородками пополам, каждый рез — отдельный шаг undo внутри конфигуратора). Мы хотим один интерактивный слой поверх грани — а не отдельный саб-редактор — поэтому семантика undo проектируется с нуля. Кандидаты: один Ctrl+Z откатывает «геометрию зоны + материал» атомарно; или два шага (сначала материал, потом геометрия). Решается вместе с UI-дизайном rect zones выше.
- **Алгоритм случайного поворота/отражения плиток (нужно продуктовое решение).** В reference алгоритм такой: каждой плитке независимо бросается случайный поворот из четырёх вариантов (0°/90°/180°/270°) — но 90°/270° разрешены только для квадратных плиток, у прямоугольных выпадает 0° или 180°; затем независимо с вероятностью 50% включается зеркальное отражение (одноосное, всегда одна и та же ось). Кандидаты для нас: (а) один-в-один как reference; (б) упростить до «только поворот» или «только отражение»; (в) дать каталогу два независимых флага (rotate/flip), а не один общий. Выбор фиксируем при первой каталог-плитке с включенным флагом.
- **Единый ли пользовательский пресет «недавно применённые»**. Для быстрой перекраски похожих поверхностей нужен доступ к последним применённым материалам — где хранить: локально по устройству, в проекте или на аккаунте? Уточняется вместе с задачей «пипетка / copy-paste материала» из бэклога.
