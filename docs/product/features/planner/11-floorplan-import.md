# 11 — Импорт растрового плана (v0)

> Раздел feature-spec planner-v0. Единицы: 1 см = 1 юнит.

## Что это

Пользователь загружает изображение бумажного плана (фото, скан, экспорт из другой программы) как подложку в 2D top-view, задаёт ей реальный масштаб по эталонному сегменту и обводит стены поверх картинки. Подложка — это пассивный визуальный слой-помощник: снапа стен к линиям изображения нет, автораспознавания стен нет. Всё, что делает система — держит картинку в правильном положении, масштабе и повороте, чтобы удобно было чертить сверху вручную.

## Загрузка изображения

- Поддерживаемые форматы: PNG, JPG, GIF. PDF в v0 **не принимаем** — растеризация PDF (нужен pdf.js или серверный конверт) выносится в бэклог. В `<input accept=...>` PDF не попадает, drag & drop PDF-файла — тоже rejects с подсказкой «PDF пока не поддерживается».
- Ограничения по размеру и разрешению — см. «Ограничения и пороги». Проверяются **обе** метрики; при нарушении показывается модалка с текстом по приоритету: сначала пиксели («Изображение слишком большое — уменьшите разрешение до 8000 px по длинной стороне»), затем размер файла («Файл слишком тяжёлый — сохраните как JPG или сожмите до 5 МБ»). Пиксельная метрика понятнее пользователю; лимит МБ защищает localStorage-черновик и save-envelope (подложка уходит base64).
- **Битый или неподдерживаемый файл** (не декодируется, не картинка под другим расширением) — модалка «Файл повреждён или не поддерживается» с кнопками «Выбрать другой файл» / «Отмена». Прежняя подложка (если была) остаётся нетронутой, редактор не остаётся в полузагруженном состоянии. В reference — молчаливый отказ; решение 2026-08-17.

> **Осознанное отклонение.** Drag & drop файла подложки прямо в 2D-канвас поддерживается как альтернатива кнопке «Импортировать план». Типовые reference-реализации ограничиваются только кнопкой; DnD-путь — недорогое улучшение UX (native HTML5 API), которое совпадает с привычкой пользователя «бросить файл в окно».

- Триггеры:
  - Кнопка «Импортировать план» в панели инструментов 2D.
  - **Drag & drop файла в 2D-канвас** — native HTML5 API (dragover/drop на canvas). Работает в дополнение к кнопке, не заменяет её.
- Прогресс загрузки: единичный шаг «выбор файла → обработка → отображение». Отдельного прогресс-бара для чтения файла нет; на время загрузки допустимо показывать общий прелоадер.

## Позиционирование подложки

- Сразу после загрузки картинка центрируется относительно мирового начала координат в 2D top-view. Смещение считается из размеров самого изображения так, чтобы его центр совпал с (0, 0).
- Дефолтный поворот — 0°, дефолтный масштаб — 1 (пиксель картинки равен юниту сцены до калибровки).
- **Двигать подложку как отдельный объект в v0 нельзя** — ни drag за саму картинку, ни move-handle. Позиционирование полностью покрывается калибровкой: пользователь ставит эталонную линейку в нужное место, и подложка «прилипает» к её положению. По нашим оценкам, калибровка закрывает ~95% сценариев позиционирования; если пользователю нужно точнее — пере-калибрует. Свободный drag подложки как отдельный объект — в бэклоге.
- Поворот подложки возможен только через калибровку (см. ниже, режим «выровнять с поворотом»). Отдельного rotate-handle на самой картинке нет.
- Масштабирование подложки возможно только через калибровку. Отдельного scale-handle на самой картинке нет.

## Калибровка по длине

Ключевой инструмент раздела. После загрузки изображения пользователь сразу оказывается в режиме калибровки — выйти из него, не задав масштаб, нельзя.

- На подложку кладётся двухточечная эталонная линейка (два перетаскиваемых маркера + сегмент между ними).
- Пользователь совмещает маркеры с концами объекта на плане, реальная длина которого известна (например, стена 4 м, размерная линия на чертеже).
- Линейка изначально появляется горизонтально в центре канваса.
- При перетаскивании маркеров сегмент угол-снапится к 0°/45°/90°/135° и симметричным; удержание Ctrl отключает угловой снап и даёт произвольный угол.
- При перетаскивании самого сегмента (не маркера) обе точки двигаются вместе.
- Пользователь тапает по подписи длины на сегменте и вводит реальное значение в единицах документа (см. [07 — Измерения](07-measurements.md), раздел «Единицы измерения»). Инпут использует тот же парсер, что и правка длины стены: метрический regex и толерантный имперский; отрицательные, ноль, значения выше 1 км — отклоняются.
- Система масштабирует подложку так, чтобы длина сегмента на картинке стала равна введённой.
- Опция «выровнять с поворотом»: одновременно с масштабированием подложка поворачивается так, чтобы эталонный сегмент стал строго горизонтальным. Это удобно, когда исходное фото плана сделано под углом. Если пользователь повторно входит в режим калибровки и снова применяет «выровнять с поворотом» — новый угол **накапливается** поверх текущего, а не заменяет его. Об этом стоит помнить, чтобы не перекручивать подложку многократными применениями.
- Warning'а на «радикальную» перекалибровку (масштаб изменился в разы) **нет** (как в reference; решение 2026-08-17): первая калибровка всегда даёт кратный скачок (пиксели → см), результат виден сразу, перекалибровка бесплатна — диалог шумел бы, не защищая.
- Повторная калибровка доступна в любой момент через инструмент «Откалибровать подложку». Маркеры и сегмент восстанавливаются в последнем положении.
- Из режима калибровки нельзя выйти для _только что загруженной_ картинки, пока не задана реальная длина > 0. Иначе показывается ошибка «Некорректная длина». Для _уже откалиброванной_ подложки (повторный вход в инструмент «Откалибровать») выйти можно в любой момент без ввода — последний валидный transform сохраняется, никаких повторных вводов система не требует.
- Клик по маркеру или сегменту без перетаскивания (короткий, до ~0.2 с) — это выбор для точной подгонки клавиатурой (стрелки).

## Прозрачность подложки

- В типовых reference-реализациях прозрачность и порядок слоёв часто заданы одним параметром «положение подложки» («над стенами», «под стенами», «скрыть») с зашитыми в код значениями прозрачности — пользователь их не крутит.
- В v0 закладываем более гибкий контроль: отдельный переключатель «над / под / скрыть» + слайдер прозрачности 0–100%. Дефолт при первой загрузке — «над стенами», прозрачность около 50%.
- Скрытие через «скрыть» полностью выключает отрисовку подложки, не удаляя её из проекта.
- В режиме калибровки подложка всегда рисуется полностью непрозрачной, чтобы пользователь видел детали плана.

## Обводка стен поверх подложки

- Стены рисуются штатными инструментами раздела 01 «Стены», без специальных режимов.
- Снапа концов стен к линиям, углам или другим особенностям изображения нет — распознавания контента подложки система не делает.
- Работает штатный снап к сетке и к уже нарисованным стенам.
- **Подложка живёт исключительно в 2D top-view.** В 3D-виде и в режиме прогулки её нет — вообще. Никакого «показать подложку как текстуру пола» / «спроецировать на пол» в v0 не делаем. Это осознанное решение: подложка — aid для обводки, не декоративный ассет сцены.

## Удаление подложки

- Кнопка «Удалить подложку» в панели инструментов 2D.
- Показываем подтверждение: «Удалить подложку? Нарисованные стены останутся».
- После удаления состояние калибровки сбрасывается к дефолтам, все стены и другие объекты сцены не трогаются.
- **Удаление подложки пушится в общий undo-стек** (см. 09-undo-redo). Ctrl+Z возвращает подложку с её последним transform (позиция + масштаб + поворот). Инструмент калибровки сам в стек не пишется, но после undo его повторный вход показывает маркеры в последнем известном положении — юзер не начинает калибровку с нуля.
- **Калибровка подложки в undo НЕ пушится** — это редкое явное действие, пользователь помнит контекст и всегда может пере-калибровать через тот же инструмент.

## Хранение подложки в проекте

- Гибридная схема:
  - **Первая загрузка** (или замена изображения) → в save-envelope уходит **inline base64** самой картинки. Клиент помечает её как «changed».
  - Сервер отвечает публичным URL и запоминает его как «текущий src».
  - **Последующие save-ы** (пока картинку не заменяли) → в envelope уходит уже **URL**, без повторной заливки base64.
- На load — эвристика по строке src: если содержит `base64` — используем inline; если начинается на `files/` (относительный путь к asset-store) — превращаем в абсолютный URL; иначе считаем raw base64 и приклеиваем data-URI префикс.
- Такая схема даёт минимальный размер save-payload при повторных ручных сохранениях и держит подложку доступной оффлайн после первого сохранения через кеш браузера.

## Ограничения и пороги (константы UX)

- Радиус захвата маркера курсором — порядка 15 пикселей экрана.
- Радиус попадания в сегмент (не в маркер) — порядка 15 пикселей.
- Порог «клик или drag» — около 0.2 секунды удержания и/или ~5 юнитов смещения.
- Угловой снап линейки — с допуском около ±1° к 0/45/90/135° и симметричным.
- Минимальная валидная длина эталонного сегмента — строго больше 0. Ноль запрещён.
- Дефолтная прозрачность подложки при первой загрузке — около 50% (в режиме «над стенами»). Пользователь может менять слайдером.
- Дефолтный слой — «над стенами».
- Лимит файла подложки — **5 МБ**; лимит разрешения — **8000 px** по длинной стороне. Проверяются оба (см. «Загрузка изображения»). Фото плана с телефона (2–4 МБ JPG) укладывается; PNG-сканы в 20+ МБ — нет, и это осознанно: подложка идёт base64 в save-envelope и в localStorage-черновик.

## Крайние случаи

- **Повторная калибровка** уже откалиброванной подложки: масштаб применяется поверх текущего, не сбрасывая предыдущую калибровку. Пользователь видит подложку в её нынешнем состоянии и лишь корректирует. Важно: механика «умножения» масштаба означает, что нельзя дважды случайно применить одну и ту же поправку — в v0 при загрузке ранее сохранённого проекта храним итоговый transform и параметры линейки раздельно, чтобы избежать двойного применения.
- **Отмена калибровки** для только что загруженной картинки: закрыть режим без ввода длины нельзя. Есть только «Отменить загрузку» — тогда картинка удаляется полностью.
- **Загрузка новой подложки поверх старой**: прежняя подложка удаляется, новая появляется по центру с дефолтным масштабом. Ранее нарисованные стены не трогаются. Старая калибровка не переносится — последнее положение эталонной линейки для новой картинки не сохраняется, каждый раз пользователь ставит калибровку заново (это допустимо: замена подложки в реальных сценариях редкая и обычно означает другой формат/масштаб). Замена **во время активной калибровки старой** подложки — тоже молча, без confirm'а (как в reference; решение 2026-08-17): калибровка — дешёвое действие, а сама замена — явное действие юзера (кнопка или drop файла).
- **Огромное изображение**: лимиты 5 МБ / 8000 px, см. «Загрузка изображения» и «Ограничения и пороги».
- **Импорт подложки или вход в «Откалибровать» во время активного рисования стен**: калибровка и рисование взаимоисключающие. Вход в калибровку **отменяет текущий черновик контура ровно как Esc** — незамкнутый контур отбрасывается, без диалога и без молчаливого коммита в комнаты (в reference — молча коммитит при ≥ 2 точках; решение 2026-08-17). Единое правило «смена инструмента = отмена текущего черновика» для всех инструментов редактора. Обратно: старт рисования стен из режима калибровки уже откалиброванной подложки — выход из калибровки с сохранением последнего валидного transform; для только что загруженной (некалиброванной) подложки инструменты рисования недоступны, пока не задана длина или не нажато «Отменить загрузку».
- **Панорамирование** канваса заблокировано, пока пользователь тащит маркер или сегмент линейки. Это защищает от случайного сдвига вида.
- **Вырожденная линейка**: если пользователь свёл маркеры линейки в одну точку и жмёт «Применить» — калибровка не применяется, показывается подсказка «Растяните линейку», предыдущий масштаб подложки сохраняется. Выход из режима калибровки без ввода нового значения для уже откалиброванной подложки разрешён — масштаб не сбрасывается.
