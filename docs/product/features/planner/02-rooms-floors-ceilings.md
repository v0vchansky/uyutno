# 02 — Комнаты, полы, потолки (v0)

> Раздел feature-spec planner-v0. Единицы: 1 см = 1 юнит.

## Что это

Комнаты, полы и потолки — производные объекты сцены, которые пользователь напрямую не рисует. Он строит контуры стен (см. [01 — Стены](01-walls-and-contours.md)), а планировщик сам определяет, какие замкнутые области получились, и заводит для каждой:

- **комнату** — замкнутую область, ограниченную стенами;
- **пол** — горизонтальную поверхность внутри комнаты на нулевой высоте;
- **потолок** — зеркальную копию пола на высоте комнаты;
- **плинтус** — «бортик» вдоль всех стен комнаты на уровне пола.

Дополнительно пользователь может вручную рисовать **зоны** — участки со сниженным потолком (арки, ниши, антресоли).

Ключевая идея: пользователь не думает в терминах «полигон комнаты». Он рисует стены — комната появляется сама. При любой правке стен весь набор комнат/полов/потолков/плинтусов пересобирается заново. Персистентные атрибуты (название, материалы, высота потолка) переезжают на новую комнату автоматически по перекрытию площади.

## Модель контур-first

Пользователь не выделяет комнату мышью, чтобы «создать» её. Он рисует замкнутый контур стен — и как только контур замыкается, внутри появляется комната с полом, потолком, плинтусом по всему периметру и материалами по умолчанию.

Правило простое: комнаты **выводятся** из текущего рисунка стен. Никакого «списка комнат», который пользователь ведёт вручную, нет. Из этого следуют важные для UX эффекты:

- Дорисовал внутреннюю стенку через комнату — она делится на две.
- Стер стену между двумя комнатами — они сливаются в одну.
- Разомкнул контур — комната исчезает (пол/потолок/плинтус вместе с ней).
- Замкнул обратно — комната появляется снова, и её сохранённые атрибуты (название, материалы, высота потолка) возвращаются, если новая форма пересекается со старой по площади.

Пересборка запускается автоматически на каждой правке контура и не требует явного «применить».

## Комнаты

**Что это для пользователя.** Комната — это замкнутая область стен с общим полом, потолком и плинтусом. Комната несёт название, высоту потолка, материалы пола/потолка/плинтуса (см. [06 — Материалы](05-materials.md)) и служит контейнером для мебели.

**Как создаётся.** Автоматически при замыкании контура стен. Никакого отдельного инструмента «создать комнату» нет.

**Как выбирается.** Клик с Ctrl (или клик по пустой области внутри комнаты, если стены при этом не хватаются) переключает выбор на комнату. Панель свойств комнаты открывает управление её атрибутами.

**Свойства комнаты.**

- Название (свободный текст).
- Высота потолка (по умолчанию 280 см) — задаётся на уровне комнаты, влияет и на потолок, и на верхнюю границу стен внутри комнаты. Новая комната, у которой не нашлось донора по перекрытию площади, получает высоту проекта (решение 2026-08-17).
- Материал пола и потолка — детали в [05 — Материалы](05-materials.md). Плинтус в свойства комнаты не входит: его материал, профиль и признак «плинтуса здесь нет» живут на грани стены (решение автора 2026-08-21; см. «Плинтусы»).
- Видимость потолка — можно скрыть у конкретной комнаты. Переключатель в свойствах комнаты выставляет флаг всем полам комнаты; если у полов состояние смешанное (часть скрыта, часть нет), переключатель показывается как indeterminate (решение 2026-08-17; хранение флага — см. «Потолки»).

**Сохранение атрибутов при правках.** После правки стен старая комната формально исчезает и на её месте появляется новая. Планировщик переносит атрибуты автоматически: новая комната наследует данные той старой, с которой у неё есть пересечение по площади. Пользователь этого не замечает — он просто видит, что «моя гостиная» осталась гостиной после того, как он передвинул стену. При разделении одной комнаты пополам обе новые комнаты могут унаследовать атрибуты старой (обе пересекаются со старой по площади) — это нормальное поведение, оба «клона» несут название, материалы и высоту исходной.

Критерий «пересечение по площади» — как в reference (решение 2026-08-17): по габаритному прямоугольнику старой комнаты строится сетка 10×10 точек; комнаты считаются пересекающимися, если хотя бы одна точка сетки лежит внутри обоих контуров; порога по доле площади нет. Донором становится первая (в порядке обхода) старая комната с таким пересечением. Требования «того же типа — внешняя для внешней, дырка для дырки» больше нет: у редактора все записи комнат — полости, а различать внешний контур и дырку при пере-привязке стало нечего (правка «спека ← код», решение автора 2026-08-20; см. ADR 0017, «Что важно знать»). Материалы стен переносятся другим механизмом — по совпадению концов грани, а не по площади (см. [01 — Стены](01-walls-and-contours.md) и [05 — Материалы](05-materials.md)); тем же механизмом переносятся переопределения плинтуса, они адресуются той же парой концов грани (см. «Плинтусы»).

## Полы

**Что это для пользователя.** Пол — горизонтальная поверхность на нулевой высоте внутри комнаты. По умолчанию комната сразу получает пол по всему своему внутреннему контуру.

**Автоматический пол.** Как только образуется новая комната, планировщик автоматически заполняет её пол материалом по умолчанию. Пользователю не нужно ничего делать. Дефолтный пол создаётся только в тех местах комнаты, где нет ни одного пола, поставленного вручную (или унаследованного через пересечение площади со старой формой). Ручные полы после правки стен _сохраняются_ и лишь ужимаются под новую форму — они не «съедаются» дефолтом.

**Multi-material пол.** Пользователь может «нарезать» пол на зоны с разными материалами — например, паркет в жилой части и плитка у входа. Для этого есть отдельный инструмент рисования пола: пользователь обводит участок внутри комнаты, задаёт ему свой материал, участок становится самостоятельным полом внутри комнаты. Внутри одной комнаты может лежать несколько полов бок о бок: нарисованный вручную пол по касанию с соседним сам собой не сливается (см. «Слияние соседних полов»).

**Внешний контур пола против дырок в полу.** У пола есть внешняя граница и, при необходимости, дырки. Дырка — это «пол-вычитание»: планировщик сам определяет, что один контур лежит внутри другого, и превращает внутренний в дырку. В v0 дырки появляются **производно** — прежде всего под комнатой внутри комнаты: пол внешней комнаты получает вырез под форму внутренней (см. «Крайние случаи»). Ручной вырез, который пользователь рисует сам — под лестницу, шахту лифта или «второй свет», — из v0 снят: все эти сценарии имеют смысл только при этаже снизу, а многоэтажности в v0 нет. Обещание возвращается вместе с многоэтажностью (правка «спека ← код», решение автора 2026-08-20).

**Что происходит с полом при перерисовке стен.** При правке контура стен планировщик пересчитывает форму пола, ужимая его до новой формы комнаты. При сжатии ручной пол автоматически подрезается по новой границе — висящих за пределами комнаты кусков не остаётся. Материалы и разбиение на участки переносятся на новые полы по тому же правилу перекрытия площади, что и для комнат. Если пользователь снёс стену и объединил две комнаты, полы обеих комнат остаются на своих местах со своими материалами — они просто оказываются в одной комнате.

**Удаление комнаты.** Если комната исчезает (стены разомкнуты или удалены), её полы уходят вместе с ней. Оставить комнату **без покрытия** пользователь не может: свободная площадь комнаты всегда застилается полом по умолчанию, отдельного состояния «пола нет намеренно» в v0 нет. Сценарии, ради которых пол убирают целиком (второй свет, шахта, проём под лестницу), существуют только при этаже снизу — обещание возвращается вместе с многоэтажностью (правка «спека ← код», решение автора 2026-08-20).

## Потолки

**Что это для пользователя.** Потолок — зеркальная копия пола, поднятая на высоту комнаты. Форма 1-в-1 повторяет форму пола, включая дырки. У каждой комнаты — свой потолок; у каждого multi-material пола внутри комнаты — свой кусок потолка сверху.

**Видимость потолка.** Потолок автоматически скрывается, когда мешает обзору:

- В виде сверху (top-view / dollhouse) потолки прячутся, чтобы пользователь видел планировку изнутри.
- При камере ниже потолка (walk-through, обычный 3D-обзор с уровня человека) — потолок показывается.
- Пользователь может дополнительно принудительно скрыть потолок конкретной комнаты в свойствах комнаты.

Логика «когда потолок исчезает» работает автоматически по положению камеры относительно высоты комнаты (потолок скрыт, если камера выше потолка комнаты) и не требует ручного переключения. Дополнительный флаг «скрыть потолок этой комнаты» в свойствах комнаты работает поверх авто-логики: если юзер явно снял видимость — потолок не показывается даже когда камера ниже него.

Флаг «скрыть потолок» хранится не на комнате, а на полу (в блоке потолка пола) и при пересборке наследуется по перекрытию площади независимо от атрибутов комнаты (имя, материал стен). При слиянии двух полов в один флаг берётся от **первого пола-донора по перекрытию** (в порядке обхода полов при пересборке) — принято по reference, пересмотреть, если на первых юзер-сессиях всплывёт как проблема.

**Высота потолка.** Задаётся на уровне комнаты (по умолчанию 280 см). Изменение высоты одной комнаты не трогает соседние. Несколько multi-material полов внутри одной комнаты не могут иметь разные высоты потолка — потолок один на всю комнату. Локальное понижение потолка (например, над кухонным гарнитуром) моделируется отдельной зоной со своей высотой (см. «Зоны»).

## Плинтусы

**Что это для пользователя.** Плинтус — «бортик» вдоль всех стен комнаты на уровне пола. Появляется автоматически по периметру каждой комнаты, без отдельных действий пользователя.

**Форма профиля.** Планировщик поставляет 16 базовых форм профиля плинтуса: 8 нижних (собственно плинтус, у пола) и 8 верхних (потолочный молдинг, у потолка). Верхние формы зеркальны нижним по форме, но имеют свои дефолтные глубину и высоту. Все 16 профилей — встроенные константы редактора (нормализованные полилинии плюс дефолтные глубина/высота, а для верхних — ещё отступ до потолка), а не каталожные ассеты; SVG-профили в рантайме не парсим (решение 2026-08-17). Форму пользователь выбирает **на грани стены**, отдельно для нижнего и верхнего (решение автора 2026-08-21; см. «Плинтус настраивается на грани, а не на комнате» ниже).

**Разрывы под проёмами.** Плинтус автоматически прерывается там, где в стене стоит проём — дверь или окно, доходящее до пола. Если проём проходит выше плинтуса (окно на уровне груди), плинтус под ним не прерывается. Правило простое: плинтус существует там, где стена не «пробита» до уровня пола.

**Материал плинтуса.** Задаётся **на грани стены**, отдельно для нижнего и верхнего (решение автора 2026-08-21; см. ниже). Применить один материал по всему периметру комнаты пользователь может разовым массовым действием.

**Плинтус настраивается на грани, а не на комнате.** Три настройки — признак «плинтуса на этой стене нет», материал и форма профиля — живут **на грани стены**, одной записью переопределений, адресуемой парой концов грани; своих настроек плинтуса у комнаты нет (решение автора 2026-08-21, [ADR 0022](../../../adr/0022-sloy-proektsii-planera-v-three.md) G4). Причина: на комнате невыразимы обычные сценарии «вдоль этой стены плинтуса не надо» (стена под кухонным гарнитуром, ниша со шкафом) и «здесь другой профиль»; в reference все три настройки тоже лежат на стене. Умолчание не меняется: пока пользователь ничего не переопределил, плинтус идёт по всему периметру комнаты одинаковым — переопределения существуют только там, где он их задал. **Обещание «одинаково по периметру» при этом не сужается**: оно достигается разовым массовым применением ко всем граням комнаты, как в reference, — просто это действие пользователя, а не свойство комнаты.

## Зоны (Areas)

**Что это для пользователя.** Зона — участок внутри комнаты со сниженным потолком. Используется для арок, ниш, антресолей, подшивных потолков над кухонным гарнитуром.

**Отличие от комнаты.**

- Зона не имеет собственных стен — только контур на плане.
- Зона не создаёт отдельной комнаты в списке — она живёт внутри существующей.
- Зона имеет собственную высоту (по умолчанию 100 см — уровень «навесной» конструкции).
- Визуально зона показана заливкой на плане и «крышкой» на своей высоте в 3D.

**Как рисуется.** Отдельным инструментом «Зона» (см. [01 — Стены](01-walls-and-contours.md), раздел инструментов). Пользователь обводит контур внутри комнаты, замыкает, задаёт высоту в появившемся диалоге.

**Пересечения.** Правила отбраковки:

- Зона не может пересекать стены комнаты — её граница должна целиком лежать внутри существующей комнаты (или касаться стен, но не пересекать их).
- Зоны не могут пересекаться между собой. Могут только касаться границами.
- Попытка нарисовать зону, нарушающую эти правила, отклоняется без сохранения.
- Если после правки стен зона теряет опору (её точки больше не совпадают с новыми стенами комнаты), зона удаляется автоматически. При авто-пересборке точка зоны считается опёртой, если существует точка комнаты с той же координатой — допуск равен шагу квантования координат, а не 10-см снапу; 10-см снап «точка к углу» работает только при рисовании зоны (решение 2026-08-17). Достаточно одной точки контура зоны, которая не нашла себе нового угла — зона удаляется целиком, частичной подгонки не бывает.

Разница между двумя типами конфликта:

- Во время **рисования зоны** (пользователь только что довёл контур и замкнул) — конфликт (самопересечение, пересечение существующей зоны или стен) означает мгновенный отказ: контур не сохраняется, ничего не появляется на сцене.
- При **автоматической пересборке после правки стен** — конфликт уже сохранённой зоны означает её удаление. Пользователь не получает диалога — зона просто исчезает вместе с падением опоры.

**Что видит пользователь.** Внутри комнаты появляется область, у которой в 3D — своя крышка на заданной высоте. Пол зона не меняет. Стены комнаты, совпадающие с ребром зоны, укорачиваются до высоты зоны и теряют верхний плинтус (молдинг); стены, целиком лежащие внутри зоны, — только укорачиваются, их верхняя часть скрыта крышкой зоны (решение 2026-08-17).

**Вертикальные грани зоны.** На тех рёбрах зоны, что идут через интерьер комнаты (не совпадают со стеной), автоматически появляется вертикальная грань — от высоты зоны до высоты стен комнаты, чтобы «навесная» конструкция не висела в воздухе. У грани собственный материал (по умолчанию — материал стен), который пользователь может сменить как у любой поверхности конструктива; он сохраняется вместе с зоной и переживает пересборку. Сами грани пользователь не рисует — они пересобираются автоматически вместе с зоной при любой правке стен (решение 2026-08-17; в сохранённом проекте — см. [10 — Save/Load](10-save-load.md)).

**Видимость крышки зоны.** Крышка зоны **не** подчиняется камерной авто-логике скрытия потолков: в top-view/2D и при камере выше потолка потолки комнат прячутся, а крышка зоны остаётся видимой — на плане она читается как заливка зоны на своей высоте. Авто-скрытие «камера выше — прячем» касается только потолков (комнат и участка потолка над зоной на высоте стен); у крышки — свой независимый флаг видимости, которым управляет только пользователь. Принято по reference.

## Автоматическая перестройка (rebuild)

**Что чувствует пользователь.** Любая правка контура стен — добавление, удаление, перетаскивание точки или ребра — мгновенно триггерит пересчёт комнат, полов, потолков, плинтусов, зон. Никакого «применить» или «пересобрать» нет.

**Что происходит внутри (продуктово, не техника).** На каждой правке:

1. Планировщик собирает актуальную картину стен и границ зон.
2. Определяет, какие замкнутые области получились — это новые комнаты.
3. Переносит сохранённые атрибуты старых комнат на новые (по пересечению площади).
4. Пересчитывает форму уже существующих полов под новую форму комнаты (ручные полы сохраняются и ужимаются).
5. Заполняет полом по умолчанию только те участки новых комнат, где после шага 4 пола не осталось.
6. Обновляет потолки под форму соответствующих полов.
7. Пересобирает плинтус по всем стенам, с разрывами под проёмами.
8. Проверяет зоны — те, что потеряли опору или пересекли новые стены, удаляются.

**Момент проверки зон.** Шаг 8 выполняется **до** шагов 1–2: зона, потерявшая опору, не должна участвовать в сборке областей — иначе её границы на один прогон режут геометрию и в списке мелькает комната, которой нет. Нумерация шагов оставлена прежней, изменён только момент проверки (правка «спека ← код», решение автора 2026-08-20; техника — ADR 0017 C6, реализация — задача 0075).

**Триангуляция.** Полы, потолки и зоны — не просто полигоны, а разбиение на треугольники (это то, что видит 3D-движок). Пользователь этого не видит напрямую, но на очень сложных сценах с сотнями комнат может ощутить короткую паузу перед отрисовкой — это как раз пересборка триангуляции.

**Пересборка при загрузке проекта.** При открытии сохранённого проекта редактор доверяет сохранённым точкам, контурам и атрибутам как единому источнику правды и выполняет обычную пересборку — ту же, что после любой правки контура (шаги 1–8 выше). Производное (тела стен, комнаты, авто-полы, потолки, плинтусы, триангуляция) в проекте не хранится и строится заново; атрибуты комнат пере-привязываются к новым комнатам по перекрытию площади, ручные полы ужимаются под комнаты, проёмы заново привязываются к осям (см. [03 — Проёмы](03-openings.md), «Оси стен»). Отдельного «облегчённого» режима загрузки без пересборки нет (решение 2026-08-18; см. ADR 0016). Записи с отсутствующими ссылками пропускаются молча. Форматы разных версий читаются через forward-compat парсер (совместимость назад).

**Undo/redo для авто-производных объектов.** Автопроизводные объекты (комнаты, полы, потолки, плинтусы, зоны) складываются в тот же снимок редактора стен, что и явно поставленные точки контура (см. [01 — Стены](01-walls-and-contours.md), «Транзакции undo/redo редактора стен»). Одно пользовательское действие = один снимок, где зафиксирован уже пересобранный набор комнат/полов/потолков. Undo возвращает всё вместе, атрибуты (название, материалы, высота) наследуются на новую комнату по перекрытию площади со старой — как при обычной пересборке.

**Порядок обработки полов.** Когда в одной комнате несколько полов и один вложен в другой (например, вырез под внутреннюю комнату внутри основного пола), планировщик обрабатывает их от меньшего к большему. Пользователь этого не видит, но именно поэтому вложенные вырезы корректно оказываются дырками именно во внешнем полу, а не съедают его целиком.

## Крайние случаи

**Комната внутри комнаты.** Если пользователь рисует замкнутый контур стен внутри уже существующей комнаты, внешняя комната получает «дырку» на месте внутренней, а внутренняя становится самостоятельной комнатой. Пол внешней комнаты автоматически получает вырез под форму внутренней. У внутренней — свой пол, свой потолок, свой плинтус. Если внутреннюю комнату потом удаляют, дырка автоматически зарастает — дефолтный пол внешней комнаты заполняет освободившееся место. Если удаляют **внешнюю** комнату — удаление каскадное: вместе с ней уходят все вложенные комнаты и их полы/потолки/плинтусы (принято по reference; откат — обычный undo одним шагом).

**Точка пола совпадает с точкой комнаты.** Если пользователь при ручном рисовании пола ставит точку ровно в угол комнаты, планировщик распознаёт совпадение и «приваривает» точку пола к точке комнаты. Совпадение ловится тем же снап-магнитом, что и в рисовании стен (см. [01 — Стены](01-walls-and-contours.md), раздел «Снап») — если точка отпущена в пределах снап-радиуса угла, они срастаются. Когда пользователь потом двигает угол комнаты, соответствующий угол пола едет вместе.

**Удаление комнаты.** Комната исчезает вместе со своими полами, потолком, плинтусом и всеми зонами, лежавшими внутри неё. Поведение мебели: **настенная** мебель (картины, розетки, встроенная сантехника) пытается перепривязаться к оси ближайшей стены в радиусе 10 см; если стены рядом нет — молча удаляется со сцены, UI показывает событие «объект снят со стены». **Напольная** мебель остаётся на своих мировых координатах, даже если под ней больше нет пола — предмет «висит на нулевой высоте». Отдельного состояния «без опоры» нет, пометки в UI тоже. Детали — в [04 — Мебель](04-furniture.md).

**Пересечение зон и отклонение зоны.** Если новая зона накладывается на существующую (не касается, а именно пересекает) или пересекает стены комнаты — новая отклоняется. Пользователь получает молчаливый отказ — контур не сохраняется. Модалок/тостов с объяснением в v0 нет; фейл-подсветку конфликтного участка проектируем отдельно, не в v0.

**Слияние соседних полов.** Два сценария:

- Если новый пол **пересекается** с существующим полом той же комнаты — объединение происходит автоматически, без запроса.
- Если новый пол лишь **касается** границей существующего (contact) — пользователю показывается модалка «Объединить?» с явным выбором. «Да» — полы объединяются в один с материалом активного (последнего нарисованного). «Нет» (и Esc — эквивалент «Нет») — новый пол остаётся отдельным, границы примыкают вплотную, каждый со своим материалом.
- Диалог «Объединить?» существует **только при ручном рисовании пола**. Если два ранее раздельных пола **пересеклись** косвенно — из-за правки стен, — они объединяются автоматически, без запроса (принято по reference: диалог посреди перетаскивания стены не поднимаем).
- Автоматическое слияние **по касанию** относится только к **автоматическим** полам. У пола хранится признак «нарисован вручную», и такие полы при касании **сами собой** не сливаются ни с автоматическим полом, ни друг с другом (по явному «Да» в модалке — сливаются, см. пункт выше) — иначе multi-material пол («несколько полов бок о бок, каждый со своим материалом») был бы недостижим в принципе. Признак заводится вместе с инструментом рисования пола (правка «спека ← код», решение автора 2026-08-20).

**Осиротевшие внутренние полы.** Если после правки стен внутренний пол (дырка) остаётся без внешнего пола-хозяина, он удаляется. Пользователь не увидит «висящий в воздухе вырез».

**Вырожденные комнаты.** Если пользователь случайно строит очень узкую или очень маленькую замкнутую область (например, две почти совпадающие точки создают «щель»), планировщик её отбрасывает как невалидную. Такие микро-комнаты не появляются в списке и не получают пола.

**Дублирование материалов пары пол-потолок.** По умолчанию потолок и пол имеют разные материалы (пол — «пол», потолок — «потолок»). Смена материала пола не тянет за собой смену материала потолка, и наоборот. Пользователь редактирует их независимо в свойствах комнаты.
