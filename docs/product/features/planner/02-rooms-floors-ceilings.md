# 02 — Комнаты, полы, потолки (v0)

> Раздел feature-spec planner-v0. Единицы: 1 см = 1 юнит.

## Что это

Комнаты, полы и потолки — производные объекты сцены, которые пользователь напрямую не рисует. Он строит контуры стен (см. [01 — Стены](01-walls.md)), а планировщик сам определяет, какие замкнутые области получились, и заводит для каждой:

- **комнату** — замкнутую область, ограниченную стенами;
- **пол** — горизонтальную поверхность внутри комнаты на нулевой высоте;
- **потолок** — зеркальную копию пола на высоте комнаты;
- **плинтус** — «бортик» вдоль всех стен комнаты на уровне пола.

Дополнительно пользователь может вручную рисовать **зоны** — участки со сниженным потолком (арки, ниши, антресоли).

Ключевая идея: пользователь не думает в терминах «полигон комнаты». Он рисует стены — комната появляется сама. При любой правке стен весь набор комнат/полов/потолков/плинтусов пересобирается заново. Персистентные атрибуты (название, материалы, высота потолка) переезжают на новую комнату автоматически по перекрытию площади.

## Модель контур-first

Пользователь не выделяет комнату мышью, чтобы «создать» её. Он рисует замкнутый контур стен — и как только контур замыкается, внутри появляется комната с полом, потолком, плинтусом по всему периметру и материалами по умолчанию.

Правило простое: комнаты **выводятся** из текущего рисунка стен. Никакого «списка комнат», который пользователь ведёт вручную, нет. Из этого следуют важные для UX эффекты:

- Дорисовал внутреннюю стенку через комнату — она делится на две.
- Стер стену между двумя комнатами — они сливаются в одну.
- Разомкнул контур — комната исчезает (пол/потолок/плинтус вместе с ней).
- Замкнул обратно — комната появляется снова, и её сохранённые атрибуты (название, материалы, высота потолка) возвращаются, если новая форма пересекается со старой по площади.

Пересборка запускается автоматически на каждой правке контура и не требует явного «применить».

## Комнаты

**Что это для пользователя.** Комната — это замкнутая область стен с общим полом, потолком и плинтусом. Комната несёт название, высоту потолка, материалы пола/потолка/плинтуса (см. [06 — Материалы](06-materials-textures.md)) и служит контейнером для мебели.

**Как создаётся.** Автоматически при замыкании контура стен. Никакого отдельного инструмента «создать комнату» нет.

**Как выбирается.** Клик с Ctrl (или клик по пустой области внутри комнаты, если стены при этом не хватаются) переключает выбор на комнату. Панель свойств комнаты открывает управление её атрибутами.

**Свойства комнаты.**

- Название (свободный текст).
- Высота потолка (по умолчанию 280 см) — задаётся на уровне комнаты, влияет и на потолок, и на верхнюю границу стен внутри комнаты.
- Материал пола, потолка, плинтуса — детали в [06 — Материалы](06-materials-textures.md).
- Видимость потолка — можно скрыть у конкретной комнаты.

**Сохранение атрибутов при правках.** После правки стен старая комната формально исчезает и на её месте появляется новая. Планировщик переносит атрибуты автоматически: новая комната наследует данные той старой, с которой у неё есть пересечение по площади. Пользователь этого не замечает — он просто видит, что «моя гостиная» осталась гостиной после того, как он передвинул стену.

## Полы

**Что это для пользователя.** Пол — горизонтальная поверхность на нулевой высоте внутри комнаты. По умолчанию комната сразу получает пол по всему своему внутреннему контуру.

**Автоматический пол.** Как только образуется новая комната, планировщик автоматически заполняет её пол материалом по умолчанию. Пользователю не нужно ничего делать. Дефолтный пол создаётся только в тех местах комнаты, где нет ни одного пола, поставленного вручную (или унаследованного через пересечение площади со старой формой). Ручные полы после правки стен _сохраняются_ и лишь ужимаются под новую форму — они не «съедаются» дефолтом.

**Multi-material пол.** Пользователь может «нарезать» пол на зоны с разными материалами — например, паркет в жилой части и плитка у входа. Для этого есть отдельный инструмент рисования пола: пользователь обводит участок внутри комнаты, задаёт ему свой материал, участок становится самостоятельным полом внутри комнаты. Внутри одной комнаты может лежать несколько полов бок о бок.

**Внешний контур пола против дырок в полу.** У пола есть внешняя граница и, при необходимости, дырки — например, вырез под лестницу, шахту лифта или «второй свет». Дырка в полу — это отдельный «пол-вычитание», нарисованный внутри основного. Планировщик сам определяет, что внутренний контур лежит внутри внешнего, и превращает его в дырку.

**Что происходит с полом при перерисовке стен.** При правке контура стен планировщик пересчитывает форму пола, ужимая его до новой формы комнаты. Материалы и разбиение на участки переносятся на новые полы по тому же правилу перекрытия площади, что и для комнат. Если пользователь снёс стену и объединил две комнаты, полы обеих комнат остаются на своих местах со своими материалами — они просто оказываются в одной комнате.

**Удаление комнаты.** Если комната исчезает (стены разомкнуты или удалены), её полы уходят вместе с ней. Пользователь может явно удалить пол и оставить комнату без покрытия — тогда пола просто не будет в 3D.

## Потолки

**Что это для пользователя.** Потолок — зеркальная копия пола, поднятая на высоту комнаты. Форма 1-в-1 повторяет форму пола, включая дырки. У каждой комнаты — свой потолок; у каждого multi-material пола внутри комнаты — свой кусок потолка сверху.

**Видимость потолка.** Потолок автоматически скрывается, когда мешает обзору:

- В виде сверху (top-view / dollhouse) потолки прячутся, чтобы пользователь видел планировку изнутри.
- При камере ниже потолка (walk-through, обычный 3D-обзор с уровня человека) — потолок показывается.
- Пользователь может дополнительно принудительно скрыть потолок конкретной комнаты в свойствах комнаты.

Логика «когда потолок исчезает» работает автоматически по положению камеры относительно высоты комнаты (потолок скрыт, если камера выше потолка комнаты) и не требует ручного переключения. Дополнительный флаг «скрыть потолок этой комнаты» в свойствах комнаты работает поверх авто-логики: если юзер явно снял видимость — потолок не показывается даже когда камера ниже него.

**Высота потолка.** Задаётся на уровне комнаты (по умолчанию 280 см). Изменение высоты одной комнаты не трогает соседние. Несколько multi-material полов внутри одной комнаты не могут иметь разные высоты потолка — потолок один на всю комнату. Локальное понижение потолка (например, над кухонным гарнитуром) моделируется отдельной зоной со своей высотой (см. «Зоны»).

## Плинтусы

**Что это для пользователя.** Плинтус — «бортик» вдоль всех стен комнаты на уровне пола. Появляется автоматически по периметру каждой комнаты, без отдельных действий пользователя.

**Форма профиля.** Планировщик поставляет 16 базовых форм профиля плинтуса: 8 нижних (собственно плинтус, у пола) и 8 верхних (потолочный молдинг, у потолка). Верхние формы — зеркальные копии нижних. Пользователь выбирает форму в свойствах комнаты, отдельно для нижнего и верхнего.

**Разрывы под проёмами.** Плинтус автоматически прерывается там, где в стене стоит проём — дверь или окно, доходящее до пола. Если проём проходит выше плинтуса (окно на уровне груди), плинтус под ним не прерывается. Правило простое: плинтус существует там, где стена не «пробита» до уровня пола.

**Материал плинтуса.** Задаётся на уровне комнаты, применяется ко всему периметру. Нижний и верхний плинтус имеют отдельные материалы.

## Зоны (Areas)

**Что это для пользователя.** Зона — участок внутри комнаты со сниженным потолком. Используется для арок, ниш, антресолей, подшивных потолков над кухонным гарнитуром.

**Отличие от комнаты.**

- Зона не имеет собственных стен — только контур на плане.
- Зона не создаёт отдельной комнаты в списке — она живёт внутри существующей.
- Зона имеет собственную высоту (по умолчанию 100 см — уровень «навесной» конструкции).
- Визуально зона показана заливкой на плане и «крышкой» на своей высоте в 3D.

**Как рисуется.** Отдельным инструментом «Зона» (см. [01 — Стены](01-walls.md), раздел инструментов). Пользователь обводит контур внутри комнаты, замыкает, задаёт высоту в появившемся диалоге.

**Пересечения.** Правила отбраковки:

- Зона не может пересекать стены комнаты — её граница должна целиком лежать внутри существующей комнаты (или касаться стен, но не пересекать их).
- Зоны не могут пересекаться между собой. Могут только касаться границами.
- Попытка нарисовать зону, нарушающую эти правила, отклоняется без сохранения.
- Если после правки стен зона теряет опору (её точки больше не совпадают с новыми стенами комнаты — с учётом того же снапа «точка к углу», что и в рисовании стен), зона удаляется автоматически.

Разница между двумя типами конфликта:

- Во время **рисования зоны** (пользователь только что довёл контур и замкнул) — конфликт (самопересечение, пересечение существующей зоны или стен) означает мгновенный отказ: контур не сохраняется, ничего не появляется на сцене.
- При **автоматической пересборке после правки стен** — конфликт уже сохранённой зоны означает её удаление. Пользователь не получает диалога — зона просто исчезает вместе с падением опоры.

**Что видит пользователь.** Внутри комнаты появляется область, у которой в 3D — своя крышка на заданной высоте. Пол зона не меняет. Стены комнаты внутри зоны автоматически «укорачиваются» до высоты зоны — их верхняя часть скрыта её потолком.

## Автоматическая перестройка (rebuild)

**Что чувствует пользователь.** Любая правка контура стен — добавление, удаление, перетаскивание точки или ребра — мгновенно триггерит пересчёт комнат, полов, потолков, плинтусов, зон. Никакого «применить» или «пересобрать» нет.

**Что происходит внутри (продуктово, не техника).** На каждой правке:

1. Планировщик собирает актуальную картину стен и границ зон.
2. Определяет, какие замкнутые области получились — это новые комнаты.
3. Переносит сохранённые атрибуты старых комнат на новые (по пересечению площади).
4. Пересчитывает форму уже существующих полов под новую форму комнаты (ручные полы сохраняются и ужимаются).
5. Заполняет полом по умолчанию только те участки новых комнат, где после шага 4 пола не осталось.
6. Обновляет потолки под форму соответствующих полов.
7. Пересобирает плинтус по всем стенам, с разрывами под проёмами.
8. Проверяет зоны — те, что потеряли опору или пересекли новые стены, удаляются.

**Триангуляция.** Полы, потолки и зоны — не просто полигоны, а разбиение на треугольники (это то, что видит 3D-движок). Пользователь этого не видит напрямую, но на очень сложных сценах с сотнями комнат может ощутить короткую паузу перед отрисовкой — это как раз пересборка триангуляции.

**Пересборка при загрузке проекта.** При открытии сохранённого проекта редактор доверяет сохранённой геометрии как единому источнику правды (точки контуров по id, всё производное — id-референсы) и восстанавливает производные структуры без полной пересборки 3D-геометрии. Полная 3D-пересборка запускается только при первой правке контура. Записи с отсутствующими ссылками пропускаются молча. Форматы разных версий читаются через forward-compat парсер (совместимость назад).

**Undo/redo для авто-производных объектов.** Автопроизводные объекты (комнаты, полы, потолки, плинтусы, зоны) складываются в тот же снимок редактора стен, что и явно поставленные точки контура (см. [01 — Стены](01-walls.md), «Транзакции undo/redo редактора стен»). Одно пользовательское действие = один снимок, где зафиксирован уже пересобранный набор комнат/полов/потолков. Undo возвращает всё вместе, атрибуты (название, материалы, высота) наследуются на новую комнату по перекрытию площади со старой — как при обычной пересборке.

**Порядок обработки полов.** Когда в одной комнате несколько полов и один вложен в другой (например, дырка под лестницу внутри основного пола), планировщик обрабатывает их от меньшего к большему. Пользователь этого не видит, но именно поэтому вложенные вырезы корректно оказываются дырками именно во внешнем полу, а не съедают его целиком.

## Крайние случаи

**Комната внутри комнаты.** Если пользователь рисует замкнутый контур стен внутри уже существующей комнаты, внешняя комната получает «дырку» на месте внутренней, а внутренняя становится самостоятельной комнатой. Пол внешней комнаты автоматически получает вырез под форму внутренней. У внутренней — свой пол, свой потолок, свой плинтус.

**Точка пола совпадает с точкой комнаты.** Если пользователь при ручном рисовании пола ставит точку ровно в угол комнаты, планировщик распознаёт совпадение и «приваривает» точку пола к точке комнаты. Совпадение ловится тем же снап-магнитом, что и в рисовании стен (см. [01 — Стены](01-walls-and-contours.md), раздел «Снап») — если точка отпущена в пределах снап-радиуса угла, они срастаются. Когда пользователь потом двигает угол комнаты, соответствующий угол пола едет вместе.

**Удаление комнаты.** Комната исчезает вместе со своими полами, потолком, плинтусом и всеми зонами, лежавшими внутри неё. Поведение мебели: **настенная** мебель (картины, розетки, встроенная сантехника) пытается перепривязаться к оси ближайшей стены в радиусе 10 см; если стены рядом нет — молча удаляется со сцены, UI показывает событие «объект снят со стены». **Напольная** мебель остаётся на своих мировых координатах, даже если под ней больше нет пола — предмет «висит на нулевой высоте». Отдельного состояния «без опоры» нет, пометки в UI тоже. Детали — в [04 — Мебель](04-furniture.md).

**Пересечение зон и отклонение зоны.** Если новая зона накладывается на существующую (не касается, а именно пересекает) или пересекает стены комнаты — новая отклоняется. Пользователь получает молчаливый отказ — контур не сохраняется. Модалок/тостов с объяснением в v0 нет; фейл-подсветку конфликтного участка проектируем отдельно, не в v0.

**Слияние соседних полов.** Два сценария:

- Если новый пол **пересекается** с существующим полом той же комнаты — объединение происходит автоматически, без запроса.
- Если новый пол лишь **касается** границей существующего (contact) — пользователю показывается модалка «Объединить?» с явным выбором. «Да» — полы объединяются в один с материалом активного (последнего нарисованного). «Нет» — новый пол остаётся отдельным, границы примыкают вплотную, каждый со своим материалом.

**Осиротевшие внутренние полы.** Если после правки стен внутренний пол (дырка) остаётся без внешнего пола-хозяина, он удаляется. Пользователь не увидит «висящий в воздухе вырез».

**Вырожденные комнаты.** Если пользователь случайно строит очень узкую или очень маленькую замкнутую область (например, две почти совпадающие точки создают «щель»), планировщик её отбрасывает как невалидную. Такие микро-комнаты не появляются в списке и не получают пола.

**Дублирование материалов пары пол-потолок.** По умолчанию потолок и пол имеют разные материалы (пол — «пол», потолок — «потолок»). Смена материала пола не тянет за собой смену материала потолка, и наоборот. Пользователь редактирует их независимо в свойствах комнаты.

## Уточнения по итогам аудита (закрытые из reference)

- **Удаление внешней комнаты с вложенной**: внутренняя становится самостоятельной комнатой; её пол, потолок, плинтус и мебель сохраняются со своими атрибутами.
- **Ручной пол при сжатии комнаты**: обрезается по новой границе автоматически, висящих кусков не остаётся.
- **Косвенное пересечение полов через правку стен**: применяется то же правило, что при ручном рисовании нового пола — INTERSECT автомёрдж, CONTACT диалог (см. «Слияние соседних полов»).
- **Частичная потеря опоры зоны**: любая одна точка зоны, не переснапившаяся к новой геометрии, → зона удаляется целиком (нет частичной адаптации).
- **Отмена диалога «Объединить полы?»** через «Нет» / Esc: новый пол остаётся отдельной сущностью, границы примыкают вплотную.
- **Наследование «скрыть потолок» при слиянии комнат**: атрибуты донирует первая старая комната того же outer-типа, чья площадь пересекается с новой (тот же механизм overlap, что и для имени/материалов). Юзер не увидит «выигрыш случайной комнаты» — правило детерминировано.
- **Дырка в полу после удаления внутренней вложенной комнаты**: зарастает автоматически (дефолтный пол внешней комнаты заполняет освободившееся место).
- **Разделение комнаты пополам**: обе новые комнаты по правилу overlap могут унаследовать атрибуты старой (обе с ней пересекаются). На практике первая по порядку обхода получает атрибуты, вторая — тоже, если её площадь тоже пересекается со старой. Оба «клона» — норма и не должны юзера удивлять.

## Открытые вопросы

- **Раздельная видимость крышки зоны в top-view.** Ведёт ли «крышка» зоны себя так же, как потолок комнаты (скрывается сверху), или всегда видна как заливка плана — не критично для v0, уточняется по мере обкатки UX 3D-обзора.
- **Пауза при первом изменении большого проекта.** Спека декларирует «ленивую» полную 3D-пересборку — только при первой правке контура после загрузки. У roomtodo этой оптимизации явно не видно (там полная сборка при чтении). Валидировать на сцене 100+ комнат: если пауза «первого mouseDown» ощущается — либо реально сделать lazy, либо честно пересобирать всё на open и признать паузу при загрузке.
