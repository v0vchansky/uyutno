# 06 — Выделение, трансформация, группировка (v0)

> Раздел feature-spec planner-v0. Единицы: 1 см = 1 юнит.

## Что это

Слой прямого манипулирования сценой: как пользователь выбирает мебель, стены, полы, комнаты и проёмы; как он двигает, крутит, ресайзит и флипает выбранное; как объединяет несколько предметов в группу и как копирует их в другое место сцены или в другой проект. Ключевой продуктовый контракт: результат любого клика — это либо «ничего не выбрано», либо «выбран объект/группа» с плавающей контекстной панелью у курсора, куда UI собирает быстрые действия.

## Виды выделения

- Одиночный клик по объекту — снимает старое выделение, выделяет новый. Клик без модификаторов по члену уже выделенной группы распускает группу и оставляет выделенным только этот один объект.
- Клик по пустой зоне — снимает всё выделение и скрывает быстрые панели.
- Ctrl/Cmd+клик по второму предмету мебели — создаёт временную группу из двух предметов.
- Ctrl/Cmd+клик по члену уже существующей группы — убирает его из группы (toggle); если в группе остаётся 1 предмет — группа автоматически распускается, оставшийся становится обычным выделением.
- Ctrl/Cmd+клик по постороннему предмету, находясь в выделенной группе — добавляет предмет в группу.
- Двойной клик по объекту в группе — descend to single-select: группа распускается, выделенным остаётся только этот один член (то же, что одиночный клик; оставлено как знакомый жест Figma/Sketch).
- Rubber-band (протяжка прямоугольника) в v0 не реализуется. Мультивыделение — только через Ctrl/Cmd-клик.
- **Группа в v0 — только временная** (multi-select). Она живёт, пока выделена: клик мимо, Esc, одиночный клик по члену — распускают её. Закреплённых (persistent, «Сгруппировать»/Ctrl+G) групп в v0 нет — они в [backlog.md](backlog.md); в проект группы не сохраняются.
- Shift+клик как «расширение диапазона» в v0 отсутствует.
- Ctrl/Cmd+A «выделить всё» в v0 не вводится — мультивыделение существует только в форме группы, а «выделить всю сцену одной командой» пользовательского сценария под собой не имеет.

## Что можно выделять

- Отдельный предмет мебели (свободностоящий или настенный).
- Отдельный элемент конструктива в 3D: стена, пол, потолок — как носители материала (кликом в 3D-виде при активном «режиме правки конструктива»).
- Группа мебели.
- Точки контура, стены и комнаты — через отдельный 2D-редактор плана (см. раздел «Стены»).

Правила смешивания:

- Мебель и конструктив не конкурируют в одном клике: набор кликаемых объектов зависит от активного режима (мебельный vs конструктивный). Одновременно выделить предмет мебели и элемент конструктива нельзя — это два взаимоисключающих режима.
- **Переключение режима мебель ↔ конструктив молча снимает текущее выделение** (и закрывает контекстные панели) — ровно как Esc. Никакого «запомнить и восстановить при возврате» и никаких confirm'ов: выделение — не правка, терять нечего; в редакторе ровно одно состояние выделения (принцип «один автомат»). В reference поведение не определено; решение 2026-08-17.
- В одну группу нельзя добавить настенные предметы — только свободностоящую мебель.
- В одну группу нельзя добавить конструктив (стены/полы/потолки).
- Группа + одиночный предмет вне группы одновременно быть выделены не могут: выделение всегда либо один объект, либо одна группа.

## Гизмо трансформации

**Перемещение (drag)**

- Активируется тем же ЛКМ, которым был сделан клик по объекту: если после нажатия курсор ушёл дальше ~5 пикселей (порог драг-vs-клик), начинается перетаскивание.
- Драг **не стартует, пока зажат Ctrl/Cmd** — нажатие с Ctrl/Cmd всегда трактуется как клик добавления/исключения из группы, а не как начало перемещения без снапа (как в reference). Отключить снап Ctrl-ом можно только зажав его _после_ того, как драг уже начался.
- Перетаскивание происходит по горизонтальной плоскости на текущей высоте объекта.
- Настенная мебель во время драга «прилипает» к ближайшей стене: магнит к оси срабатывает в радиусе ~20 см (визуальное прилипание), финальная посадка на mouseUp — в радиусе ~10 см (иначе объект удаляется, см. раздел «Крайние случаи»).
- Промежуточные положения во время драга в историю не пишутся — фиксируется только финальное положение на mouseUp. То же правило действует для гизмо-вращения, гизмо-масштаба и правки размеров/трансформа слайдерами/числовыми полями: один шаг истории на релиз/blur, промежуточное — не сохраняется.

**Клик vs драг**

- Порог: движение курсора после нажатия ЛКМ меньше 5 пикселей — событие считается кликом (выбор объекта). 5 пикселей и больше — драг (перетаскивание).

**Вращение**

- В 3D-виде — гизмо в виде трёх колец (X/Y/Z) вокруг предмета, активируется отдельным режимом «повернуть в 3D». Набор колец одинаков для напольной и настенной мебели: настенный предмет тоже вращается свободно по всем трём осям, ограничения «только вокруг оси стены» нет (принято по reference; пересмотреть, если на юзер-сессиях розетки/картины начнут «уезжать» со стены).
- В 2D-плане — вращение через контекстные кнопки (шаг 90°, произвольный угол — через ввод в правой панели).
- По окончании вращения угол округляется до целых градусов.
- Быстрая панель на время вращения прячется и появляется снова по завершении.

**Ресайз (только в 2D-плане)**

- 4 маркера ресайза по серединам сторон повёрнутого прямоугольника предмета.
- Каждая ось тянется независимо, без сохранения пропорций.
- Настенная мебель имеет только 2 маркера (по ширине).
- Минимальный размер стороны через грип — 2 см; максимум — общий кламп объекта 10 м (см. ниже «Ограничения»).
- Ресайз недоступен, если у модели включён «фиксированный размер».
- Во время вращения ресайз-маркеры прячутся.

**Флип**

- Отражение по горизонтальной и по фронтальной оси — через контекстные кнопки в быстрой панели / боковой панели.

**Пропорциональный масштаб**

- Правится числами в правой панели (ввод множителя или размера); этот путь параллельный ресайз-маркерам.
- Числовые поля/слайдеры размеров и elevation работают только для одиночного выделения; при multi-select они задизейблены (как в reference) — групповой размер меняется только гизмо-масштабом.

**Индикация**

- Активный хендл (кольцо, маркер) подсвечивается на hover и во время драга.
- Общая обводка выделения — цветной контур по силуэту объекта (жёлто-оранжевый), а не bounding-box.
- Hover до клика в v0 контуром не подсвечивает: hover-outline на мебель/стены/группы не вводим. Единственный hover — на своих линейках (см. 07-measurements), у них подсветка меняет цвет линии.

## Копирование / вставка

**Ctrl/Cmd+C**

- Копирует активную мебель, активную группу или активный конструктив (в последнем случае — только материал и его параметры укладки, без геометрии).
- В буфере — один слот (перезаписывается каждой копией). Слот живёт в localStorage браузера под ключом с идентификатором пользователя (как `r2d_clipboard_<key>` у reference): переживает перезагрузку и закрытие вкладки, общий между вкладками одного пользователя в этом браузере; не чистится ни при загрузке проекта, ни при выходе из аккаунта — только перезаписью следующей копией (решение 2026-08-17).

**Ctrl/Cmd+V**

- Если под курсором есть валидная точка сцены (пол/поверхность) — предмет/группа кладутся точно под курсор.
- Если под курсором нет попадания — одиночный предмет вставляется рядом с оригиналом со сдвигом на собственную ширину (чтобы копия не легла ровно поверх). Группа при таком клике не вставляется вовсе — вставка выполняется только с реальной точкой под курсором.
- Для мебели, стоящей на стене, при вставке подбирается ближайшая валидная стена.
- В перспективной камере угол поворота копии дополнительно доворачивается к ближайшему кратному 90° относительно текущего разворота камеры.
- Каждая вставка фиксируется в истории.

**Что копируется**

- Позиция, поворот, размер, флипы, масштаб.
- Ссылка на модель каталога и её материалы.
- Для параметрических моделей — их конфигурация.
- Для света — его настройки.
- Для группы — состав + трансформ группы. После вставки вставленные копии становятся новой временной группой (активное выделение); оригинальная выборка снимается.
- Для настенной мебели связь «мебель ↔ конкретная стена» при копировании не сохраняется: в буфер уходят только параметры оформления рамы/подложки. На вставке объект попадает под курсор и заново прилипает к ближайшей стене в радиусе 10 см (та же процедура, что при drop'е из каталога). То есть «розетка со стены A» перепривяжется к стене B, если пользователь вставил её под курсором на стене B. Если рядом с точкой вставки нет валидной стены, копия настенного предмета ложится со сдвигом на собственную ширину от оригинала.

**Копирование материала конструктива**

- Ctrl/Cmd+C на выделенной грани конструктива (стена/пол/потолок/плинтус/зона) кладёт в буфер **материал грани**: базовый материал, финиш, поворот и смещение текстуры. Копия включает **и базу, и финиш** — в отличие от reference, где финиш в копию не попадал и вставка его сбрасывала; у нас финиш — полноценный второй слот и копируется вместе с базой (см. [05 — Материалы](05-materials.md), «Применение к стенам» и «Копирование материала между поверхностями»; решение 2026-08-17). Геометрия не копируется.
- Ctrl/Cmd+V при выделенной грани конструктива применяет материал из буфера к этой грани — один шаг истории, как обычное применение материала. Если в буфере мебель, а выделена грань (или наоборот) — вставка no-op.
- Отдельный инструмент «пипетка» (клик по грани → её материал становится активным) — в [backlog.md](backlog.md).

**Кросс-проектный буфер**

- Системный буфер обмена ОС в v0 **не используется** — ни на запись, ни на чтение (решение 2026-08-17; у reference планировщик в ОС-буфер тоже не пишет, там есть лишь односторонний мост «внешний сайт → планировщик»).
- Перенос между вкладками и между проектами нашего редактора идёт через тот же localStorage-буфер (см. «Копирование / вставка»): скопировал в одной вкладке/проекте — Ctrl/Cmd+V в другой вкладке/проекте того же пользователя в этом браузере вставляет как обычно; повторный Ctrl/Cmd+V вставляет снова, пока не сделан новый Ctrl/Cmd+C. Так переносятся и одиночный предмет, и группа, и материал конструктива — всё, что умеет локальный буфер.
- Мост из ОС-буфера (вставка модели извне — с сайта/каталога) — в [backlog.md](backlog.md#мост-из-системного-буфера-ос).

## Дублирование (без буфера)

- Отдельное действие «дублировать» из контекстной панели / горячей клавиши — не трогает буфер обмена.
- Ставит копию в ближайшую свободную соседнюю ячейку (сдвиг на ширину/глубину предмета); если места нет — сообщение «недостаточно места» / «за границами сцены».
- Дублирование группы кладёт копию сбоку от оригинала (сдвиг на ширину габаритного прямоугольника).

## Группировка

**Создание группы**

- Основной жест — Ctrl/Cmd+клик по второму предмету (см. раздел «Виды выделения»). Мультивыделение существует только в форме группы; отдельного «списка выделенных» нет.
- Кнопки «Сгруппировать» в v0 нет — группа всегда временная.
- Rubber-band-протяжка для набора «выделить ≥ 2» в v0 не вводится.

**Разгруппировка**

- Клик по пустой зоне, Esc или одиночный клик по члену при выделенной группе — распускает группу.
- Отдельной кнопки «Разгруппировать» не нужно — группа распускается вместе со снятием выделения.
- Сборка/роспуск временной группы — это состояние выделения, а не правка сцены: в историю не пишется, Ctrl+Z распущенную выборку не возвращает (см. [09 — Undo/Redo](09-undo-redo.md), «Что НЕ попадает в историю»). В историю попадают только трансформации/удаление, сделанные над группой.

**Закреплённые (merged) группы — не в v0**

- В reference группа несёт флаг `merged` (переживает клик мимо, сохраняется в проект). У нас в v0 такого флага нет: любая группа — временная и исчезает, как только теряет выделение. Persistent-группы — в [backlog.md](backlog.md).

**Что становится группой**

- Реальная сущность сцены со своим пивотом, габаритами и трансформом.
- Пивот группы — центр габаритного прямоугольника по горизонтали, низ — по вертикали.
- Пивот пересчитывается автоматически при любом изменении состава группы (Ctrl-клик добавил/убрал член, удаление предмета) — по новому габаритному прямоугольнику. Юзер видит «прыжок» центра вращения при добавлении крупного предмета — это ожидаемое поведение, а не баг.

**Трансформация группы**

- Перемещение, поворот, флип, пропорциональный масштаб применяются к группе как к целому; члены наследуют трансформ.
- Групповой драг проходит через тот же snap-контракт, что и одиночный объект: магнетизм считается по внешнему 2D-прямоугольнику группы; Ctrl/Cmd на драге отключает магнетизм. На релизе mouseUp фиксируется один шаг истории.
- Внутрь группы во время её выделения зайти к отдельному члену можно двойным кликом по нужному члену — выборка распускается, остаётся выделенным только этот один объект (см. «Виды выделения»). Отдельного режима «редактирование состава группы» нет.

**Ограничения группы**

- Настенная мебель в группу не берётся.
- Конструктив (стены/полы) в группу не берётся.
- Вложенные группы (группа внутри группы) в v0 не поддерживаются: одновременно существует не более одной (временной) группы — активной выборки; ссылки на членство хранятся как обратный указатель `объект→группа` на время её жизни.

**Удаление группы**

- Delete на выделенной группе удаляет всех её членов одним шагом истории; сама группа как выборка исчезает вместе с ними.

## Удаление

- Клавиши Delete и Backspace удаляют активный предмет / активную группу.
- Удаление предмета, стоящего у стены, разрывает связь с этой стеной.
- Удаление предмета, входящего в группу, уменьшает состав группы; если в группе остался 1 предмет — группа автоматически распускается.
- Удаление последнего оставшегося члена группы фиксируется одним шагом истории: финальное состояние (без объекта и без вырожденной группы) записывается одной записью, отдельного шага «группа исчезла» нет.
- Удаление игнорируется, когда фокус в поле ввода.
- Каждое удаление фиксируется в истории.

## Клавиатурный нудж

- Стрелки и WASD двигают активный предмет / активную группу; активный материал конструктива тоже двигается стрелками (сдвиг узора по грани).
- Базовый шаг — 1 см; Shift — 10 см; Shift+Ctrl/Cmd — 0.1 см.
- В имперской системе единицы — дюймы/футы (шаг тот же, но в дюймах).
- Если ничего не выделено — стрелки двигают камеру.
- По отпусканию клавиши WASD движение фиксируется в истории.
- Модификатор Ctrl/Cmd отключает snap только во время мышиного драга; на клавиатурный нудж он не влияет (для стрелок работают только Shift ×10 и Shift+Ctrl/Cmd ×0.1).

## Snap-поведение

- При драге предметы «магнитятся» к линиям стен и к габаритным прямоугольникам других предметов; радиус магнита — около 15 см.
- При магните к стене доводится и угол поворота предмета.
- Snap группы включён по умолчанию; удержание Ctrl/Cmd во время драга временно отключает snap.
- Настенные предметы при драге всё время идут по стенам, при отпускании — окончательно «сажаются» на ближайшую валидную стену.

## Outline / подсветка выделения

- Активное выделение обводится ярким цветным контуром по силуэту объекта (пост-эффект по глубине сцены).
- Цвет обводки — жёлто-оранжевый (референс), в v0 берём фирменный акцентный из темы.
- Bounding-box вокруг выделения не рисуется — только контур.
- Разные цвета для hover vs select v0 не вводит.

## Контекстная плавающая панель

- Сразу после выделения у курсора появляется маленький тулбар с быстрыми действиями.
- Позиция панели — экранные координаты курсора (или курсора со смещением вверх на пару десятков пикселей для конструктива и walls-редактора), а не проекция 3D-точки.
- Панель прячется на время драга и вращения и появляется снова по завершении жеста.
- Клик по пустой зоне и по «линейке» скрывает все панели.
- Состав кнопок панели зависит от типа выделения. Ядро планера отдаёт UI-слою дескриптор `{state, type?, quickPanel:{x,y}}`; state — один из: выделенный продукт, выделенная группа, выделенный конструктив (с уточнением типа: стена/пол/потолок/зона/плинтус), выделенная комната, выделенная линейка. Конкретный состав кнопок для каждого state — отдельный feature-spec «Контекстные панели».

## Escape и возврат в «пусто»

- Esc снимает текущее выделение и возвращает сцену в состояние «ничего не выбрано».
- Одновременно закрываются все контекстные панели.

## Ограничения

- Ресайз-маркеры в 2D — фиксированного размера ~7 px, не масштабируются с зумом.
- Гизмо-кольца вращения в 3D — размер не зависит от габарита объекта: радиус пропорционален расстоянию от камеры до объекта (внутренний радиус = дистанция/10, толщина = дистанция/400; в 2D дистанция берётся как (1 − zoom) × 1250), пересчитывается при каждом повороте/пане/зуме камеры — визуально кольца примерно постоянного экранного размера и для вазы, и для дивана. Во время вращения активное кольцо «растягивается» до точки курсора (радиус ≤ 300 см), после отпускания возвращается к расчётному. Принято по reference.
- Размер объекта клампится на уровне самого объекта в **[1 см, 10 м]** по любой стороне — для грипов, числового ввода и гизмо-масштаба одинаково (как в reference). Грип-ресайз дополнительно не даёт уйти ниже 2 см. Те же числа — в [04 — Мебель](04-furniture.md), «Ограничения и пороги».
- Snap-радиус магнита при драге — 15 см.
- Порог различения клика и драга — 5 px.
- Порог старта драга — 1 px после первого сдвига.
- Округление угла вращения — до целых градусов; при вставке в перспективе — до кратных 90°.
- Границы сцены по горизонтали фактически не ограничены (клампа нет) — v0 задаёт свои разумные лимиты отдельно.
- Одновременно может быть выделен только один объект или одна группа (нет мультивыделения списком).
- Locked-объекты (isLockedOnScene) не участвуют в выделении, драге, группировке и нудже. Режим «призраков» скрытых элементов (полупрозрачные силуэты того, что спрятано) в v0 не делаем — [backlog.md](backlog.md#режим-призраков-скрытых-элементов); базовое скрыть/показать остаётся как есть (решение 2026-08-17).
- Клик сквозь стены в 3D не работает: пиккер возвращает первое пересечение по глубине, стена в передней позиции перехватывает клик. Чтобы кликнуть в предмет, спрятанный за стеной, стену сначала нужно временно скрыть через отдельный механизм видимости конструктива (реестр «скрытых элементов»).

## Крайние случаи

- Клик по пустой зоне — снимает выделение, скрывает все контекстные панели.
- Клик мимо у группы — распускает её (закреплённых групп в v0 нет).
- Удаление предпоследнего члена группы — авто-роспуск, оставшийся становится обычным выделением.
- Ctrl/Cmd+клик по настенному предмету при попытке группировки — предмет в группу не берётся.
- Paste без валидной точки под курсором — копия ложится рядом с оригиналом со сдвигом на ширину.
- Paste в другой проект / вкладку — через тот же localStorage-буфер (в рамках браузера и пользователя); ОС-буфер в v0 не используется (решение 2026-08-17; см. «Кросс-проектный буфер»).
- Paste группы — вставленные копии становятся новой временной группой; списка групп в сцене нет.
- Нажатия клавиш игнорируются, когда фокус в поле ввода / текстовом редакторе.
- Настенная мебель, потерявшая стену (стена удалена): предмет пытается перепривязаться к оси ближайшей стены в радиусе 10 см; если такой оси нет — предмет удаляется из сцены с уведомлением UI (событие «объект уехал со стены»). Он не «падает» на пол.
- Смена режима мебель ↔ конструктив при активном выделении — выделение снимается молча (см. «Правила смешивания»).
