# 12 — Каталог (v0)

> Раздел feature-spec planner-v0. Единицы: 1 см = 1 юнит. AI-рендеринг, экспорт GLTF/OBJ/PDF/360, платные функции — вне v0.

## Что это

Каталог — основной источник контента для сцены: пользователь **перетаскивает мебель и проёмы** из библиотеки прямо на планировку через native HTML5 DnD. **Материалы из каталога drag'ом не применяются** — они выбираются через модалку каталога, открытую из панели свойств выделенной поверхности (см. [05 — Материалы](05-materials.md), «Каталог материалов»).

В v0 каталог наполняется только нашим собственным контентом. Пользовательских загрузок (своих GLB-моделей, своих текстур) нет — ни кнопок «Upload», ни вкладки «My uploads»; фича целиком в [backlog.md](backlog.md#custom-uploads-пользовательские-модели-и-текстуры).

## Каталог (browsing)

### Категории мебели (Furniture)

- Диваны, кресла, столы, стулья
- Шкафы, комоды, стеллажи
- Кровати, тумбы, матрасы
- Кухни и техника
- Освещение
- Декор (лампы, вазы, растения)

_(Плинтус — это не мебель, а материально-профильная надстройка комнаты; он задаётся в свойствах комнаты и в каталог мебели не попадает — см. [02 — Комнаты](02-rooms-floors-ceilings.md) и [05 — Материалы](05-materials.md).)_

### Категории проёмов (Openings)

> **Осознанное отклонение.** Арки и дверные проходы без створок вынесены в отдельную UI-категорию «Проёмы» рядом с «Дверями» и «Окнами». Reference-реализации обычно моделируют это как тип двери с прозрачной/пустой створкой без отдельного раздела в каталоге; мы отделяем категорию, чтобы пользователь, которому нужен «просто проход», нашёл его напрямую, не разбираясь в типах дверей.

Отдельная секция каталога рядом с мебелью и материалами, три категории:

- **Двери** — со створкой (одностворчатые, двустворчатые, раздвижные).
- **Окна** — с рамой и стёклами.
- **Проёмы** — арки, дверные проходы без створок, декоративные ниши. Технически проём = дверь с пустой моделью створки, но в UI-каталоге лежит отдельной категорией, чтобы пользователь сразу нашёл «нужен проход без двери».

Размещение проёмов на стенах — по правилам раздела 03 «Проёмы»: drop на ось стены, привязка к стене, elevation, flip.

### Категории материалов (Materials)

- Обои и покраска (для стен)
- Плитка (стены и пол)
- Ламинат, паркет, линолеум (для пола)
- Ковры
- Постеры и картины (на стену)
- Чистый цвет (color picker) — без текстуры

### Skyboxes (небо/окружение)

Отдельный раздел каталога с эквиректангулярными панорамами для 3D-сцены (см. [08 — Камеры и виды](08-cameras-views.md), раздел «Небо и окружение»). Пользователь выбирает панораму как обычный элемент каталога (клик по карточке применяет её к скайбоксу текущей 3D-сцены). Drag на канвас для skybox не работает — только клик-select. В v0 набор небольшой (3–5 базовых).

Панорамы неба живут своим разделом каталога и не смешиваются с обычными материалами. Обычный материал (обои, ламинат) на skybox через панель материалов или drag'ом не применяется, и наоборот — панорама неба выбирается только из своего раздела каталога.

### Навигация каталога

- Дерево категорий с подкатегориями.
- Поиск по каталогу (текстовый, по названию/тегам). Поиск — отдельный режим панели, а не фильтр внутри дерева: при входе в поиск дерево категорий сворачивается (тумблер дерева в шапке результатов скрыт), при выходе из поиска обратно в каталог — раскрывается в прежнее состояние; ранее выбранная категория при этом сохраняется. Подсветки «в каких категориях нашлось» нет. Один запрос на Enter/клик по лупе, без параметра категории. Принято по reference.
  - **Пустой результат поиска** — empty-state «Ничего не найдено. Попробуйте другой запрос» и кнопка «Сбросить», которая очищает поле и возвращает в каталог (дерево раскрывается в прежнее состояние, прежняя категория активна). В reference спецсостояния нет; решение 2026-08-17.
- **Пустая категория / пустой каталог** — вместо пустой сетки показывается заглушка «Здесь пока пусто — мы наполняем каталог». Пустые категории из дерева **не прячем**: пользователь видит структуру каталога. На старте MVP это ожидаемое состояние многих разделов. В reference плейсхолдера нет; решение 2026-08-17.
- Фильтры по категории/размеру/цвету (визуальная механика фильтров — задача дизайна каталога, не планера).
- Превью-миниатюры (thumbnail) для каждого элемента.
- Список категории грузится **целиком одним запросом**, без пагинации и без догрузки по скроллу; тяжёлое — только картинки, они lazy-load по мере прокрутки. Поиск — так же, целиком. Позиция скролла категории запоминается при уходе/возврате. Принято по reference; пересмотреть, если размер категории перевалит за несколько сотен карточек.
- Избранное (favorites): помеченные пользователем элементы каталога вынесены в отдельную вкладку. Избранное хранится на сервере per-user и синхронизируется между устройствами при входе (локальный кэш только в памяти, ничего в браузерное хранилище не сохраняем). Один и тот же товар в разных цветовых вариантах избраннится независимо: ключ — пара «товар + вариант цвета». Гостям (без входа) избранное недоступно: вкладка «Избранное» у гостя в каталоге не показывается.

### Drag & drop на сцену

- Из панели каталога элемент перетаскивается на сцену через **native HTML5 Drag & Drop** (`dataTransfer`). Никаких кастомных event-шин, никаких сторонних библиотек типа react-dnd — native-API покрывает сценарий полностью.
- Панель каталога на `dragstart` кладёт в `dataTransfer` JSON-payload вида `{type, itemId, previewURL}`.
- Канвас слушает `dragover`/`drop`; превью drag'а показывается через `dataTransfer.setDragImage(thumbnail)`.
- При наведении на сцену показывается превью размещения (позиция + ghost-объект).
- Отпускание фиксирует объект в позиции курсора; вставка — один шаг undo.
- Подробности размещения по типам — в разделах 04 «Мебель» и 05 «Материалы». Материалы из каталога drag'ом **не** применяются: карточки материалов **не draggable** (`draggable=false`, `dragstart` не стартует) — «случайного drag'а» материала физически не бывает, поэтому ни тултипа, ни игнора не нужно; применение материала идёт через свойства выделенного объекта (см. 05). В reference drag материала (mousedown + документные mousemove/mouseup, превью 28×28) поддержан — осознанное отклонение.

### Региональность каталога

В v0 каталог единый для всех регионов; региональные подборки в MVP не делаем.

## Каталог в v0

- В v0 UX каталога следует привычным отраслевым паттернам, но контент — свой; в MVP каталог может быть маленьким или пустым
- Экономически: редактор бесплатен; платные ветки (AI, рендер, экспорт) — вне v0

## Клавиатура и мышь

| Действие                             | Клавиша/жест                   |
| ------------------------------------ | ------------------------------ |
| Перетащить элемент каталога на сцену | Drag & drop                    |
| Открыть панель каталога              | Клик по иконке каталога        |
| Поиск по каталогу                    | Ввод в поле поиска             |
| Добавить в избранное                 | Клик по «сердечку» на карточке |

## Ограничения и пороги (константы UX)

- Превью-миниатюра в каталоге: 240×240 px

## Крайние случаи

- **Каталожный элемент удалён из библиотеки после того, как использован в проекте.** При открытии проекта редактор пытается подгрузить метаданные каждого сохранённого объекта из каталога. Если товара в каталоге больше нет — объект в сцене просто не создаётся; остальная сцена собирается штатно и не падает. Плейсхолдера на месте пропавшего объекта в v0 нет — он молча пропускается (принято по reference; плейсхолдер по сохранённым габаритам — кандидат в бэклог, если на юзер-сессиях всплывут жалобы на «дыры»). Отличать от временной ошибки загрузки: если товар в каталоге есть, но модель не скачалась — работает сценарий из [10 — Save/Load](10-save-load.md) (плейсхолдер + плашка «N объектов не удалось загрузить», повтор). При попытке добавить в проект такой же товар — карточка помечена «недоступно» в каталоге, drag & drop отклоняется.
- **Избранное на удалённом из каталога товаре.** Избранное хранится по товару (и варианту цвета), а не по проекту: удаление проекта не чистит избранное. Если сам товар удалён из каталога — он **скрывается из списка избранного** (сервер отдаёт во вкладку «Избранное» только живые товары; запись избранного при удалении товара чистится или отфильтровывается на сервере). Никаких «серых» карточек с плашкой «недоступно» в v0 нет. Решение 2026-08-17.
- **Модель, не влезающая в сцену по габаритам.** Размещается, но UI показывает подсказку «предмет заметно больше комнаты».
- **Skybox без выбранной панорамы.** Дефолтный фоновый градиент (см. 08), никаких «пустых сфер».
- **Пустой поиск / пустая категория** — empty-state'ы, см. «Навигация каталога».
