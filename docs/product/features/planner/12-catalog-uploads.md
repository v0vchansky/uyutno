# 12 — Каталог и пользовательские загрузки (v0)

> Раздел feature-spec planner-v0. Единицы: 1 см = 1 юнит. AI-рендеринг, экспорт GLTF/OBJ/PDF/360, платные функции — вне v0.

## Что это

Каталог — основной источник контента для сцены: пользователь **перетаскивает мебель и проёмы** из библиотеки прямо на планировку через native HTML5 DnD. **Материалы из каталога drag'ом не применяются** — они выбираются через модалку каталога, открытую из панели свойств выделенной поверхности (см. [05 — Материалы](05-materials.md), «Каталог материалов»).

В v0 каталог наполняется нашим собственным контентом. Пользовательские загрузки (свои GLB-модели, свои текстуры) в MVP не поддерживаются — фича вынесена как отдельная задача L-размерности в [backlog.md](backlog.md) «Custom uploads». Раздел «Загрузка моделей / материалов» ниже описан как задел на будущее и в MVP не реализуется.

## Каталог (browsing)

### Категории мебели (Furniture)

- Диваны, кресла, столы, стулья
- Шкафы, комоды, стеллажи
- Кровати, тумбы, матрасы
- Кухни и техника
- Освещение
- Декор (лампы, вазы, растения)

_(Плинтус — это не мебель, а материально-профильная надстройка комнаты; он задаётся в свойствах комнаты и в каталог мебели не попадает — см. [02 — Комнаты](02-rooms-floors-ceilings.md) и [05 — Материалы](05-materials.md).)_

### Категории проёмов (Openings)

> **Осознанное отклонение.** Арки и дверные проходы без створок вынесены в отдельную UI-категорию «Проёмы» рядом с «Дверями» и «Окнами». Reference-реализации обычно моделируют это как тип двери с прозрачной/пустой створкой без отдельного раздела в каталоге; мы отделяем категорию, чтобы пользователь, которому нужен «просто проход», нашёл его напрямую, не разбираясь в типах дверей.

Отдельная секция каталога рядом с мебелью и материалами, три категории:

- **Двери** — со створкой (одностворчатые, двустворчатые, раздвижные).
- **Окна** — с рамой и стёклами.
- **Проёмы** — арки, дверные проходы без створок, декоративные ниши. Технически проём = дверь с пустой моделью створки, но в UI-каталоге лежит отдельной категорией, чтобы пользователь сразу нашёл «нужен проход без двери».

Размещение проёмов на стенах — по правилам раздела 03 «Проёмы»: drop на ось стены, привязка к стене, elevation, flip.

### Категории материалов (Materials)

- Обои и покраска (для стен)
- Плитка (стены и пол)
- Ламинат, паркет, линолеум (для пола)
- Ковры
- Постеры и картины (на стену)
- Чистый цвет (color picker) — без текстуры

### Skyboxes (небо/окружение)

Отдельный раздел каталога с эквиректангулярными панорамами для 3D-сцены (см. [08 — Камеры и виды](08-cameras-views.md), раздел «Небо и окружение»). Пользователь выбирает панораму как обычный элемент каталога (клик по карточке применяет её к скайбоксу текущей 3D-сцены). Drag на канвас для skybox не работает — только клик-select. В v0 набор небольшой (3–5 базовых).

### Навигация каталога

- Дерево категорий с подкатегориями.
- Поиск по каталогу (текстовый, по названию/тегам).
- Фильтры по категории/размеру/цвету — см. «Открытые вопросы».
- Превью-миниатюры (thumbnail) для каждого элемента.
- Способ прокрутки длинных списков (пагинация / бесконечная лента) — см. «Открытые вопросы».
- Избранное (favorites): помеченные пользователем элементы каталога вынесены в отдельную вкладку.

### Drag & drop на сцену

- Из панели каталога элемент перетаскивается на сцену через **native HTML5 Drag & Drop** (`dataTransfer`). Никаких кастомных event-шин, никаких сторонних библиотек типа react-dnd — native-API покрывает сценарий полностью.
- Панель каталога на `dragstart` кладёт в `dataTransfer` JSON-payload вида `{type, itemId, previewURL}`.
- Канвас слушает `dragover`/`drop`; превью drag'а показывается через `dataTransfer.setDragImage(thumbnail)`.
- При наведении на сцену показывается превью размещения (позиция + ghost-объект).
- Отпускание фиксирует объект в позиции курсора; вставка — один шаг undo.
- Подробности размещения по типам — в разделах 04 «Мебель» и 05 «Материалы». Материалы, к слову, из каталога drag'ом **не** применяются: применение материала идёт через свойства выделенного объекта (см. 05).

### Региональность каталога

В v0 каталог единый для всех регионов. Региональные подборки — открытый вопрос (см. раздел ниже).

## Пользовательские загрузки — в MVP не включаются

> Пользовательские 3D-модели (`.glb`), собственные текстуры/обои/ковры/постеры, вкладка «My uploads» — **вне v0 планера**. Фича вынесена как отдельная задача L-размерности в [backlog.md](backlog.md#custom-uploads-пользовательские-модели-и-текстуры).

В MVP:

- Кнопки «Upload custom model» / «Upload custom material» в UI **не появляются**.
- Вкладки «My uploads» в каталоге **нет**.
- Все sub-questions по форматам, лимитам, per-part материалам, автогенерации 2D-иконки, «публичная модель», синхронизации между устройствами — решаются на этапе активации фичи (список — в backlog).

Раздел оставлен здесь как якорь: когда фича активируется, соответствующая часть спеки переносится сюда из backlog.

## Каталог в v0

- В v0 UX каталога следует привычным отраслевым паттернам, но контент — свой; в MVP каталог может быть маленьким или пустым
- Обязательное поведение drag & drop, превью и лимитов загрузок — по устоявшемуся отраслевому образцу, чтобы пользовательский рефлекс не ломался
- Экономически: сам редактор + загрузки бесплатны; платные ветки (AI, рендер, экспорт) — вне v0

## Клавиатура и мышь

| Действие | Клавиша/жест |
|---|---|
| Перетащить элемент каталога на сцену | Drag & drop |
| Открыть панель каталога | Клик по иконке каталога |
| Поиск по каталогу | Ввод в поле поиска |
| Добавить в избранное | Клик по «сердечку» на карточке |
| Открыть загрузку | Кнопка «Upload…» в панели каталога |
| Отменить загрузку/предпросмотр | Esc / крестик в попапе |

## Ограничения и пороги (константы UX)

- Превью-миниатюра в каталоге: 240×240 px
- Лимиты для пользовательских загрузок (модели ≤ 60 МБ, ≤ 60 000 треугольников, ≤ 50 частей; текстуры ≤ 20 МБ) относятся к фиче Custom uploads из backlog, в v0 планера не применяются.

## Крайние случаи

- **Каталожный элемент удалён из библиотеки после того, как использован в проекте.** В существующих проектах экземпляр остаётся (он ссылается на снапшот модели из save-envelope). При попытке добавить ещё один такой же — карточка помечена «недоступно» в каталоге, dnd отклоняется.
- **Модель, не влезающая в сцену по габаритам.** Размещается, но UI показывает подсказку «предмет заметно больше комнаты».
- **Skybox без выбранной панорамы.** Дефолтный фоновый градиент (см. 08), никаких «пустых сфер».

## Уточнения по итогам аудита (закрытые из reference)

- **Favorites** — хранятся на сервере per-user (GET/PUT/DELETE эндпоинты); синхронизируются между устройствами автоматически, не через localStorage. Локальный кэш в памяти обновляется на успешный ответ сервера. Guest-favorites — не поддерживаем (для гостя вкладку «Избранное» скрываем).
- **Skybox vs материалы** — skybox это просто категория каталог-товаров с тегом `category_tag=skybox`. Обычный материал (обои, ламинат) на skybox _не применяется_ — это разные типы, каталог их не смешивает.
- **Каталожный элемент удалён из библиотеки, а он был в проекте** — экземпляр остаётся в сцене; если 3D-геометрия при open проекта не грузится (модель удалена совсем), объект отображается плейсхолдером, сцена не падает. При попытке добавить ещё один такой — карточка помечена «недоступно», dnd отклоняется.
- **Favorites на моделях из удалённого проекта** — favorites хранятся по productId (не по projectId); удаление проекта не чистит favorites. Если сам товар удалён из каталога — остаётся в favorites, но не грузится (плейсхолдер + пометка).

## Открытые вопросы

- **Пагинация или бесконечная лента.** Для больших разделов каталога нужен способ навигации. Обычно бесконечная лента приятнее пользователям, но пагинация проще для «вернуться к 5-й странице». Дизайн-решение после первой сборки каталога.
- **Механика фильтров.** Категория, размер, цвет — как визуально устроены (dropdowns, chips, боковая панель). Задача каталог-дизайнера, не самого планера.
- **Поведение дерева категорий во время поиска.** Когда юзер начинает поиск — дерево сворачивается / остаётся видимым / подсвечивает найденные категории? Валидировать на первой сборке каталога.
- **Кто и как наполняет каталог из коробки** (наш арт, партнёрство с брендами, free CC-паки) — see README «Открытые вопросы верхнего уровня».
- **Региональные подборки.** Разные регионы — разный контент? В MVP не решаем, каталог единый.
- **Пустой результат поиска (нужно продуктовое решение)** — UX не описан ни в reference, ни у нас. Предложение: показывать плашку «Ничего не найдено. Попробуйте другой запрос» + кнопку «Сбросить фильтры». Дерево категорий — оставить видимым.
- **Пустой каталог в MVP (нужно продуктовое решение)** — на самом старте каталог может быть очень маленьким. Предложение: показывать заглушку «Каталог наполняется. Начните с рисования стен, мебель добавим скоро» — а не пустую сетку.
- **DnD карточки материала на канвас (нужно продуктовое решение)** — по нашему решению материалы применяются только через панель свойств. При случайном drag'е материала: (а) молчаливое игнорирование, (б) короткий tooltip «Материалы применяются через свойства выделенного объекта». Второй вариант учит юзера правильному паттерну.
- **Element заметно больше комнаты (нужно продуктовое решение)** — сейчас размещается «с подсказкой». Кандидат: не блокировать, но показывать плашку «Предмет заметно больше комнаты — уменьшить?» с кнопкой авто-подгонки под комнату.
