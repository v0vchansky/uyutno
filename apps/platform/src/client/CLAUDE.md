# Конвенции внутренней раскладки клиентских модулей — `src/client/`

Этот файл описывает **что лежит внутри клиентского модуля**. Список самих модулей, граф импортов и registry-паттерн — в [ADR 0007](../../../../docs/adr/0007-arhitektura-proekta-moduli.md).

## Структура модуля

Каждый модуль внутри `src/client/` может содержать:

```
feature/
├── api/          # запросы к серверу
├── components/   # переиспользуемые компоненты модуля
├── hooks/        # хуки специфичные для модуля
├── lib/          # утилитарные функции
├── pages/        # страницы (компоненты роутов)
└── index.ts      # публичный API модуля
```

Не все директории обязательны — создавай только те что нужны. `pages/` есть только у модулей со страницами (`landing`, `project`, `application`); у модулей-библиотек (`auth`, `planner`, `core`, `common`) страниц нет.

## Модуль `application`

Особый модуль, в котором собирается всё приложение. Содержит корневой React-компонент, роутинг, глобальные провайдеры, сборку `Registry`. Только то что нужно для сборки приложения, не для бизнес-логики.

## Страницы (`pages/`)

- Страница — это компонент который маппится на роут
- Каждая страница — **обязательно папка**, даже если там один файл
- Страница может содержать layout-компоненты специфичные только для неё

```
pages/
└── SettingsPage/
    ├── SettingsPage.tsx
    └── SettingsLayout.tsx  # только если нужен layout для этой страницы
```

- Бизнес-логику выносить в хуки, не держать в странице. Исключение — совсем простые случаи (пара `useState`), но осознанно
- Тяжёлые компоненты не являющиеся страницами (визарды и т.п.) — в `components/`, не в `pages/`

## Компоненты (`components/`)

- `components/` — плоская структура, только папки компонентов без вложенных группировок
- Каждый компонент — **обязательно папка**
- Подкомпоненты используемые только внутри одного компонента лежат рядом в той же папке

```
components/
└── FunnelItem/
    ├── FunnelItem.tsx        # основной компонент
    └── FunnelItemStatus.tsx  # подкомпонент, только для FunnelItem
```

- Нет `index.ts` внутри папки компонента — импорт напрямую из файла
- Правило **«один компонент — один файл»**: если компонент сильно разрастается — выноси части в подкомпоненты. До 500–700 строк в одном файле — норм
- Компонент используемый только в одном месте — может лежать рядом с родителем, **только если родитель тоже компонент** (не страница). Если родитель — страница, компонент идёт в `components/`
- Провайдеры называются `SomeProvider` и кладутся в `components/`

## API (`api/`)

- Один файл — один запрос
- Использовать фабрики `createQuery` / `createMutation` из модуля `common`
- Прямой `useQuery` / `useMutation` допустим только если фабрики не подходят
- Единственный HTTP-клиент — из модуля `core` (см. ADR 0007), модули не создают свой
- Все внешние API проксируются через backend, клиент работает только с `/api/v1`

```ts
// feature/api/getSomething.ts
import { api } from 'core';
import { createQuery } from 'common';

export const getSomethingQuery = createQuery({
  queryKey: ['something'],
  queryFn: () => api.get('/something'),
});
```

## Хуки (`hooks/`)

- `common/hooks/` — только хуки которые используются в нескольких модулях одновременно
- Хук специфичный для одного модуля — в `hooks/` того модуля
- Именование: `useCamelCase.ts`

## Lib (`lib/`)

Утилитарные функции модуля. Не хуки, не компоненты.

## Тесты

- Co-location: `foo.ts` + `foo.test.ts` лежат рядом. Никаких `__tests__/`.

## Типизация компонентов

Все React-компоненты типизируются как `React.FC` (или `React.FC<Props>`, если есть пропсы). Единый визуальный маркер «это компонент», отличает от обычных функций. Импорт — `import type React from 'react'`: только тип, без runtime-стоимости.

```tsx
import type React from 'react';

export const HomePage: React.FC = () => { ... };

interface Props {
  userId: string;
}

export const UserCard: React.FC<Props> = ({ userId }) => { ... };
```

Правила про раскладку типов и констант (без `types.ts` / `constants.ts`, циклические `import type` — норма) — общие для клиента и сервера, см. [`../../CLAUDE.md`](../../CLAUDE.md).

## Именование

| Что                  | Формат                       |
| -------------------- | ---------------------------- |
| Компоненты, страницы | `PascalCase.tsx`             |
| Хуки                 | `useCamelCase.ts`            |
| Утилиты, API         | `camelCase.ts`               |
| Папки модулей        | `kebab-case` или `camelCase` |
